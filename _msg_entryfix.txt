A - PROJECTION PROVENANCE: THREE BYPASSES FOUND, NOW CLOSED
  Reproduced before the fix, each reaching Omega10/Omega11 and reading an unrevealed node:
    A1 Direct `TrustedPublicProjection(... revealed_nodes=(7,9) ..., snapshot_identity=None)`
       -> projection gate OK, binding reported BOUND, Omega11 OK, Omega10 OK, QUALITY_LB_OK.
    A2 `projection_from_revealed_maps(..., snapshot_identity=None)` -> same.
    A3 the legacy callable path, whose `_legacy_projection` set tw_start = 0 AND identity None
       -> same.
  The two root causes were located in source: `m1b_q2_certifier.py` guarded the binding check
  with `if projection.snapshot_identity is not None and ...`, so None SILENTLY SKIPPED it; and
  `isinstance(projection, TrustedPublicProjection)` was the only qualification test while both
  the class constructor and the diagnostic helper were public entry points.
  IMPORTANT: all three had composite False, but ONLY because of the later continuous-thermal
  gate. That is exactly why each layer is reported separately rather than treating a later
  refusal as evidence that the earlier gates were sound.
  THE FIX: a module-level factory token plus an issuance registry, so only
  `build_projection_from_env` can mint a certifiable projection; `snapshot_identity=None` is
  refused AT CONSTRUCTION; the certifier compares the snapshot identity unconditionally; a new
  `projection_challenge()` digests every trusted field and binding and is recomputed after
  certification so a trusted field cannot be swapped; and the certifier INDEPENDENTLY re-verifies
  the visible set against `env.reveal_time`, so a declaration exceeding what the environment
  reveals is refused even if it somehow carried a valid token. Diagnostic and legacy
  constructors now produce objects the certifier refuses, so the legacy callable path cannot
  certify anything at all.
  Honest scope recorded: the token and registry are an in-process PROTOCOL boundary, not
  cryptographic isolation against arbitrary malicious code.

B - PROOF PARAMETER INTEGRITY: TWO BYPASSES FOUND, NOW CLOSED
  B1 overriding `per_class_constants` with `{q0_safe: 1e6, rate_per_hour: 0.0}` produced
     `QUALITY_LB_OK` with q_lb = 1e6 against a contract-true 8.548.
  B2 `t_min = 1e6` collapsed H_max to 0 so q_lb degenerated to the initial value 8.999999999.
  THE FIX: a non-None `per_class_constants` is now REFUSED, so quality parameters come only
  from the identity-certified contract (recorded in a new `quality_parameters` receipt gate with
  the contract hash); and `t_min` is accepted only through `verified_t_min` accompanied by an
  `env` witness, otherwise the conservative clock origin 0.0 is used and `t_min_source` records
  which applies. Rates, thresholds, time unit and initial-value tolerance remain contract- or
  constant-derived and consistent with the proof's applicability domain.
