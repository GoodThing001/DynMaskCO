G0 residual-risk counterexamples: 7 fixes confirmed by execution, A-3b confirmed still open

The P0 audit named residual risks and classified them by reading the source. This change makes the
confirmation EXECUTABLE on the current code, and separates two things that a single "detected"
boolean would have conflated:

  FIX_CONFIRMED        the risk is closed -- the code now refuses or reports correctly
  RISK_CONFIRMED_OPEN  the risk is real and still open -- the code cannot see it (a FINDING)

8 counterexamples, 7 FIX_CONFIRMED, 1 RISK_CONFIRMED_OPEN:

  A-2  no certifier        -> the transaction refuses with reason 'no_certifier', zero installs
  A-2  certified A/B       -> installing a plan that is not the certified one is refused with
                              'certified_plan_identity_mismatch'
  A-4b reference mutation  -> the ledger stores a VALUE COPY; mutating the caller's plan object
                              afterwards cannot change what was recorded
  A-4b unhashable plan     -> a plan whose identity cannot be computed is refused, never installed
                              on a None identity
  A-5d no rollback_fn      -> reported as rollback_unverified / committed_state_restored=False,
                              NOT as a completed restoration
  A-5d with rollback_fn    -> reported as committed_state_restored with exactly one call
  A-5b double finish       -> the second finish is refused ('already_finished'), one install total
  A-3b committed prefix    -> CONFIRMED STILL OPEN: the sampler moves a customer that already sits
                              in a committed route, i.e. the adapter has no committed-prefix guard.
                              The real guard lives on VehicleState + the B mask pool; the audit
                              already recorded that a same-named fake field in the adapter would
                              not fix it. Recorded as an open finding, not as a pass.

The first run of A-3b routed the probe through the install gate and produced a false "detected"
from an unrelated failure; that run is not kept as evidence and the scenario was rewritten as a
direct mechanism check. Its artifact also now classifies A-3b as RISK_CONFIRMED_STILL_OPEN rather
than counting it among the closed items.

This does NOT qualify G0. Still open: state certification (G-L), real-write uniqueness (G-C), the
conservative quality guarantee, A-3b above, and the fact that an install receipt cannot observe the
environment's own commit. No live install, no F forward, no comparison, no training.
