## 3. 三项边界锁定（用户 2026-10-14 指定）

### 3.1 自对照**不能**要求新旧源码 SHA 相同

> 「原 REV2」§2 曾写"**同代码身份**" —— **该表述作废**：
> C2 一旦增加记录字段，新版源码 SHA **必然改变**。

**登记版定义**：

| 项 | 规定 |
|---|---|
| 主对照 | **冻结的旧版实现**（§8.1 的 SHA 全集）为**唯一**主对照 |
| 待验证方 | 新版实现，登记为 **TO_BE_FROZEN**（§8.2 变更清单 + 冻结时的 SHA） |
| 必须一致 | **策略配置**（`K`、`time_limit`、`inner_gate`、`arm_seed`、`p_c`、`energy_pricing`、`future_policy`）、**决策输入**（同决策点集合与 digest）、**随机流**（同种子与同抽样器构造）、**判据**（§5/§7） |
| 允许差异 | **仅限** §8.2 白名单内的事前列明**诊断实现**；白名单外任何字节差异 ⇒ 视为**算法改变** ⇒ §10 分叉② |
| 必须记录 | ① 旧版完整 SHA；② 新版**变更清单**（文件 / 函数 / 行区间 / 语义说明）；③ **行为一致性验收方法**（§7）；④ 新版冻结时的 SHA |

### 3.2 `not_applicable` 必须以**真实求值路径**为准

> 「原 REV2」§4.1 把 `B − e_o < 0` 时的**另一预算分支**列为 `not_applicable` 的例子
> —— **该例子作废**。

**源码事实（只读核对）**：`CC_Compare/tools/role_c_opportunity_cost.py:151-157`

```
b      = float(budget)
b_lo   = b - e                       # 可能为负
infeasible = b_lo < 0.0
b_lo_eval  = max(b_lo, 0.0)          # 下界**截到 0**
try:
    v_hi = float(future_value_fn(b))
    v_lo = float(future_value_fn(b_lo_eval))     # ← **仍然求值**
```

⇒ `B − e_o < 0` 时下界被**截到 0 并继续计算**，
**`lo` 预算点是被真实进入的**。

**登记版规定**：

* **凡真实进入过的预算分支，一律不得标记为"未执行"或 `not_applicable`**；
  此时 `lo` 的状态按 §4.1 的真实结果判定（可完成、可超时、可 `forward_invalid`），
  并**另外**置 `lo_clipped_to_zero = true`、`b_lo_raw = b − e_o`（保留原始负值）以示区分；
* `not_applicable` **只**允许用于**结构性确实不适用**的场合，且必须给出该结论的**路径证据**
  （例如该分支**根本没有被调用**）；
* `not_entered` **只**允许用于**按设计短路、未进入前瞻**的路径
  （如 `e_o <= 0` 的 B1 早退、`insertion_infeasible` 硬短路），并须由边界字段证明。

### 3.3 fallback 去重：必须先定义"同一决策内是否允许重复回退"

> 「原 REV2」§4.2.2 把 `n_fallbacks` 按 `(decision_point, fallback_kind)` 去重
> —— **该规则不完整**。

**登记版规定**：

* 先声明**是否允许同一决策内重复回退**：
  * 若**允许** ⇒ **必须**为每次回退分配**独立事件 ID**（`event_id`），
    计数按 `event_id` 去重；**不得**因为两次回退 `fallback_kind` 相同就自动合并成一次；
  * 若**不允许** ⇒ 必须给出**结构性理由**（为什么同决策至多一次），
    并在实现中加**断言/护栏**（违反即 `execution_error`，而不是静默合并）；
* 同一条规则**同时适用于** `n_deadline_timeouts` 与 `n_execution_errors`：
  按 `(decision_point, event_id)` 去重，**同一决策内多次抛错不得计成多个决策超时**；
* **未声明** ⇒ 不允许进入 L1（属登记不完整）。

## 4. 分类契约（**两预算点**；登记版）

**两轴**：先给每个预算点记子状态，再合成总状态。

| 字段 | 取值 |
|---|---|
| `hi.status` / `lo.status` | 见下表 |
| `hi.n_scenarios_entered` / `hi.n_scenarios_completed` | `0..K` |
| `lo.n_scenarios_entered` / `lo.n_scenarios_completed` | `0..K`（`lo` 被截到 0 时**仍然**适用，见 §3.2） |
| `lo.b_lo_raw` / `lo.lo_clipped_to_zero` | 保留原始 `B − e_o`（可为负）与截断标记 |
| `n_budget_points_entered` | `0 / 1 / 2` |
| `n_budget_points_completed` | `0 / 1 / 2`；**`== 2` 才允许总状态 `completed`** |

| 类别 | 含义 | 判定证据 |
|---|---|---|
| `completed` | **两个**预算点都跑完 `K` 个场景 | 进度/事件 |
| `deadline_timeout` | 前瞻没跑完，且**有异常路径证据**表明是硬截止打断（按**异常类型**，**不是**文案） | 异常路径 |
| `forward_invalid` | 前瞻**跑完**但 `Ĵ` 非有限或差分未定义 ⇒ `λ_B` 未定义 | 数值 + `forward` 原文诊断 |
| `infeasible` | 事前边界规则命中（`B2_budget_out_of_range`）或无可行插入位 | 边界字段 |
| `execution_error` | 其它异常（非 `DecisionTimeout`）导致前瞻未完成 | 异常路径 |
| `not_entered` | 按设计**未进入**前瞻（B1 早退等） | 边界字段 |
| `not_applicable` | **结构性确实不适用**，且给出路径证据 | 路径证据 |
| `unknown` | 证据不足 | —— |

* `forward_invalid` 与 `deadline_timeout` **必须可分**（现状都压成 `B3_lambda_undefined`）；
* **未取得证据一律 `unknown`**，不得默认成某一因；
* `evaluation_status`（进度可证）与 `timeout_cause`（需异常路径证据）**分开存放**；
  `timed_out` **不蕴含** `deadline_timeout`；
* 分类**只进诊断与归档**，**不改判决行为**。

## 5. 四通道规格（登记版）

| 通道 | 要独立回答 | 最小实现要求 | 核验方式 |
|---|---|---|---|
| **C1 行为回退** | 发生时系统做了什么？ | 落盘 `fallback_applied`、`fallback_kind`、**`event_id`**、回退前候选计划、回退后计划 | 归档逐决策点重放：回退种类与 `action`/`plan` 一致 |
| **C2 异常来源** | 被什么打断？ | 在捕获点记录 `exception_type` / `exception_stage` / `budget_point(hi\|lo)` / `hard_deadline_exception`（`isinstance(exc, DecisionTimeout)`）/ `evaluation_status` / `event_id` / `decision_point`；**必须绕过 B3 分支的诊断丢弃**进入**决策记录**；**原 B3 拒单路径不变** | 合成反例（按类型注入）+ 真数据字段非空且取值在枚举内 |
| **C3 超时计数** | 真实超时几次？ | 独立统计器；**不得**要求 `n_deadline_timeouts == n_fallbacks`；每个计数有**事件定义 + 去重规则**（§3.3） | 逐事件分类 ↔ 汇总计数**双向对账** |
| **C4 归档事件** | 事件流完整吗？ | 归档 `raw_events`/`events`/`leaf_counts`/`event_stream_complete`；A 类未闭合区间标 **`CENSORED`**（**不补写 exit**） | **独立实现**的离线扫描重算 `ΣA_i`/`G` 并与在线对账 |

**"独立核验"判定**：核验程序**不得**调用被测/驱动侧的同一函数；**必须**在归档字节上可复跑。

## 6. 反例矩阵（**执行前锁定**；验证类别，**不是**新的科学实验）

**必覆盖 8 类**；每类的**次数上限 / 通过标准 / 失败停止规则**在执行前锁定如下。

| # | 类别 | 次数上限 | 通过标准 | 失败停止规则 |
|---|---|---|---|---|
| 1 | `hi` 预算点超时 | ≤ 3 | `hi.status = deadline_timeout`，且 `exception_type = DecisionTimeout`、`hard_deadline_exception = true`、`budget_point = "hi"` | 归到 `forward_invalid`/`unknown` ⇒ **停止** |
| 2 | `lo` 预算点超时（含 `B−e_o<0` 被截到 0 后**仍进入**的情形） | ≤ 3 | `lo.status = deadline_timeout` **且** `lo.lo_clipped_to_zero` 与该例设计一致；**`lo` 不得被标 `not_applicable`** | 标成 `not_applicable`/未执行 ⇒ **停止**（违反 §3.2） |
| 3 | 真实非有限值（`Ĵ` 为 `NaN`/`±Inf`，**非异常**） | ≤ 3 | 归类 `forward_invalid`，且**不得**带 `hard_deadline_exception = true` | 归类成 `deadline_timeout` ⇒ **停止** |
| 4 | 普通异常（非 `DecisionTimeout`，如 `ValueError`） | ≤ 3 | `exception_type = ValueError`、`hard_deadline_exception = false`，归类 `execution_error` 或（若前瞻完成）`forward_invalid` | 归类成 `deadline_timeout` ⇒ **停止** |
| 5 | B1 合法短路（`e_o <= 0` 早退） | ≤ 3 | `not_entered`，**不产生**任何超时/异常事件 | 计入超时 ⇒ **停止** |
| 6 | B2 不可行边界（`e_o > B`） | ≤ 3 | `infeasible`（`B2_budget_out_of_range`），且未进入前瞻 | 计入超时 ⇒ **停止** |
| 7 | 正常双预算点完成 | ≤ 3 | `n_budget_points_completed == 2` 且总状态 `completed` | 判成 `timed_out` ⇒ **停止** |
| 8 | **同一决策内重复异常** | ≤ 3 | 计 `n_deadline_timeouts == 1`（按 `event_id` 去重）**且**逐事件记录**保留 2 条** | 计成 2 次决策超时，或把两条合并成 1 条 ⇒ **停止** |

**共用规则**：

* 全部 8 类**合计**不超过 **24 次**注入/构造；**不得**为凑通过而增加次数；
* 每次注入必须**可复现**（确定性构造 + 记录构造参数）；
* **失败即停止**：任一类不通过 ⇒ 记 `PROTOCOL_REVIEW_FAILED`，**不得**放宽容差、
  **不得**改判据、**不得**重跑到通过；
* 本矩阵是**验证类别**；**不产生**效用数据，**不构成**科学批次。

## 7. 行为一致性验收（怎样才算"只改变记录、不改变算法"）

### 7.1 主判（**必须逐位相同**）

在**同一** `M=8` 决策点（digest `5b432f28…`）上，旧版与新版：

* `action` 序列（accept/reject）**逐位相同**；
* 被采纳计划的 `plan_of`（同车同序）**逐位相同**。

**任一不同 ⇒ §10 分叉② FAIL**（按"新方法"另行注册，不得以"只是记录改动"通过）。

### 7.2 次判（**必须如实报告**，不要求相同）

`boundary`、`reject_reason`、`lambda_B`、`e_o`、`certify_ok`、`n_scenarios_entered/completed`：
数值项按 **`P1A_RoleC_方案1_PhaseA_归因登记_2026-10-14.md` §7.2** 的规则判等
（`|a−b| ≤ max(1e-12, 1e-12·max(|a|,|b|))`；零、显式 `None`、字段缺失分别处理）。

⚠️ **为什么次判不要求相同**：新的**诊断写入本身要花时间**，而它在 `10 s` 预算**之内**
⇒ 预算内完成的工作量**可能**合法地少一点。因此：

* 任何次判差异**必须**与该次的**实测诊断开销**（§7.3）一并报告；
* **不得**因为"多了个诊断"就默认豁免差异；差异**必须逐字段列出**，
  总判定记为 `behavior_consistency: PARTIAL` 并附差异清单；
* 若差异**不能**由实测开销解释 ⇒ 按 §10 分叉② 处理。

### 7.3 诊断开销必须实测

* 按 G3 的同一口径测"记录开 / 记录关"的**真实墙钟差**，并另跑一个
  **`write_off_control`**（同一新版代码、写入改到内存/丢弃）以把
  "记录开销导致的轨迹差"与"算法改动"分开；
* 开销只作**诊断**，**不得**据此调整 §4.3 对账容差、**不得**据此放宽 `10 s`。

### 7.4 次数与停止

* 一致性回归：`M=8` 决策点各 **1** 次 + `write_off_control` 各 **1** 次，**共 16 次**；
  **不得**增加次数重跑到通过；
* 任一主判不符 ⇒ **停止**。

### 14.1 终态 fallback 至多一次；原始异常事件可重复（裁定 ②）

**锁定语义**：

| 概念 | 规定 |
|---|---|
| **终态行为回退**（terminal fallback） | **每个订单决策至多一次**。依据：`decide_candidate()` 只有**一次**最终接拒返回；`RoleCReplanner._decide_one()` 按该决定处理**一次**计划采纳或拒单 |
| **原始异常事件** | **允许**一次决策产生多条，且**必须完整留痕**（逐条原文，不去重、不合并） |
| **重复的真实终态 fallback** | ⇒ 触发 `execution_error`（**异常**），**而不是**被去重器**静默吞掉** |

**计数分层命名（不得混用）**：

| 字段 | 统计对象 |
|---|---|
| `n_deadline_timeouts` | **受影响的唯一决策数**（决策级） |
| `n_deadline_timeout_events` | **异常事件条数**（事件级） |
| `n_execution_errors` | ⚠️ **必须显式注明**统计的是"决策数"还是"事件数"；**不得**在一个字段里混用 |
| `n_fallbacks` | 终态回退次数（每决策 ≤ 1） |

**示例（同一决策注入两条 `DecisionTimeout`）**：应记
`n_deadline_timeout_events = 2` 而 `n_deadline_timeouts = 1`。

### 14.2 `PARTIAL` 是诊断标签，**不是通过**（裁定 ④）

| 实测情况 | 判定 |
|---|---|
| 主判与次判**均一致**、四通道可复核 | 可以按规定评价**完整工程资格** |
| 主判一致、次判存在差异 | **`PARTIAL`** —— **只能报告部分行为一致** |
| 主判不同 | **`FAIL`** |
| 差异来源**无法复核** | **`inconclusive`** —— **不得**当作 PASS |

* `write_off_control` 表明诊断写入有额外开销，**不足以**证明次判差异**完全**由开销造成；

  "**行为不变性已完整建立**"。

### 14.5 由白名单推出的**事实**：真实路径每决策至多 1 条异常事件

**只读核对**：`role_c_opportunity_cost.py:155-160` 的 `try` **同时**包住
`future_value_fn(b)` 与 `future_value_fn(b_lo_eval)` —— 第一次抛出后**第二次不再执行**；

⇒ **在现行控制流下，真实路径每个决策至多产生 1 条异常事件**：
`n_deadline_timeout_events ∈ {0, 1}`（真实路径）。

**随之锁定的三条**：

* §14.3 第 8 类（同一决策重复异常）**只能通过人工注入**在**记录层**产生，
  用于验证**去重逻辑**；它**不是**真实路径的可达状态；
* `budget_point`（`hi`/`lo`）的判定**只允许在 `except` 体内**做**只读推断**
  （`FutureValueFn.calls` 只在成功返回后追加 ⇒ 长度为 0 判 `hi`、否则判 `lo`）；
  **不**允许在 `try` 内新增语句（那会越出 §14.4 白名单）；
  推断不可得时写 **`unknown`**；
* `DecisionTimeout` 的**类型**判定：若该类型**不可用**（导入失败等），
  `hard_deadline_exception` 必须写 **`None`（未知）**，**不得**写 `False` ——
