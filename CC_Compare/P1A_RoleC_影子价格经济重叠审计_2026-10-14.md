# P1-A Role C：影子价格与前瞻边际的**经济重叠**审计（2026-10-14）

**性质**：**只读源码审计**（未改动任何文件、未跑实验、未做资源计时）
**触发**：`CC_Compare/P1A_RoleC_四项裁定落库_2026-10-14.md` §5 --
用户登记了一项**独立接口风险**并要求"须单独立项审计，**不改动** D2 的既有结论"：

> 若**前瞻 SAA 的接拒效用差已经通过**"有限能耗预算 ⇒ 未来订单被拒"等机制**反映了资源机会成本**，
> 那么再额外扣除 `λ_B·e_o`，仍可能**重复惩罚同一种资源稀缺性**。
> 这是**价值函数与影子价格的经济含义重叠**，**不是**物理成本重复。

**结论：重叠**确实存在**，且**在已冻结的对照配置下就已经生效**（与 `overage_price` 无关）。

## 1. 审计问题（可判定的形式）

对照臂 `cond_hist + SAA` 的接/拒依据是**场景集合上的效用差**。问：这个效用差
**是否已经**把"现在占用预算 ⇒ 未来订单装不下"计入？若已计入，那么 Role C 再减 `λ_B·e_o`
就是对**同一种稀缺性**罚两次（经济重叠）。

## 2. 证据（只读，逐行）

`C-VRP_Cold-chainVehicleRoutingProblem/scripts/evaluation/scenario_saa.py`，场景完成函数末尾：

```python
# :910-919  场景内未来订单的打包循环
for o in scen_order:
    tc = int(space.tc[o])
    e  = c0_marginal_energy(tc, float(space.demand[o]), share, self.contract)
    if est_used + e > self.budget + 1e-9:      # ← **影子预算闸门**
        rej_loss += self.reject_penalty[tc]    #   装不下 ⇒ 计**拒单罚金**
        continue                               #   ⇒ **丢失该单收入**
    ...
    est_used += e
...
plan_rev = sum(REV[...] for s in st.values() for o in s['route'])
fuel     = dist_units * KM_PER_UNIT * FUEL_COST_PER_KM
u        = plan_rev - fuel - rej_loss          # :933  ← SAA 投票用的效用
if self.overage_price is not None and energy > self.budget + 1e-9:
    u -= self.overage_price * (energy - self.budget)   # :938-939 终局超额连续罚
```

两处关键事实：

1. **`est` 闸门（`:913`）与 `overage_price` 是两条独立通道。**
   已冻结的对照配置 `overage_price = None`（`P1A_CONTROL_FROZEN.json`）
   ⇒ **终局超额连续罚关闭**；但 **`est` 闸门仍然生效**。
2. **源码注释自己就说明了这一点**（`:923-928`，2026-09-26 的修复说明）：
   > 「**`est` 门槛（上面的循环）才是未来策略的预算规则**，影子计划把未来一天的订单塞满后
   > 真实能耗几乎恒超 B，逐场景置 `-1e6` 会把场景相关的价值信息淹没……真实 C0 预算仍由
   > 实际接单步骤的 `certify_plan` 强制」

⇒ 当预算紧张时，场景内的未来订单会被**拒掉并计罚金**，于是 `u` **随剩余预算下降而下降**。
**"占用预算"的机会成本已经体现在 `u` 里**，且**不需要** `overage_price` 参与。

## 3. 结论（与 D2 的关系：**并列，不修改**）

| 层次 | 结论 | 是否重复 |
|---|---|---|
| **物理成本**（D2 的既有结论） | `energy_kwh` 是**硬约束**（由 `certify_plan` 把关）；`fuel = distance × FUEL_COST_PER_KM` 是**行驶燃料**。两者不是同一货币成本 | **不重复** —— D2 结论**不改** |
| **经济含义**（本审计） | 前瞻边际 `u` 已通过 `est` 闸门**惩罚"现在占用预算"**；`λ_B·e_o` 惩罚的是**同一件事**的连续边际版本 | ⚠️ **存在重叠** |

**精确措辞（不得说过头）**：
* 重叠是**部分且非同一机制**：`est` 闸门是场景内的**离散"装不下"**效应，
  `λ_B` 是当前候选 `e_o` 上的**连续边际**价格 —— 二者不等价，但都惩罚"现在用预算"。
* 因此**不能**断言"必然重复计入"到 `2·λ_B·e_o` 那种程度；能断言的是
  **"两者定价的是同一种稀缺性，故 `μ_shadow` 与前瞻边际并非正交"**。
* 是否在**某一次具体决策**上真的重复，取决于该单的 `e_o` 是否已经在场景的
  `rej_loss` 路径里被计过 —— **本审计是源码层判定，不声称给出逐决策的数值分解**。

## 4. 这对 Role C 设计意味着什么（不动既有裁决）

   **对照的前瞻边际已经把该稀缺性定过价了**（本审计给出的替代解释）。
   ⇒ 主张必须写成"**在已含 `est` 闸门的前瞻边际之上，再引入连续影子价格是否有增量**"。
