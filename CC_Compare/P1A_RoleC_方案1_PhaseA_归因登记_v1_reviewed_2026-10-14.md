## 3. 计量分母 `T_decision`（**精确定义**）

```
T_decision(d) := perf_counter() 环绕「对决策点 d 的**一次** decide_fn(order, ctx) 调用」
              （进入前取 t0、返回后取 t1；t1 − t0）
```

* **单位**：秒。**不含**预热（`warmup` 调用不计入；且预热次数事前写死）。
* **分母唯一**：所有分区份额的分母**都是** `T_decision(d)`（逐决策点各自的分母，
  不是"所有决策点总和"）。
* **上游不计入**：捕获决策点那一趟（搭单元 / 跑一天 / 场景抽样之外的 env 推进）
  **不进入** `T_decision`；只在报告中单独列出其墙钟，供解释用。
* **仪器自开销**：必须先把"空仪器"（不挂任何分区、仅挂总计时）跑一遍，测出
  **仪器自开销**并在报告中列出；若对账不通过（§4.3）则判 `inconclusive_accounting_error`。

## 4. 互斥时间分区（**正式 50% 判据唯一允许使用的口径**）

### 4.1 inclusive vs exclusive（两套都记，用途不同）

* **inclusive time**（含子调用）：`T_i^incl` = 函数 `i` 及其**全部后代**在本次决策内的
  墙钟累计。**用途：定位热点**。⚠️ 同级 inclusive 之间**可以重叠**，**不得**用于份额分解。
* **exclusive time**（净自身）：`T_i^excl` = `T_i^incl` 减去**所有被统计后代**的
  inclusive 时间 ⇒ 即"只属于 `i` 自身"的时间。**用途：互斥分解与 50% 判据**。
* **采集机制**：在**独立分析脚本**里用包装器实现（**不改生产代码**）；
  维护一个"当前活动叶子栈"，每个包装器把自己的 inclusive 时间累加到自身，
  并把**正在活动的最近后代**的 inclusive 时间从其 exclusive 中扣除
  （标准 self-time 归属）。

### 4.2 事前定义的**互斥叶子分区**（一次决策）

分区是**树**：**只对叶子求和**；**不得**把父节点与其子节点同时计入份额。

```

```

不通过 ⇒ 本次决策判 `inconclusive_accounting_error`，**不得**计入份额统计；
若失败率 > 0 ⇒ 整体结论为 `inconclusive_accounting_error`（**不得**降级成"无瓶颈"）。

## 5. 两类观测（**分开报告，绝不混合**）

### 5.1 A 类：完整路径归因（无内部截止 + **外层资源硬上限**）

* `time_limit = ∞`（**关闭**内部 10 s 截止），目的：让完整计算路径跑完以观察成本分布。
* **外层资源硬上限（必备）**：由**外层监督器**强制（子进程硬杀并回收），
  上限值**事前写死**并在登记核准时一并确认；不得用"跑很久"代替上限。
* ⚠️ **A 类输出 ≠ 在线输出**：关闭截止会改变被观测到的动作（在线 10 s 下可能被截断）。
  A 类**只用于成本归因**，**不得**当作在线行为证据。
* **截断处置（用户明确）**：若任一固定决策点在**外层上限内仍未完成** ⇒
  该次判 **`inconclusive_censored`**；**不得**把未完成的函数当作**零成本**；
  **不得**把该情形判成 **"无单一主导瓶颈"**。 ⇒ 份额统计**只在完成的决策点**上算，
  并把**被截断的条数**与**被截断的叶子**一并列出；**只要有截断，就不给瓶颈判定**。

### 5.2 B 类：在线截止诊断（**保留原 10 s 截止**）

目的：回答"**10 秒截止到来时算法执行到了哪一步**"（这正是用户指出的关键问题）。

逐决策点必须记录：

| 字段 | 说明 |
|---|---|
| `forward_entered` | 前瞻是否**实际进入**过 |
| `evaluation_status` | **三态互斥**：`not_entered` / `completed` / `timed_out`（另有 `error`） |
| `n_scenarios_entered` / `n_scenarios_completed` | 进入/完成了几 个场景（`K=10`） |
| `stages_entered` | 本次进入过哪些阶段（对 §4.2 叶子的布尔掩码） |
| `deadline_hit` | 是否触发内部截止 |
| `timeout_reason` | 触发时的原因串（如 B3 路径） |
| `boundary` | 事前边界规则命中（尤其 `B3_lambda_undefined`） |
| `action` | accept / reject |
| `lambda_B` / `e_o` | 判决所用数值 |

⚠️ **三态语义（用户强要求）**：`not_entered`、`completed`、`timed_out`
**必须是可区分的三种状态**；**不得**一律填 `deadline_hit=false` ——
否则会把**未观察到的信息**写成**否定证据**。
字段缺失时：要么**明确标记不适用并给出结构性理由**，要么判**记录不完整**；
**不得**凭汇总结果反推具体动作。

**报告分离要求**：A 类给出分区份额；B 类给出阶段进入率、场景完成数分布、
B3 触发次数与动作分布。**两者不得合成一个"耗时占比"。**

### 5.3 L1 / L2 / L3 的次序与边界（用户同意）

* **L1（确定性计数）**：不改生产代码的计数包装，输出各调用点的**调用次数/候选数**。
  **只作解释证据**（用于解释 L2 的份额），**不参与**主导判定。
* **L2（分段计时）**：按 §4 的互斥分区测量，**主导判定由 L2 承担**。
* **L3（采样 profiler）**：**仅在 L1 与 L2 互相矛盾时另行申请**；
  **不得自动触发**，且**不得**用来**事后推翻**已经锁定的 50% 门槛。

## 6. 50% 判据（**只用互斥 exclusive 分区**）

### 6.1 逐决策点份额

```
share_i(d) = T_i^excl(d) / T_decision(d)          # i ∈ 叶子集合（P1..P8）
```

### 6.2 预声明的汇总规则（**防止事后挑选状态**）

* **主判据**：对固定决策点集合取**中位数**：
  `M_i = median_d share_i(d)`；判定 `max_i M_i ≥ 0.5`。
* **稳定性要求**：`argmax_i share_i(d)`（逐决策点）在**≥ 6/8** 个决策点上**一致**
  （即同一叶子在多数决策点上都是最大项）。
* **必须上报**：**全部** 8 个决策点的**完整份额分布**（不只报中位数与最大值），
  以及每点的 `T_decision`、对账残差。
* ⚠️ **禁止**事后挑一个"恰好超过 50%"的决策点作为整体主导证据。

### 6.3 三档结论（**不得混淆**）

| 结论 | 条件 | 处置 |
|---|---|---|
| **达到门槛** | `max_i M_i ≥ 0.5` ∧ 稳定性满足 ∧ 该叶子**不属必要工作量**（§6.5） | 允许进入 Phase B 登记（仍需用户裁定） |
| **未达门槛** | `max_i M_i < 0.5` ∧ 稳定性满足 ∧ 无截断 ∧ 对账通过 | 触发 §9 分叉①（**按 §9 修正措辞**收束） |
| **不确定** | 有截断（`inconclusive_censored`）／对账失败（`inconclusive_accounting_error`）／稳定性不满足 | 记对应 `inconclusive_*`；**不得**写成"无单一主导瓶颈"，**不得**据此进 Phase B |

### 6.4 已删除的替代判据

草案"L1 候选数占比 ≥50% 且 L2 耗时与其一致"**已删除**：调用次数多 ≠ 耗时占比高；
L1 仅解释、L2 定夺。

### 6.5 必要工作量（不可优化项）

若达到门槛的叶子属于**结构性乘数**（每决策的"`K` 场景 × 预算两点 × 场景内未来订单数"
这一层，对应叶子组 `P7a/P7b/P7d` 的**总次数**），则该成本是**协议要求的必要工作量**，
**不得**通过减少 `K`、缩短前瞻深度、降低场景数来"解决"（那会改变协议）。
⇒ 该情形按 §9 分叉① 收束，并**按 §9 的修正措辞**表述（**不得**写成"任何计算优化都不可能"）。

## 7. 语义等价检查（Mode C；Phase B 之后才用）——**含零/缺失/非有限规则**

在**旧版 vs 新版**、`time_limit=∞`、同一固定决策点集合下逐条比对。

### 7.1 逐条比对项

1. `action`（accept/reject）序列**逐位相同**；
2. `boundary` 与 `reject_reason`（若拒）**相同**；
3. 数值项 `λ_B`、`e_o`、`myopic_net`、`net_after_opportunity_cost`：按 §7.2 规则判等；
4. 被采纳计划 `plan_of` **逐位相同**（同车同序）。

### 7.2 **数值比较规则（写死；用户要求补齐零/缺失/非有限）**

| 情形 | 判定 |
|---|---|
| 两侧均为**有限** | `|a−b| ≤ max(1e-12, 1e-12 · max(|a|,|b|))` ⇒ 等；否则**不等** |
| 两侧均为 **0**（含 `+0.0`/`−0.0`） | **等** |
| 两侧**均缺失**（`None`） | **等**（并在报告中标注为"两侧都未定义"） |
| **一侧缺失、另一侧有值** | **不等**（FAIL） |
| 任一侧为 **NaN / ±Inf** | **`inconclusive_numeric`** —— **不得**当作"等"；NaN 表示"未定义"（例如截止被触发），把它算作匹配等于把不确定性当证据 |
| 两侧为**同号** Inf | 仍判 `inconclusive_numeric`（不做等值断言） |

⚠️ 相对误差 `≤1e-12` **对零值不完整**（这正是用户指出的问题）⇒ 上表把零、缺失、
非有限分别写死。**任何 `inconclusive_numeric` ⇒ 本次一致性检查不给通过**。

### 7.3 报告要求

必须给出**全部**决策点的逐条比对记录与"不一致条数"，
**不得**只给汇总结论；耗时不参与等价判定（耗时差异与语义等价是两件事）。

| **⑤ 不确定** | `inconclusive_censored` / `inconclusive_accounting_error` / `inconclusive_numeric` / 稳定性不满足 | **不得**判成①，**不得**进 Phase B；如实上报并**停止**，等待用户另行裁定 |

⚠️ 分叉①**不得**写成草案原句"在当前协议约束下不可通过计算优化解决"——
那超出证据：**不存在 >50% 的单一热点 ≠ 不存在语义等价优化**
（多个小环节各占一定比例，仍可能有共享计算或实现层面的改进空间）。

## 10. 源码身份要求

* 新版**另立身份**：`provider_dependency_sha256` 按新闭包重算；
  杠杆必须进 `solver_config_sha256`；改邻域/插入/停止条件 ⇒ 升
  `NEIGHBORHOOD_ID` 与 `SOURCE_SPEC`（换代，**不原地改**）。
* 基线身份保持可复核：15 个模块 SHA-256 + 入库提交 `8089021`
  （见 `P1A_RoleC_收束裁定_2026-10-14.md` §2.1）；**不得**回填到基线登记或历史 gate。
* 交付产物必须**逐字节**可校验（上一轮教训：文本往返会改字节，不能称其为"原件"）。

## 11. 结论词典（`inconclusive_*` 的精确定义）

| 状态 | 含义 | 禁止的读法 |
|---|---|---|
| `inconclusive_censored` | A 类在**外层上限内**未完成（有截断） | ❌"未完成的函数成本为 0"；❌"无单一主导瓶颈" |

| `inconclusive_numeric` | §7.2 出现 NaN/Inf 或缺失不一致 | ❌ 当作"等"；❌ 通过一致性检查 |
| `inconclusive_unstable_hotspot` | §6.2 稳定性不满足（argmax 在多点上不一致） | ❌ 写成"无单一主导瓶颈"；❌ 进 Phase B |
