## 0. 研究问题（用户给定，逐字）

> 当 Role C 的前瞻计算遭遇截止或数值未定义时，如何使**行为回退**、**异常来源**、
> **超时计数**和**归档事件**四者在同一协议下可**独立核验**？

**动机（公平性）**：若两个动态对照都采用 `10 s` deadline，但 timeout/fallback 的
**统计口径不同**，则**不能**直接比较超时率。`CC_Compare/tools/role_c_opportunity_cost.py:158-160`
的宽泛 `except Exception` 会把一次真实的硬超时转成普通的 `B3_lambda_undefined`：

* **行为层**：拿不到机会成本 ⇒ 按 B3 拒单（这本身是设计内的边界规则）；
* **审计层**：一次真实的硬超时**可能没被计入超时**，而只表现为普通 B3 拒单 ——
  这正是要修的**记录**问题。

**本件要区分**：行为层维持不变；只把**审计层**做到可独立核验。

## 4. 协议规格：四条**可独立核验**的通道

> 原则：**每一条通道都必须能被一个不依赖其它通道的读数核验**。
> 任一通道只能靠"另一个通道的结论"来支持 ⇒ 记为不可核验。

### 4.1 统一超时分类契约（**通用 schema**；**本版只施加于 Role C**）

> **适用范围裁定（§10 第②项）**：可以设计**通用**超时 schema；
> 但**暂不修改**其他动态对照（PyVRP-RH-D / OR-Tools-RH-D / RRNCO / `cond_hist+SAA` 等）。
> 把它们纳入同一契约属**比较协议修订**，须另行裁定。

> **REV2 修正一（§10 三处修正之第一处）：`completed` 必须按"两次预算前瞻"定义。**
> Role C 的机会成本要评估 **两个**预算点 `Ĵ(B)` 与 `Ĵ(B − e_o)`。
> 只完成第一个预算点的 10 个场景、第二个还没完成时，**不能**把整个机会成本估计标成
> `completed`。
>
> 「原草案（REV1，保留备查）」原文曾写作：
> `completed` = 前瞻跑完了全部 `K` 个场景（`n_scenarios_entered == K` 且
> `n_scenarios_completed == K`） —— 该定义**只看单个预算点**，已按上句收紧。

**两轴：每个预算点各自的子状态，再合成总状态。**

| 子状态字段 | 取值 | 说明 |
|---|---|---|
| `hi.status` | 见下表 | `hi` = `Ĵ(B)`（`b_hi`） |
| `lo.status` | 见下表 | `lo` = `Ĵ(B − e_o)`（`b_lo_eval`）；若 `B − e_o < 0` 则截到 `0` 并置 `infeasible` |
| `n_budget_points_entered` | `0/1/2` | 实际进入过几个预算点 |
| `n_budget_points_completed` | `0/1/2` | **两侧都完成**才允许总状态 `completed` |

| 类别 | 含义 | **必须由什么证据判定** |
|---|---|---|
| `completed` | **两个**预算点都跑完 `K` 个场景（`n_budget_points_completed == 2`） | 进度/事件 |
| `deadline_timeout` | 前瞻**没跑完**，且**有异常路径证据**表明是**硬截止**打断（按**异常类型** `DecisionTimeout`，**不是**文案） | 异常路径 |
| `forward_invalid` | 前瞻**跑完了**，但 `Ĵ` 非有限（`NaN`/`±Inf`）或差分未定义 ⇒ `λ_B` 未定义 | 数值 + `forward` 原文诊断 |
| `infeasible` | 事前边界规则命中（`B2_budget_out_of_range`）或因无可行插入位而强制拒单 | 边界字段 |
| `execution_error` | 其它异常（非 `DecisionTimeout`）导致前瞻未完成 | 异常路径 |
| `not_entered` | **合法短路**：按设计**无需**进入前瞻（例如 `e_o <= 0` 的 B1 早退 ⇒ 机会成本恒 0） | 边界字段 |
| `not_applicable` | 该通道/该预算点**结构性不适用**（如 `B − e_o` 被截到 `0` 的另一支） | 边界字段 |
| `unknown` | **未取得**足以判定上述任一类别的证据 | —— |

⚠️ **`not_entered` / `not_applicable` 是合法路径，不得归入超时。**
（`e_o <= 0` 时 `shadow_price_budget` 早退、`insertion_infeasible` 硬短路等，
都属于"按设计没进前瞻"，把它们算成超时会**虚增**超时率并破坏公平性比较。）

⚠️ **要求**：
* `forward_invalid` 与 `deadline_timeout` **必须可分**。
  现状把它们都压成 `B3_lambda_undefined`，**这是本件要修的**；
* **未取得证据时一律 `unknown`**，**不得**默认成某一因；
* `evaluation_status ∈ {not_entered, completed, timed_out}`（**进度可证**）与
  `timeout_cause ∈ {None, unknown, SIGALRM_decision_timeout, forward_internal_deadline,
  unknown_exception, budget_exhausted_inside_forward}`（**需异常路径证据**）
  **分开存放**；`timed_out` **不蕴含** `deadline_timeout`；
* 本契约**不改判决行为**：分类只进诊断与归档。

### 4.2 四条通道

| 通道 | 要能独立回答 | 最小实现要求 | 核验方式 |
|---|---|---|---|
| **C1 行为回退** | 超时 / 未定义发生时，**系统做了什么**？ | 每次回退必须落盘：`fallback_applied`、`fallback_kind`、回退前的候选计划、回退后的计划 | 由归档逐决策点**重放**：回退种类与 `action`/`plan` 一致 |
| **C2 异常来源** | 那次没跑完，是**被什么**打断的？ | 见 §4.2.1：**只记录结构化异常来源，不改控制流** | 合成反例（按类型注入）+ 真数据里字段非空且取值在枚举内 |
| **C3 超时计数** | 本次运行**真实**超时了几次？ | 见 §4.2.2：**独立统计器** + 逐事件分类与汇总**一致**（**不**要求与 fallback 次数相等） | 逐事件分类 ↔ 汇总计数**逐条对账**；事件与决策记录**一一对应** |
| **C4 归档事件** | 事件流是否**完整**？ | 归档 `raw_events` / `events` / `leaf_counts` / `event_stream_complete`；A 类未闭合区间标 **`CENSORED`**（**不补写 exit**） | 用**独立实现**的离线扫描重算 `ΣA_i` 与 `G`，并与在线通道对账 |

**"独立核验"的判定**：核验程序**不得**调用被测/驱动侧的同一函数（例如截断重放必须有
第二份独立实现），且**必须**在归档字节上可复跑。

#### 4.2.1 C2：**记录异常类型，不改控制流**（§10 第④项裁定）

> **裁定取向**：本轮**不采用"原样重抛"作为默认方案**。
>
> 理由（用户给出，本件照录）：直接重抛虽然修复了外层超时计数，却**可能改变运行语义**——
> 原来是在 B3 分支**正常返回拒单**；改后则进入**外层超时回退**。即使最终动作同样是
> `reject`，两条路径也**不一定**具有完全相同的**计划保留、日志写入和异常处理**行为。
> 本轮主假设既然是"**行为不变、仅提升可审计性**"，就**不能默认重抛**。

**在异常被捕获的位置**（`shadow_price_budget` 的 `except` 分支）记录结构化信息，
**原有 B3 拒单路径保持不变**：

```
{
  "exception_type":            type(exc).__name__,
  "exception_stage":           "shadow_price_budget.future_value",
  "budget_point":              "hi" | "lo",          # 见 §4.1 两预算点
  "hard_deadline_exception":   isinstance(exc, DecisionTimeout),
  "evaluation_status":         "timed_out",
  "event_seq":                 <本决策内单调递增的事件序号>,
  "decision_point":            <决策点标识>
}
```

**要求**：

* 该结构必须**绕过 B3 分支的诊断丢弃**（源码事实 F6），
  即：**不得**只留在被丢弃的 `_d0` 里 —— 它必须进入**决策记录**；
* **新的独立统计器**根据**有来源证据的异常事件**计算 `n_deadline_timeouts`；
* **保留旧 `timed_out` 字段的原始含义**：**不得静默合并**两者，
  也**不得声称旧统计值已被修正**（历史值保持原样，新的值是**新增通道**）；
* 新统计器**必须证明异常事件与决策记录存在一一对应**：
  用 `event_seq` + `decision_point` 去重，**同一决策内多次抛错不得被计成多个决策超时**；
* ⚠️ **记录本身也有开销** ⇒ 失败条件里的"**行为不变**"是**待验证假设**，
  **不是**改代码前就能宣布的事实（见 §2 判据、§6.1 L1）。

#### 4.2.2 C3：超时计数与 fallback 次数**不得要求相等**（§10 三处修正之第二处）

> 「原草案（REV1，保留备查）」曾把 C3 的核验写成
> `n_deadline_timeouts` 与 `n_fallbacks` **对账** —— 该表述会被读成"两者应相等"。
> **REV2 更正**：**不得**要求相等。

理由（用户给出，本件照录）：**普通数值未定义也会触发 B3 拒单，但那不属于硬超时**；
**有些截止事件可能发生在候选计划产生之前**。因此：

* 核验的是**逐事件分类与汇总计数的一致性**，而**不是**
  `n_deadline_timeouts == n_fallbacks`；
* **每个计数都必须有明确的事件定义与去重规则**：

| 计数 | 事件定义 | 去重规则 |
|---|---|---|
| `n_deadline_timeouts` | 一次**带类型证据**的 `DecisionTimeout` 异常事件 | 按 `(decision_point, event_seq)` 去重；**每决策点最多计 1** |
| `n_fallbacks` | 一次**实际发生的**行为回退（C1） | 按 `(decision_point, fallback_kind)` 去重 |
| `n_forward_invalid` | 前瞻**完成**但 `Ĵ` 非有限 | 按 `(decision_point, budget_point)` 去重 |
| `n_execution_errors` | 非 `DecisionTimeout` 的异常事件 | 按 `(decision_point, event_seq)` 去重 |
| `n_not_entered` | 合法短路（B1 等）**未进**前瞻 | 按决策点计数 |
| `n_unknown` | 证据不足 | 按决策点计数 |

* 汇总计数必须能**逐条还原**为该决策点的分类记录集合（双向对账）。
