## 0. 研究问题（用户给定，逐字）

> 当 Role C 的前瞻计算遭遇截止或数值未定义时，如何使**行为回退**、**异常来源**、
> **超时计数**和**归档事件**四者在同一协议下可**独立核验**？

**动机（公平性）**：若两个动态对照都采用 `10 s` deadline，但 timeout/fallback 的
**统计口径不同**，则**不能**直接比较超时率。`CC_Compare/tools/role_c_opportunity_cost.py:158-160`
的宽泛 `except Exception` 会把一次真实的硬超时转成普通的 `B3_lambda_undefined`：

* **行为层**：拿不到机会成本 ⇒ 按 B3 拒单（这本身是设计内的边界规则）；
* **审计层**：一次真实的硬超时**可能没被计入超时**，而只表现为普通 B3 拒单 ——
  这正是要修的**记录**问题。

**本件要区分**：行为层维持不变；只把**审计层**做到可独立核验。

## 4. 协议规格：四条**可独立核验**的通道

> 原则：**每一条通道都必须能被一个不依赖其它通道的读数核验**。
> 任一通道只能靠"另一个通道的结论"来支持 ⇒ 记为不可核验。

### 4.1 统一超时分类契约（**所有动态对照共用**）

| 类别 | 含义 | **必须由什么证据判定** |
|---|---|---|
| `completed` | 前瞻**跑完了全部 `K` 个场景**（`n_scenarios_entered == K` 且 `n_scenarios_completed == K`） | 进度/事件 |
| `deadline_timeout` | 前瞻**没跑完**，且**有异常路径证据**表明是**硬截止**打断（按**异常类型** `DecisionTimeout`，不是文案） | 异常路径 |
| `forward_invalid` | 前瞻**跑完了**，但 `Ĵ` 非有限（`NaN`/`±Inf`）或差分未定义 ⇒ `λ_B` 未定义 | 数值 + `forward` 原文诊断 |
| `infeasible` | 事前边界规则命中（`B2_budget_out_of_range`）或因无可行插入位而强制拒单 | 边界字段 |
| `execution_error` | 其它异常（非 `DecisionTimeout`）导致前瞻未完成 | 异常路径 |
| `unknown` | **未取得**足以判定上述任一类别的证据 | —— |

⚠️ **要求**：
* `forward_invalid` 与 `deadline_timeout` **必须可分**。
  现状把它们都压成 `B3_lambda_undefined`，**这是本件要修的**；
* **未取得证据时一律 `unknown`**，**不得**默认成某一因；
* `evaluation_status ∈ {not_entered, completed, timed_out}`（**进度可证**）与
  `timeout_cause ∈ {None, unknown, SIGALRM_decision_timeout, forward_internal_deadline,
  unknown_exception, budget_exhausted_inside_forward}`（**需异常路径证据**）
  **分开存放**；`timed_out` **不蕴含** `deadline_timeout`；
* 本契约**不改判决行为**：分类只进诊断与归档。

### 4.2 四条通道

| 通道 | 要能独立回答 | 最小实现要求 | 核验方式 |
|---|---|---|---|
| **C1 行为回退** | 超时 / 未定义发生时，**系统做了什么**？ | 每次回退必须落盘：`fallback_applied`、`fallback_kind`、回退前的候选计划、回退后的计划 | 由归档逐决策点**重放**：回退种类与 `action`/`plan` 一致 |
| **C2 异常来源** | 那次没跑完，是**被什么**打断的？ | 吞没点**按类型**识别 `DecisionTimeout`：或**原样重抛**（推荐，`_run_with_limit` 即可正确计入），或至少把 `type(exc).__name__` 与抛出点标签写进 `lambda_diag`，并在 B3 分支**保留**该诊断 | 合成反例（按类型注入）+ 真数据里字段非空且取值在枚举内 |
| **C3 超时计数** | 本次运行**真实**超时了几次？ | 计数**不得**只依赖 `timed_out`/`deadline_hit`；须由**独立累加器**在异常/截断边界上计数，并与 C1 的回退次数**对账** | `n_deadline_timeouts`、`n_fallbacks`、`n_forward_invalid`、`n_execution_errors` 四者与逐决策点记录**逐条对账** |
| **C4 归档事件** | 事件流是否**完整**？ | 归档 `raw_events` / `events` / `leaf_counts` / `event_stream_complete`；A 类未闭合区间标 **`CENSORED`**（**不补写 exit**） | 用**独立实现**的离线扫描重算 `ΣA_i` 与 `G`，并与在线通道对账 |

**"独立核验"的判定**：核验程序**不得**调用被测/驱动侧的同一函数（例如截断重放必须有
第二份独立实现），且**必须**在归档字节上可复跑。

## 5. 归档字段与身份

### 5.1 必归档字段（下一版硬要求）

| 字段 | 目的 |
|---|---|
| `raw_events`（`('enter'/'exit', label, ts)`） | 独立重建 enter/exit 配对与调用栈 |
| `events`（`(label, t_enter, t_exit)`） | 验证区间嵌套、包含与互斥 |
| `leaf_counts` | 重算 `stages_entered` 与调用数量 |
| `decision_point_digest` | 防止决策点被替换 |
| `timer_origin` / `clock_domain` | 确认时间戳属于**可比较**的时钟 |
| `instrumentation_source_sha256` | 确认插桩源码身份 |
| `event_stream_complete` | 明确是否因异常/强制截断导致事件缺失 |
| `timeout_cause` / `evaluation_status` | §4.1 的两轴，分开存放 |

### 5.2 两类观测的事件丢失处置

* **A 类（外层硬杀）**：事前规定**周期性落盘**或外部事件日志；截断时**未闭合**区间标
  **`CENSORED`**，**不得补写退出事件**；
* **B 类（`10 s` 内部截止）**：**只有**在事件流完整、双通道计量与离线重算符合原规格时，
  才允许报告"通道 C 的真实数据验收结果"；否则只能报告"**不可在本批数据上独立重算**"。

### 5.3 身份与写入纪律

* 被测模块的 15 个计时模块 SHA 按封存裁定 §2.1 **保持可复核**；本件**不修改**它们；
* 新增的插桩/审计模块必须登记 SHA（含"**写入后验收**"：非 0 字节、关键字段非空、SHA 可复算）；
* **长任务必须放 `tmux`**；但 `tmux` **不替代**增量持久化与写入后验收。
