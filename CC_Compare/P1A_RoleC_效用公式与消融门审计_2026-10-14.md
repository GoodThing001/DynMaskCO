## 1. D1：符号错误（推导 + 反例）

### 1.1 权威效用定义（取自源码，不是文档转述）

`C-VRP_Cold-chainVehicleRoutingProblem/scripts/evaluation/coldchain_evaluator_a1.py:142-145`

```python
revenue     = sum(REV[int(temp_class[o])] for o in served_set)
fuel        = distance_km * FUEL_COST_PER_KM          # ← 行驶燃料，不是冷链能耗
reject_loss = sum(float(reject_penalty_by_class[int(temp_class[o])]) for o in rejected_set)
utility     = revenue - fuel - reject_loss
```

而 `energy_kwh ≤ B` 是**独立硬约束**（同文件 `:110-112`），**不进入 utility**。
⇒ 单日目标：`J = Σ_{o∈A} R_o − c_f·(行驶距离) − Σ_{o∈Rj} p_{c,o}`，其中 `A ⊎ Rj = 全部已揭示订单`。

### 1.2 从两动作完整效用逐项推导

按用户要求，不猜符号，直接对**同一状态**下"接 o"与"拒 o"两点作差（其余决策固定）：

```
J(接 o) − J(拒 o)
 = [ Σ_{o'∈A∪{o}} R_{o'} − c_f·D(A∪{o}) − Σ_{o'∈Rj}     p_{c,o'} ]
 − [ Σ_{o'∈A}     R_{o'} − c_f·D(A)     − Σ_{o'∈Rj∪{o}} p_{c,o'} ]

 = R_o − c_f·ΔD                     ← 收入增、燃料增
   + p_{c,o}                        ← 拒单罚金**不再发生**，是**正向增量**
   + Δ(未来项)
```

⇒ **近视净增益（accept − reject）= `revenue_o − fuel_o + reject_loss_o`**。
规格与代码写的 `revenue_o − fuel_o − reject_loss_o` 把 `p_c` 的符号写反了。

### 1.3 可推翻该结论的**反例**（单点即可判）

取 `p_c,o = 15`、`R_o = 10`、`fuel_o = 0`、`λ_B·e_o = 0`：

| | 计算 | 判决 |
|---|---|---|
| **正确** | `10 − 0 + 15 = +25 > 0` | **接单** |
| **现规格/现代码** | `10 − 0 − 15 = −5 ≤ 0` | **拒单** |

真实效用上，接单比拒单好 **25** 个单位；现判据选了**严格更差**的那个动作。
偏差幅度 = `2·p_c,o`：p_c 档 `(5,10,15)` 对应偏差 `(10,20,30)`。
⇒ **p_c=15 档的单笔偏差（30）就已经超过 P1-A 的效果门 δ=20**；这不是"文风/口径"问题，是判决错误。

### 1.4 为什么它至今没被发现（两个掩盖机制）

1. **主档 p_c=0**：`reject_penalty_by_class` 全为 0 时 `+p_c` 与 `−p_c` 数值相同 ⇒ 主档完全不可见，只有敏感性档才暴露。
2. **测试把错值写死为期望**：`test_role_c_opportunity_cost.py:100-101`

   ```python
   ck('myopic_net = revenue − fuel − reject_loss（不含机会成本）',
      rc.myopic_net(100.0, 30.0, 10.0) == 60.0)      # ← 期望值 60.0 正是错的那一个
   ```

   15/15 全绿给出的是**假保证**：该用例在符号正确时应为 `100 − 30 + 10 = 80.0`。
   这与项目已记录的"审计失败多来自我自己的测试口径"属同一类，必须连同测试一起改，否则修了代码测试会红。

### 1.5 已执行的修正

* `role_c_opportunity_cost.myopic_net` 改为 `revenue − fuel **+** reject_loss`，并写入推导与反例；
* 测试期望 `60.0 → 80.0`，**新增** p_c>0 反例用例（p_c=15 / R=10 / F=0 ⇒ 必须 `accept`），
  该用例在旧符号下必红 ⇒ 修正**可证伪**；
* 规格 §2.1 公式与 §2.6 表格同步更新，并保留一处显式的"2026-10-14 符号修正"块。

## 2. D2：机会成本有没有重复计入

### 2.1 结论一：**能量侧不存在重复计入**，但规格给的理由不成立

规格 §2.1.1 的 (i)/(ii)/(iii) 三分法与"（iii）禁用"是**正确的**，护栏（`decide()` 一旦同时收到 `lambda_B` 与 `lookahead_delta` 就抛错）也是**正确的**。

但要注意规格没有说清的一点，它直接影响论文表述：

> **A-v1 效用里没有冷链能耗项。** `fuel` 是 `distance_km × FUEL_COST_PER_KM`（行驶燃料）；
> `energy_kwh`（C0 制冷能耗）**只以硬约束 `≤ B` 的形式存在**，由 `certify_plan` 把关。

因此正确的分解是"拉格朗日/影子价格"结构，而不是"再扣一次成本"：

```
max  Σ R − c_f·D      s.t.  E(计划) ≤ B
一阶条件：接单 ⟺ Δ(R − c_f·D) − λ·ΔE > 0 ,  λ = ∂J*/∂B ≥ 0
```

`λ_B·e_o` 定价的是**约束的稀缺性**（θJ*/θB），`myopic_net` 里没有任何能耗货币项 ⇒ **两者物理量不同，不可能重复计**。
（反过来讲：若哪天 A-v1 把能耗货币化进 utility，那么 `λ_B·e_o` **才会**变成真正的重复计入 —— 这是必须写进论文的**接口约束**。）

### 2.2 结论二：**真正存在混淆的是"两臂近视基准不一致"**（新发现）

规格 §2.6 用一张表声明 `B‑shadow` 与 `B‑density` "**其余全同**"，只差 λ 来源。实现不是这样：

| 臂 | 近视基准 | 来源 |
|---|---|---|
| Role C（`decide_candidate`） | `myopic_net_fn(order)` = `R − fuel + p_c` | `role_c_opportunity_cost.py:159` |
| `B‑density`（`decide_b_density_control`） | `revenue_fn(order)` = **`REV`**（无 fuel、无 p_c） | `role_c_controls.py:65,68` |

⇒ `B‑shadow − B‑density` 同时改变了 **① λ 的估计方式** 与 **② 近视基准**，**无法把差异归因给"内生化"**。
更严重的是，负责守这条的核对函数漏掉了那个唯一不同的字段：

```python
# role_c_controls.py:89  —— 只查三样，恰好不查 myopic_net
for k in ('e_o', 'certify_ok', 'budget_B'):
```

而现有测试用例 ⑤ **正是**用 `myopic_net_fn=lambda _o: 3.0`（shadow）与 `REV=5`（density）构造了一对基准不同的臂，
并断言 `arms_are_matched(...) is True`（`test_role_c_controls.py:122-128`）。
⇒ 这不是"理论上可能漏"，而是**已有一条通过的测试在示范这个漏检**。

**已执行的修正**：`arms_are_matched` 加入 `myopic_net` 比对，并在诊断里回传两臂基准；
测试用例 ⑤ 改为断言"基准不一致 ⇒ **必须**判可归因性不成立"，另加一条"基准一致 ⇒ 成立"的正例。

**仍待用户裁定（不宜由我替选）**：`B‑density` 应当
(a) 改用与 Role C **相同的**近视基准（则确为单因素，但就不再忠实于上游 `knn/valuee` 的 `REV − λe`），或
(b) 保留 `REV` 基准（忠实上游），但**把"近视基准"登记为第二个被检验因素**，`B‑shadow − B‑density` 只能解释为"两种资源门槛机制之差"。
规格 §2.6 的表格必须按裁定结果改写，否则论文会主张一个无法归因的差值。

### 2.3 结论三：`fuel_o` 的**口径**必须写死为"边际"

`myopic_net` 里的 `fuel_o` 只在它是**接这一单的边际行驶燃料** `c_f·ΔD(插入 o)` 时才等于 §1.2 的推导项。
若实现传入的是**分摊/平均**行驶燃料（或整日燃料），符号虽仍为负（不产生 D1 那类符号错误），
但近视基准的量级错、并与 `certify_plan` 里"实际完成的计划"不对应 ⇒ 归因失真。
规格目前只写 `fuel_o` 而**未定义口径**，须补一句"= `FUEL_COST_PER_KM × Δdistance(插入 o)`"。

### 2.4 结论四：`λ_B ≥ 0` 是一条**同义反复**的测试

T9 断言①"`λ_B ≥ 0`"，但 `shadow_price_budget` 里 `lam = max(raw, 0.0)`（clip）⇒ 该断言**永远不可能失败**，不构成证据。
有信息量的判据是对**未截断**的 `lambda_raw`：应报告 `raw<0` 的**比例**，并把它当作"采样噪声/模型设定有误"的**诊断量**（不是门）。
`diag` 里已有 `lambda_raw` 与 `clipped` 字段，只是没被当作证据用。建议 T9 增一条：**报告 `clipped` 计数**，不设阈值。

## 3. D3：消融（工程）与效果门（科学）的区别

### 3.1 已正确的部分（确认，不需再改）

* §2 开头"差异恒为零 ⇒ 判实现缺陷（FAIL）；差异不为零但不显著 ⇒ **一律不得判 FAIL**"——**正确**，且理由（零效应是合法结果；否则等于预设结论）成立。
* §5 把可判 FAIL 的限定为「机制未接入 / 因果·承诺·预算被违反 / 身份不匹配」，把"不显著、方向不符、CI 跨 0"划归科学结论——**正确**。
* `role_c_decision_audit` 的 `not_applicable` 不计入 `problems`——**正确**（避免结构性不适用被记为失败）。
* 效果门 δ=20 保持独立、不并入机制研究（§10 M1–M3）——**正确**。

### 3.2 仍残留的方向性预设（§2.2）

> 「一致率**变高**是"前瞻确实在起作用"的行为证据」

这句把**一个方向**预设成了证据。机制是否接入，只看"消融前后是否完全相同"；
一致率**升高或降低**都只是**被记录的行为差异**，不构成"前瞻在起作用"的证据（前瞻完全可能让动作更远离对照）。
⇒ 已改为中性表述：报告一致率，**不给方向赋义**。

### 3.3 T2 判据不稳健（本轮最重要的第三条）

**现判据**：`λ_B≡0`（消融）与不消融的决策序列**不得完全相同**，完全相同 ⇒ FAIL。

**问题**：这条把两种截然不同的情形判成了同一件事——

1. 机制**确实没接进**决策路径（应 FAIL）；
2. 机制**接好了**，但在被检验的状态集合上**资源根本不稀缺** ⇒ 正确实现下 `λ_B ≈ 0` ⇒ 决策序列**理应相同**（不应 FAIL）。

**仓库实据（登记规则 v4 的 1000 条决策日志，只读统计）**：

| 量 | 实测 |
|---|---|
| `b_rem` 最小值 | **197.27** kWh（`B = 710.6548`） |
| `b_rem < 50` 的决策数 | **0 / 1000** |
| `reject_budget`（硬前置检查）触发次数 | **0 / 1000** |
| 每日 `spent_before` 峰值 | 446.61 / 448.30 / 513.39 / 446.61 / 499.23 kWh（≤ **72.2%** B） |
| λ 落在网格**下限** 0.25 | **291 / 1000** |
| λ 触及网格**上限** 8.0 | **0 / 1000** |

⇒ 在**下限记账**（`Σ e_lower`）下，这五天的预算**基本不稀缺**：一个实现正确的内生 λ_B 会大面积 ≈0，
消融臂与不消融臂**完全可能给出同一串决策**，于是 T2 会把"实现正确"判成 FAIL。

**必须补的限定（否则 T2 是伪判据）**：

* T2 只能在一个**已登记、且证明 `λ_B > 0` 被真正触发**的状态集合上运行——
  例如 §10‑M1 的**预算档**（须事前登记 α，见下）或已有的 TRAIN 交叉诊断（该诊断中影子价格拒绝在 **200/200 日**活跃）；
  并且在判"完全相同"**之前**先断言"本集合内 `raw>0` 的决策数 > 0"，否则报 **not_applicable**，不报 FAIL。
* 纯函数层的接入证明**已经存在且更强**（T9 ③：`Ĵ` 换成常数 ⇒ `λ_B ≡ 0`，20 组 (B,e) 全 0）
  ⇒ T2 不必依赖"结果序列不同"这种间接证据。

**一条必须同时说清的边界（避免我把话说过头）**：上表的 `spent_before` 是 `Σ e_lower`（**下界**记账），
而权威预算检查是 `certify_plan` 的**完整续行能量**（含 WAIT 到 booking_end 与返仓），后者可能大得多。
因此上表证明的是「**下界前置检查松**」，**不等于**「`certify_plan` 松」。
⇒ 登记规则 v4 的决策日志**没有记录 `certify_energy`**，这是个**字段缺口**：Role C 的写入器
（`role_c_decision_log`）已经记录 `certify_energy`，旧规则日志没有。
补字段不需要重跑，但结论"资源是否真的稀缺"在本轮**尚未闭合**，须按此措辞。

### 3.4 顺带：`§10‑M1` 的 α 档不能凭感觉取

既然下界记账下 ≤72.2% B 才不稀缺，`α` 档（`B` 与 `αB`）必须**由已测的松紧度事前推出**并登记，
使得**至少一档确实绑定**；否则 M1 会得到"C0 稀缺度不影响结论"的**空结果**，而那是**档位选错**造成的，不是机制结论。
（禁止按结果挑 α —— 这一条规格已写对，只是没给出"如何选到有效档"的可操作规则。）

## 4. 对用户研究判断的回应（我的独立判断）

**同意的部分**

1. **先修基础、不要先训模型**——完全同意。本轮 D1/D2b/D3b 三条都是**判决层**错误，
   在它们之上跑任何新训练/新批次，得到的效用差都可以被公式错误解释掉。
2. **不要只是再加一个 decision-aware loss**——同意，且仓库证据支持：I3 的决策感知训练
   相对纯重建与暖启动控制都未建立可归因收益；把同一个想法加权重再来一次，先验成功率低。
3. **必须保留强非学习对照，且对照臂要"真正独立"**——同意；本轮 D2b 正是这条原则在**自家对照臂**上的破口。
4. **效果门不能被机制解释替代**——同意。

**需要修正/加强的部分**

1. **优先级应再前移一步**：用户把"D 系列机制诊断"排在前面，我建议在它**内部**先做**最便宜、且能一票否决两个方向**的一项——
   **"资源通道到底会不会绑定"**。理由见 §3.3：现有五天在下界记账下**不稀缺**（≤72.2% B、λ 常处下限）。
   如果连"构造出资源真正稀缺的状态"都做不到，那么**方向二（资源状态感知）没有基底**，
   方向一（决策相关场景生成）也会因为"决策不随未来场景改变"而退化。这一项只读、极便宜，应先做。
2. **MaskCO 归因门应前置，而不是排在效果门之后**：用户把 `E vs C` 列为最关键、`E vs D` 次之。
   我认为在当前证据下应当**反序**：先做 `F−D`（同掩码、非学习几何修复）与 `F−E`（同架构随机修复）**等时**对照。
   如果已训练 MaskCO **连几何/随机修复都胜不过**，那么"资源感知 + 决策相关场景"再成功，
   也无法支撑"MaskCO 贡献"这一主张，`E vs C` 的证据救不回来。而这两项对照**已有现成资产**
   （固定状态比较、掩码池统一、等时请求），是**低成本高杀伤**的证伪实验，应当在建设大型新机构**之前**跑掉。
