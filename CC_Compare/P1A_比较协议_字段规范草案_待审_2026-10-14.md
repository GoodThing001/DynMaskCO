## 0. 三条标注纪律（**本草案的核心**）

| 情形 | 必须写成 | 含义 |
|---|---|---|
| 该字段**对本法方法不适用** | **`NOT_APPLICABLE`** + **理由** | 例如不采样的方法没有 `K` |
| 该字段**本应存在但缺失** | **`NOT_VERIFIABLE`** | 表示"无法核验"，**不是**"不存在"、更**不是**"未发生" |
| 字段存在且值已登记 | **值本身**（+ 身份哈希） | —— |

⚠️ **不得**要求所有方法都必须有 Role C 专属参数
（`inner_gate` / `future_policy` / `energy_pricing` / `rho` 等）；
⚠️ **不得**把"缺失"与"不适用"混为一谈 —— 前者是**证据缺口**，后者是**结构性豁免**。

## 1. 六类字段

### 1.1 因果信息（**通用**：所有 strict-online 方法）

| 字段 | 适用性 | 要求 |
|---|---|---|
| `booking_horizon` | **通用·强制封存** | 取值必须显式登记，且**比较双方一致**；`None` 必须显式写 `None` 而**不是**省略（`booking_horizon=None` 会让 `has_future_reveal` **读真实未来**） |
| `visible_order_boundary` | **通用** | 可见订单边界的判定口径（信息边界如何确定） |
| `strict_online` | **通用** | 布尔标志；`false` 的方法不得与 strict-online 方法同框比较 |

> `booking_horizon` 是**所有** strict-online 方法共同的因果问题 ⇒ 新正式比较中**强制**。
> 历史 gate 缺该字段一律标 `NOT_VERIFIABLE_FROM_ARCHIVED_GATE`
> （**不推定**泄漏、**不追溯**改旧裁决）。

#### 1.1.1 ⚠️ **因果硬门**（本轮新增；**登记 ≠ 通过**）

`booking_horizon` 必须**拆成两道门分别判定**，**两道都过**该臂才可进入跨方法比较：

| 门 | 名称 | 判据 | 通过条件 |
|---|---|---|---|
| 门 1 | **身份门** | 该字段是否**显式登记**且**比较双方一致** | 显式登记 + 双方取值相等 |
| 门 2 | **因果门** | **执行路径**是否**从未访问**未揭示信息 | 需给出路径级证据；**仅登记不构成通过** |

**门 2 的硬性规定**：

1. **已知的未来读取路径 `None` 不能靠"已登记"过关。**
   若某臂的执行路径上存在取值 `None` 的 `booking_horizon`
   （即调用 `has_future_reveal` 时会**读真实未来**），则该臂因果门判 **`FAIL`**，
   即便它把 `None` **如实登记**了。登记只满足门 1。
2. 因果门的证据必须是**路径级**的：能说明从决策入口到返回的调用链上
   **没有任何**读取未揭示订单/未来揭示时间/未来状态的分支；对"未检查到"
   只能记 `NOT_VERIFIABLE`，**不得**记 `PASS`。
3. 因果门 `FAIL` 或 `NOT_VERIFIABLE` 的臂，**不得**与门 2 通过的方法
   并入同一比较框；若仍要报告，必须**单独分框**并显式标注该门状态。
4. 因果门**不追溯**：历史 gate 缺该字段仍记 `NOT_VERIFIABLE_FROM_ARCHIVED_GATE`
   （**不推定**泄漏、**不追溯**改旧裁决）。

#### 1.1.2 复合身份的适用范围（澄清）

§2 的**复合身份是"每个臂各自的自我身份"**（用来判定"这个臂的这次运行是否可复现"），
**不是**跨方法可比性的充分条件。跨方法比较另需三步：

1. 先确认双方**任务协议 / 数据 / C0 合同**可比（不可比则不得配对）；
2. 两侧各自通过**门 1 + 门 2**；
3. 再按 `day_id` 配对。

⚠️ **不同 provider 正是被比较的对象**，因此 provider 差异**不构成**不可比的理由；
但**任务协议 / 数据身份 / 合同**不同则**不可比**。

### 1.2 采样协议（**条件**：仅对使用场景采样的方法）

| 字段 | 适用性 |
|---|---|
| `K`（场景数） | 使用场景采样 ⇒ 必填；不用 ⇒ `NOT_APPLICABLE` + 理由 |
| `sampler_identity` | 抽样器身份（如 `cond_hist` / `uncond_hist` / `None`） |
| `random_seeds` | 随机种子集合（`train` / `dev` / 保留种子）与**逐臂** `arm_seed` |

### 1.3 决策协议（**通用**，但取值因方法而异）

| 字段 | 要求 |
|---|---|
| `accept_reject_rule` | 接拒规则的**可复核表述**（如写法 (i) 的判据式） |
| `deadline` | 单决策时限（秒）+ **计时定义**（含/不含包装、时钟域） |
| `fallback_semantics` | 回退语义：**必须区分** 普通拒单 / 保守拒单（如 B3）/ 超时回退；仅凭 `action=reject` **不得**推断回退（证据不足 ⇒ `NOT_VERIFIABLE`） |

### 1.4 冷链约束（**通用**）

| 字段 | 要求 |
|---|---|
| `contract_sha256` | 冷链合同身份 |
| `c0_certification` | C0 认证口径（预算 `B`、认证函数身份） |
| `energy_model_identity` | 能耗模型身份（含 `cooling_share` 口径） |

### 1.5 源码与数据（**通用**）

| 字段 | 要求 |
|---|---|
| `source_stable` | 跨运行共享源码身份是否稳定；**必须给哈希**而不只是路径 |
| `data_sha256` | 数据集身份 |
| `version_and_adapter_identity` | 方法版本 + 适配器身份（**适配器不是原论文方法**，必须写明） |

### 1.6 方法专属（**条件·按适用性**）

| 字段 | 适用性 |
|---|---|
| `inner_gate` | **仅**对具备该机制的算法适用；**是否通用须结合对应算法确定**，**不得机械推广** |
| `future_policy` | 同上前提 |
| `energy_pricing` | 同上前提 |
| `rho` | 同上前提 |

> ⚠️ 用户明确：`inner_gate` 是否属于通用字段"需要结合对应算法确定，
> 而不是机械推广"。⇒ 本草案把它列为**条件字段**，并要求在每个方法的登记里
> 显式给出 `APPLICABLE`（附理由）或 `NOT_APPLICABLE`（附理由）。

## 2. 配对键（**复合身份**）

历史做法用 `method` 或 `gate_path` 配对，已被证明**会误聚合**
（见 `P1A_对比方法_provider身份歧义_只读补充审计_2026-10-14.md`）。
新正式比较的配对键**至少**区分：

```
(provider, variant, sampler, p_c, protocol, source_identity, data_identity)
```

再用 `day_id` 建立逐日配对。目的：
① 不把**不同 provider** 当成同一算法的重复运行；
② 不把**同一 provider 的不同变体**（如 `coenrich_nopchgs` / `coenrich_pchgs`）混为一谈。

| 字段类别 | 该法方法的状态 | 缺失/不适用的标注 |
|---|---|---|

| 冷链约束 | 逐项给值 | 缺 ⇒ `NOT_VERIFIABLE` |
| 源码与数据 | 逐项给**哈希** | 只有路径 ⇒ `NOT_VERIFIABLE` |
| 方法专属 | `APPLICABLE` / `NOT_APPLICABLE` + 理由 | 见上 |

## 4. 本草案**不**做什么

* **不**升级现存 gate；**不**要求历史记录补齐字段；**不**重新裁决任何历史结果；
* **不**把"缺失"当"违规"：缺失只降低**可核验性**，不改变历史结论；
* **不**产生任何效用/性能结论；
* **不**授权任何运行（L1/L2/服务器任务/科学批次）。
