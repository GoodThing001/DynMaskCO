## 2. 三级对比体系

| 级别 | 定位 | 回答什么 | 放哪 |
|---|---|---|---|
| **第一级：动态接拒主对照** | **论文核心** | 动态未来信息 + 预算机会成本 + 路线优化，能否改善**正式主档**效用 | 正文 Table 1 |
| **第二级：资源与 MaskCO 消融** | 机制归因 | 区分**冷链资源控制 / 非学习搜索 / 预训练 MaskCO / 重复重构**的独立贡献 | 正文 Table 2（A–F 见 Role C 规格 §9） |
| **第三级：外部 NCO 适配方法** | 覆盖与关系 | 与代表性路由算法的关系；**按实际保留能力**分类展示 | 正文 Table 3（代表方法）+ 补充材料（完整清单） |

### 2.1 第一级明细（**主对照仍只有一个**）

| 方法 | 核心机制 | 比较目的 | 当前状态 |
|---|---|---|---|
| Myopic + C0 | 当前可行即接，无未来信息 | 最基本在线参照 | 已有历史结果 |
| Value/Energy Rule | 收益/能耗固定门槛 | 检验**简单资源规则**的解释力 | λ=2 已有历史结果 |
| `uncond_hist + SAA` | 无条件历史场景前瞻 | 检验**是否需要条件**未来信息 | 已有历史结果 |
| **`cond_hist + SAA`** | 条件历史场景前瞻 | **P1-A 唯一主对照**（已锁定） | 已有合格同批结果 |
| Resource-Reserve + SAA | 显式预留有限冷链预算 | 检验**简单资源预留是否已足够** | ⚠️ **建议新增对照，尚未建立** |
| **Role C**：Resource-Aware Lookahead | 内生资源机会成本 + 独立前瞻路线优化 | 检验**新动态接拒机制** | 已有设计规格；**尚未获正式运行资格** |

> ⚠️ **Role C 是待验证的候选方法，不得在结果出来前称"已验证的最强基线"。**
> P1-A 的唯一主比较是 `Role C − (cond_hist + SAA)`；**不增加多个主对照、不事后更换**。
> 新增的 `Resource-Reserve + SAA` 是**第一级里的另一个对照臂**（回答"简单预留够不够"），
> 它**不取代**主对照。

**文献定位（只作背景，不据此改协议）**：Soeffker 等（OR Spectrum 2024）把
动态请求接受、车辆资源分配与前瞻规划**分开考察**；Wu 等（Flexible Services and
Manufacturing Journal 2024）用 ADP/rollout 研究取货中的**未来容量价值** ——
但其设定**允许取消请求**，**不能**原样移植到本项目的**不可撤销承诺**协议。
⇒ 借鉴的是"资源预算 + 前瞻接拒"的**比较思路**，不是其问题设定。

## 3. 第三级：按**实际保留的算法能力**分类（不按发表等级）

⚠️ 本表**只描述能力与可比性**，**不**按 CCF 等级/效用排名排序。
"论文里的实际做法"一栏是**必须随方法名一起出现**的限定。

| 类别 | 方法 | 建议处理 | 原因（实际保留的机制） |
|---|---|---|---|
| **代表性路线求解器** | OR-Tools-RH、PyVRP-RH | **保留**在代表组 | 可检验**路线搜索**；但接/拒策略较弱（myopic） |
| **Zero-shot ordering 适配** | POMO、RouteFinder、MVMoE、CaDA | 保留**若干代表**；其余进补充表 | 当前主要是 **zero-shot ordering**（提供优先级），非原生动态策略 |
| **动态 VRPTW 改造** | CO-enriched-ML（官方权重 / 重训变体 / ±PC-HGS） | **保留**，并**明确区分**三个变体 | 原论文针对**动态 VRPTW**，但我们的**逐揭示适配改变了原机制** ⇒ 方法名旁须标 **adapted ordering variant**，**不得**称完整复现原论文在线策略 |
| **取送动态适配** | MAPT | 保留**适配报告**；**暂不**用于完整原方法能力结论 | 当前主要保留**部分排序动作**（前 ~3 位），取送映射仍有限制 |
| **原生搜索/改进受限** | SGBS、DeepACO、LIH | **放补充表**，报告**完整搜索预算与超时** | 部分原生搜索/改进机制**被适配接口限制** |
| **合法但不具信息量** | `rule: value/energy λ=3` | 保留**资格说明**，**不**列为有意义的性能竞争者 | **合法全拒**（0 接单）⇒ 无排序信息量（非"性能很差"） |

**RRNCO** 归入「Zero-shot ordering 适配」组（`学习型（排序）`），与上表同规处理。
**Ours（A3 / I3）** 是**本工作**，单列，不计入外部方法。

**CCF 等级、Params(M)、checkpoint 等信息** ⇒ 移入**补充材料**
（等级列已在总表提供，见 `读表注意与已知限定.md` §2.10）。

## 4. 正式比较必须同时满足的 5 条硬要求

### 4.1 统一记录并检查的字段

```
protocol_id · day_id · future_policy · shadow_mode · K · time_limit
contract_sha256 · data_sha256 · data_meta_sha256
shared_source_sha256（跨 gate 共享源码） · 依赖闭包 SHA · method_class
booking_horizon   ← 因果性开关（必须非 None 且两臂相等；见下）
```

⚠️ **`booking_horizon` 必须记录（2026-10-14 读源码发现）**：
`StrictOnlineEnv(booking_horizon=None)` 会让 `has_future_reveal` **读真实未来**
（源码自述"旧行为…非因果主张"）⇒ **整个 strict-online 协议失效**。
所有 runner 运行时都传了 `BOOKING_HORIZON = 16.0`，但**既有 gate 的 `config` 里没有这个字段**
⇒ 因果性**无法从落盘产物审计**。新协议必须显式记录并与对照臂相等。

### 4.2 五条要求

1. **同日 `day_id` 一一对应**：不得缺日、不得复制日（原始记录层校验，见 `check_pairing_identity.py` D 段）。
2. **同一可见信息协议 + 同一冷链合同 + 同一主档** `p_c=(5,10,15)`。
3. **跨 gate 的共享源码身份相符** —— **不只是**各自 `source_stable=True`
   （后者只证明"启动==结束"，**不能**替代跨运行同源；这正是 A3 被判 `CROSS-SOURCE` 的原因）。
4. **身份闭包通过**：`learned` ⇒ checkpoint + 依赖闭包；`nonlearning_solver` ⇒
   配置 + 依赖闭包（**不得**伪造 checkpoint）；`rule` ⇒ 共享身份。
   工具：`qualification_gate.py`、`nonlearning_identity.py`。
5. **硬约束 / 超时 / fallback / 异常全部计入**，并随结果一并报告。

### 4.3 主档**不得**只做事后罚金重计分（F3 的处理）

下一版必须明确区分两类实验，**不得混列**：

| 实验类型 | 策略是否**重新决策** | 允许的解释 |
|---|---|---|
| **固定策略合同敏感性** | 否 | 同一策略面对不同拒单损失时，**核算**效用如何变化 |
| **合同感知动态决策** | 是 | 策略如何**根据拒单损失调整接拒行为** |

⇒ **正式主档**应使用**运行前冻结**的主档拒单损失，让策略按**其声明的机制**在线决策。

> ⚠️ **旧数据不改**：既有 gate 与历史表格**保持只读**，继续作为**历史比较**；
> 新协议**另行生成**。**禁止**修改原 gate 使新旧结果"看起来一致"。

**工具（不重新发明门禁）**：`qualification_gate.py`（资格）、`check_pairing_identity.py`（配对/CI）、
`nonlearning_identity.py`（非学习身份）、`check_control_config.py`（对照配置与两臂可配对性）。

## 6. 本协议**不做**的事（边界）

* **不**跑任何实验、烟测或正式批次；**不做**资源计时（须先锁定硬件/线程/预算/停止条件）；
* **不**修改任何既有 gate、冻结树、已封存结果或已交付数字；
* **不**把历史数值填进 §5 的空表；
* **不**因外部方法排名"已经好看"而重跑几十个模型找更高效用；
* **不**因 Role C 将来可能成为强对照而事后替换 P1-A 已锁定的唯一主对照；
* **不**触碰保留最终测试种子（`20260927` / `20260928`）；**不**合并 `main`、**不**创建 Release。
