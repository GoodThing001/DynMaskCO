## 1. 缺口 A：把「决策完成」与「权威提交」拆成两个维度

### 1.1 被取代的判定（缺陷）

现行 `classify_fallback()` 开头：

```python
if not commit_observed:
    return {'fallback_applied': None, 'fallback_kind': 'FALLBACK_NOT_VERIFIABLE'}
```

**为什么错**：拒单**通常不产生**新计划的权威提交，但它**仍然可以是一条已经完成的决策**。
在分类**入口**仅因 `commit_observed=False` 就返回 `NOT_VERIFIABLE`，
会把 B3 超时拒单这类**已有充分证据**的决策丢掉，
直接损害 **C1（异常证据）与 C3（回退计数）能否分别独立核验**。

### 1.2 新语义：三个**分开**的维度

| 维度 | 含义 | 取值 |
|---|---|---|
| `decision_outcome_observed` | 是否取得**本次决策完成**及其**动作**证据 | `True` / `False` / `None`(未知) |
| `authoritative_commit_observed` | 是否取得**新计划实际采纳**的权威证据 | `True` / `False` / `None`(未知) |
| `retained_plan_verified` | 是否取得**决策后实际保留的权威计划**证据 | `True` / `False` |

**硬性规定**：

1. **观察到硬超时导致 B3 拒单 ≠ 观察到真实的终态计划回退。**
   异常原因、拒单动作、**实际保留的权威计划**必须**分开记录**。
2. **缺少 `retained_plan_verified` 时，`fallback_applied` 不得写 `True`。**
   ⇒ 新分类结果 `b3_hard_deadline_retained_plan_unverified`（`fallback_applied=None`）。
3. `retained_plan_verified=True` 必须同时满足：
   - 权威证据种类 ∈ `RETAINED_PLAN_EVIDENCE_KINDS`
     = (`post_decision_plan_readback`, `no_change_commit_receipt`)；**且**
   - 保留的计划与决策前计划 `plan_before` **内容相等**。
4. `decision_outcome_observed` 为 `False`/`None` ⇒ 仍判 `FALLBACK_NOT_VERIFIABLE`
   （连"决策完成"都不知道，不得往下推）。
5. **旧的单一 `commit_observed` 对 `classify_fallback` 不再是充分入口**：
   该布尔**混淆**了"决策完成"与"计划采纳"，正是缺口 A 的成因。
   `plan_variants` 中 `commit_observed` 语义**不变**（那里它确实只指计划采纳）。

### 1.3 分类真值表（固定）

| 条件 | `fallback_applied` | `fallback_kind` |
|---|---|---|
| `decision_outcome_observed` 非真 | `None` | `FALLBACK_NOT_VERIFIABLE` |
| `boundary == B2_budget_out_of_range` | `False` | `b2_boundary_reject` |
| `B3` + 硬截止异常 + **保留计划已核验** | `True` | `timeout_fallback` |
| `B3` + 硬截止异常 + **保留计划未核验** | `None` | `b3_hard_deadline_retained_plan_unverified` |
| `B3` + 非截止异常 | `False` | `b3_conservative_reject` |
| `B3` + 无 `exception_audit`／类型不可用 | `None` | `FALLBACK_NOT_VERIFIABLE` |
| 仅 `action=reject` | `None` | `FALLBACK_NOT_VERIFIABLE` |
| 其余 | `False` | `none` |

> 新增 kind `b3_hard_deadline_retained_plan_unverified` 必须加入 `FALLBACK_KINDS`
> 白名单；非法 kind 仍由 `add_fallback` fail-closed 拒绝。

## 2. 缺口 B：归档必须能**从原始字节独立重建输入身份**

### 2.1 被取代的口径（缺陷）

现行 `record()` 只写 `input_decision_id` **摘要**，**不**写规范化输入快照。

⇒ 独立复核者拿到全部 JSONL 也**无法**恢复车辆状态、冻结计划、可见订单集合、
完整决策上下文，也**无法**逐元素核验三臂输入一致。
`input_decision_id` 相同只能作**关联线索**，**不足以**完成独立的逐元素输入核验。

现行 `verify_written()` 只检查：文件存在、非 0 字节、末行可解析、含 `input_decision_id`。
**没有**证明末行**就是**刚写入的目标记录，也**没有**验证快照与 SHA 的对应关系。

### 2.2 新语义

1. **归档记录内必须同时保存规范化输入快照**：
   - `input_snapshot`：**规范化**后的快照副本（决策前量，且已过严格 schema）；
   - `input_snapshot_sha256`：该规范化字节的 SHA-256；
   - `input_decision_id`：由**同一**规范化形式派生 ⇒ 三者必须**互相自洽**。
2. **冻结与复核分离**：新增 `freeze_input(decision_point, input_snapshot) -> FrozenInput`。
   - 冻结时：严格 schema 校验 + 深拷贝 + 规范化 + 记录摘要；
   - `FrozenInput.assert_unchanged(observed)`：把**再观测**到的快照重新规范化并比对，
     不等 ⇒ `InputIdentityError`。
   - **调用前后各验一次**：三臂共享同一输入对象**不天然**保证输入不可变
     ⇒ 必须由调用方在决策**前**与**后**分别核验快照未被修改。
3. **`record()` 写完后必须证明末行 == 目标记录**：
   `verify_written(expect_record=rec)` 要求末行**与目标记录的规范化行逐字节相等**，
   并**重算** `input_decision_id` 与 `input_snapshot_sha256`，与归档字段比对。
4. **独立复核工具**：新增只读复算程序，
   仅凭归档 JSONL 字节重算输入身份与快照 SHA，**不依赖**记录器内存状态。

## 3. 缺口 C：归档输出路径必须**运行时**受限

### 3.1 被取代的口径（缺陷）

`static_selfcheck()` 的 AST 检查**没有**、也**不能**证明
`SidecarRecorder._open()` **动态传入**的 `sidecar_path` 不可能指向受保护源码。
⇒ AST 未命中冻结模块文件名**不构成**写入路径隔离的证明。

### 3.2 新语义（fail-closed）

1. `output_root` 成为 `SidecarRecorder` 的**必填**参数；
   缺失或为 `None` ⇒ 构造时抛 `ArchivePathError`（**不允许**隐式推断输出目录）。
2. 归档路径必须位于 `output_root` **之内**（按 `realpath` 规范化后判定，
   拒绝 `..` 逃逸、拒绝符号链接逃逸）。
3. 规范化真实路径**不得**指向：
   - 源码目录（含四个冻结模块所在目录）；
   - 冻结树；
   - 历史归档原件（登记在案的原件文件名）。
4. **写入前后各验一次目标身份**（`st_dev`/`st_ino` 一致）
   ⇒ 防止路径替换（symlink/rename）造成误写。
5. 未过任一门 ⇒ **不写**，按 `ARCHIVE_INCOMPLETE` 降级并如实上报原因。

> `does_not_write_frozen=True` 是**静态**结论，**不得**用来宣布缺口 C 已解决；
> 缺口 C 的关闭证据是**运行时**路径门的回归。
