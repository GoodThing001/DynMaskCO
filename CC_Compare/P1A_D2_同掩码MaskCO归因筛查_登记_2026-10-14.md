# D2 诊断登记：**同掩码 MaskCO 归因筛查**（F−D / F−E，只读或固定状态）

**日期**：2026-10-14 · **状态**：**登记（未执行）** · **性质**：固定状态归因筛查，**不是**等时在线比较
**授权**：用户 2026-10-14 裁定④「批准先做两项有限诊断」第二项：
「固定状态、掩码、保留边、候选资格、C0 合同和比较预算，分别检查模型相对几何修复与随机对照的
可执行动作、候选质量及真实提交差异。」
**边界**：不启动新训练、不启动正式批次、不触碰最终测试种子、不修改任何 gate / 冻结证据 / 封存结果。

---

## 1. 唯一主问题

> 在**同一个初始解、同一掩码、同一保留边集、同一候选资格、同一 C0 合同、同一比较预算**下，
> 已训练 MaskCO 修复（F）相对**非学习几何修复**（D）与**随机对照**（E）是否产生
> **可执行动作 / 候选质量 / 真实提交**上的差异？

本诊断**只做归因筛查**：回答"学习权重是否产生独立差异"。
它**不**回答"效果是否为正"（那须独立预声明 + 效果门），**也不**取得正式科学比较资格。

## 2. 输入（冻结；缺字段 ⇒ `not_qualified`，不去重建）

执行者必须**在运行前**把下列路径与 sha256 填入本登记的 `inputs` 表（空着即视为未完成登记，不得运行）：

| 角色 | 要求 |
|---|---|
| 固定状态/教师状态集合 | 已封存的固定状态资产；sha256 与登记值一致 |
| 掩码池 | 必须来自统一掩码池（`mask_candidate_pool` 语义），并附 `validate_mask_scope` 通过证据 |
| 几何修复实现（D） | 非学习几何修复的源码 sha256 + 配置 sha256 |
| 随机对照实现（E1/E2） | 见 §3 的两级定义；两者的源码/种子/训练协议 sha256 |
| 已训练 MaskCO（F） | checkpoint sha256 + 加载配置 sha256 |
| C0 合同 / 数据 | `contract_sha256` / `data_sha256` / `data_meta_sha256` 与登记值一致 |

⚠️ **若既有封存资产不含所需字段**（例如缺少"可执行动作"或"真实提交差异"的逐候选记录），
**必须**输出 `not_qualified` 并另立**字段缺口登记**；**禁止**事后补造日志、也**禁止**
用近似量（如候选分数替代可执行动作）凑齐比较。

## 3. F−E 必须分两级（用户裁定④明确要求）

| 级别 | 定义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **E1** | **未经训练的随机权重** | 当前权重是否产生与几何修复不同的结果 | **不能**证明预训练/学习带来增益 —— 它只说明"这组权重不一样" |
| **E2** | **同架构、同任务、同训练协议**的**随机初始化**对照 | 学习/预训练相对"同等训练但随机起点"是否有增量 | 仍不证明效果为正 |

⇒ **正式归因至少需要 E2**。只做 E1 时，结论必须写成"**仅示当前权重与几何修复不同**"，
**不得**出现"预训练/掩码生成有独立贡献"一类表述。

## 4. 唯一主对照与判据

主对照写死为三对单因素比较，**每一对只允许被检验因素不同**：

```
F − D   学习权重 vs 非学习几何修复（同掩码、同保留边、同候选资格、同预算）
F − E2  学习/预训练 vs 同任务同协议随机初始化
E1 − D  仅作描述（不用于任何归因主张）
```

**可归因性核对（机械，fail-closed）**：三臂的 `(初始解 hash, 掩码 hash, 保留边 hash,
候选资格集合, contract_sha256, budget)` **必须逐字段相等**；任一不等 ⇒ 该对**判不可归因**，
输出 `not_comparable`，不进入比较。

**判据只判"是否产生差异"**（不判方向、不判显著性）：
若 F 与 D 在**可执行动作集合**与**真实提交**上**完全相同** ⇒ 报
`no_attributable_difference`（**明确不是**"MaskCO 无效"的普遍结论，
只对本掩码池/本状态集合成立）；有差异 ⇒ 报可识别，并**如实列出**差异条数。
方向与效应量归未来的独立预声明，**本诊断不判**。

## 5. 输出字段（逐项必填）

```text
inputs                     {role: {path, sha256}}
arm_identity               {D: cfg_sha, E1: seed_cfg_sha, E2: train_cfg_sha, F: ckpt_sha}
attributability            {pair: equal | not_comparable, per_field_diffs}
actions                    {arm: {n_executable_actions, action_hash_set_size}}
candidate_quality          {arm: {n_candidates, plan_hash_dedup_count}}
committed_differences      {pair: {n_action_diff, n_plan_diff, n_commit_diff}}
runtime                    {arm: {wall_seconds, n_solver_calls}}   # 真实耗时，不用"脚本很快"代替
comparison_scope           "same_state_offline" | "equal_time_online"
field_gaps                 [缺失字段清单]      # 非空 ⇒ verdict=not_qualified
verdict                    qualified | no_attributable_difference | not_comparable | not_qualified
```

## 6. 资格边界（必须在结论里原样出现）

* 若只复用**已存评分或候选**，`comparison_scope` 必须写 **`same_state_offline`**，
  结论只能称"**同状态离线归因诊断**"；
  **不得**因为脚本算得快就称"等时在线比较合格"。
* **配送完整请求仍未闭合**：完整 **8+2 秒发布门**是**工程资格前置条件**。
  本轮已实测"实际加载闭包"单点捕获 **22.77–26.74 s**（3753 文件 / 2007 模块）、
  推理 **0.667 s**；两者**范围不同**，**不能相减**，也**不构成**完整请求计时。
  ⇒ **不得**通过"把身份验证移出请求窗口"来满足该门（用户裁定明确）。
* 本诊断**不**产出效果结论，**不**并入 P1-A 效果门，**不**取得跨基线资格。

## 7. 失败条件（任一命中 ⇒ `not_qualified`）

1. `inputs` 表未填齐或任一 sha256 与登记值不符；
2. 掩码池无法证明来自统一池（缺 `validate_mask_scope` 证据）；
3. 三臂可归因性核对出现 `not_comparable` 且无法在同一登记内消除；
4. 缺少"可执行动作"或"真实提交"字段（⇒ 报字段缺口，不重建）；
5. 只提供 E1 却要作预训练归因主张（⇒ 该主张直接不允许，输出 `not_qualified`）。

## 8. 资源门

* **CPU-only**，`JAX_PLATFORMS=cpu` / `CUDA_VISIBLE_DEVICES=''`；不启动 GPU 依赖阶段；
* 固定状态筛查预期有限核并行 + 明确墙钟上限（运行前填入，不得边跑边放宽）；
* 长任务必须可断点/可回收；共享机上不得与既有正式批次争抢同一核组。

## 9. 本诊断**不**主张

* 不主张 MaskCO 有效或无效；`no_attributable_difference` **只**对本掩码池/本状态集合成立；
* 不把 E1 的结果当作预训练增益；
* 不因本诊断通过而启动新训练、扩大网络容量或增加训练轮数。
