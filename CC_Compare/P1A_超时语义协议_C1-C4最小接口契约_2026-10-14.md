## 0. 为什么不直接改三个核心文件

用户给出的理由（照录并同意）：当前缺口**不只是传字段**，还包括
**持久化原子性、决策身份、双预算点进度、独立事件复算**。
单纯扩展 `logger` 的参数**不一定**解决问题，反而可能**改变既有决策日志的事务语义**
（`DecisionLogger` 是"先校验、后改状态、任何异常都不留痕迹"的写入器）。

⇒ **首选路线：分析侧 wrapper + sidecar 归档 + 独立统计器**，
核心接口**只在证明无法绕开时**才提交**函数级白名单**，由下一轮单独批准。

## 1. Sidecar 归档：数据结构契约

**一条 sidecar 记录 = 一次决策事件**（不是一次运行）。字段分四组：

### 1.1 运行与决策身份（**必填**，解决"决策身份未绑定"）

| 字段 | 来源 | 说明 |
|---|---|---|
| `run_id` | 运行开始生成（`uuid4` 或 `sha256` 前 16 位） | 三臂各自唯一 |
| `arm` | 运行参数 | `old` / `c2` / `write_off` |
| `decision_point` | **wrapper 注入**（决策点序号 0..7） | ⚠️ 补上 C2 目前缺的那一项 |
| `decision_points_digest` | 由上下文重算 | 必须 `== 5b432f28…` |
| `event_id` | 现有 `exception_audit.event_id`（进程内单调） | 与 `decision_point` 联合定位 |
| `event_seq_in_decision` | wrapper 计数（本决策内第几条事件） | 供"同决策多事件"去重 |
| `clock_domain` / `timer_origin` | `time.perf_counter` / `time.monotonic` 标注 | 时间戳跨记录可比性 |
| `instrumentation_source_sha256` | 插桩/审计模块 SHA | 身份 |

### 1.2 异常与回退（**必填**，解决"异常来源 + 行为回退"）

| 字段 | 来源 |
|---|---|
| `exception_audit`（原样透传） | `role_c_opportunity_cost._exception_audit`（`c2-v1`） |
| `exception_type` / `exception_stage` / `budget_point` / `hard_deadline_exception` / `evaluation_status` | 同上（已在 `exception_audit` 内） |
| `fallback_applied` / `fallback_kind` | **新增**：wrapper 观察到回退时记录（当前 **MISSING**） |
| `terminal_fallback_count` | 本决策终态回退次数（§14.1：**至多 1**；>1 ⇒ `execution_error`） |

### 1.3 双预算点进度（**必填**，解决"hi/lo 状态不完整"）

| 字段 | 说明 |
|---|---|
| `hi.status` / `hi.n_scenarios_entered` / `hi.n_scenarios_completed` | 第一个预算点 |
| `lo.status` / `lo.n_scenarios_entered` / `lo.n_scenarios_completed` | 第二个预算点 |
| `lo.b_lo_raw` / `lo.lo_clipped_to_zero` | 保留原始 `B − e_o`（可负）与截断标记（§3.2） |
| `n_budget_points_entered` / `n_budget_points_completed` | `completed` 需 `== 2` |

### 1.4 决策身份（计划）与完整性

| 字段 | 说明 |
|---|---|
| `plan_before_sha256` / `plan_after_sha256` | 计划**身份**（规范化序列化后的 SHA），用于**主判**的 `plan_of` 比较 |
| `plan_before` / `plan_after` | **逐元素**计划（`{vid: [orders]}`），供逐位比较与独立复算 |
| `action` / `boundary` / `reject_reason` / `lambda_B` / `e_o` / `certify_ok` | 与现有 `diag` 对齐 |
| `raw_events` / `events` / `leaf_counts` | C4：原始事件流（`('enter'/'exit', label, ts)`）与区间表 |
| `event_stream_complete` | `true` / `false`；**异常或强制截断导致缺失时如实标 `false`** |
| `censored_intervals` | A 类被硬杀时**未闭合**的区间（标 `CENSORED`，**不补写 exit**） |

## 2. Sidecar 与**原有决策日志**的关系（绑定规则）

| 规则 | 内容 |
|---|---|
| **不改原有写入语义** | `DecisionLogger.log_event()` 的"先校验、后改状态、不留痕迹"**保持不变**；sidecar **不参与**该事务 |
| **绑定键** | `(run_id, decision_point)` ↔ 原日志的 `(inst_idx, day_id, clock, order_id, decision_hash)`；sidecar 记录里**同时**保存 `decision_hash` 以建立可核验的桥 |
| **写入顺序** | **先**写 sidecar（事件级、append-only），**后**写原日志；sidecar 失败 ⇒ **不**阻止原日志（保持既有行为），但记录 `sidecar_write_failed=true` |
| **原子性** | sidecar 采用 **append-only JSONL + 每行一次 `write` + `flush`**（不用 `fsync`）；崩溃只会丢**尾部未完成行**，由 `event_stream_complete=false` 标识 |
| **失败处理** | 写入失败**必须**留痕（`sidecar_write_failed` + 原因），**不得**静默丢弃；**不得**因此改变判决 |
| **独立复算** | 复核程序**只读 sidecar 字节**，重算 ①`ΣA_i`/`G`（离线扫描）②事件级/决策级计数 ③`plan_of` 逐位比较；**不得**调用被测/驱动侧同一函数 |

### 2.1 写入后验收（**硬要求**）

每条 sidecar 落盘后必须**读回验收**：非 0 字节、关键字段非空、SHA 可复算。
（这是"写盘失败"事故的教训：`tmux` **不能**替代增量持久化与写入后验收。）

## 3. 独立统计器契约（C3）

| 计数 | 定义 | 去重键 | 归属 |
|---|---|---|---|
| `n_deadline_timeouts` | **受影响的唯一决策数** | `(run_id, decision_point)` | 决策级 |
| `n_deadline_timeout_events` | 异常**事件条数** | `(run_id, decision_point, event_id)` | 事件级 |
| `n_execution_errors` | 非 `DecisionTimeout` 异常 | 同上；**必须注明是决策数还是事件数** | 显式标注 |
| `n_fallbacks` | 终态回退次数 | `(run_id, decision_point, fallback_event_id)`；**每决策 ≤ 1** | 决策级 |
| `n_not_entered` / `n_unknown` | 合法短路 / 证据不足 | `(run_id, decision_point)` | 决策级 |

⚠️ **不得要求** `n_deadline_timeouts == n_fallbacks`（§14.2/§4.2.2）；
核验的是**逐事件分类 ↔ 汇总计数双向一致**。
⚠️ **真实路径**每决策至多 **1** 条异常事件（§14.5）⇒
`n_deadline_timeout_events ∈ {0,1}`；第 8 类"双异常"仅**人工注入**。

## 4. 最小实现路线**可行性审查**（是否必须改核心接口）

| 缺口 | 能否用**分析侧 wrapper / sidecar** 解决 | 结论 |
|---|---|---|
| `decision_point` 绑定 | ✅ wrapper 在调用 `decide_fn` 前把决策点序号放进上下文，写 sidecar 时带上 | **不需要**改核心 |
| `exception_audit` 进归档 | ✅ sidecar 直接读 `diag['exception_audit']` 落盘（**不需要** `logger` 接收） | **不需要**改核心 |
| `plan_of` 记录 | ✅ wrapper 在调用前后各抓一次计划（`ls.plan_of` / replanner 的 `_plan`），算 SHA 并落盘 | **不需要**改核心 |
| `hi`/`lo` 子状态 | ⚠️ **部分**：wrapper 只能看到"进了几个场景"（经插桩计数器），**看不到** `b_hi`/`b_lo_eval` 的内部进度 ⇒ 完整子状态**需要**核心侧暴露（或插桩在 `shadow_price_budget` 内部加计数钩子） | **可能**需要**函数级白名单** |
| `fallback_applied` / `fallback_kind` | ⚠️ wrapper 可从 `diag['boundary']` + `action` **推断**回退种类，但"回退"在 Role C 里是**判决结果**而非独立事件 ⇒ 语义需先定义 | **需先定义语义** |
| `raw_events` / `events` / `leaf_counts` | ✅ 已有插桩层（`role_c_phasea_instrument`）产出，只需**归档** | **不需要**改核心 |
| 计数与独立复算 | ✅ 分析侧独立模块 | **不需要**改核心 |

**可行性结论**：**大部分缺口可以不碰核心接口**；
只有 **`hi`/`lo` 完整子状态**与 **fallback 语义定义**两项**可能**需要
**函数级白名单**。⇒ 建议下一步先做**分析侧最小实现**（覆盖可绕开的部分），
对那两项**单独提交函数级白名单**，由下一轮裁定。
