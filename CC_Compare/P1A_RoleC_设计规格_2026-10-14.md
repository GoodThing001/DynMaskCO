## 1. Role C 的定义与"独立"的含义

Role C = **不使用 MaskCO、不使用任何学习权重**的**前瞻接拒 + 前瞻路线优化**规划器
（`method_class = 'nonlearning_solver'`，见 §0.2.1）。

"独立"指以下三件事**同时**成立：

1. **无学习组件**：无 checkpoint、无训练产物参与决策（身份闭包按 §0.2.1 闭合）。
2. **决策函数与本项目既有的 `SaaReplanner` 不同**：不是换名重用（§9.1 明文禁止）。
3. **路线搜索是自己的前瞻优化**，不是"排序 → 交给共同下游打包"。

## 2. 四维度机制规格（§9.1 要求"消融可识别"）

以下每一项都给出：**规格** + **必须实现的消融开关** + **消融后应观察到的退化**。
消融开关是"机制差异确实存在"的**判据**，不是可选功能。

### 2.1 候选动作评估：**预算机会成本（内生影子价格）**

**规格**：在每次揭示事件，对每个新揭示订单 `o`，显式比较**接单 vs 拒单**的效用差，
其中接单侧要扣掉它占用的**预算机会成本**：

```
净增益(o) = [ revenue_o − fuel_o − reject_loss_o ] − λ_B · e_o
接单 ⟺ 净增益(o) > 0  且  certify_plan(接单后计划) ≤ B
```

* `e_o` = `c0_marginal_energy(c, q, cooling_share, contract)`（与既有实现同一物理口径）。
* **`λ_B` 必须是内生的**：由**同一场景集合**在预算 `B` 与 `B − e_o` 两点上的
  期望效用差估计（`λ_B ≈ [J(B) − J(B − e_o)] / e_o`），**不是**外生设定的常数价格。
  ⚠️ 这是与 `SaaReplanner` 的 `overage_price`（外生连续价格）**机制上的分界**：
  Role C 的价格由"预算收紧的响应"**导出**，可被单独关闭。

**消融开关** `--ablate-opportunity-cost`（= 令 `λ_B ≡ 0`）：
**预期退化** ⇒ 净增益只由 `revenue − fuel − reject_loss` 决定 ⇒ 行为趋近
"**可行即接**"（`certify_plan` 仍把关硬可行性，但不再有预算稀缺信号）。

### 2.2 路线搜索：**独立前瞻路线优化**

**规格**：对每个候选动作（接单插入位置 / 拒单后保持 incumbent），Role C 用**自己的**
前瞻路线优化在**场景集合**上评估后果；优化器须在 `time_limit` 内给出计划并被 `certify_plan` 认证。
**不复用** `SaaReplanner` 的共同下游作为其唯一搜索来源。

**消融开关** `--ablate-lookahead`（= 只在**当前已揭示**订单上做**近视（myopic）**评估，
不使用场景前瞻）：
**预期退化** ⇒ 与 `cond_hist`（条件历史排序 + 可行即接）行为趋同
（用配对差与动作一致率衡量，见 §5 T2/T3）。

### 2.3 场景使用：**固定的条件历史采样器**

**规格**：场景**只**从**允许的训练历史**采样（与 `CondHistoricalSampler` 同一"允许来源"定义），
采样器版本与参数**冻结**并计入身份闭包；`K` 与 `cond_hist + SAA` **一致**（不因新算法表现改 K）。

**消融开关** `--ablate-scenarios {shuffle,truncate}`：
* `shuffle`：打乱场景与时钟的对应 ⇒ 前瞻信息被破坏；
* `truncate`：只留 1 个场景（`K=1`）。
**预期退化** ⇒ 结果显著变化（若**不**变化，说明前瞻实际未参与决策 ⇒ 机制主张不成立）。

### 2.4 认证顺序：**先评估 → 再认证 → 后提交**

**规格（硬性，违反即判实验失效）**：
```
候选评估（场景前瞻 + 机会成本） → certify_plan ≤ B（含已提交承诺与已执行前缀）
   → 提交（ irrevocable accept/reject）
```
* **严格冻结已执行前缀**与**已接受承诺**（不可撤销、不可重排）。
* 非先行性（non-anticipatory）：决策只能使用 `clock` 时刻**已揭示**的信息；
  场景前瞻是**采样**，**不得**读取真实未来。
**判据**：任何一次"先提交后认证"或"读取真实未来"⇒ 该臂**失效**，不解释为方法差异。

## 4. `nonlearning_solver` 身份闭包（跑批前必须可独立重算）

按 §0.2.1，Role C **没有也不得伪造** `checkpoint_sha256`；必须闭合：

| 字段 | 含义 | 独立重算方式 |
|---|---|---|
| `source_stable` | 启动 == 结束的源码哈希 | runner 自哈希 |
| `contract_sha256` / `data_sha256` / `data_meta_sha256` | 共享身份（**所有**臂强制） | 磁盘重算 |
| `provider_dependency_sha256` | **源码 + 第三方依赖闭包** | 对文件清单逐个 SHA-256 后按**相对路径排序**聚合（顺序无关） |
| `solver_config_sha256` | **求解器配置**（§3 全部旋钮 + 预算/时限/种子） | 规范化 JSON（键排序、浮点规范化）后 SHA-256 |

**工具**：`CC_Compare/tools/nonlearning_identity.py` —— 产出上述字段，
并提供**从磁盘独立重算**的 `actual_hashes`，交给
`qualification_gate.evaluate(..., method_class='nonlearning_solver')` 做 fail-closed 三重校验
（字段齐备 / 64 位小写十六进制 / 独立重算逐字段相符）。
**身份块自述不能自证**：未提供 `actual_hashes` ⇒ 判不合格。
