## 1. Role C 的定义与"独立"的含义

Role C = **不使用 MaskCO、不使用任何学习权重**的**前瞻接拒 + 前瞻路线优化**规划器
（`method_class = 'nonlearning_solver'`，见 §0.2.1）。

"独立"指以下三件事**同时**成立：

1. **无学习组件**：无 checkpoint、无训练产物参与决策（身份闭包按 §0.2.1 闭合）。
2. **决策函数与本项目既有的 `SaaReplanner` 不同**：不是换名重用（§9.1 明文禁止）。
3. **路线搜索是自己的前瞻优化**，不是"排序 → 交给共同下游打包"。

## 2. 四维度机制规格（§9.1 要求"消融可识别"）

以下每一项都给出：**规格** + **必须实现的消融开关** + **消融开关的验收方式**。
消融开关是"机制差异确实存在"的**实现判据**，不是可选功能。

⚠️ **验收方式的措辞（2026-10-14 修正）**：原稿写"消融后**应观察到的退化**"，这是**不合理的判据** ——
它把"**必须显著退化**"变成门禁条件，于是①合法的**零效应**结果会被记成失败；②等于**预设结论**
（机制一定有用）。现改为：**记录并报告行为差异**（接单率 / 与对照的动作一致率 / 效用差）；

* **差异恒为零 ⇒ 判实现缺陷（FAIL）** —— 说明该消融开关**根本没接进决策路径**；
* **差异不为零但不显著 ⇒ 一律不得判 FAIL** —— 显著性属**科学结论**，不属资格/回归门
  （等级 / 效应量 / 是否过门由 §5 之外的效果门管，见 `P1A_阈值锁定裁定_2026-10-14.md`）。

### 2.1 候选动作评估：**预算机会成本（内生影子价格）**

⚠️ **2026-10-14 修正（用户指出两处）**：①**符号/定义要写死**；②**必须避免重复计机会成本**。

**规格（唯一有效表述）**：在每次揭示事件，对每个新揭示订单 `o`：

```
myopic_net(o) = revenue_o − fuel_o − reject_loss_o          # 只含"接这一单"的直接净收益
λ_B(o)        = clip( [ Ĵ(B) − Ĵ(B − e_o) ] / e_o , 0, +∞ )  # 预算的边际价值（≥0）
接单 ⟺  myopic_net(o) − λ_B(o) · e_o  >  0   且   certify_plan(接单后计划) ≤ B
```

* `e_o` = `c0_marginal_energy(c, q, cooling_share, contract)`（与既有实现同一物理口径）。
* `λ_B` **必须内生**：由**同一场景集合**、在预算 `B` 与 `B − e_o` 两点上的期望效用差导出，
  **不是**外生常数价格 —— 这是与 `SaaReplanner` 的 `overage_price` 的机制分界。
* `clip(·, 0, +∞)`：可用预算变少**不可能**提高效用 ⇒ 理论上差 ≥ 0；
  负值只能是采样噪声 ⇒ 截到 0，避免"负的影子价格"反向补贴接单。

#### ⚠️ 2.1.1 禁止重复计机会成本（判据不是文风，是**会算错**）

`Ĵ`（场景前瞻价值）在本规格里**只有一个用途：估计 `λ_B`**。
**不得**把 `Ĵ` 当作第二个价值项再加进接单判据。两种写法只能**二选一**：

| 写法 | 判据 | 预算稀缺性从哪来 | 结论 |
|---|---|---|---|
| **(i) 近视净收益 + 显式影子价格**（**本规格采用**） | `myopic_net − λ_B·e_o > 0` | 来自 `λ_B`（由 `Ĵ` **估计**得到） | ✅ 自洽 |
| (ii) 直接前瞻比较 | `V̂(接单计划, B) > V̂(拒单计划, B)` | 已含在 `V̂` 里（预算 B 进 rollout） | ✅ 自洽，但**不是本规格** |
| (iii) 两者相加 | `V̂(接单) − V̂(拒单) − λ_B·e_o > 0` | **算了两次** | ❌ **禁用** |

**为什么 (iii) 是错的**：在写法 (ii) 里，`V̂(·, B)` 已经是在**同一个预算 B** 下 rollout，
"这一单占用 e_o 会让未来少用 e_o"**已经体现在 `V̂` 的差里**；再减一次 `λ_B·e_o`
等于把同一笔预算稀缺**扣两遍** ⇒ 系统性**过度拒单**（且随 `e_o` 增大而放大）。
同理，(i) 里 `Ĵ` 必须**只含未来**（不含 `revenue_o`），否则又会把 `myopic_net` 重复计入。

**可测的硬判据（T9，纯函数、不读效用）**：
`λ_B ≥ 0`；`e_o = 0 ⇒ λ_B·e_o = 0`（不得凭空产生机会成本）；
把 `Ĵ` 整体替换为常数 ⇒ `λ_B ≡ 0`（证明 `λ_B` 确实**只**来自 `Ĵ` 的预算响应）；
且**代码路径里不存在**第二个把 `Ĵ` 加进接单判据的项。

**已实现（2026-10-14）**：`CC_Compare/tools/role_c_opportunity_cost.py`
（`shadow_price_budget` / `decide` / `myopic_net`，纯函数、不读效用）
+ `CC_Compare/tools/test_role_c_opportunity_cost.py`（**15/15**：T9 全部不变量 +
消融恒等 + 单调性 + 硬约束优先 + 边界 + **契约接地**）。
⚠️ 该模块**只做**"估计 `λ_B` + 按写法 (i) 判决"；**不**负责路线搜索。
⇒ 它对应 A–F 表的 **A/B 版**（"共享非学习修复"），**不需要**先定前瞻求解器；
求解器选型只影响 **C 版**（独立前瞻路线搜索，见 §2.2，**仍待裁定**）。

**消融开关** `--ablate-opportunity-cost`（= 令 `λ_B ≡ 0`）：
此时判据退化为 `myopic_net > 0 ∧ certify_plan ≤ B`；`certify_plan` 仍把关硬可行性，
但**不再有预算稀缺信号**。验收方式见本节开头（记录差异；**恒零=实现缺陷；不显著≠失败**）。

### 2.2 路线搜索：**独立前瞻路线优化**

**规格**：对每个候选动作（接单插入位置 / 拒单后保持 incumbent），Role C 用**自己的**
前瞻路线优化在**场景集合**上评估后果；优化器须在 `time_limit` 内给出计划并被 `certify_plan` 认证。
**不复用** `SaaReplanner` 的共同下游作为其唯一搜索来源。

**消融开关** `--ablate-lookahead`（= 只在**当前已揭示**订单上做**近视（myopic）**评估，
不使用场景前瞻）：
**验收方式（2026-10-14 修正）**：记录与 `cond_hist` 的**动作一致率**与配对差 ——
一致率**变高**是"前瞻确实在起作用"的行为证据；**恒等于无前瞻版本 ⇒ 判实现缺陷**；
但"变高多少"**不作为**门禁阈值（不要求"显著"）。

### 2.3 场景使用：**固定的条件历史采样器**

**规格**：场景**只**从**允许的训练历史**采样（与 `CondHistoricalSampler` 同一"允许来源"定义），
采样器版本与参数**冻结**并计入身份闭包；`K` 与 `cond_hist + SAA` **一致**（不因新算法表现改 K）。

**消融开关** `--ablate-scenarios {shuffle,truncate}`：
* `shuffle`：打乱场景与时钟的对应 ⇒ 前瞻信息被破坏；
* `truncate`：只留 1 个场景（`K=1`）。
**验收方式（2026-10-14 修正）**：记录三种设置下的决策差异（动作一致率 / 接单率 / 效用差）。
**三者输出完全相同 ⇒ 判实现缺陷（FAIL）**（说明场景根本没接进决策）；
**有差异但不显著 ⇒ 一律不得判 FAIL** —— 原稿"结果显著变化（否则机制主张不成立）"
把**科学结论**写成了**门禁**，已删除。

### 2.4 认证顺序：**先评估 → 再认证 → 后提交**

**规格（硬性，违反即判实验失效）**：
```
候选评估（场景前瞻 + 机会成本） → certify_plan ≤ B（含已提交承诺与已执行前缀）
   → 提交（ irrevocable accept/reject）
```
* **严格冻结已执行前缀**与**已接受承诺**（不可撤销、不可重排）。
* 非先行性（non-anticipatory）：决策只能使用 `clock` 时刻**已揭示**的信息；
  场景前瞻是**采样**，**不得**读取真实未来。
**判据**：任何一次"先提交后认证"或"读取真实未来"⇒ 该臂**失效**，不解释为方法差异。

## 4. `nonlearning_solver` 身份闭包（跑批前必须可独立重算）

按 §0.2.1，Role C **没有也不得伪造** `checkpoint_sha256`；必须闭合：

| 字段 | 含义 | 独立重算方式 |
|---|---|---|
| `source_stable` | 启动 == 结束的源码哈希 | runner 自哈希 |
| `contract_sha256` / `data_sha256` / `data_meta_sha256` | 共享身份（**所有**臂强制） | 磁盘重算 |
| `provider_dependency_sha256` | **源码 + 第三方依赖闭包** | 对文件清单逐个 SHA-256 后按**相对路径排序**聚合（顺序无关） |
| `solver_config_sha256` | **求解器配置**（§3 全部旋钮 + 预算/时限/种子） | 规范化 JSON（键排序、浮点规范化）后 SHA-256 |

**工具**：`CC_Compare/tools/nonlearning_identity.py` —— 产出上述字段，
并提供**从磁盘独立重算**的 `actual_hashes`，交给
`qualification_gate.evaluate(..., method_class='nonlearning_solver')` 做 fail-closed 三重校验
（字段齐备 / 64 位小写十六进制 / 独立重算逐字段相符）。
**身份块自述不能自证**：未提供 `actual_hashes` ⇒ 判不合格。

## 5. T 系列回归（**不看效用的正确性**回归，先于任何计时/烟测）

⚠️ **判据措辞已于 2026-10-14 全局修正**：T 系列**只判"机制是否真的接进了决策路径"**，
**不判"有没有用"**。因此：

* **可以**判 FAIL 的：机制**未接入**（消融前后输出**完全相同**）、因果/承诺/预算被违反、身份不匹配；
* **不得**判 FAIL 的：效应**不显著**、方向与预期不符、`CI` 跨 0 —— 这些是**科学结论**
  （由 P1-A 效果门与 δ=20 裁定管），把它们写成门禁等于**预设结论**、
  并会让合法的**零效应**结果被记成"实现失败"。

| 编号 | 断言 | 判据 |
