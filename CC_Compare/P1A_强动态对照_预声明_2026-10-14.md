## 3. 机制假设的证据基础（**区分已验证与推断**）

用户提出的机制假设：
> 「模型生成器只输入订单 token 和时钟，未直接表达车队负载、预算余量与已接受承诺。」

**本次直接读源码的核查结果**：

| 结论 | 状态 | 证据 |
|---|---|---|
| 生成器只条件于**可见订单 token + 时钟桶** | ✅ **已验证** | `scripts/models/maskco_scenario.py`：`MaskCOScenarioModel.__init__`（L239，含 `clock_emb`）与 `__call__(self, tokens, attn_mask=None, clock_bin=None)`（L265）—— 输入只有 token 序列、注意力掩码、`clock_bin`；时钟只经 `clock_bin`（token 头 + 池化表示）进入，**没有**车队负载 / 预算余量 / 已接受承诺的输入 |
| 解码/掩码构造只看**计划(路由)结构与时间窗/坐标** | ✅ **已验证** | `scripts/decoding/maskco_dynamic.py`：`event_driven_keep_mask(routes,…)`、`build_frozen_prefix_mask(routes,…)`、`compute_dynamic_tw_mask(coords, tw_start, tw_end,…)`；该文件里的 `total_budget_ms` 是**计算时间预算**，**不是** C0 能量预算 `B` |
| C0 能量预算 `B` 与"剩余预算"未进入**学习表示**，只在外层 `certify_plan` 起作用 | ✅ **已验证（限这两个模块）** | 上述两个模块全文未出现能量预算 `B`；`certify_plan` 是共享的接受门 |
| **该机制是否就是 I3 负结果的原因** | ⚠️ **仍为推断** | 负向结果已建立，但其**根因**未经实验分离 |

⇒ **本预登记的假设只能建立在"已验证"那一行之上**：
「学习表示缺乏预算/承诺状态」是一个**可检验的表示缺口**，不是已确认的失败根因。

### 若要走该机制，必须先证明（用户列出的前置条件）

1. 同一可见订单历史、**不同车辆与资源状态**下，真实最优接拒偏好**确实存在差异**（离线可算）；
2. **非学习资源感知控制器不能完全解释**这些差异；
3. 新模型**确实利用了资源状态**，而不是仅新增参数或扩大计算预算；
4. 对照**共享初始化、训练预算与下游认证**，保持 strict-online；
5. 训练结束按**预声明固定 checkpoint**，**不按开发效用挑选**。
