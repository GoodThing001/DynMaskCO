V1.21: the runtime source-dependency freeze is closed by derivation, and drift is detected everywhere

The gap: IDENTITY_TARGETS froze 14 paths, but the real F execution path also imports the authorizer,
the execution context, the V1.16 forward control (and through it the V1.14 phase journal) and
d3_l1_v18_readonly_audit.typed_bytes -- which computes the bitwise-repeat decision. The closure is
30 source files, not 9. Editing any of the missing ones would have changed execution, identity
checking, timing or the result decision while --readiness still printed READY.

Fix: the watch set is no longer hand-written, it is DERIVED.
  scripts/data/d3_l1_v121_dependency_closure.py builds the transitive local-import closure of the
  execution path's seeds (top-level AND in-function imports, resolved across the extension's
  scripts/ tree to a fixed point), excludes tooling with a recorded reason each, and reports every
  path in ONE canonical repository-relative form. The identity module appends the four non-source
  assets with an explicit root each -- weights/data/profile are extension-relative, the backbone is
  repository-relative -- because spelling those inside the closure mixed two roots and silently
  demoted the derived freeze back to the old 14-path list during development.

  --readiness gained `runtime_watch_covers_closure`: the frozen set is cross-checked against the
  derived closure, so a freeze that omits a file the execution path imports reports NOT_READY and
  names the missing entries. The freeze and the freeze CHECK now come from one place.
