# 锁版 MASKCO 同期补充实验方案

建议补做锁版 ORDER_SPLIT、同规则纯距离 ORDER_SPLIT_D 和 ALNS 的同期复核；纳入 PyVRP 可同时连接近期六法比较。目的为消除跨批次表格中热图增量和强传统对照差额的计时混杂，不改变锁版算法或检查点。本方案尚未执行。

## 实验矩阵

| 项目 | 固定设置 |
|---|---|
| 案例 | 复用 recent5 的 30 个已测案例：27 个主面板案例，加 3 个低重叠 XTW 补例 |
| 面板汇总 | 主面板按丹麦、XTW、GH 分别汇总；低重叠 XTW 单列，重合的 7 个案例不重复执行 |
| 随机种子 | 沿用 33001、33002、33003，便于核对历史同案例同种子结果；本轮属于同期重复评估 |
| 核心三法 | ORDER_SPLIT、ORDER_SPLIT_D、ALNS |
| 推荐四法 | 核心三法加 PyVRP；PyVRP 沿用已验收的 0.11.3 冷链适配 |
| 预算 | 每终点单物理核、模型就绪后在线 60 秒；准备阶段另记，保留原始计时口径 |
| 配对 | 同一案例和种子内各法顺序执行，使用同一物理核、同一初解，并轮换方法次序 |
| 规模 | 三法为 90 个配对区组、270 个终点、16,200 核秒；四法为 360 个终点、21,600 核秒，均不含准备时间 |

30 例清单直接采用 [recent5 元数据](../recent5_20261120/metadata.json) 和 [90 区组矩阵](../recent5_20261120/matrix.json)。所有案例均已使用，不读取另留的 32 例。每个来源先对同一几何内的案例和种子求平均，再报告几何宏平均、改善几何数及几何整簇重采样区间。主要对比固定为 MASKCO−D、MASKCO−ALNS；四法方案另报 MASKCO−PyVRP。低重叠面板作为单独复核，不与主面板重复计权。

## 可复用实现

锁版三法可在独立工作目录调用 [independent.py 的 endpoint](../maskco_perishable_external_20261119/independent.py)，使用 `training_only=False`、`seconds=60`，并复制 [锁版方法描述](../maskco_perishable_external_20261119/reserved_validation/locked_method.json) 及 [reserved_validation/solver](../maskco_perishable_external_20261119/reserved_validation/solver/pool_search.py) 中的原始求解文件。共同实例元数据合并方式沿用 [recent_plan.py](../recent5_20261120/recent_plan.py)，原始输入字节及其既有身份信息不变。

PyVRP 可复用 [recent_worker.py 的 execute](../recent5_20261120/recent_worker.py) 与 [recent_or.py](../recent5_20261120/recent_or.py)。它的 HGS 内部采用距离、制冷与品质损失下界组成的代理目标，终点由统一完整冷链目标严格评价；本轮不改其目标或参数。准备阶段计时不覆盖所有解释器启动与导入，不能据此声称首调用端到端速度。

新执行入口、矩阵和结果均放在本目录；远端建议使用 `/home/hzeng/project/MASKCO-Main/_maskco_supplement_sync_20261120/sync01`，会话名 `maskco_supplement_sync01`。相对目录深度应与 recent5 保持一致，以继续只读访问已有 `_maskco_cross_dataset_20261119` 依赖。编译产物留在新工作目录，不覆盖任何既有实验文件。

## 与 FLEET_PRICE 的资源分离

[FLEET_PRICE 计时登记](../maskco_perishable_external_20261119/整车队定价的限时开发.md) 的六臂是 FLEET_PRICE、FLEET_PRICE_D、PREFIX_DISTANCE、ORDER_SPLIT、DIST、DIST_SLOT。它没有 ORDER_SPLIT_D、ALNS 或 PyVRP；FLEET_PRICE_D 含额外定价前缀，不能替代锁版 ORDER_SPLIT_D。本轮不重复其六法开发实验。

应避开远端 `_maskco_perishable_external_20261119/fleetqual01`、`fleetscreen01`、`fleetdev01` 目录及 `maskco_heat_fleetqual01`、`maskco_heat_fleetscreen01`、`maskco_heat_fleetdev01` 会话。实际在用物理核以这些阶段的远端 `status.json`、进程亲和性和当前作业状态为准；本地已有的 `fleetqual01` 记录只证明短时验收结束。

[development_runner.py](../maskco_perishable_external_20261119/development_runner.py) 尚未登记本轮目录，[recent_runner.py](../recent5_20261120/recent_runner.py) 也只按瞬时负载选择 CPU。两者的自动空闲检测不能保证相互避让。推荐在 FLEET_PRICE 计时阶段结束后启动本轮；若需要并行，由执行端预先划分互不重叠的物理核，连同 SMT 兄弟核一并排除，并用控制器进程的 CPU 亲和性限制本轮。仅选当前低负载核不足以保证隔离。全部求解可沿用 CPU 后端，不使用 GPU。
