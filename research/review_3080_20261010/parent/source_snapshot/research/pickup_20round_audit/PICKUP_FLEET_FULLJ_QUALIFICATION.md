# 取货：整队全 J 重放资格（P-LIVE-QUALIFY-FLEET-v2）

2026-10-10，交接续办第 1 轮。工具：`live_qualify_fleet.py`。
产物：`live_qualify_fleet_v3/result.json`（**v2 协议，通过**）；`live_qualify_fleet_v2/result.json`（**v1 协议，判据失败，原样保留**）；`fleet_scan_v1/scan.json`（宽度扫描）。

> **这不是性能结果。** 无臂间比较、无路线改进、无增益声明。未建立项：稳定在线增益、MaskCO 归因、取货不可能性、等价性。

## 1. 为什么做这件事

`P-LIVE-QUALIFY-FULL-v1` 已闭合五项工程资格，但它自己的范围注记写着：**15 个车队槽位中只有 1 辆车曾被派遣，未触及的余量未被行使**。面板注册（v1/v2）需要"整队全 J 重放"才能开跑，而这一项**从未闭合**。根因是采样方式：原设计按固定时钟步长取点，落在 clock 2.0–5.8h —— 而那正是车队还空着的时候。

## 2. 做法

1. **PASS 1 宽度扫描**（便宜、不抓快照）：跑参考日，在每个决策点记录 (clock, event_id, **派遣车队宽度**, 是否有 committed 前缀)。
2. **按派遣宽度选点**（最宽优先、时钟互异、并为"确有 committed 前缀"保留一个槽位），取代盲目的时钟步长。
3. **PASS 2** 重跑并只在选中点抓取公开 recourse 快照，并**断言重跑复现了 PASS 1 的 (clock, width)**；不一致即失败（`selection_consistent_all=true`）。
4. 在每个快照上于**全新 env** 中做**无干预整日重放**，要求终局 full A-v1 J、accepted 集合、served 数**三项精确一致**。

## 3. 结果

| 项 | 值 |
|---|---|
| 捕获数 | 12（4 实例 × 3） |
| 时钟范围 | **14.15 – 17.37 h**（此前 2.0–5.85h） |
| **派遣车队宽度** | **3–4 / 15**（此前 **1** / 15） |
| **整队全 J 重放一致性** | **12/12 精确**（`max_abs_delta = 0.0`；accepted 集合、served 数、hard 全等） |
| 重放确定性（C0） | 12/12 |
| 选点可复现 | 12/12 |
| 能量通道是否活跃 | **是**（5/12 检出） |
| `all_qualifications_pass` | **true** |

宽度扫描分布（4 实例、1158 个决策点）：宽度 0×8、1×362、2×329、**3×394、4×65** —— 宽度 ≥3 的点有 459 个，所以整队行使是**可达的**，此前的宽度 1 纯粹是采样缺陷。

## 4. 新发现（本轮最有价值的一条）

**能量账本通道是活的，但只在 5/12 的捕获上"决策相关"。**

| 探针 | 检出率 |
|---|---|
| C1：某派遣车 `cumulative_energy_kwh` **+50 kWh** | **5/12**（0.4167） |
| C4：同一字段 **+10000 kWh**（远超预算） | **5/12**（0.4167，**与 C1 完全相同的捕获集合**） |

检出的 5 次给出的效用变化是**大幅负向**（−29.96 / −14.99 / −164.84 / −74.92 / −29.92）——即账本被 `certify_plan` 读取，能量抬高后当日**少接单**。通道确实活着。

**C4 与 C1 击中同一组捕获**排除了"探针太小"这一解释：不是幅度问题，而是那 7 个捕获上**没有可被翻转的后续预算决策**。

**用测量检验该解释**（`remaining_decision_points_after_capture`）：

| 组 | 剩余决策点数 | 均值 |
|---|---|---|
| 检出（5） | 16, 27, 29, 37, 63 | **34.4** |
| 未检出（7） | 0, 0, 0, 0, 9, 14, 43 | 9.4 |

- **4/7 未检出捕获的剩余决策点数恰为 0** ⇒ 结构上不可能检出（已测量）。
- **3/7 未检出捕获仍有 9 / 14 / 43 个剩余决策点**，即使 +10000 kWh 也无变化 ⇒ 那些点上预算通道没有 binding。这与程序已登记的拒单归因（**threshold 92.71% / budget 7.29%**，P-ATTRIB-v1）一致，但**本工件没有直接测量**这一点，属**未闭合的解释缺口**，如实标注。
- 反例说明剩余点数并非充分解释：inst0 cap0 剩余 43 点却惰性，inst1 cap0 剩余 63 点则检出。

**方法学含义**：把一个扰动能否改变结果当成**仪器属性**是错的——它是**决策相关性**属性。这正是 i-DMVRP 机会成本文献的论断（近似误差只有在改变决策且发生在实际访问到的状态时才影响解质量，[arXiv:2412.13851](https://ar5iv.labs.arxiv.org/html/2412.13851)）。因此判据修订为：**通道必须在整个捕获集上至少活跃一次**（可失败的对照），同时**必须报告检出率与实测剩余决策数**，使读者能区分"通道死了"与"扰动与决策无关"。

> ⚠️ **判据修订的披露**：v1 判据要求 C1 在**每个**捕获上都检出；该判据在观察到 v1 运行后被更正（v1 运行 `live_qualify_fleet_v2`，`all_qualifications_pass=false`，**原样保留**）。v2 的修订**提高了报告要求**（新增检出率与剩余决策数），并未移除任何对照。

## 5. 另一项如实边界：承诺不可改在**快照路径**上不敏感

- 在**包路径**上，承诺不可改由 packet 校验器强制，其负向对照在 `P-LIVE-QUALIFY-FULL-v1` 的 q3 中**确实触发**。
- 在**快照重放路径**上，把 `committed_next` 折进 `mutable_suffix` 并重算状态哈希后，**终局 J 未变**（可行使的 1 个捕获上 0/1）。
- ⇒ **终局 J 一致性不是承诺不可改的敏感检验**；强制点仍是校验器。此项记为范围边界，不记为缺陷。

## 6. 这与面板资格的关系

`P-LIVE-DEV-PANEL-v2` §6 的第 3 项（整队 full-J replay）**由本工件闭合**；第 4 项（各臂实际解码调用数相等）仍须在执行时从运行自身计数器断言。剩余待办：运行注册（pin 实例数、重检索种子全新性、声明 S3-3/S3-4/S3-4-D3/软 k-NN 开关）与三臂实现。

## 7. 跨主机验证（3080）

同一脚本在 3080（`desktop-9v1opdi\zh`，`D:\anaconda\envs\MASKCO_env\python.exe` = py3.10.20 / numpy 2.2.6）与本地（py3.12.7 / numpy 1.26.4）各跑一次宽度扫描：

| 比较项 | 结果 |
|---|---|
| 宽度 profile（每实例最大宽度、决策点数、宽度直方图） | **完全一致** |
| 1158 个决策点的 **`event_id` 序列** | **0 处差异** |
| 1158 个决策点的 **派遣宽度序列** | **0 处差异** |
| 1158 个决策点的 **`has_commit` 序列** | **0 处差异** |
| `clock` 浮点值 | 有差异，**1e-9 ~ 2e-8**（float 重结合，非轨迹分歧） |

⇒ **离散轨迹跨主机一致**；只有时钟浮点带 ~1e-8 噪声。**不得**写成"逐位完全相同"——正确表述是"离散决策结构逐位一致，时钟浮点有 1e-8 级差异"。

## 8. 本轮顺带发现的基础设施缺陷（已修）

`tools/_srv_exec.py` 文件末尾**重复出现** `if __name__ == '__main__': main()` 两次 ⇒ **每条远端命令被执行两遍**。首次执行成功、第二次因 `FileExistsError`（输出目录已存在）失败。危害：经该工具启动的任何实验都会被**静默跑两遍**（翻倍算力；若脚本非幂等则可能污染结果）。

- 已删除重复块（`tools/_srv_exec.py`）。
- 该缺陷**不影响**任何已归档科学数值：重复执行只可能得到相同输出或因目录已存在而报错，不会产生第二套不同数字。
- 本工件即为发现它的一次真实触发（首次远端扫描成功、第二次失败）。
