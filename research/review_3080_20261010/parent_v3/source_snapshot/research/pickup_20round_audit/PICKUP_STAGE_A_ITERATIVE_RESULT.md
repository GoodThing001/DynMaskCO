# 取货 Stage A：迭代 vs 一次性（P-MASKCO-ARM-ITER-v1）—— 结果与阻断

2026-10-10，交接续办第 3 轮。工具 `pickup_arm_iterative.py`。
产物：本地 `stage_a_iter_v1/result.json`；**3080** `stage_a_iter_3080_v1/result.json`（两者**全部决定性量逐位一致**）。

> 只跑 4 个**全新**实例（数据种子 `2026120201`，注册件所 pin），掩码种子 `2026120231`。描述性，无 alpha。未建立项：稳定在线增益、MaskCO 归因、取货不可能性、等价性。

## 1. 为什么测这一项

两个已归档 pilot 都是**单点一次性干预**；而注册的面板描述的是 MaskCO 的**迭代 mask-and-reconstruct 精化循环**。所以"迭代"是处理臂里**唯一未被测过**的部分。

可行性关键（读源码得到）：`pickup_maskco_arm.propose` 的**子问题完全由传入的 `order_ids` 构造**（`partial_adjacency([[loc[o] for o in order_ids]], …)`），`env` 只提供坐标与需求。因此**加一轮就是把上一轮的置换再喂回去**——不需要动活动计划、不需要写回，安装仍走已合格的 `force_suffix` 路径。风险因此很低。

## 2. 决定性结果一：**子问题规模受限，够不到奖赏区制**

对 4 个完整日、每个决策点、每辆车的**可变后缀中已揭示未服务订单数**做普查：

| 子问题规模 | 机会数 |
|---:|---:|
| 0 | 10921 |
| 1 | 11 |
| 2 | 12 |
| 3 | 9 |
| 4 | 6 |
| 5 | 4 |
| 6 | 2 |
| ≥7 | **0** |

- **最大可用规模 = 6**；**规模 ≥12 的机会数 = 0**。
- 而节点 **n13** 把 oracle 奖赏定位在 **n≥12** 且需按**客户**决策；n14 又在该特征族上把"学打分项"关闭。
- ⇒ **按"单车可变后缀"构造的注册面板，在结构上无法到达奖赏存在的区制。** 这不是关于方法的结论，是关于**问题定义/子问题构造**的结论。

这条从新方向独立复现了本项目最老的结构事实：`P-CENSUS-v1` 测得 **382 条路线平均 2.09 单/车、71.5% 的路线 ≤2 单**（即"C0 组合密度≈0"）。

## 3. 决定性结果二：**迭代不带来任何东西**

每状态 3 轮、三模式、解码调用各 21 次（**匹配**）：

| 模式 | 最好相对"不做任何事" | 对不做任何事 正/零/负 | 有任何一轮被接受的状态数 | 第 1 轮均值 |
|---|---:|---|---:|---:|
| **maskco** | **+0.000000** | 0 / 7 / 0 | **0 / 7** | **−0.070342** |
| recon_only | +0.003431 | 1 / 6 / 0 | 1 / 7 | −0.004665 |
| discard | +0.003431 | 1 / 6 / 0 | 1 / 7 | −0.004665 |

配对（迭代后）：`maskco − recon_only` = **−0.003431**（赢 0 / 输 1 / 平 6）；空对照 `recon_only − discard` = **0.0**（7/7 全平）。

读法：
- **引导臂在 7 个状态上没有任何一轮被接受**，最好结果**恰为 0**（即从未超过不做任何事）；第 1 轮平均已**更差**（−0.0703），后续轮次从未挽回。
- 唯一非零的 +0.003431 来自**纯距离对照**，即**并非来自引导项**；相对约 700 的日效用是 **0.0017%**，比 ≥20 的门低**三个数量级以上**。
- 空对照 7/7 全平，再次复核"discard ≡ recon_only"。

## 4. 停止规则：如实处理（**不把别的理由洗成"规则触发"**）

注册件写的停止条件是：**"引导项零局部获胜" 或 "两个重构臂都差于不做任何事"**。

- 引导项局部获胜在普查中是 **74/200**（非零）⇒ 该条件**不触发**。
- 两臂对"不做任何事"分别是 0 / 6 / 0 与 1 / 6 / 0，**没有任何一例更差**（它们是**惰性**，不是有害）⇒ 该条件**同样不触发**。

**因此：字面停止规则并未触发。** Stage A 给出的是一条**比停止规则更强**的理由：**结构上够不到奖赏区制 + 处理臂效应恰为 0**。二者合起来**不足以授权 Stage B**——在这些子问题规模上跑五臂面板，等于在一个**已知惰性**的区制里花预算。本文件如实写成这个理由，**不**声称"停止规则已触发"。

## 6. 结论与建议

1. **不要按现规格建 Stage B 五臂面板**：单车后缀的子问题太小（≤6），奖赏区制（n≥12）不可达。
2. **有证据的下一步是改子问题构造，而不是再调配方**：即**多车联合重指派**（交接 §8 第 7 项，亦即主门缺陷处置时被列为选项 (C) 的方向）——它能把子问题从"单车 ≤6 单"扩到跨车规模，且本项目早前测得 `G_fleet=17.891%` 的联合车队-路线动作空间。
3. 若仍要走取货接受/拒绝维度，须先改**合同/问题定义**（预算区制或车队规模），并重新计其动作集——这与交接 §3.3 的 (b) 结论一致（放宽预算不能分离采样器）。
4. 本轮的**探索性发现**不构成任何不可能性主张：它说的是"**这个子问题构造**在该问题定义下够不到奖赏"，**不是**"不存在更好的策略"。

## 7. 不得声称

稳定在线增益、MaskCO 归因、取货不可能性、等价性；本工件只覆盖 4 个全新实例、7 个状态、3 轮、|S|≤6 的单点迭代，**不覆盖**在线全事件迭代策略，也**不覆盖**多车联合子问题。
