## 2. L2 规格（可认证的决策质量）

### 2.1 唯一比较

- 固定状态集合：**事前冻结**的 inst × event 清单（含 sha256），来源与 L1 分离或**显式标注复用**；
- 两臂：F（恢复的 MaskCO 权重）与主对照 D-Geo（`-Δd`），**共享**快照 / P0 / 掩码 / 有序 legal /
  可变车辆集合 / 合同 / 信息边界；
- 单因素：沿用 L1 的机械检查（同一 state 对象、运行前后 state 摘要三处相等、
  `DECLARED_VARYING_FIELDS = ('scorer_id',)`）。

### 2.2 质量口径（三个层次必须分开，不得混用）

| 口径 | 定义 | 使用限制 |
|---|---|---|
| `candidate` | 臂提出的计划质量；失败按 J0 计 | **不得**称"部署" |
| `accepted` | 经 `min(J0, J)` 接受规则后的质量 | 与 `candidate` 分开报告 |
| `closed_loop` | 在共同 JF1-H-F 延续下的终局质量 | L3 才允许作为在线口径 |

### 2.3 认证

- 每个候选计划必须经**完整 C0 认证**（TW / 容量 / 返回 / 支持温区 / **能耗预算 B**）；
- **B 必须先经用户裁定**；**禁止**用 `SYNTHETIC_ONLY` / `1e9` / 历史 CAL 夹具 `300.0` 冒充正式 B；
- 认证失败**不剔除**：记 `cert_fail` 并留在分母。

### 2.4 统计计划（执行前冻结）

- 逐状态**配对**；报告均值差与不确定度（bootstrap 需按**实例分组**，不得把状态当日独立样本）；
- 缺失、超时、认证失败**完整披露**并计入分母；
- **不得**事后调整判据、追加状态、挑选结果。

## 3. L3 规格（在线效用）

- **新鲜开发日**：事前登记、与开发期数据不相交；**不得**使用最终测试种子；
- **等预算**：至少**同时**约束墙钟与同定义的候选工作量（六项分别实测：
  `n_actions_enumerated` / `n_actions_scored` / `n_candidate_plans_certified` /
  `n_action_applications` / `n_solver_calls` / `wall_seconds`）；工程阶段最大值**只作容量规划**；
- 效用口径：`收入 − 燃油 − 拒绝损失`（**品质不货币化**）；`distance_cost` 与 `coldchain_cost`
  **严格分离**；硬约束（C0 能耗 ≤ B）不满足即不提交；
- **多重比较校正**与主判据在**读取新鲜结果前**固定；
- 若继承既有最低增益要求，须**同时**满足均值门与 95% CI 下界 > 0；
- 8+2 秒完整在线发布门**不得**靠把身份验证移出请求窗口解决。

## 4. 失败语义与停止规则（fail-closed）

- 超时记 `timeout` / `censored`，**不剔除状态、不追加运行直到有利**；
- 身份不符、认证失败、空池一律**如实保留**；
- 任一层的负结果**不得**被改写；**不得**用 L2 结果替代 L3，也**不得**用 L1 结果替代 L2；
- 崩溃/资源异常保留原件，**不重跑、不调参**。
