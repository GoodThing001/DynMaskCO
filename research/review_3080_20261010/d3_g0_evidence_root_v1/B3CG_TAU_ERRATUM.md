# B3-CG 勘误附录：τ 收紧的数学作用与已装 lot 的剩余衰减表述

**日期**：2026-10-14 · **基准 commit**：`079ed7f` · **性质**：**勘误**，不改写任何历史裁定或已验收结论。
**触发**：用户指出"收紧 τ 才能让下界触发阈值"在数学上不成立。**该指正正确，且结论比原说法更强。**

---

## 1. 勘误一：收紧 `τ^max` **提高**下界，因此**不可能**产生更多不可售拒绝

下界形式 `Q^LB = Q^start · exp[−k(T^max)·τ^max]`，当 `k > 0`：

```
∂Q^LB / ∂τ^max = −k · Q^LB < 0
```

⇒ **减小** `τ^max` 会**增大** `Q^LB`。即"收紧 τ"只会让认证**更容易通过**，不会让它识别出更多不可售计划。

**实测（v1 合同、`T^max = hard_upper`、`Q_start = 1`）**

| 温区 | 阈值 | τ=24 h | τ=12 h | τ=6 h | τ=1 h | τ=0.1 h |
|---|---|---|---|---|---|---|
| 0 | 0.80 | **0.9316** | 0.9652 | 0.9824 | 0.9971 | 0.9997 |
| 1 | 0.85 | **0.9413** | 0.9702 | 0.9850 | 0.9975 | 0.9997 |
| 2 | 0.90 | **0.9754** | 0.9876 | 0.9938 | 0.9990 | 0.9999 |

⇒ 越收紧越远离阈值。**原稿与独立复核中"收益必须来自更紧的 τ"的说法，只在"减少误拒 / 提高可放行率"这一含义下成立；在"让下界能够识别不可售计划"这一含义下不成立。**

**更正后的优先级**：更紧的 `τ^max` 属**可用性优化**，**不是**让认证具备判别力的手段。

## 2. 勘误一的**强化版**（本轮新增，比双方原说法都更强）

两个因子**都已经处在"保持健全性"的极端上**：
- `τ^max = tw_end[0] − now`（此处 24 h）：任何被交付 lot 的在舱时间都 **≤** 它 ⇒ 它是**最松的健全时长上界**，因而给出**最小**的 `Q^LB`；
- `T^max = hard_upper`：F-a 已闭合（开门升温在**同段内**被计数）⇒ 越界温度**不在 Ω 内** ⇒ 它是**最高的健全温度**，同样给出**最小**的 `Q^LB`。

⇒ **`Q^LB` 已经是该形式在当前配置下"健全可取"的最小值。既然它现在都不触发任何阈值，那么任何健全的 `(T^max, τ^max)` 都不可能让它触发。**

**推论（方向性结论，供下一阶段定方向）**：
1. 在本配置下，**静态 T/τ 形式的下界在判别力上恒为空**——不是"样本不够"，而是**形式本身的极限**；
2. 要得到一个**能触发**的认证，必须换**函数形式**（例如利用**当前真实舱温**与**计划实际剩余时长**的**计划/状态条件化**界），代价是覆盖范围变窄：它只对"该计划被执行"成立，而**不再对 Ω 全体成立**；
3. 另一种可能是：**在本配置下品质阈值本来就不是约束性瓶颈**。这一点只能用只读诊断说明（例如统计"若用最有利的健全界是否仍有订单无法售"），**不得**为了让它成为绑定约束而事后更换正式实验档位。

## 3. 勘误二：已装 lot 的**剩余衰减**表述（分段落证明）

原稿（含我按独立复核更正过的那一版）仍把已装 lot 的量说成"完整在舱时间受 `tw_end[0] − now` 约束"，**这不正确**：对 `t_load ≤ now` 的 lot，其完整在舱时长**不一定**被该量上界约束。

**正确论证（分两段）**
- **已在舱 lot**（`t_load ≤ now`，当前真实品质 `q_now = quality_remaining`）：只累计 **now → 交付** 的剩余衰减
  ```
  Q_delivery = q_now · exp[ −∫_{now}^{t_delivery} k(T(t)) dt ]
             ≥ q_now · exp[ −k(T^max) · (t_delivery − now) ]
  ```
  需要的是 `t_delivery − now ≤ τ^max`（而**不是** `t_delivery − t_load`）。因交付时刻 = 返仓到达 = `end_time`（`coldchain_state.py:286-291`）且 ≤ `tw_end[0]` ⇒ 成立 ✓。
- **尚未取货订单**（`t_load ≥ now`，起算品质 = 装货时的 `initial_quality`，装货前不衰减）：
  ```
  t_delivery − t_load ≤ tw_end[0] − t_load ≤ tw_end[0] − now = τ^max
  ```
  ⇒ 同一个 `τ^max` 也成立 ✓。

**与代码的一致性**：这正是 `bound_for_state` 的做法——已装用 `lot.quality_remaining`，未装用 `env.initial_quality`。因此勘误后**表述与实现一致**，而此前的表述虽然结论正确但**理由写错了段落**。
