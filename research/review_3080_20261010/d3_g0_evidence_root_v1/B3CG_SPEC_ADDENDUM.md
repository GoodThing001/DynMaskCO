## A-1. 静态整窗界的可声明范围（限制量词，不放弃结论）

**被修正的原措辞（不得再使用）**：把"`tw_end[0] − now` 是最松的可靠时长界、`hard_upper` 是最高可靠温度 ⇒ 该形式**永不生效**"当作一般结论陈述。

**为什么必须限制量词**：更大的任意常量会把该界**形式上**压低，这个论证就成了空洞的真命题；同时该比值论证**并不覆盖**所有已装货批次的品质——`Q_start` 是各批次**当前剩余品质**，不是初始品质。因此"对所有状态 / 所有批次都无区分力"是**过度声明**。

**现行有效声明（逐字，可作为论文/报告用语）**：

> 在本配置下（数据集 `initial_quality = 1.0`、`T^max = (30, 8, −12)`、`τ^max = 24.0 h`、v1 `QualityConfig` 的 `unsalable_quality_threshold = (0.8, 0.85, 0.9)` 与 `reference_rate_per_hour = (0.001, 0.002, 0.0035)`），**静态整窗界缺乏拒绝能力（refusal capability）**：在 τ = 24 h 处测得的品质比值为 0.9316 / 0.9413 / 0.9754（class 0/1/2），全部高于对应阈值 0.8 / 0.85 / 0.9；τ 收紧到 12 / 6 / 1 h 时比值单调**远离**阈值（12 h：0.9652 / 0.9702 / 0.9876；6 h：0.9824 / 0.9850 / 0.9938；1 h：0.9971 / 0.9975 / 0.9990）。该结论**限定于上述配置与初始品质 1 的批次**，**不**是对"任意状态 / 任意 `Q_start` 批次"的一般性断言。

**配套要求**：
- 报告中凡引用该结论，必须同时给出配置（阈值、τ、`iq`）与"初始品质 1.0"这一前提，且不得写成"对所有批次无区分力"。
- 若未来引入 `initial_quality ≠ 1` 或更低阈值，**必须重新测量**，不得沿用本结论。
- 与 `B3QP_ADJUDICATION.md` 的独立审计判定保持一致：条件蕴含 Ω = **PROVEN**；Ω 在提交处被执行 = **NOT_ESTABLISHED**；作为执行引擎性质 = **FALSIFIED**。

## A-2. 唯一写入者 = **由闸门授权的提交事务**，不是闸门本身

**被修正的原架构倾向（不得采用）**：让认证/闸门模块自己成为写入者（即"闸门顺便把状态写下去"）。那只是把旁路换了个位置，会**产生新的旁路**：任何绕过闸门的代码路径只要还持有写入能力，缺陷原样存在。

**现行有效架构要求**：

1. **唯一写入者**是**提交事务（commit transaction）**——它由闸门**授权**后才可执行；闸门本身**不写状态**，只产出/校验授权凭证（`CertificationCredentialV1` + `pre_install_reverify` 的判定）。写入能力与判定能力必须分离。
2. **授权与写入必须绑定为一次原子操作**：授权凭证必须携带可被写入侧独立校验的身份（`certified_plan_hash` / `plan_digest_anchor_v1` / `state_hash`），并且写入事务在**持有授权的同时**完成校验+写入，中间不得存在"可被第三方插入状态变化"的窗口。
3. **F8（TOCTOU）不能靠再比三次哈希来消解**。B3-CF 的 CP-F8 已经实测复现：S1 批准（`state_hash 0b81882cb625`）→ 状态变为 S2（`9ff1117d7b5e`）→ **不再验证**仍写入头 38。再比较三个哈希**既不原子也不排他**；必须由 (1)(2) 的架构性质来消解，而不是靠增加比较次数。规格层面 F8 在下一批验收中保持 **UNVERIFIED** 直至 (1)(2) 落地。
4. **历史旁路必须被关闭，而不是被绕过**：B3-CG 静态审计列出的 7 个 `certify_plan` 非测试调用点（`rolling_optimizer.py:197`、`rrnco_accept_replanner.py:150`、`run_a1_downstream_ablation.py:88`、`run_exp_energy_c0.py:302`、`solver_accept_replanner.py:424`、`pickup_budget_sweep.py:96`、`pickup_rejection_attribution.py:97`）在下一批中要么改走授权提交事务，要么显式登记为"非提交路径"并证明其无法写生产状态。**只关掉一个不叫关闭。**

## A-3. D0 语义拆分：`REFUSE_NO_MUTATION` vs `WAIT_BY_ENV_PROTOCOL`

**被修正的原措辞**：把两种"没有发生变化"的结果都叫 D0 / "零状态变化"。二者因果完全不同，混用会把"闸门拒绝"记成"环境按协议等待"（或反之），从而把一个**通过**读成一个**拒绝**。

**现行有效定义**：

| 名称 | 触发者 | 语义 | 状态变化的含义 | 计入哪个判据 |
|---|---|---|---|---|
| `REFUSE_NO_MUTATION` | **闸门/认证**（`compose_certification` 产出 `installable=False`，或 `pre_install_reverify` 拒绝） | 一个**本来会被执行**的写入被**拒绝**；写入方收到拒绝理由 | 状态**必须**逐字节不变，且该"不变"是**拒绝的结果** | G-L / 拒绝能力证据；必须记录具体 `REFUSE_*` 理由 |
| `WAIT_BY_ENV_PROTOCOL` | **环境协议**（无可行客户且未来有揭示时返回 `[]` WAIT，或 `booking_horizon` 内无可做之事） | 环境**按设计**没有产生任何写入需求；不存在"被拒绝的写入" | 状态不变是**协议的正常输出**，不是拒绝 | 不得计入拒绝能力；只能作为决策点分布/覆盖统计 |

**落地要求**：
- 两者必须使用**不同的判据标签**出现在矩阵中，且**不得**合并成"0 state change"一类计数。
- `REFUSE_NO_MUTATION` 必须附 `REFUSE_*` 理由（拒绝理由来自 `d3_geo_adapter.REFUSAL_REASONS`）与"若无闸门则会发生的写入"的反事实证据；否则该记录无效。
- `WAIT_BY_ENV_PROTOCOL` 的存在**不能被用作**"闸门有效"的证据。B1 已发现 `replan_reason` 是**粘性**的（353 行 vs 133 次真实揭示），所以"等待/揭示"的识别必须用**可见集增长**，不能用 `replan_reason`——这也决定了 D0 拆分必须以可见集与凭证校验为准，而不是以原因字符串为准。

## A-4. τ 方向性（承接 `B3CG_TAU_ERRATUM.md`，对 B3-CF 的含义）

`B3CG_TAU_ERRATUM.md` 已记录：

> `∂Q_LB/∂τ^max = −k·Q_LB < 0`，因此**收紧 τ 只会抬高下界**，只能让认证**更容易**，**不可能**产生新的拒绝。所谓"收益必须来自更紧的 τ"仅对**可用性**（减少误拒）成立，对**区分力**不成立；更紧的 τ 降级为**延后的性能项**。

**对 B3-CF 的直接含义**：本批不得把任何拒绝/缺陷复现归因于 τ；CP-F10 / CP-F8 的复现与 τ 无关，它们是**提交路径缺少授权闸门**的结果。任何"通过收紧 τ 来获得拒绝能力"的方案在下一批中同样**不予受理**。
