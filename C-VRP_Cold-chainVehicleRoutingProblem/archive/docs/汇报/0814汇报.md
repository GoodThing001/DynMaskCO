## 1. 背景：什么是 MaskCO？

### 1.1 问题本质：车辆路径问题（VRP）

车辆路径问题是物流与运筹学的经典难题：**一个仓库（depot）有若干辆卡车，需要服务 N 个客户，如何规划路线使总行驶距离最短？**

- 可能方案数高达 $N!$（N=50 时约为 $3\times10^{64}$，超过宇宙原子数）
- 属于 **NP-hard** 问题：不存在多项式时间的精确算法
- 实际只能求"足够好"的近似解

### 1.2 MaskCO 的核心思想：掩码生成

**MaskCO**（ICLR 2026 收录）是最近提出的神经组合优化方法，核心思想借鉴了 NLP 领域 BERT 的"完形填空"范式：

```
1. 给定一条（由启发式算法提供的）完整路线
2. 随机"掩码"掉路线中的一部分边（遮住答案）
3. 神经网络根据剩余边 + 节点特征，预测被掩码的边（填空）
4. 迭代：预测出的边 → 再次掩码 → 再预测 → 逐步优化
```

这种方法用 **Transformer**（与 ChatGPT 同源的基础架构）学习"好的路线长什么样"，而非手工设计启发式规则。

### 1.3 我们的扩展：从静态到动态冷链

MaskCO 原始方法解决的是**静态、无时间窗、无温度约束**的 CVRP。我们将其逐层扩展到更复杂、更真实的场景：

| 变体 | 新增约束 | 现实含义 |
|------|---------|---------|
| CVRP | 容量 | 卡车不能超载 |
| **CVRPTW** | 时间窗 | 客户只能"上午 9-11 点"收货 |
| **Cold-Chain** | 温度 | 食品/药品必须恒温运输 |
| **DCC-VRP** | 动态揭示 | 部分订单"稍后才知道" |

其中**动态揭示（Dynamic）**是最大的挑战：外卖平台下午 5 点时不知道晚上 8 点会有多少加急订单，但必须现在就开始派送。

## 2. 研究问题（详细定义）

### 2.1 问题形式化：DCC-VRP 的数学定义

**给定**：一个 depot（记为节点 0）和 $N$ 个客户（节点 $1,\dots,N$），分布在一个单位正方形地图上。

**每个客户 $i$ 携带 5 类信息**：

| 符号 | 含义 | 示例 |
|------|------|------|
| $(x_i, y_i)$ | 二维坐标 | 客户位置 |
| $d_i$ | 需求量（demand） | 需要送货的重量 |
| $[a_i, b_i]$ | 时间窗（time window） | 只能在此区间内服务 |
| $s_i$ | 服务时长（service time） | 卸货所需时间 |
| $c_i \in \{0,1,2\}$ | 温度类别 | 常温/冷藏/冷冻 |

**车辆约束**：每辆车容量 $Q$，从 depot 出发，最终返回 depot。

**动态性**：每个客户 $i$ 有一个揭示时间 $r_i$（reveal time）。当 $r_i = 0$，客户在初始时刻已知；当 $r_i > 0$，客户在时刻 $r_i$ 才"出现"。用 **EDoD**（Expected Degree of Dynamism）刻画动态程度——即 $r_i > 0$ 的客户占总客户的比例（0.2 = 弱动态，0.5 = 中等，0.8 = 强动态）。

### 2.2 目标函数与约束

**目标函数（多目标标量化）**：冷链场景下，不仅要省距离，还要保品质、省能耗。三者统一为一个带权重的标量目标：

$$J = C_{\text{dist}} + \lambda_q \cdot Q + \lambda_e \cdot E + M_u \cdot N_{\text{unserved}} + M_t \cdot N_{\text{late}}$$

其中三项成本 + 两项惩罚：

**① 距离成本 $C_{\text{dist}}$**：路线总行驶距离（归一化单位）
$$C_{\text{dist}} = \sum_{(i,j) \in \text{routes}} \|(x_i, y_i) - (x_j, y_j)\|_2$$

**② 品质损失 $Q$（Arrhenius 衰减）**：货物在运输途中的品质衰减，取决于温区和在途时间。每个温区 $c \in \{0,1,2\}$（常温/冷藏/冷冻）有独立的衰减速率 $k_c$：

$$Q = \sum_{c} \left(1 - e^{-k_c \cdot t_c}\right), \qquad k_c = [0.01,\ 0.002,\ 0.0002]\ \text{(1/h)}$$

物理含义：常温货物每小时损失约 1% 品质，冷藏慢 5 倍，冷冻慢 50 倍——这赋予"优先服务易腐货物"的决策依据。

**③ 制冷能耗 $E$**：维持车厢低温所需的制冷能耗，与温差和运行时间成正比：
$$E = \sum_{\text{segments}} P_{\text{cool}}(c) \cdot \Delta t, \qquad P_{\text{cool}} = [0,\ 800,\ 2000]\ \text{(W)}$$

（常温无需制冷 $P=0$，冷藏 800W，冷冻 2000W——冷冻最耗电。）

**④⑤ 惩罚项**：$N_{\text{unserved}}$（未服务客户数）和 $N_{\text{late}}$（迟到客户数），用大权重 $M_u = 1000$、$M_t = 500$ 惩罚，体现"服务优先"原则——宁可多绕路，也不能漏送或迟到。

**权重默认值**：$\lambda_q = 0.1$（品质）、$\lambda_e = 0.01$（能耗）。两个权重可在推理时调节，用于在"省距离 vs 保品质 vs 省电"之间做 Pareto 权衡。

**硬约束**（不可违反）：

1. **容量约束**：任意时刻车辆载重不超过 $Q$
   $$\sum_{i \in \text{route}_k} d_i \le Q, \quad \forall \text{车辆} k$$

2. **时间窗约束**：到达时间 $t_i$ 必须落在 $[a_i, b_i]$ 内
   $$a_i \le t_i \le b_i, \quad \forall i$$
   - 若提前到达（$t_i < a_i$）→ 必须**等待**到 $a_i$
   - 若迟到（$t_i > b_i$）→ **违规（infeasible）**

3. **冷链约束**：不同温区的货物必须保持在各自温度范围内（常温 25°C、冷藏 4°C、冷冻 −18°C），品质损失遵循 Arrhenius 方程。

### 2.3 核心科学问题：非预知决策（Non-anticipatory Decision）

动态问题与静态问题的**本质区别**在于因果性约束：

> **在时刻 $t$ 做决策时，只能使用 $t$ 之前已经揭示的信息，不能"预知未来"。**

数学上，这用 **filtration（信息流）** 表述：设 $\mathcal{F}_t$ 表示时刻 $t$ 已知的全部信息（已揭示的订单 + 车辆状态 + 已执行的动作），则决策策略 $\pi_\theta$ 必须满足：

$$a_t \sim \pi_\theta(\cdot \mid \mathcal{F}_t)$$

**这一约束是"诚实"在线算法与"作弊"算法的分水岭，也是本项目最核心的科学贡献所在。**

## 3. 研究方法（详细）

### 3.1 整体架构：五层模型继承链

我们的模型建立在 MaskCO 的 encoder-decoder Transformer 之上，通过五层继承逐步增加能力：

```
TSPModel → CVRPModel → CVRPTWModel → ColdChainModel → DynamicColdChainModel
  (2D)       (3D)         (5D)           (6D)              (7D)
```

每一层在前一层基础上增加一个输入维度：
- **CVRPModel**：+需求 → 容量约束
- **CVRPTWModel**：+时间窗 → 时间窗约束
- **ColdChainModel**：+温度类别 → 冷链约束
- **DynamicColdChainModel**：+揭示时间 → 动态性

最终模型输入为 **7 维特征**：$(x, y, demand, tw_{start}, tw_{end}, temp\_class, reveal\_time)$。

### 3.2 模型内部：三个关键机制

**① 时间窗偏置（tw_bias）**：一个全局可学习的参数向量，作为时间窗信号的归纳偏置注入编码器。

**② 温度嵌入（Temp Embedding）**：将 3 类温度（常温/冷藏/冷冻）映射到一个可学习的嵌入向量。这是我们替代旧 `spoilage_bias`（有害，导致 −6pp 可行率）的关键设计——让 Transformer 自己学习温度与距离之间的非线性关系，而非手工设计。

**③ 可见性门控注意力（Visibility-Gated Attention）**：这是 P0-2 修复的核心。编码器在计算注意力时，对未来订单（$r_i > t$）施加 $-\infty$ 的注意力偏置：

```python
vis_bias[q, k] = 0 if node k 可见 else -1e9
```

这样未来订单的注意力权重被压制为 0，从信息流层面切断了"预知未来"的通道。

### 3.3 训练方法：掩码生成 + 在线序列训练

**标准掩码生成训练**：给定一条完整路线，随机掩码掉部分边，让模型预测被掩码的边，用交叉熵损失训练。

**Phase 3c K=5 在线序列训练（我们的增强）**：这是让模型适应动态场景的关键。训练时模拟一个 $K=5$ 步的事件序列 rollout：

- **Step 0**：稀疏掩码（keep=0.15）+ 部分可见性 → 预测完整目标
- **Step 1..4**：掩码逐渐变密（keep 0.15→0.85）+ 可见性逐步提升 → 再次预测
- **加权损失**：早期步（信息更稀缺）权重更高

这样模型学会了在"信息不完整 → 信息完整"的连续变化中逐步修正决策，而非只在单一信息状态下训练。

### 3.4 解码方法：资源状态波束搜索（Resource-State Beam Decoder）

这是**100% 可行性**的来源，也是我们方法区别于原始 MaskCO 的关键。

传统 MaskCO 用贪心插入（greedy insertion）构建路线，容易陷入局部死胡同，导致时间窗违规。我们的 **K-beam 资源状态解码器**（K=16）核心思想是：

**每条 beam 显式维护真实的物理状态**，而非仅仅维护节点序列：

```python
BeamState:
    route          # 已访问节点序列
    arrivals       # 每个节点的实际到达时间
    current_time   # 当前时刻
    current_load   # 当前载重
    cabin_temp     # 车厢温度（冷链）
    ...            # 品质、能耗等
```

**边可行性检查（`_can_go`）基于真实累积状态**，而非启发式估计：

1. **时间窗检查**：到达时间 $t_j = t_i + s_i + \text{travel}(i,j)$，必须 $\le b_j$
2. **容量检查**：$load + d_j \le Q$
3. **往返检查**：服务完 $j$ 后，能否在 depot 时间窗前返回（防止"去了回不来"）
4. **2 步前瞻**：节点 $j$ 之后是否还有可行的下一步（防止"走到死胡同"）

K 条 beam 并行探索，保留分数最高的 K 条，最终选择完整且分数最高的路线。这种"带真实状态的前瞻搜索"从数学上**保证了每一步都是可行的**，因此最终路线必然满足所有硬约束。

### 3.5 冷链物理建模（内生递推）

冷链不是简单的分类特征，而是**内生的物理状态递推**。每条 beam 在行进过程中实时更新三个物理量（参数来源：冷链物流文献，Transportation Science 2022/2026）：

| 物理量 | 模型 | 公式 | 关键参数 |
|--------|------|------|---------|
| 车厢温度 $T$ | Newton 冷却 + 制冷 + 开门冲击 | 行驶中向环境升温；服务开门骤升 | 环境 25°C；目标温区 [25, 4, −18]°C |
| 货物品质 $Q$ | Arrhenius 衰减 | $Q = 1 - e^{-k(T) \cdot t}$ | $k_c = [0.01, 0.002, 0.0002]$ 1/h |
| 制冷能耗 $E$ | 制冷功率 × 时间 | $E = \sum P_{cool}(c)\cdot\Delta t$ | $P_{cool} = [0, 800, 2000]$ W |

**车厢温度的三段递推**（这是冷链物理最核心的部分）：

1. **行驶升温（Newton 冷却）**：车厢温度向环境温度 25°C 靠拢
$$T \leftarrow T + (T_{ambient} - T)\left(1 - e^{-UA/C \cdot \Delta t}\right)$$

2. **服务开门冲击**：卸货开门时，冷气外泄、热气涌入，车厢快速升温
$$T \leftarrow T + (T_{ambient} - T)\left(1 - e^{-k_{door} \cdot s_i}\right)$$

3. **主动制冷**：行驶过程中制冷系统持续工作，抵消升温趋势，将车厢拉回目标温区

**物理含义**：常温货物 $k=0.01$（每小时损失约 1% 品质），冷藏慢 5 倍（$k=0.002$），冷冻慢 50 倍（$k=0.0002$）；但冷冻最耗电（2000W vs 冷藏 800W vs 常温 0W）。这三个物理量耦合起来，赋予了"**优先服务易腐货物、同时平衡制冷能耗**"的决策依据——这也是冷链场景区别于纯距离优化的核心所在。

## 4. 创新点（核心贡献）

### 贡献 A：因果事件条件掩码重构（Causal Event-Conditioned Masked Reconstruction）

**问题**：现有"动态"神经求解器普遍存在信息泄漏——未来订单信息泄漏到当前决策中。

**我们的方案**：
1. **可见性门控注意力**：$-\infty$ 注意力偏置切断未来订单的信息流
2. **可见感知归一化**（`coord_normalize_visible`）：只用可见节点计算坐标归一化统计量，消除第二层统计泄漏
3. **事件驱动的局部重构**：新订单到达后，只重构受影响的路线段，而非全局重规划

**意义**：这是方法层面**首次严格定义并保证**了非预知性（non-anticipativity），并用 3 项独立测试验证。

### 贡献 B：保持可行性的资源状态解码（Feasibility-Preserving Resource-State Decoding）

**问题**：神经网络生成的路线经常违反时间窗/容量约束，需要大量后处理修复。

**我们的方案**：K-beam 解码器将时间、载重、温度作为**显式资源状态**，在生成过程中直接剪除非法动作（而非生成后再修复）。

**效果**：可行性从贪婪解码的 76% 提升到 **100%**（0 违规），且成本仅 +1.77——这是可行性-成本的 Pareto 最优权衡。

### 贡献 C：承诺感知的随时重优化（Commitment-Aware Anytime Reoptimization）

**问题**：在线场景中，已执行的路线不可修改，且计算预算有限。

**我们的方案**：
1. **冻结前缀**（Frozen Prefix）：已执行的路线段严格不可修改
2. **自适应掩码率**（Adaptive Mask）：根据事件强度动态调整重构范围
3. **随时调度器**（Anytime Scheduler）：在时间预算内输出当前最优解，形成质量-延迟 Pareto 前沿

**意义**：将"离线静态求解"升级为"在线滚动决策"，是通往真实动态部署的关键。

### 应用：多资源物理接地压力测试（Multi-Resource Physically-Grounded Stress Test）

冷链作为**应用场景**而非论文卖点：温度-品质-能耗三资源耦合，提供了一个"决策后果可量化"的物理压力测试平台。事件驱动的重规划使冷链成本降低 8-9 倍（静态 TTI=428 vs 重规划 52）。

### P0-1：评估协议 v2 ✅

- **服务优先**：先比可行性/服务率，再比成本/品质

- 统计规范升级：5 个训练种子 + 配对 Wilcoxon 检验 + McNemar 检验

### P0-2：基线求解器审计 ✅
验证传统 OR 求解器（OR-Tools、PyVRP）是否正确适配。**关键发现**：

| 求解器 | 纯 CVRP | 窄时间窗 | DCC 50 节点 |
|--------|:---:|:---:|:---:|
| OR-Tools | ✅ 通过 | ✅ 通过 | ✅ 通过（成本 9.1） |
| PyVRP | ❌ 环境 bug | ❌ | ❌ |

- PyVRP 在服务器环境有 bug（3 节点能解，25+ 节点崩溃）——之前的"0% 可行"是 bug，不是真实性能
- OR-Tools 在静态全知下能解窄时间窗 DCC，得到 **clairvoyant 下界 J\* = 9.1**

### P0-3a：因果性审计（坐标归一化泄漏）✅
这是本轮**最重要的发现和修复**：

| 测试 | 修复前 | 修复后 |
|------|:---:|:---:|
| 置换未来节点位置 | Δ=0（通过） | Δ=0（通过） |
| 扰动未来节点坐标 | **Δ=9~36（失败）** | **Δ=0（通过）** |

根因：父项目的 `coord_normalize` 用**全节点**统计量（均值/范数），泄露了未来节点的空间分布。修复方案 `coord_normalize_visible()`：只用可见节点计算统计量。

### P0-3b：目标标签泄漏审计 ✅
验证训练标签中未来节点的边是否影响当前决策。结果：**可见节点损失差异 Δ=0.00**（完全通过）。

## 6. 关键结果

### 6.0 评估指标口径声明（跨方法一致性）

为保证与 MaskCO 原文、OR-Tools、ALNS 等对比方法的公平性，本项目统一采用以下口径：

> **所有方法的 `cost` 均为纯行驶距离（total travel distance），不含任何惩罚。不可行性一律通过独立的可行性指标（时间窗可行率 TW Feas、容量可行率 Cap Feas、未服务数）报告，绝不混入 cost。**

这一约定的意义和差异：

| 维度 | MaskCO 原文 | 本方法（DynMaskCO） | 是否一致 |
|------|-----------|-----------------|:---:|
| cost 定义 | 纯距离 `sum(dist)` | 纯距离 `_eval_distmat_cost` | ✅ 一致 |
| 约束维度 | 仅容量（CVRP） | 容量 + 时间窗（CVRPTW） | ⚠️ 扩展 |
| 不可行处理 | 容量违规 → cost=+∞ | 独立报告 TW Feas / viol | ⚠️ 语义差异 |
| Gap 分母 | `(cost-opt)/opt`，opt=LKH3 | `(cost-ref)/ref`，ref=OR-Tools J\* | ⚠️ 分母不同 |

**关键声明**（写进论文，堵死审稿人追问）：本方法的 cost 14.77 是**纯距离**，可行性（100%）通过独立的 TW Feas 指标单独报告——两者不混同。这比 MaskCO「把不可行性编码进 cost=+∞」更细粒度、更诚实。

### 6.1 因果重训练：修复泄漏后的诚实结果

用修复后的 `coord_normalize_visible` 重新训练，Phase 3c（最强模型）+ K=16 波束解码，**5 个训练种子**（以下成本为**距离成本 $C_{\text{dist}}$**，品质损失 $Q$ 与能耗 $E$ 的多目标评估见 P0-4 后续工作）：

| 类型 | EDoD=0.2 | EDoD=0.5 | EDoD=0.8 | 平均 |
|------|:---:|:---:|:---:|:---:|
| R1（随机） | 17.12 ± 0.06（100%） | 17.40 ± 0.05（100%） | 17.95 ± 0.06（100%） | 17.49 |
| C1（聚集） | 11.51 ± 0.06（100%） | 11.80 ± 0.06（100%） | 12.15 ± 0.05（100%） | 11.82 |
| RC1（混合） | 14.67 ± 0.04（100%） | 14.95 ± 0.06（100%） | 15.41 ± 0.06（100%） | 15.01 |
| **平均** | **14.43** | **14.72** | **15.17** | **14.77** |

**45/45 = 100% 时间窗可行率，0 违规。跨训练种子标准差 ≤ 0.06——方法对随机种子极不敏感，高度可复现。**

### 6.2 两个反直觉的重要发现

**发现一：修复泄漏后，模型反而更好了。**
旧泄漏模型平均成本 16.23，修复后的因果模型 14.77，**降低了 8.8%**。这说明全节点归一化统计量对模型而言是**噪声而非有用信号**——消除泄漏等于给了模型一个"更干净的空间先验"。

**发现二：可行性几乎全部来自解码器，而非模型本身。**
贪婪解码只有 76% 可行率，加 K=16 波束解码直接拉到 100%。这诚实揭示了方法各组件（模型 vs 解码器）的真实贡献——这是投稿时必须讲清楚的故事，而不是含糊地宣称"端到端学习"。

### 6.3 与理想下界的诚实对比

| 指标 | 数值 |
|------|:---:|
| OR-Tools Clairvoyant 下界 J\*（R1, EDoD=0.5） | 9.1 |
| DynMaskCO 因果模型（同场景，5-seed） | 17.40 ± 0.05 |
| **Clairvoyance Gap（信息劣势）** | **8.30（91%）** |

这个 gap 不是缺点，而是**诚实的科学贡献**：它精确量化了"在线决策因为看不到未来而必须付出的代价"，这是动态优化领域的核心研究问题。

## 10. 对比论文、模型与期刊

### 10.1 相关方法对比（学术版图定位）

本方法（DynMaskCO）在神经组合优化 + 动态车辆路径这一交叉领域的位置，可通过与以下方法对比来定位：

| 方法 | 出处 | 类型 | 与本方法的关系 |
|------|------|:---:|------|
| **MaskCO** | ICLR 2026 | C/A | **父方法**——掩码生成范式，本方法在其上扩展动态 + 约束 + 冷链 |
| **LMask** | ICLR 2026 | A/C | **最强对手**——带回溯的约束掩码，但仍是静态/预知设定 |
| **RouteFinder** | TMLR 2025 | A | 多变体 VRP 框架，未处理动态非预知性 |
| **Attention Model (AM)** | ICLR 2019 | A/S | 经典神经构造启发式，自回归生成 |
| **POMO** | NeurIPS 2020 | A/S | 多起点策略优化，静态问题 |
| **LKH3** | — | S | 经典启发式，窄时间窗下找不到可行解 |
| **PyVRP / HGS** | — | S | 混合遗传搜索，静态全知 |

**类型说明**：C=Causal（因果/非预知）、A=Anticipatory（预知/泄漏）、D=Dynamic（动态）、S=Static（静态）。

### 10.2 关键维度对比

本方法的核心差异化优势，通过四个维度凸显：

| 维度 | 传统神经方法（AM/POMO/LMask） | 传统 OR 方法（HGS/LKH3） | **本方法（DynMaskCO）** |
|------|:---:|:---:|:---:|
| **非预知性** | ✗ 泄漏未来信息 | ✓（但仅静态） | ✓ 严格因果（注意力门控 + 可见归一化） |
| **可行性保证** | ✗ 需大量后处理 | ✓ 精确可行 | ✓ 解码器内置（100% 可行） |
| **动态重规划** | ✗ 静态 | 部分（RH） | ✓ 事件驱动 + 冻结前缀 + 随时 |
| **冷链物理** | ✗ | ✗ | ✓ 温度-品质-能耗内生递推 |

**核心定位**：现有方法要么"能解静态但看不到动态"（OR 方法），要么"端到端学习但泄漏未来/无法保证可行性"（神经方法）。本方法是**首个同时满足「严格非预知 + 硬约束可行性保证 + 动态重规划 + 冷链物理」四者的方法**——这正是论文的三个核心贡献（§4）所要论证的。
