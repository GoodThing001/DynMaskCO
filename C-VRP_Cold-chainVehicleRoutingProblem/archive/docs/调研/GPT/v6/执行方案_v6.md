## 1. 可行性保持与搜索策略增强

### 1.1 Week 1 完成：束搜索 + 约束切割 ✅

#### 实验结果（2026-08-19）

**配置**：27 个（3 types × 3 EDoDs × 3 configs），耗时 1h 9min

| Config | 平均成本 | vs Baseline | 可行性 | 状态 |
|--------|:-------:|:-----------:|:-----:|:----:|
| **Baseline** | 13.90 | — | 100% | ✅ |
| **Fast (All)** | 13.96 | **+0.4%** | 100% | ⚠️ 无改进 |
| **Fast (Top32)** | 9.36 | **-32.7%** | 100% | ⚠️ 异常 |

#### 关键发现

1. **Fast_heuristic（全检查）无改进**：
   - 约束切割没有带来成本降低（+0.4%）
   - 原因：快速启发式过于保守，**误判率高**
   - 剪掉了一些实际可行且质量好的路径

2. **Fast_top32 意外更好**：
   - 只检查 top-32 候选，成本反而降低 33%
   - 原因：限制检查范围保留了搜索多样性
   - rank > 32 的候选跳过检查，避免被误判剪掉

3. **误判示例分析**：
   ```
   Batch 1: Baseline 16.65 → Fast_top32 11.37 (−31.7%)
   ```
   说明约束切割剪掉了通向成本 11.37 的好路径

#### 核心洞察

**约束切割的问题不是"不够激进"，而是"过于激进 + 有误判"**

- ❌ 全检查（Fast_heuristic）→ 剪枝过度 → 损害解质量
- ✅ 限制检查（Fast_top32）→ 保留多样性 → 意外改进
- 💡 启示：束搜索的**多样性**比"更精确的约束检查"更重要

#### 实现细节

- **代码**：`constraint_checker.py`（400 行）+ 集成到 `resource_beam.py`
- **测试**：5 个单元测试全部通过
- **性能**：0.008 ms/check（50 节点）
- **可行性**：27/27 = 100% feasible, 0 violations

#### 论文价值

⚠️ **不适合直接作为论文贡献**，因为：
- 改进来自"少检查"而非"更好的检查"
- 说明实现有问题（误判率高）

但提供了重要洞察：
- 验证了束搜索多样性的重要性
- 为后续方向提供了经验（避免过度约束）

**完整分析**：`docs/实验记录/第一周约束切割实验结果.md`

### 1.2 Week 2 取消：束-栈回溯搜索 ❌

#### 为什么取消 Week 2？

**原计划**：实现束-栈回溯，维护历史栈，当束搜索陷入局部最优时回溯到之前的分支点。

**取消原因**（基于 Week 1 结果）：

| # | 原因 | 详细说明 |
|:-:|------|---------|
| 1 | **Week 1 显示搜索策略优化效果不佳** | 约束切割无改进，说明问题不在"搜索不够全面"，而在"约束检查有误判" |
| 2 | **束-栈回溯会放大误判问题** | 更复杂的搜索策略 → 更多的约束检查调用 → 误判累积 → 可能更差 |
| 3 | **实现和调试成本高** | 束-栈回溯难度高（内存管理、收敛性、循环检测），投入产出比低 |
| 4 | **Week 3 局部搜索更直接** | In-cycle 2-opt 不涉及约束检查，风险更低，预期改进更稳定 |
| 5 | **时间资源有限** | 6 周 → 5 周，优先投入到更有希望的方向 |

#### 决策依据

**Week 1 结束时的判断标准**（来自原计划）：
> "如果 Week 1 的束搜索+约束切割带来显著提升（cost −5%+ 或 feas 更稳定），则继续 Week 2；否则跳过回溯搜索，直接进入 Week 3。"

**实际结果**：
- ❌ 成本：+0.4%（无改进）
- ✅ 可行性：100%（已稳定）
- 🔍 新发现：约束切割有误判，限制搜索反而更好

**结论**：**不满足继续条件，触发跳过机制 → 取消 Week 2**

#### 技术原因详解

**束-栈回溯的核心思想**：
```python
# 标准束搜索：一旦剪枝就无法恢复
beam = expand_and_prune(beam, K)  # 只保留 top-K

# 束-栈回溯：保存被剪枝的候选，允许回溯
beam = expand_and_prune(beam, K)
history_stack.push(pruned_candidates)  # 保存被剪枝的

if stuck_in_local_optimum():
    beam = history_stack.pop()  # 回溯
```

**为什么 Week 1 的结果说明这不会有效？**

1. **Fast_top32 的改进来自"避免检查"**：
   - 被跳过的候选（rank > 32）保留在搜索空间中
   - 这些候选没有被约束切割误判剪掉
   - 最终找到了更好的解

2. **束-栈回溯会"检查更多"**：
   - 回溯意味着重新评估之前被剪枝的候选
   - 这些候选会经过约束检查
   - 高误判率 → 好解仍然被剪掉 → 回溯无效

3. **类比**：
   - Week 1：全检查（误判）< 限制检查（保留多样性）
   - Week 2：标准搜索 < 回溯搜索（更多检查 → 更多误判）
   - 逻辑矛盾 → Week 2 不会改进

#### 替代方案

**不是放弃搜索优化，而是换个方向**：

| 方向 | Week 2（取消） | Week 3（新重点） |
|------|--------------|---------------|
| **目标** | 更全面的搜索 | 更好的局部优化 |
| **方法** | 束-栈回溯 | In-cycle 2-opt |
| **依赖** | 约束检查 | 距离计算（无误判） |
| **风险** | 高（误判累积） | 低（成熟技术） |
| **预期** | 不确定 | 5-10% 改进 |

    if state.remaining_capacity < sum(demands[state.unvisited]):
        return False

    unvisited_sorted = sorted(state.unvisited, key=lambda i: tw_end[i])

        current_time = max(arrival, tw_start[node]) + service_time[node]

    return True

### 1.2 方案二：束-栈回溯搜索（Week 2，P2，可选）

#### 动机

标准束搜索的局限：一旦某个高分候选被剪枝，即使后续发现它可能通向更优解，也无法恢复。**束-栈回溯**维护一个"历史栈"，当当前束搜索陷入局部最优时，可以回溯到之前的分支点重新扩展。

#### 实现概要

```python
class BeamStackSearch:
    def __init__(self, beam_width, stack_depth):
        self.beam = []
        self.history_stack = []  # 存储 (step, pruned_states)
        self.max_stack_depth = stack_depth
    
    def search(self):
        while not all_nodes_visited():
            # 标准束搜索步骤
            candidates = expand_beam(self.beam)
            top_k = sorted(candidates)[:beam_width]
            pruned = sorted(candidates)[beam_width:]
            
            # 保存被剪枝的高质量候选到栈
            if len(pruned) > 0:
                self.history_stack.append((current_step, pruned[:beam_width]))
            
            self.beam = top_k
        
        best_solution = self.beam[0]
        
        # 如果解不够好 且 栈非空 → 回溯
        if best_solution.cost > threshold and len(self.history_stack) > 0:
            step, alt_states = self.history_stack.pop()
            self.rollback_to(step)
            self.beam = alt_states
            return self.search()  # 递归
        
        return best_solution
```

**关键挑战**：
- 搜索空间爆炸（需要严格限制回溯深度和次数）
- 内存开销（存储历史状态）
- 收敛性（可能陷入循环）

#### 评估与决策

**条件判断**：
- 仅当 Week 1 的约束切割带来 **cost −5%+ 或明显的搜索质量提升** 时才启动
- 否则跳过 Week 2，直接进入 Week 3（局部搜索集成）

**预期提升**：中等（cost −2~5%），但实现和调试难度高。

**时间规划**：2-3 天实现 + 2 天实验 + 1 天分析。

### 1.3 方案三：局部搜索集成（Week 3，P1）

#### 动机

当前流程：`Mask-Reconstruct (40 cycles)` → `EDD repair` → `TW 2-opt (4 steps)`。
局部搜索只在**最后阶段**执行。如果在 mask-reconstruct **过程中**频繁插入 2-opt，可以：
- 早期发现并锁定局部优化机会
- 为后续 cycle 提供更好的起点
- 可能突破当前 cost plateau

#### 实现方案

```python
def mask_reconstruct_with_local_search(encoder_output, cycles=40):
    current_solution = initialize()
    
    for cycle in range(cycles):
        masked_solution = mask_edges(current_solution, keep_rate=0.3)
        reconstructed = decode(encoder_output, masked_solution)
        repaired = edd_repair(reconstructed)
        
        # === 新增：cycle 内局部搜索 ===
        if cycle % 5 == 0:  # 每 5 个 cycle 执行一次（控制开销）
            locally_optimized = two_opt(repaired, steps=2)
        else:
            locally_optimized = repaired
        
        if cost(locally_optimized) < cost(current_solution):
            current_solution = locally_optimized
    
    # 最终全局 2-opt（仍保留）
    final_solution = two_opt(current_solution, steps=4)
    return final_solution
```

**超参数**：
- `local_search_frequency`：每 N 个 cycle 执行一次（建议 3-5）
- `local_search_steps`：cycle 内 2-opt 步数（建议 1-2，避免过度优化）
- `local_search_start_cycle`：从第几个 cycle 开始（建议 10，让初期探索更充分）

## 2. 因果性与可解释性验证

### 2.1 方案一：边影响分析（Week 4 前半，P0）

#### 动机

顶会审稿人会质疑：*"模型为什么选择这条边而不是那条？"* 借鉴 RouteExplainer (ArXiv 2024) 的思路，通过**反事实实验**量化每条边的重要性。

#### 实现方法

**Counterfactual Edge Removal**：
1. 对测试集中的每条路线，依次移除一条边 `(u, v)`
2. 用备用方法（贪心插入或重新调用模型）填补缺口
3. 比较移除前后的成本变化：`Δcost = cost_after_removal - cost_original`
4. `Δcost` 越大 → 边 `(u, v)` 越关键

**边分类**：
- **Critical edges**（Δcost > 10%）：移除后成本大幅上升
- **Beneficial edges**（Δcost > 0）：有正向贡献
- **Neutral edges**（Δcost ≈ 0）：可替代
- **Harmful edges**（Δcost < 0）：移除后反而更好（说明模型错误）

#### 实现代码

```python
def edge_influence_analysis(solution, model, data):
    """
    solution: 最终路线（list of edges）
    model: 训练好的 DynMaskCO 模型
    data: 实例数据
    """
    original_cost = evaluate_cost(solution)
    influences = {}
    
    for edge in solution:
        # 移除边
        partial_solution = [e for e in solution if e != edge]
        
        # 重建：调用模型预测缺失边
        reconstructed = model.reconstruct(partial_solution, data)
        new_cost = evaluate_cost(reconstructed)
        
        delta = new_cost - original_cost
        influences[edge] = {
            'delta_cost': delta,
            'delta_pct': delta / original_cost * 100,
            'category': categorize(delta)
        }
    
    return influences

def categorize(delta):
    if delta > 0.1: return 'critical'
    elif delta > 0: return 'beneficial'
    elif abs(delta) < 0.01: return 'neutral'
    else: return 'harmful'
```

#### 评估与可视化

**统计指标**：
- Critical edges 占比（预期 10-20%）
- Harmful edges 占比（预期 < 5%，越低越好）
- 平均 Δcost 分布（直方图）

**可视化**：
```python

def constraint_ablation_experiment(data, model, perturbation_type):
    """
    perturbation_type: 'temp_swap' | 'tw_relax' | 'capacity'
    """
    original_solution = model.solve(data)
    
    # 应用扰动
    perturbed_data = apply_perturbation(data, perturbation_type)
    perturbed_solution = model.solve(perturbed_data)
    
    # 比较
    return {
        'cost_change': perturbed_solution.cost - original_solution.cost,
        'feas_change': perturbed_solution.feasible - original_solution.feasible,
        'route_overlap': compute_route_similarity(original_solution, perturbed_solution)
    }

def apply_perturbation(data, ptype):
    data_copy = copy.deepcopy(data)
    if ptype == 'temp_swap':
        # 随机选 2 个节点交换 temp_class
        i, j = random.sample(range(1, 51), 2)
        data_copy['temp_class'][i], data_copy['temp_class'][j] = \
            data_copy['temp_class'][j], data_copy['temp_class'][i]
    elif ptype == 'tw_relax':
        # TW 宽度 × 2
        mid = (data_copy['tw_start'] + data_copy['tw_end']) / 2
        width = data_copy['tw_end'] - data_copy['tw_start']
        data_copy['tw_start'] = mid - width
        data_copy['tw_end'] = mid + width
    # ...
    return data_copy
```

## 3. 模型扩展与规模泛化

### 3.1 方案一：跨规模泛化（Week 5，P1）

#### 动机

当前模型在 50-node 训练，100-node 测试已证明 100% feasible。但更大规模（200-500 节点）是否仍有效？参考 DGL (IJCAI 2025) 的**动态全局-局部信息聚合**方法，可以提升大规模实例的处理能力。

#### 实现思路

**核心挑战**：
- Transformer 的注意力复杂度是 O(N²)，200 节点 → 4× 计算量
- 长序列信息稀释（远距离节点相关性弱）

**DGL 启发的解决方案**：
- **局部窗口编码**：将 200 节点分为 4 个 50-node 局部区域（spatial clustering）
- **全局上下文聚合**：提取每个区域的代表节点（质心）→ 全局编码器
- **两阶段解码**：先决定区域访问顺序 → 再在每个区域内细化路线

```python
class HierarchicalEncoder:
    def encode(self, nodes_200):
        # 1. K-means 聚类 → 4 个局部区域
        regions = kmeans_cluster(nodes_200, k=4)
        
        # 2. 局部编码（并行）
        local_embeddings = []
        for region in regions:
            emb = self.local_encoder(region)  # 50-node Transformer
            local_embeddings.append(emb)
        
        # 3. 全局聚合
        centroids = [emb.mean(axis=0) for emb in local_embeddings]
        global_context = self.global_encoder(centroids)  # 4-node Transformer
        
        # 4. 融合
        final_embeddings = []
        for local_emb, global_ctx in zip(local_embeddings, global_context):
            final_embeddings.append(local_emb + global_ctx)
        
        return concatenate(final_embeddings)  # 200-node embeddings
```

### 3.2 方案二：多专家/多任务训练（P2，时间允许时）

#### 动机

Luo et al. (ArXiv 2025) 发现 NCO 模型会**过拟合训练时的约束强度**。例如，只见过窄 TW (R1) 的模型在宽 TW (R2) 上表现不佳。多专家架构可以缓解：
- 训练时混合不同约束强度的数据（R1+R2, EDoD 0.2~0.8）
- 模型内部有多个"专家"分支，根据实例特征动态选择

#### 实现概要（简化版）

```python
class MultiExpertModel:
    def __init__(self):
        self.shared_encoder = Encoder()
        self.expert_r1 = ExpertDecoder()  # 窄 TW 专家
        self.expert_r2 = ExpertDecoder()  # 宽 TW 专家
        self.router = RouterNetwork()    # 根据 TW 宽度选择专家
    
    def forward(self, data):
        encoding = self.shared_encoder(data)
        
        # 路由决策
        tw_width = (data['tw_end'] - data['tw_start']).mean()
        weights = self.router(tw_width)  # softmax([w_r1, w_r2])
        
        # 专家输出加权
        logits = weights[0] * self.expert_r1(encoding) + \
                 weights[1] * self.expert_r2(encoding)
        return logits
```

- 混合 R1+R2+C1+C2+RC1+RC2 数据
- 损失函数加入路由正则（鼓励专家分化）
