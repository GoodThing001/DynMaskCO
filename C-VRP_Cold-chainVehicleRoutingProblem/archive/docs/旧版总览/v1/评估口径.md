## 1. 评价优先级 (Service-First)

评价必须分层，不可跳过第一层直接比较第二层。

### 1.0 cost 语义统一声明（跨方法指标一致性）

> **所有方法的 `cost` 均为纯行驶距离（total travel distance），不含任何惩罚。不可行性一律通过独立的可行性指标（TW Feas / Cap Feas / 未服务数）报告，绝不混入 cost。**

这一约定是与 MaskCO 原文、OR-Tools、ALNS 等所有对比方法对齐的基础。具体分工：

| 函数/求解器 | cost 定义 | 用途 |
|------------|----------|------|
| `_eval_distmat_cost`（DynMaskCO 最终报告） | **纯距离**，无惩罚 | 统一最终口径 |
| `_eval_single_route_cost`（DynMaskCO 2-opt 内部） | 距离 + 容量软惩罚 | **仅** 2-opt 边选择，不进最终报告 |
| MaskCO 原文 `eval_cost` | 纯距离，容量违规 → +∞ | 对齐（可行解上一致） |
| OR-Tools / ALNS | 纯距离 | 对齐 |

**与 MaskCO 原文的差异**（需在论文中显式说明）：
1. **约束维度**：MaskCO 是 CVRP（仅容量），本方法是 CVRPTW（容量 + 时间窗），故多一层「时间窗可行性」指标。
2. **不可行处理**：MaskCO 用 `cost = +∞` 标记容量违规；本方法用独立的 TW Feas / TW viol 报告不可行性，cost 仍输出纯距离。这是更细粒度的语义，但需显式声明，避免审稿人误以为 cost 已含惩罚。

### 第一层: 硬可行性 + 服务水平

| 指标 | 符号 | 定义 |
|------|------|------|
| 时间窗可行率 | TW Feas | $\frac{1}{N}\sum_i \mathbb{1}[\text{viol}_i = 0]$ |
| 容量可行率 | Cap Feas | $\frac{1}{N}\sum_i \mathbb{1}[\text{overload}_i = 0]$ |
| 路线完成率 | Completion | 所有客户被服务的实例比例 |
| 未服务客户数 | $N_{\text{unserved}}$ | 平均每个实例未服务的客户数 |
| 迟到客户数 | $N_{\text{late}}$ | 平均每个实例迟到的客户数 |

**规则**: 只有在 TW Feas + Cap Feas + Completion 均无显著差异时，才能比较第二层指标。

### 第二层: 成本 + 品质

| 指标 | 符号 | 定义 |
|------|------|------|
| 距离成本 | $C_{\text{dist}}$ | 路线总行驶距离 |
| Gap_ref | $\text{Gap}_{\text{ref}}$ | $(C_{\text{dist}} - C_{\text{ref}}) / C_{\text{ref}} \times 100\%$ |
| 品质损失 | $Q$ | 累计 Arrhenius 品质衰减 |
| 制冷能耗 | $E$ | 累计制冷能耗 |

### 第三层: 效率 + 稳定性

| 指标 | 符号 | 定义 |
|------|------|------|
| p50/p95/p99 延迟 | latency | 从事件进入到新决策可执行的端到端时间 |
| 路线变更率 | Churn | 相邻重规划之间改变的未执行边比例 |
| 前缀违反 | Prefix viol | **必须严格为 0** |

## 2. 新增核心指标: Conditional Recourse Regret

### 2.1 定义

在事件 $e$，所有方法已执行相同的 committed prefix $P_e$。让 clairvoyant solver 在**不允许修改 $P_e$** 的条件下看到剩余真实未来：

$$J_e^* = \min_{x \in \mathcal{X}(P_e)} J(x \mid \omega_{e:E})$$

DynMaskCO 的方案成本为 $J_e^\pi$。定义：

$$R_e^{\text{rec}} = J_e^\pi - J_e^*$$

### 2.2 归一化形式

$$\text{NR}_e^{\text{rec}} = \frac{J_e^\pi - J_e^*}{|J_e^*| + \epsilon}$$

### 2.3 为什么重要

> "既然过去已经不可改变，从当前时刻开始，我的在线重规划距离知道未来的最好补救方案还有多远？"

这个指标比单纯的 Gap_ref 强得多，因为它精确量化了**在线决策的信息劣势**。

### 2.4 报告方式

- 主表: 在多个 event epoch $e \in \{1, 3, 5, 8\}$ 上的 $R_e^{\text{rec}}$
- 图表: $R_e^{\text{rec}}$ vs event epoch 的折线图

---

## 3. 在线目标函数 (Scalar Form)

如必须产生单一 scalar 用于 ranking:

$$J = C_{\text{dist}} + \lambda_q Q + \lambda_e E + M_u N_{\text{unserved}} + M_t N_{\text{late}}$$

其中 $M_u, M_t$ 必须在 benchmark 前固定，且足够大以体现 service-first preference。

默认值: $M_u = 1000, M_t = 500, \lambda_q = 0.1, \lambda_e = 0.01$

## 4. 不可行实例处理 (修订)

| 情况 | v1 处理 | v2 处理 | 原因 |
|------|------|------|------|
| 容量不可行 | 标记 Infeasible, cost=∞ | **不排除，报告 count + rate** | 不能选择性过滤 |
| 时间窗违规 | 不排除，诚实报告 | **不排除，诚实报告** | 与 v1 一致 |
| 路线不完整 | cost=C_ref × 1.5 | **标记 unserved count + 1** | 更精确的惩罚 |
| 全部方法均 infeasible | 未定义 | **报告 infeasible rate，不做 ranking** | 避免在不可比数据上排名 |

## 7. 非预知性定义 (新增)

### 7.1 Filtration

$$\mathcal{F}_e = \sigma(\text{orders revealed by } e, \text{vehicle states}, \text{executed actions}, \text{known exogenous info})$$

### 7.2 Non-anticipativity

策略必须满足：

$$a_e \sim \pi_\theta(\cdot \mid \mathcal{F}_e)$$

对于任意两个 episode $\omega, \omega'$，只要 $\omega|_{\mathcal{F}_e} = \omega'|_{\mathcal{F}_e}$，就要求：

$$p_\theta(a_e \mid \omega) = p_\theta(a_e \mid \omega')$$

### 7.3 验证测试

| 测试 | 扰动内容 | 验收标准 |
|------|------|------|
| Future attribute perturbation | 改变未来节点坐标/demand/TW | 当前 logits 不变 (max|Δ|<1e-6) |
| Future cardinality | 改变未来订单总数 | 当前 logits 不变 |
| Target structure | 置换未来节点的 target edge | 当前 loss 不变 |
| Padding invariance | 改变 padding/dummy slots | 模型输出不变 |

## 9. JF2 Attribution Gates + Service-First Blocking Tests（2026-08-31 新增）

> 主方法从「edge-ordering」升级为「fleet assignment」（JF2）。评价除 §1 的 service-first 指标外，新增四条 attribution gates 与 blocking tests。

### 9.1 Attribution Gates（论文四条贡献关系）

固定完全相同的 inference skeleton，唯一差异是 assignment score：

| Gate | 判据 | 含义 |
|------|------|------|
| **Gate A** | $JF2_{MaskCO} < JF1-H$（100% service 前提） | learned fleet assignment 有实用价值 |
| **Gate B** | $JF2_{Real} < JF2_{Shuffle}$ | learned score 非随机（有结构化信号） |
| **Gate C** | $JF2_{MaskCO} < JF2_{Feature}$ | MaskCO representation 提供超越人工 fleet 特征的增量 |
| **Gate D** | $JF2_{MaskCO} < JF\text{-}Old$ | 新 fleet head 语义优于旧 edge-logit assignment（task alignment） |

> Gate C 不成立时，**不得**强行 claim MaskCO embedding 是性能来源。这是科研诚实性底线。

### 9.2 JF2 Blocking Tests（正式训练前必须 PASS）

- **Regression**：`α=0` 精确复现 JF1-H（24.5019 / 100% complete）；同输入 deterministic repeat；FeatureOnly/MaskCO 只改变 embedding path，不改变 search semantics。
- **Causality**：future unrevealed customer 不进入 fleet head candidate；future perturbation 不改变当前 assignment logits。
- **Ownership**：served 客户永不重现；committed 客户不换车；mutable 可跨车；客户最多属于一辆车。
- **Vehicle**：closed 不接新客户；committed 用 committed-next 作 anchor。
- **Feasibility**：hard mask 不依赖 learned score；Real/Shuffle/FeatureOnly 共用同一 candidate set；**no silent drop**；unresolved customer 进入 repair/fallback。
- **Service-first**：candidate service 差于 incumbent 必须 reject；guard reject 后恢复 incumbent；duplicate=0；TW/cap/return violation=0。

### 9.3 禁止 Silent Drop

正式 JF2 禁止 `if no candidate: drop customer`。必须 `unresolved.append(customer)` → repair/fallback。最终 joint candidate 无法完整服务时，**guard 回退当前 feasible incumbent**，维持 100% service-first。

### 9.4 统计单位提醒

5 个 shuffle seeds **不是** 5 个 training seeds；统计单位是 training seed（42/123/999/2025/2026）。JF2-M0 先 seed42，只有显著超过 JF1-H 后才进 3-seed。

## 10. Cost-Aware Preference Gate（2026-09-01 新增，HFR-M0 F3 后）

> HFR-M0 Gate A（F3）证明：structural imitation（CE 模仿 OR adjacency）的模型虽可学（S1/S2/S3 PASS），但不转化为 online decision utility。评价主线从「重构准确率」转向「downstream cost」。

### 10.1 联合 recourse action 定义

$$a = (\text{route slot}, \text{insertion position})$$

一个 action 同时决定 customer 属于哪个 partition + 在 route 的什么位置（对应 partition×sequencing interaction）。

### 10.2 Preference 监督

对 customer $j$ 的两个可行 action $a, b$，用 OR/强 continuation solver 得到 $J(a), J(b)$：

$$L_{pref} = -\log\sigma(y[s_\theta(a) - s_\theta(b)]), \qquad y = \begin{cases}+1 & J(a)<J(b) \\ -1 & J(a)>J(b)\end{cases}$$

margin 可反映 cost gap：$w_{ab} = |J(a)-J(b)|$，$L = w_{ab}L_{pref}$（小错≠大错）。

### 10.3 最终 Gate 不变

$$\boxed{\text{CostAware-M0} < JF1-H \ \text{(100% service)}}$$
