# 03_各个阶段可能会遇到的问题以及解决预案

> **版本**：v2.0 — 2026-09-01  
> **用途**：按研究阶段记录高概率失败模式、症状、诊断顺序、解决方案、停止条件与科研解释。  
> **原则**：先判断“问题属于协议 / 数据 / 监督 / 表示 / 决策集成 / 搜索 / 统计中的哪一层”，不要一看到性能差就增加模型复杂度。

---

# 0. 总诊断框架

出现问题时按以下顺序排查：

```text
Layer 0  Evaluation / protocol
Layer 1  Candidate / feasibility semantics
Layer 2  Dataset / label correctness
Layer 3  Symmetry / identifiability
Layer 4  Representation learning
Layer 5  Loss / optimization
Layer 6  Score integration / calibration
Layer 7  Search / trajectory interaction
Layer 8  Generalization / statistics
```

只有前一层确认没问题，才进入后一层。

# 1. Phase 0 — Strict-online / JF1-H Closure

## 问题 1：JF1-H 无法重复 24.5019

### 症状

```text
同一 seed 每次 cost 不同
B=1 结果和 reference 不一致
某些 instance route hash 不同
```

### 高概率原因

- customer order 改了；
- candidate semantics 改了；
- MRV 偷偷进入；
- tie-break 不稳定；
- set/dict 迭代顺序；
- float sort tie；
- event loop 改动。

### 预案

1. 逐 instance assignment fingerprint；
2. 找 first divergence event；
3. 对比 customer order；
4. 对比 candidate list；
5. 对比 score；
6. 对比 tie-break。

### Stop

reference 不 exact，不进入 JF2。

---

# 2. Phase 0 — Pair Feasibility

## 问题 2：safe pair 让 completion 下降

### 症状

```text
cost 可能变化不大
complete 从 100% 下降
```

### 原因

hard filter false-negative。

### 预案

对每个 rejected pair：

```text
approx reject
→ force assignment
→ formal route planner
→ oracle feasibility
```

若 oracle 可行，则该 reject reason 只能做 soft feature。

# 3. Phase 1 — Fleet Head Skeleton

## 问题 3：α=0 不能回归 JF1-H

### 含义

这是工程 skeleton 改变了搜索，不是 learning gain。

### 预案

比较：

```text
candidate mask
customer order
base score
rank
tie break
route sequencing
fallback
```

### Stop

α=0 不 exact，禁止训练。

---

# 4. Phase 2 — Expert Dataset

## 问题 4：teacher label 不在 candidate set

### 症状

```text
teacher_candidate_valid < 100%
```

### 原因

- OR semantics 与 production semantics 不一致；
- hard mask 过严；
- committed anchor 错；
- stale ownership；
- teacher 使用了 production 不允许的信息。

### 预案

fail-hard，不允许：

```python
if teacher_invalid:
    continue
```

必须保存 state 复现。

---

# 5. Phase 2/3 — Vehicle Symmetry（已经真实发生）

## 问题 5：one-hot exact vehicle CE 看起来完全学不会

### 已观察症状

```text
M0-v1 disagreement top-1 = 3.9%
≈ 25车随机 4%
```

### 根因

95.3% OR/min-travel disagreement 是等价 idle@depot 车辆间的任意 ID 差异。

### 已有效修复

canonicalization：

```text
等价类 → 最小 vehicle id
```

得到：

```text
true disagreement top-1 = 56.7%
```

### 长期预案

canonicalization 不作为最终理论方案，升级为：

```text
equivalence-class target
set-valued CE
permutation-equivariant scorer
route-slot partition
```

---

# 6. Symmetry 修复后的新风险

## 问题 6：canonicalization 造成“小 ID 偏置”

### 症状

随机 permutation vehicle IDs 后：

```text
raw prediction 不按 permutation 变化
小 ID 被频繁选择
```

### 原因

min-id 是人为坐标系。

### 预案

新增 permutation test。

若失败：

- 用 set-valued CE；
- 删除 raw ID embedding；
- scorer 对 vehicle axis 使用共享参数；
- global pooling 用 permutation-invariant aggregation。

---

# 7. Phase 3 — 训练指标很好但 Gate A 无改善

## 问题 7：56.7% top-1，但 cost ≈ 24.50

### 可能原因 A：decision 没真正进入 action

检查：

```text
rank flip rate
true disagreement override rate
alpha*residual magnitude
```

若模型 prediction 正确但 production rank 不变：

→ score calibration / alpha 问题。

### 可能原因 B：这些 disagreement downstream regret 很小

→ 做 regret-mass decomposition。

### 可能原因 C：真实重要决策集中在极少 early events

→ 按 progress bin 统计。

### 可能原因 D：teacher exact choice 与最终 trajectory objective 不对齐

→ preference/regret learning。

---

# 8. Phase 3 — Gate A 变差

## 问题 8：JF2 cost > 24.50，但 service=100%

### 不要立即做

- 不加层；
- 不解冻 encoder；
- 不扩大 beam。

### 先统计

```text
wrong override count
wrong override regret
correct override gain
net gain
```

定义：

\[
Net = \sum Gain(correct\ override)-\sum Regret(wrong\ override)
\]

如果错误 override 数量少但 regret 大，说明 CE 没有 cost sensitivity。

### 预案

进入 regret-weighted preference。

---

# 9. Phase 3 — Gate A service < 100%

## 问题 9：模型提升/降低 cost 同时出现漏单

### 这是 blocking failure

service-first 下不能比较 cost。

### 排查

1. learned score 是否影响 hard mask；
2. no-candidate 是否 silent drop；
3. unresolved 是否 fallback；
4. candidate assignment 后 sequencing 是否失败；
5. guard 是否拒绝 service-worse candidate；
6. committed ownership 是否被破坏。

### Stop

修到 100% service 后再看 cost。

---

# 10. Phase 4 — Gate B Real vs Shuffle 不显著

## 问题 10：Real ≈ Shuffle

### 含义

learned residual 可能没提供结构化信息。

### 检查

- shuffle 是否真的破坏 learned information；
- shuffle 是否同时破坏 candidate semantics；
- residual 是否实际参与 ranking；
- Real/Shuffle action divergence 是否为 0。

### 预案

若实现无误仍 null：

> 不 claim learned score 是 performance source。

转向 stronger objective / representation。

---

# 11. Phase 4 — Gate C MaskCO ≈ FeatureOnly

## 问题 11：MaskCO embedding 没有增量

### 科研含义

当前收益可能主要来自 handcrafted FleetState features。

### 不允许

继续写：

> “MaskCO representation 显著提升 fleet allocation”。

### 预案

按顺序：

1. 加 Generic Transformer control；
2. 检查 MaskCO H 是否被冻结在 route-edge task，不适配 fleet；
3. route/fleet consistency；
4. 低 LR encoder fine-tune；
5. 保留 route auxiliary loss。

若仍无增量：

重新定义贡献边界，不强 claim representation transfer。

---

# 12. Phase 4 — Gate D 新 Fleet Head ≈ Old Edge

如果 OldEdge 已知过去有害，而新 Head 仍没有明显优势：

### 可能原因

- 新 head 仍然只是 anchor→customer 局部打分；
- opportunity features 没被用；
- representation 输入被 handcrafted features 淹没；
- teacher 监督有效信号太稀。

### 预案

先 feature ablation：

```text
travel-only
fleet features only
MaskCO only
MaskCO+fleet
```

确定信号来源。

---

# 13. Phase 5 — Set-valued CE 训练不稳定

## 问题 13：等价集合太大，模型只学“idle class”

### 症状

```text
class acc 很高
true disagreement acc 下降
```

### 原因

自然数据里大多数 easy symmetry states 占梯度。

### 预案

- stratified sampling；
- true disagreement oversample；
- disagreement loss weighting；
- separate metrics，不用 overall accuracy 做 early stopping。

---

# 14. Phase 5 — “partition”重构后性能反而下降

## 原因可能不是 partition idea 错

可能是：

- slot identity 不稳定；
- new-route slot 数量不足；
- active route slot 与 idle class 混在一起；
- slot→physical vehicle matching 增加新误差。

### 预案

先做 oracle slot projection：

```text
OR physical assignment
→ convert to slot/partition target
→ deterministic vehicle matching
```

验证 projection 本身不损失 objective。

若 oracle projection 都变差，slot 定义有问题。

---

# 15. Phase 6 — Preference / Regret Query 太贵

## 问题 15

每个 pair 都跑 OR counterfactual，CPU 成本爆炸。

### 预案

只 query：

```text
true disagreement
model/teacher disagreement
high uncertainty
low feasible_vehicle_count
early/high-pending
```

再优先 top regret proxy。

---

# 16. Phase 6 — Regret noisy

OR 在短 budget 下可能不同运行得到不同 counterfactual objective。

### 预案

- 固定 seed；
- 对 calibration subset 重复求解；
- 记录 stability；
- 对 gap 小于 solver noise 的 pair 不训练 preference；
- 只保留 margin 足够大的 preference。

---

# 17. Phase 6 — Preference loss 提高 pairwise accuracy 但 cost 不变

可能仍然是：

```text
pairwise objective != trajectory objective
```

### 预案

进入 DAgger：

```text
current JF2 rollout
→ student states
→ OR residual expert
→ aggregate
```

因为 state distribution 已被模型自己改变。

---

# 18. Phase 7 — Best insertion features 没收益

### 可能原因

canonical benchmark 每车客户太少 / TW 主导，anchor 已经足够。

### 预案

分析：

```text
anchor score vs insertion score rank correlation
错误 decision 中 insertion 是否能纠正
```

若高度相关且无法纠错：停止，不继续堆 insertion features。

---

# 19. Phase 7 — Route Head / Fleet Head conflict

## 症状

fleet loss 降，但 route reconstruction loss 恶化；或反之。

### 预案

- gradient norm 分析；
- separate head normalization；
- loss weight sweep；
- PCGrad/gradient surgery 只在明确冲突后考虑；
- encoder low LR。

不要一开始就上复杂 multi-task optimizer。

---

# 20. Phase 8 — JF3 beam 再次 null

### 先判断是否真的 non-separable

如果 beam state 仍然只累加：

\[
\sum travel(anchor_k,j)
\]

那还不是真正 JF3。

真正 expansion 必须改变：

```text
provisional route
vehicle location/time/load
next feasible set
insertion cost
future opportunity
```

如果这些都变了但 B 仍 null，才是有价值的 negative result。

---

# 21. JF3 beam 越大反而更差

### 原因

- timeout budget 固定，宽 beam 搜索深度反而不足；
- pruning bug；
- branch state contamination；
- best feasible incumbent 没保留。

### 预案

分别报告：

```text
fixed expansion budget
fixed wall-clock budget
```

并强制：

```text
beam search 永远保留 best feasible incumbent
```

# 22. Stochastic Phase — Scenario model 没收益

先做 VOI diagnostic。

如果知道真实 future scenario 也只能改善很少：

> future prediction 不值得做。

不要为了“动态”强上生成模型。

# 23. Cold-chain Phase — 温度项仍然很弱

不要强调 temperature-driven routing。

# 24. Generalization — fleet-tight regime 失败

### 可能原因

当前训练 canonical K=25 容量宽松，model 没学强 coupling。

### 预案

- curriculum fine-tune；
- fleet-tight training mixture；
- capacity-active mix；
- scarcity features 重标定；
- route-slot formulation。

不要把 canonical 成功直接 claim 到 tight fleet。

# 25. 统计阶段问题

## 问题 25：单 seed VAL128 改善很小

比如：

```text
24.50 -> 24.42
```

不能直接写显著提升。

### 预案

若机制 Gate A 已 PASS，可以进入 3 training seeds：

```text
42 / 123 / 999
```

再看方向稳定性。

最终 5 seeds。

# 26. 伪重复风险

128 validation instances 不是 128 个 training replicate。

禁止：

> 用 128 个 instance 当 n=128 证明模型训练结果稳定。

最终统计单位以 training seed 为主；instance-level paired test 作为同一模型内的 paired performance evidence。

---

# 27. Test leakage

如果任何方法根据 TEST 调：

```text
alpha
loss weight
beam width
feature set
checkpoint
```

最终 test 就失去 one-shot 意义。

预案：所有这些只用 VAL。

# 29. 当前问题的诊断优先级

现在只需要回答四个问题：

## A. M0-v2 能不能让 cost < 24.50？

Gate A。

## B. 如果能，收益来自哪里？

Gate B/C/D。

## C. 如果不能，1866 个 real disagreement 有没有高 regret mass？

Regret decomposition。

## D. 如果 regret mass 很大但 M0 捕捉不到，应该改 loss 还是改 action space？

- score 有 signal → preference/regret；
- exact vehicle action 本身 ill-posed → partition/slot。

# 31. 什么时候正式转向 Partition Head

满足至少一个：

1. permutation audit 显示 min-id bias 明显；
2. set-valued CE 明显优于 canonical CE；
3. cost gap 的主要改善来自 opening/grouping routes，而不是选择具体 active vehicle；
4. OR/JF1-H 的主要真实差异可用 partition similarity 更好解释；
5. exact vehicle accuracy 与 cost 相关性弱，而 partition metric 与 cost 相关性强。

在此之前，不要因为一个直觉立刻推翻当前 scorer。

# 32. 建议新增 Partition Metrics

为了验证 Q1，后续可计算：

### Pair co-assignment accuracy

对于 customer pair \((i,j)\)：

\[
C_{ij}=1[vehicle(i)=vehicle(j)]
\]

忽略 vehicle ID，只看是否同 route group。

比较 JF1-H / OR / JF2 的 co-assignment matrix。

### Adjusted Rand Index / NMI

把 customer-to-route assignment 当 clustering。

注意：只在当前 mutable customer partition 上比较，处理已有 active route anchors 时要固定 anchor-associated cluster。

### Partition edit distance

从 JF1-H partition 改成 OR partition 需要移动多少 customer。

这些指标比 exact vehicle accuracy 更适合 symmetry-aware fleet analysis。

# 33. 什么时候 Go / No-Go JF2

## GO

满足至少：

```text
Gate A PASS
Real > Shuffle
```

且最好：

```text
MaskCO > FeatureOnly
```

## Conditional GO

Gate A 很弱，但 regret / partition analysis 显示明确可学习高杠杆结构。

可以进入 symmetry-aware / preference redesign。

## NO-GO 当前 JF2 formulation

如果：

```text
Gate A fail
regret mass 很小
partition difference 与 cost 也弱
MaskCO≈FeatureOnly≈Shuffle
```

则当前 fleet-learning formulation 缺少有效 objective，应转向 JF3/route-level hierarchical reformulation，而不是继续调 MLP。

# 34. 最后原则

每遇到负结果先问：

> 是模型能力不够，还是“我们要求模型预测的对象根本没有可识别语义”？

M0-v1 已经给出了一个典型答案：

> 不是模型能力不够，而是 exact vehicle ID 在同质车队里具有 permutation symmetry，one-hot label 本身是噪声。

后续所有方法设计都应优先寻找这样的“问题结构”，而不是先堆工程复杂度。
