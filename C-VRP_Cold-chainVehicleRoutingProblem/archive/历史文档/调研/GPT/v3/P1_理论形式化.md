## 1. 问题形式化

### 1.1 在线决策过程

动态冷链车辆路径问题（DCC-VRP）是一个**事件驱动的在线决策过程**。设事件序列 $e = 0, 1, 2, \dots$ 按时间顺序发生，每类事件是以下之一：

1. **订单揭示事件**：新客户 $i$ 在时刻 $r_i$ 被揭示
2. **服务完成事件**：车辆完成当前客户服务，进入下一决策点
3. **其他外生事件**：交通、天气等（本项目暂未建模）

在每个事件 $e$，决策者基于当前已知信息，输出一组（可能被部分修改的）路线 $x^{(e)}$，随后车辆沿已确定的前缀执行。

### 1.2 Filtration 定义

**定义（Filtration）**：事件 $e$ 的信息流 $\mathcal{F}_e$ 是如下信息的 $\sigma$-代数：

$$\mathcal{F}_e = \sigma\big(\underbrace{\{(x_i,y_i,d_i,a_i,b_i,s_i,c_i)\ :\ r_i \le t_e\}}_{\text{已揭示订单的属性}},\ \underbrace{\text{vehicle states}}_{\text{车辆位置/载重/时间}},\ \underbrace{\text{executed actions}}_{\text{已执行动作}},\ \underbrace{\text{exogenous info}}_{\text{已知外生信息}}\big)$$

**关键性质**：$\mathcal{F}_e$ 是**单调递增**的——$\mathcal{F}_e \subseteq \mathcal{F}_{e+1}$。信息只会增加，不会减少。

## 2. 定义：非预知在线掩码重构（Non-Anticipatory Online Masked Reconstruction）

**定义**：策略 $\pi_\theta$ 称为**非预知（non-anticipatory）**的，当且仅当其在事件 $e$ 的动作分布只依赖 $\mathcal{F}_e$：

$$a_e \sim \pi_\theta(\cdot \mid \mathcal{F}_e)$$

换言之，对于任意两个在 $\mathcal{F}_e$ 上不可区分的未来 realization $\omega, \omega'$（即 $\omega|_{\mathcal{F}_e} = \omega'|_{\mathcal{F}_e}$），策略必须给出相同的动作分布：

$$p_\theta(a_e \mid \omega) = p_\theta(a_e \mid \omega')$$

这是"诚实"在线算法的数学定义，也是本文区别于"作弊"（anticipatory）方法的核心。

## 3. 命题 1：未来不变性（Future-Invariance）

### 3.1 陈述

**命题 1**：若以下条件成立，则策略 $\pi_\theta$ 是**非预知**的（即满足 §2 的定义）：

- **(A1) 特征掩码**：未揭示客户（$r_i > t_e$）的输入特征被替换为**与 realization 无关的常数**（坐标 $\to (0.5, 0.5)$，需求/TW/温度 $\to 0$）
- **(A2) 注意力门控**：编码器对未揭示客户施加注意力偏置 $-\infty$（实现为 $-10^9$），使其注意力权重为 $0$
- **(A3) 可见归一化**：坐标归一化统计量（均值、范数）**仅由已揭示客户计算**
- **(A4) 参数与种子固定**：模型参数 $\theta$ 与随机种子在比较的两个 realization 间保持不变

### 3.2 证明

**证明**：设 $\omega, \omega'$ 是满足 $\omega|_{\mathcal{F}_e} = \omega'|_{\mathcal{F}_e}$ 的两个未来 realization。

**步骤 1（编码器输入只依赖 $\mathcal{F}_e$）**：由 (A1)，每个节点的输入特征 $x_i^{\text{in}}$ 是

$$x_i^{\text{in}} = \begin{cases} \text{真实属性}(i) & r_i \le t_e \\ \text{常数}(0.5, 0, 0, \dots) & r_i > t_e \end{cases}$$

其中"常数"部分与 $\omega, \omega'$ 的具体未来实现无关。故 $x^{\text{in}}$ 是 $\mathcal{F}_e$-可测的。

**步骤 2（注意力切断了未来节点的影响）**：由 (A2)，在自注意力中，可见节点 $i$ 对未来节点 $j$（$r_j > t_e$）的注意力权重为

$$\alpha_{ij} = \text{softmax}\left(\frac{q_i^\top k_j}{\sqrt{d}} - 10^9\right)_j \approx 0$$

（在 float32 精度下为精确的 $0$）。因此未来节点 $j$ 的值 $v_j$ 不会流入任何可见节点的输出。

**步骤 3（归一化统计量只依赖可见节点）**：由 (A3)，中心化均值 $\bar{x}$ 与缩放范数 $\|\cdot\|$ 满足

$$\bar{x} = \frac{\sum_{i: r_i \le t_e} x_i}{|\{i: r_i \le t_e\}|}, \qquad \text{norm} = \frac{\sum_{i: r_i \le t_e} \|x_i - \bar{x}\|_2}{|\{i: r_i \le t_e\}|}$$

只对已揭示节点求和，与未来实现无关。

**步骤 4（编码器输出是 $\mathcal{F}_e$-可测的）**：综合步骤 1–3，任意可见节点的编码 $h_i$ 是 $\mathcal{F}_e$ 的可测函数，且对 $\omega, \omega'$ 取相同值。

**步骤 5（动作分布只依赖 $\mathcal{F}_e$）**：解码器的边 logits 是 $h$、当前部分邻接矩阵（$\mathcal{F}_e$-可测）、资源状态（$\mathcal{F}_e$-可测）的函数，故 logits 只依赖 $\mathcal{F}_e$。由 (A4)，softmax 后的动作分布 $p_\theta(a_e)$ 在两个 realization 下相同。$\blacksquare$

**注**：命题 1 的验证对应 P0-3a 测试（`test_future_cardinality.py`），实测「置换/扰动未来节点 → 可见节点编码 $\Delta = 0$」。

## 4. 命题 2：冻结前缀不变性（Frozen-Prefix Invariance）

### 4.1 陈述

**定义（前缀与后缀）**：在事件 $e$，当前解 $x$ 被划分为

$$x = \underbrace{(v_0, v_1, \dots, v_{k_e})}_{P_e:\ \text{已执行前缀}} \oplus \underbrace{(v_{k_e+1}, \dots)}_{S_e:\ \text{可修改后缀}}$$

其中 $v_0 = 0$（depot），$v_{k_e}$ 是车辆当前位置。$E(P_e) = \{(v_0,v_1), \dots, (v_{k_e-1}, v_{k_e})\}$ 为前缀边集。

**命题 2**：若掩码支持集 $M_e$（本次重构允许修改的边）满足

$$M_e \cap E(P_e) = \emptyset$$

则任意 $k$ 次 mask-and-reconstruct 迭代后，前缀保持不变：

$$P_e^{(k)} = P_e^{(0)}, \quad \forall k \ge 0$$

### 4.2 证明

**证明**：对迭代次数 $k$ 归纳。

- **基步**：$k=0$，显然 $P_e^{(0)} = P_e^{(0)}$。
- **归纳步**：假设 $P_e^{(k)} = P_e^{(0)}$。第 $k+1$ 次重构只替换 $M_e^{(k+1)} \subseteq E \setminus E(P_e)$ 中的边。由于 $M_e^{(k+1)}$ 与 $E(P_e)$ 不相交，前缀的所有边均不被修改，故 $P_e^{(k+1)} = P_e^{(k)} = P_e^{(0)}$。

由归纳原理，命题对所有 $k$ 成立。$\blacksquare$

**对应代码**：`maskco_dynamic.build_frozen_prefix_mask()` 将前缀边收集到 `frozen_edges`，`resource_beam.reconstruct()` 从冻结边出发、不修改冻结边。

## 5. 定理：资源状态可行性保持（Resource-State Feasibility Preservation）

> 这是本文**最核心**的定理——它解释了 100% 可行性的来源。

### 5.1 陈述

**定义（资源状态）**：一条 beam 的状态为四元组

$$z = (i, t, q, V)$$

其中 $i$ 为当前节点，$t$ 为到达时间，$q$ 为当前载重，$V$ 为已访问节点集合。

**定义（状态转移）**：$z' = T(z, j)$ 表示从 $z$ 转移到访问节点 $j$ 后的状态。

**定义（可采纳动作集）**：$j \in \mathcal{A}(z)$ 当且仅当以下**全部**满足：

1. **未访问**：$j \notin V$ 或 $j = 0$
2. **容量**：$j \neq 0$ 时，$q + d_j \le Q$
3. **时间窗**：$arr_j = \max(t + s_i + \text{travel}(i,j),\ a_j) \le b_j$
4. **往返可行**：服务 $j$ 后能在 depot 时间窗内返回（$j \neq 0$ 时检查 $arr_j + s_j + \text{travel}(j, 0) \le b_0$；$j = 0$ 时检查 $t + s_i + \text{travel}(i, 0) \le b_0$）

**定理（可行性保持）**：若初始状态 $z_0 = (0, 0, 0, \{0\})$ 可行，且每步从 $\mathcal{A}(z_k)$ 中选取下一节点，并在完成所有客户后正确返回 depot，则生成的完整路线满足所有**被 $\mathcal{A}$ 显式检查的硬约束**（容量、时间窗、返回 depot）。

### 5.2 证明

**证明**：对路线长度归纳，维护以下不变式：

$$\text{Inv}(z_k):\ q_k \le Q \ \wedge\ t_k \le b_{i_k}$$

- **基步**：$z_0 = (0, 0, 0, \{0\})$ 满足 $q_0 = 0 \le Q$、$t_0 = 0 \le b_0$。$\text{Inv}(z_0)$ 成立。

- **归纳步**：设 $\text{Inv}(z_k)$ 成立，选 $j \in \mathcal{A}(z_k)$。

  **容量**：若 $j \neq 0$，由条件 2，$q_{k+1} = q_k + d_j \le Q$；若 $j = 0$（depot reset），$q_{k+1} = 0 \le Q$。两种情况均保持容量约束。

  **时间窗**：若 $j \neq 0$，由条件 3，$t_{k+1} = arr_j \le b_j$；若 $j = 0$，由条件 4，$t_{k+1} \le b_0$。两种情况均保持时间窗约束。

  **往返可行性**：由条件 4，每一步都保证「服务当前节点后能返回 depot」，因此在路线终止时，车辆必然能合法返回 depot。

由归纳原理，$\text{Inv}(z_k)$ 对任意 $k$ 成立，故完整路线满足全部硬约束。$\blacksquare$

**重要观察**：
1. 该定理是**构造性**的——它不依赖"事后修复"，而是在生成过程中逐步剪除非法动作。
2. `_can_go` 实现中的 `tw_margin = 0.05` 将条件 3 加强为 $arr_j \le b_j - 0.05$，因此定理保证的可行性比"恰好满足时间窗"更强（有安全裕度）。
3. **2 步前瞻**（`resource_beam` 中 `_can_go` 后检查 $j$ 是否仍有可行后继）额外保证"不进入死胡同"，这是对定理结论的补充强化，非必需。

**对应代码**：`resource_beam.ResourceBeamSearcher._can_go()`。

## 6. 命题 3：随时单调性（Anytime Monotonicity）

### 6.1 陈述

**命题 3**：若 incumbent 更新规则为「仅当 $J(x') < J(x^{(k)})$ **且** $x' \in \mathcal{X}_{\text{feasible}}$ 时，令 $x^{(k+1)} = x'$；否则 $x^{(k+1)} = x^{(k)}$」，则目标值序列单调不增：

$$J(x^{(k+1)}) \le J(x^{(k)}), \quad \forall k$$

### 6.2 证明

**证明**：分两种情形。

- **情形 1（替换）**：$J(x^{(k+1)}) = J(x') < J(x^{(k)})$，成立。
- **情形 2（不替换）**：$J(x^{(k+1)}) = J(x^{(k)})$，成立。

故对任意 $k$，$J(x^{(k+1)}) \le J(x^{(k)})$。$\blacksquare$

**推论**：在任意时间预算内中断 anytime 求解器，返回的 incumbent 是「已探索的解中目标值最小的可行解」——这保证了 anytime 求解器的**输出质量随预算单调改善**。

**对应代码**：`maskco_dynamic.AnytimeScheduler`（预算调度）配合 incumbent 替换规则。

## 8. 结论

上述 1 个定义 + 3 个命题 + 1 个定理构成了 DynMaskCO 的**完整理论闭环**：

1. **命题 1** 保证方法的**因果正确性**（非预知）
2. **定理** 保证方法的**可行性**（100% 无违规的来源）
3. **命题 2 + 3** 保证方法的**在线可用性**（前缀不可变 + 预算内单调改善）

三个理论结果恰好对应论文的三个核心贡献（§4 创新点 A/B/C），形成了「贡献 → 形式化 → 证明」的完整证据链。
