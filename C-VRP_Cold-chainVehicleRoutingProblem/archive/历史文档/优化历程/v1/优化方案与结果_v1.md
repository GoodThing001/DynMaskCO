## 2. 为什么不能单一归因 supervision（4 个因素）

`H2 > H3` 证明有 signal；`H2 < H1` 证明 raw intervention 无净收益。至少 4 个因素可能造成：

1. **raw selection 无条件接受 model candidate**（即使比 incumbent 差也执行）；
2. clairvoyant projected-NN supervision 与真实 online state 分布错位（R4）；
3. edge-wise CE 与最终 route cost 不完全对齐；
4. 当前最终 edge scorer 对称（`L_ij = h_i^T h_j = L_ji`），无法表达 TW 方向性。

其中 2 是 R4 根因，Method Charter 已把 visible/frozen-prefix expert 留到 Phase B。但**先做几乎零成本的 guarded H2**（因素 1），因为它能区分「proposal 不行」vs「selection 不行」。

## 3. R1.6 Proposal/Selection Closure（第一优先级，今天就做）

### 3.1 H2-G guarded

新增第 5 个方法：

| 名称 | Incumbent | 模型 | Selection |
|------|-----------|------|-----------|
| H0 | EDD | 无 | heuristic |
| H1 | NN | 无 | heuristic |
| H2 | NN | real logits | **raw** |
| H3 | NN | shuffled logits | **raw** |
| **H2-G** | NN | real logits | **guarded** |

**Guarded selection rule（service-first lexicographic，`Φ(x)=(-N_served, N_late, N_viol, C_dist)`）**：

```python
if candidate is None:                      chosen = incumbent  # candidate_missing
elif candidate_service > incumbent_service: chosen = candidate  # more_service
elif candidate_service < incumbent_service: chosen = incumbent  # less_service
elif candidate_feasible and candidate_cost < incumbent_cost - 1e-9:
                                           chosen = candidate  # lower_cost_same_service
else:                                      chosen = incumbent  # not_better
```

R1 全部 service-equivalent 时退化为 `candidate_cost < incumbent_cost`。**必须记录 acceptance rate**：`AR = #accepted / #candidate_exists`，audit 增加 `candidate_accepted` + `selection_reason`。

### 3.2 Proposal Quality Audit（分析现有 event_audit.csv，不需重训）

只取 `candidate_exists=True` 的 H2 事件，定义 `ΔC_e = C_candidate − C_incumbent`（service-equivalent）：

```
improving: ΔC < −ε
neutral:   |ΔC| ≤ ε
harmful:   ΔC > ε        （ε = 1e-6，浮点噪声大可 1e-5）
```

报告：`candidate_exists_rate / improve_rate / harm_rate / neutral_rate`，`mean/median ΔC`，`mean improvement |ΔC<0`，`mean degradation |ΔC>0`。

**4 个维度切片**：
1. **replan_reason**（initial / reveal / plan_exhaustion）—— 若 reveal 大量 harmful，直接证明「监督没教会 online recourse」；
2. **initial_actionable_count**（2–3 / 4–7 / 8+）—— 候选越多越坏 = ranking 能力不够；
3. **visible_pending_count**（1–5 / 6–10 / 11–20 / 20+）—— 判断哪种动态复杂度下失效；
4. **episode progress**（clock 分位 0–25/25–50/50–75/75–100%）—— early 差 = 高不确定 supervision 不足；late 差 = 表示不足。

### 3.3 Go/No-Go（G1/G2/G3）

- **G1**：`H2_G < H1`（哪怕 0.5–1%）且 100% service → **模型已有 practical utility**，formal 方法必须用 incumbent-preserving guard，继续 Phase B。
- **G2**：`H2_G ≈ H1` 且 improve_rate 极低 → **supervision/objective 是主瓶颈**，直接进 B0/B1。
- **G3**：`H2_G ≈ H1` 但 improve_rate 高 → 局部 suffix cost 改善与长期 episode objective 不一致，**B2 objective-guided preference 优先**。

### 3.4 R1.6 结果（2026-08-30）：G1 命中 —— 模型有 practical utility

**H2-G VAL128（R1 EDoD=0.5，128 实例，全部 100% complete / 0 viol）**：

| 方法 | cost | accept | local_first_div |
|------|------|--------|-----------------|
| EDD (H0) | 30.37 | — | — |
| NN (H1) | 27.66 | — | — |
| model raw (H2) | 28.20 | 1.0 | 0.613 |
| model_shuffle (H3) | 30.19 | 1.0 | — |
| **model_guarded (H2-G)** | **27.10** | **0.099** | 0.638 |

- H2-G vs NN：**−2.02%**（首次超越 H1，100% service）
- H2-G vs raw：guard 把 28.20 → 27.10（+3.9%）
- H2-G vs shuffle：−10.2%（signal 保持，local div 升至 63.8%）

**结论（G1）**：模型已有 practical utility。raw reconstruction 不稳定，但 model proposals 有正价值；formal 方法必须用 incumbent-preserving guard。这是 Contribution II（feasibility-preserving reconstruction）的直接证据：

> **MaskCO generates useful improvements over a feasible NN incumbent, while incumbent-preserving selection converts proposal utility into reliable online gains.**

**acceptance 拆解（model_guarded，45425 事件，candidate_exists=56.9%）**：

| selection_reason | 事件数 | 占 candidate | 方向 |
|------|--------:|:---:|------|
| candidate_missing | 19595 | —（43% 总事件） | 无 candidate，回退 incumbent |
| not_better | 22365 | 86.6% | 同服务更贵 → 拒 |
| less_service | 912 | 3.5% | 服务更少 → 拒 |
| **more_service** | **2209** | **8.6%** | 服务更多 → 接 |
| **lower_cost_same_service** | **344** | **1.3%** | 同服务更省 → 接 |

> **关键**：guard 的接受里 **86.5% 是 `more_service`**（2209/2553），13.5% 是 `lower_cost_same_service`（344/2553）。即模型相对 NN 的 2% 收益**主要来自「每条 route 服务更多订单」（beam 前瞻找到 NN 贪心卡住时漏掉的更长可行 suffix）**，而非「同服务数下更省」。这为 B0/B1 提供明确靶点。

**Proposal Quality Audit（22860 个 service-equivalent candidate 事件）**：

- overall：improve 1.3% / neutral 94.4% / harm 4.3%，mean ΔC +0.0192。
- **94.4% neutral** = 模型 candidate 距离与 NN incumbent 完全一致 → 复现 NN（R4 监督的直接证据）。
- harm 集中在四个区：**initial 56.0%**（vs reveal 4.0%）、**8+ actionable 76.2%**、**20+ pending 58.3%**、**0-25% episode 23.4%**。
- → 病根 = **① 高决策自由度下排序能力不足；② initial 状态监督缺失**，不是「模型没用」。

**对 B0 的指导**：B0 针对性回答 OR-Tools expert 是否在 initial + 高 actionable 状态明显强于 NN。是 → B1 蒸馏有靶点；否 → 差距在 fleet 层，转 Joint Fleet。

## 3.5 R1.7 结果（2026-08-30）：H3-G 归因闭环 —— learned preference 提供全部 2% 收益

**H3-G（guarded shuffle，5 个 shuffle seed 42/43/44/45/46，adjacency mask 由 decode_seed=42 固定）**：

| 方法 | cost | accept | complete |
|------|------|--------|----------|
| NN (H1) | 27.66 | — | 100% |
| H2-G (real) | 27.10 | 9.9% | 100% |
| H3-G s42 | 27.81 | 9.7% | 100% |
| H3-G s43 | 27.66 | 9.5% | 99.2% |
| H3-G s44 | 27.65 | 9.6% | 100% |
| H3-G s45 | 27.66 | 9.4% | 100% |
| H3-G s46 | 27.66 | 9.4% | 100% |
| **H3-G mean ± std** | **27.69 ± 0.07** | ~9.5% | — |

**归因分解（导师 §4.3 情况 A）**：

```
G_search  = NN − H3-G = 27.66 − 27.69 = −0.03（−0.10%，≈0）
G_learned = H3-G − H2-G = 27.69 − 27.10 = +0.59（+2.13%）
```

**结论（强主张成立）**：

> **beam + guard 本身（shuffled logits）几乎不能超过 NN**（H3-G 27.69 ≈ NN 27.66，甚至略差 −0.10%）；**learned structured preference 提供了全部 2.1% 的实际增益**。

这直接回答 R1.7 核心问题：**2% 收益完全来自 learned logits，不是 beam + guard。** 至此「MaskCO learned preference 有独立价值」的证据链闭合：

1. `H2 < H3`（28.20 < 30.19）→ learned preference 非随机；
2. `D_local = 61.3%` → 模型真实进入决策；
3. `H2-G < H1`（27.10 < 27.66）→ 有 practical utility；
4. **`H3-G ≈ H1 ≫ H2-G` → 这 2% 全部来自 learned preference，非 beam/guard。**

**机制细节（acceptance rate 相近但 cost 差 0.59）**：H3-G 与 H2-G 的 acceptance rate 接近（~9.5% vs 9.9%），说明 learned preference 的价值在「接受候选的**质量**」而非「数量」——real logits 引导 beam 找到**更便宜的 longer route（more_service）** + **更优排序（lower_cost_same_service，344 事件）**；shuffled logits 的 beam 虽也找到 more_service（~2209），但 route 更贵，且几乎找不到 lower_cost（344 全丢）。

**唯一异常**：H3-G s43 有 1/128 实例 incomplete（99.2% complete，1 unserved）——guard 局部 myopic 的罕见失效，正好是 R1.7-4（Guard Long-Horizon Audit）要查的；真实方法 H2-G 100% complete 不受影响。

## 3.6 R1.7-2 结果（2026-08-30）：Proposal Structure Audit —— 情况 1（模型大量复制 NN）

**核心数据（H2-G，25830 个 candidate_exists 事件）**：

| 指标 | 值 |
|------|------|
| exact_route_equal_rate | **82.2%** |
| first_action_equal_rate | 87.0% |
| same_cost_rate | 82.7% |
| same_cost_diff_route_rate | **0.45%** |
| more / less / same_service | 8.6% / 3.5% / 87.9% |

**结论：情况 1（复制 NN），不是情况 2（等成本 alternative）。**

之前 94.4%「neutral cost」的真相：82.2% candidate 是 NN 的**逐节点精确复制**（route 相同 → cost 相同），只有 **0.45%** 是「等成本但结构不同」的 alternative solution。

**完整分解（25830 candidate）**：
- 82.2% 精确复制 NN
- 0.45% 等成本不同结构（情况 2，极少）
- 5.25% 同服务数不同排序（成本变化）
- 8.6% more_service（beam 找到更长路线）
- 3.5% less_service

**guard 精准保留了「结构性偏离」**：
- accepted（2553）：exact_route_equal=**0.000**、first_action_equal=0.210、edge_jaccard=0.159、service_delta=+1.44 → 每个 accepted candidate 都是对 NN 的结构性改变（0% 复制）。
- rejected（23277）：exact_route_equal=0.912 → 91% 是 NN 复制（被拒，因 not_better/less_service）。

**模型在哪偏离 NN（4 维切片）**：
- replan_reason：initial 仅 **6.5%** 复制（56.5% more_service）；reveal **83.5%** 复制。
- actionable_count：1→90% 复制；**8+→0.1% 复制**（几乎从不复制）。
- pending_count：1-5→94.9% 复制；**20+→5.8% 复制**。
- progress：0-25%→28.7% 复制；**75-100%→98.7% 复制**。

**对 R1.7-4 的意义**：等成本 alternative（有 future-flexibility 差异）只占 0.45%，几乎不存在。模型的偏离几乎总是「改变服务数量（more/less_service）」，不是「等成本换结构」。所以 Guard Long-Horizon 里 future-flexibility 的差异主要来自 more_service 改变车辆位置/时序，而非等成本换路。

## 3.7 R1.7-3 结果（2026-08-30）：State/Leverage —— 模型价值与 harm 同集中在高自由度状态

**核心数据（H2-G，25830 candidate，accept/improve/harm/结构分叉 4 维切片）**：

| 维度 | 最活跃（accept 最高） | harm 最高 | improve vs harm |
|------|------|------|------|
| replan_reason | initial 62.0% | initial 15.4% | 5.5% vs 15.4%（~2.8×） |
| actionable | 4-7 组 56.2% | 8+ 组 21.4% | 7.5% vs 21.4%（~2.9×） |
| pending | 20+ 组 60.0% | 20+ 组 18.3% | 6.4% vs 18.3% |
| progress | 0-25% 40.4% | 0-25% 14.5% | 5.4% vs 14.5% |

**guard 在工作**：
- accepted（2553）：harm=**0.000**（guard 只接受 more_service 86.5% + lower_cost 13.5%）、structure_divergence=1.000。
- rejected（23277）：neutral=91.7%（精确复制 NN）、harm=4.3%、structure_divergence=8.8%。

**关键发现 1：improve << harm —— 同服务数重排序不可靠**：
- 「更优同服务排序」（lower_cost 344）vs「更差同服务排序」（rejected harm ~1010）≈ **1:2.9**。
- 模型的**排序能力不可靠**（坏排序 3× 于好排序），尤其高自由度（8+ 候选 harm 21.4% >> improve 7.5%）。
- 直接指向 **A\* directional scorer（非对称 QK）+ B1 OR expert（更好排序监督）**。

**关键发现 2：模型价值 = more_service（数量），不是 better ordering（质量）**：
- accepted 86.5% 是 more_service（beam 找到更长路线，real logits 使其更便宜）；lower_cost（better ordering）仅 13.5%。
- 所以 H2-G 的 2% 增益主要来自「服务更多订单」，而非「同订单更优排序」。

**high_leverage（lower_cost 局部收益集中度）**：Top 10% 贡献 35%（vs 均匀 10%），中度集中——lower_cost 收益较分散、不脆弱。⚠️ 完整版需 R1.7-4 long-horizon（more_service 长期收益未含）。

**完整故事链（R1.5-M → R1.7 闭合）**：模型有 learned preference（H2<H3、D_local 61%）→ 价值 = more_service + 少量 lower_cost → 弱点 = 同服务排序不可靠（坏 3× 好）→ guard 必需（过滤坏排序）→ 净收益 H2-G 27.10 < NN 27.66。**修法 = B1（OR 监督）+ A\*（directional scorer）提升排序可靠性。**

**gap 分解（paired 口径，已消除 completeness 混淆）**：
- `G_seq`（sequencing）= **−1.25%**（精确重排序比 NN 贪心**还差 1.25%**）
- `G_fleet`（fleet alloc）= **17.90%**（跨车重分配是主导 gap）

**clean metrics（return-depot bug 修复后重跑，256 实例）**：

| 指标 | NN→OR-fixed | OR-fixed→OR-joint |
|------|------------|-------------------|
| Completion Δ | +0.4% | +3.5% |

| **Service-eq cost Δ** | **−0.336**（n=253） | **+4.978**（n=247） |

> **return-depot bug 修复后数字几乎不变**（NN 27.42 vs 27.41，G_seq −1.248% vs −1.25%），说明该 bug 是次要的；但 **service-eq cost Δ 给出了最干净的分解：sequencing −0.336（NN 反而更便宜）、fleet +4.978（OR-joint 便宜 18%）**。

**核心结论（confirmed，干净口径）**：

> **17.6% gap 几乎全是 fleet allocation（service-eq +4.978 ≈ 18%），sequencing 是负的（service-eq −0.336 ≈ −1.2%）。** 冻结 assignment 后，精确 TSPTW 重排序对 NN 贪心**没有正收益，反而略差**。

**为何 sequencing 是负的（不改变结论）**：
1. **局部最优 vs 全局（现在更可能）**：return-depot bug 修复后负值仍在（−0.336），说明主因**不是**那个 bug，而是精确 TSPTW 最小化当前 suffix、却可能把车辆送到对未来 reveal 不利的位置（局部最优 ≠ 全局最优）。
2. return-depot check 差异：已被修复，贡献极小。

**与 R1.7 的呼应**：R1.7 发现 H2-G 的 2% 收益 86.5% 来自 `more_service`（改变归属），B0 从 baseline 侧独立证实「sequencing 换顺序 ≈ 0 甚至负、fleet 换归属 ≈ 18%」。两条线同一结论：**瓶颈在 fleet allocation，不在 sequencing**。

**对路线图的影响（方向分叉已定）**：
- **Joint Fleet（fleet 层联合分配）优先级应大幅上调**——这是 17.9% gap 的唯一主要来源。
- **B1（OR supervision）/ A\*（directional scorer）收益上限很低**——sequencing 已饱和（负），继续优化排序没有意义。
- 下一步应是 **Joint Fleet**（JF1 joint assignment → JF2 full joint fleet resource beam），而非 B1/A*。

## 3.10 JF1 四路 result（2026-08-31，VAL128）—— 联合分配收益来自搜索空间，不是 learned preference

**JF1 四路（greedy joint assignment + 单车 greedy sequencing，唯一差异是 assignment score）**：

| 方法 | cost | complete |
|------|------|----------|
| OR-joint | 23.04 | 100% |
| **JF1-H（heuristic：min travel）** | **24.50** | 100% |
| JF1-R（real：edge logits） | 26.84 | 97.7%* |
| NN (H1) | 27.66 | 100% |
| JF1-S（shuffle：打乱 logits） | 29.10 | 96.1%* |

> **冻结标注（导师 §2/§45）**：`*` = complete 非 100%，按 service-first protocol **不可与 100% 方法按 cost 直接排名**（26.84/29.10 的服务水平已下降，cost 不可直接宣称优于 NN）。JF1-H 是四路里唯一 100% complete 且最优的方法。结果目录 `results/jf1_three_way/`；代码 hash 待服务器 sha256 补。

**核心结论（决定性）**：

> **JF1-H（纯启发式 min travel）是四路里最好（24.50，−11.4%），而 JF1-R（真实 logits）比 JF1-H 差 9.5% 且 complete 掉到 97.7%。** 联合分配的收益**完全来自搜索空间拓扑（sequential → joint），不是 learned preference**；现有 MaskCO edge logits 作 assignment score **反而有害**（成本更贵 + 漏服务）。

**为何 learned preference 是「坏」的 assignment score（R4 根因）**：
MaskCO 的 edge logits 训练在 **NN 顺序路线**上（masked reconstruction CE），`L[i,j]` 回答「NN 路线里 i 后面接不接 j」——这是 **sequential 偏好**，不是「车 k 该不该接客户 j」的 **fleet assignment 质量**。语义错配 + logit 不感知 TW/容量可行性 → 分配到 TW-infeasible 的车、漏服务 2.3%。

**这坐实了导师 §6/§22 的预判**：
> 学习目标应从 route-edge ordering 转向 fleet-level assignment preference；B1 应从 OR sequencing teacher 改造成 **OR-joint assignment teacher**。

**下一步 = JF2**：训练真正的 `S(k,j | FleetState)`（State-Aware Fleet Assignment Scorer）——输入车辆 anchor state（node/time/load/TW slack/capacity slack/return slack）+ 客户 embedding + fleet context，用 OR-joint 的 assignment 决策（`y_kj` 或 `Q(k,j)`）作监督。

## 6. A0.5 Directional Scorer（第五优先级，B1 之后独立做）

当前 final edge score 对称 `L_ij = h_i^T h_j`，但 CVRPTW 中 `i→j` 与 `j→i` 决策不同（到达时刻/TW 顺序/车辆 state 不同）。

**最小改造**：

```
q_i = W_q h_i,   k_j = W_k h_j,   L_ij = q_i^T k_j / √d   （W_q ≠ W_k，先不做 MLP）
```

**机制指标**：

```
A_asym = (1/|E|) Σ_{i≠j} |L_ij − L_ji|      旧 scorer ≈0，新 scorer >0
```

看 `A_asym` 是否与 TW 紧迫状态中的性能改善相关。**A0.5 只换 scorer**（same OR labels / loss / subset / steps / beam），对比 `B1-symmetric` vs `B1-directional`。

## 7. B2 Preference Learning（第六优先级）

B1 仍是模仿 expert route；edge CE 会把「非 expert 边」全当错，不完全等价于 route objective。B2 解决「不要机械复刻 exact edge；学习哪个 action 更好」。

**最简单 pairwise ranking**：

```
L_rank = −log σ((L(a+) − L(a−))/τ)，  τ=1
```

**非一视同仁的 pair 权重**（expert action j+，候选 j1/j2/j3，OR/short rollout 估 J(j)）：

```
w_+- = clip((J(a−) − J(a+)) / (|J(a+)| + ε), 0, w_max)
L_pref = −w_+- · log σ(s_+ − s_−)
```

**不删 CE**：`L = L_CE + λ_p L_pref`，扫 `λ_p = 0.1 / 0.3 / 1.0`（2K screening，非 50K）。
