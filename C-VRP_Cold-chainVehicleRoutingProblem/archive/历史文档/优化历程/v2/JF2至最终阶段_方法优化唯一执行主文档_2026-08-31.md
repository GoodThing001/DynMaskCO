# Part I. 后续所有代码都不能破坏的系统语义

## 1. 运行时状态以 `strict_online_env.py` 为准

[LOCKED]

论文抽象有时写 `idle / active / committed / closed`，但当前真实代码的 `VehicleState.status` 是：

```text
idle / ready / committed / returning / closed
```

后续 JF2 代码必须按**五态运行时语义**实现：

| 状态 | 运行时含义 | 可否接新客户 | assignment anchor |
|---|---|---:|---|
| `idle` | 尚未 dispatch，当前在 depot | 可以 | depot，时间必须是当前 `clock`，不能是 0 |
| `ready` | 已完成上一步服务、当前无 committed leg | 可以 | `current_node`, `ready_time` |
| `committed` | 已承诺去某客户且不可撤销 | **不能改变 committed 客户**；可规划其后 suffix | `committed_next`, `committed_finish` |
| `returning` | 已承诺返回 depot | 不可以 | 无 |
| `closed` | 已返回 depot，single-route-per-vehicle 结束 | 不可以 | 无 |

[RISK] 最容易写错的是把 `ready` 当成“新车从 depot 出发”，或者把 `committed` 的 anchor 仍写成 `current_node`。这会同时造成时间穿越、重复服务、TW 判定错误。

### 1.1 committed anchor 的正确资源状态

[IMPLEMENT]

对 ready/idle：

```python
anchor_node = v.current_node
anchor_time = max(v.ready_time, clock) if v.status == 'idle' else v.ready_time
anchor_load = v.current_load
```

对 committed：

```python
anchor_node = v.committed_next
anchor_time = v.committed_finish
anchor_load = v.current_load + demand[v.committed_next]
```

这里 `anchor_load` 必须是“完成 committed customer 后”的资源状态。当前 `strict_online_env.py` 只有在 committed service 真正完成时才执行：

```python
v.current_load += demands[node]
```

所以若 JF2 在 committed 完成前规划其后续 suffix，而仍直接使用 `v.current_load`，就会少算 committed customer 的 demand。

[GATE] 为 committed anchor 单独写 toy test：若 `current_load=40`、committed demand=8、Q=50，则 suffix customer demand=3 必须判 capacity impossible（48+3>50），不能按 40+3 错放行。

## 4. Frozen prefix / committed leg 不得被 JF2 “重优化”

[LOCKED]

动态 recourse 允许改变的是：

```text
mutable ownership + mutable suffix
```

禁止改变：

```text
served prefix
committed next leg
returning action
closed vehicle history
```

后续所有 candidate 必须满足：

\[
E(P_e) \cap M_e = \varnothing
\]

即已执行前缀不在 MaskCO reconstruction 的修改支持集中。

## 5. Mutable ownership 的正确理解

[LOCKED + IMPLEMENT]

当前 `StrictOnlineEnv.get_reserved_customers()` 会 reserve：

- committed_next；
- 所有车辆当前 `mutable_suffix` 中客户。

这是为了避免 stale-tail duplicate。

但 JF2 的目标又是：**在一个 joint recourse event 中允许 selected vehicles 的 mutable ownership 跨车释放与重分配**。

因此严谨实现不是删掉 `get_reserved_customers()`，而是定义“锁定”和“释放范围”：

```python
def get_locked_customers(vehicles, release_vehicle_ids):
    locked = set()
    for v in vehicles:
        if v.status == 'committed' and v.committed_next not in (None, 0):
            locked.add(v.committed_next)

        # 只有不参与本轮 joint recourse 的车，其旧 tail 才继续锁住
        if v.vehicle_id not in release_vehicle_ids:
            locked.update(x for x in v.mutable_suffix if x != 0)
    return locked
```

[RISK]

- 若所有 tail 都 reserve：JF2 看似 joint，实际上 ownership 根本不能释放。
- 若所有 tail 都解除 reserve：不参与重规划的车辆旧 plan 会被别车抢走，重新出现 duplicate。

[GATE] 必须有 3 车 toy：A/B 参与 recourse，C 不参与。A/B tail customer 可互换；C tail customer 不得进入 A/B candidate pool。

# Step 1. 实现 `legacy_jf1h` faithful mode

## 1.1 目的

[LOCKED]

JF1.5 B=1 当前约 24.68/99.2%，没有精确退化到 JF1-H 24.5019/100%。原因已定位为：`pair_feasible` hard filter + MRV 改变 candidate semantics。

因此第一步不是训练，而是建立一个**完全忠实的旧行为模式**。

## 1.2 推荐接口

```python
class JointAssignmentBeamReplanner(Replanner):
    def __init__(self, ..., candidate_mode='legacy_jf1h', beam_width=1):
        assert candidate_mode in {'legacy_jf1h', 'safe_pair'}
        self.candidate_mode = candidate_mode
        self.beam_width = beam_width
```

核心原则：

```python
if candidate_mode == 'legacy_jf1h':
    # 只能走冻结 JF1-H 的旧路径
    # 不允许调用新 pair_feasible
    # 不允许 MRV 重排
    # 不允许新增 fallback
    return self._plan_legacy_jf1h(...)
```

不要写成：

```python
cands = self._safe_candidates(...)
if candidate_mode == 'legacy_jf1h':
    score = legacy_score(cands)
```

因为此时 candidate set 已经被新逻辑改变，**不再是 faithful regression**。

## 1.3 必须冻结的行为

至少冻结：

1. mutable customer pool 构造顺序；
2. customer 遍历顺序；
3. vehicle candidate 顺序；
4. min-travel score 公式；
5. tie-break；
6. assignment 后的 per-vehicle sequencing；
7. fallback；
8. WAIT / return semantics；
9. `replan_ids` 处理。

### 推荐：生成行为指纹

```python
fingerprint = {
    'customer_order': customer_order,
    'assignment': [(j, k) for j, k in ...],
    'vehicle_suffixes': {k: tuple(suffix) for ...},
}
```

对 VAL128 逐实例保存：

```text
results/jf2_closure/jf1h_reference_instance.jsonl
```

不要只比较平均 cost，因为两套逻辑可能平均值接近但逐实例不同。

## 1.4 [GATE]

必须同时满足：

```text
B=1
candidate_mode=legacy_jf1h
summary distance diff < 1e-6
completion = 100%
instance-level deterministic output identical
```

如果浮点路径导致 cost 无法 exact bitwise 相同，至少要求：

```text
assignment fingerprint identical
route sequence identical
abs(cost_i_new - cost_i_ref) < 1e-6
```

## 1.5 常见错误

- 在 legacy 模式里仍然调用 `pair_feasible`。
- customer order 从旧固定顺序变成 MRV。
- Python `set` 直接迭代导致 nondeterministic tie-break。
- `np.argsort` / `jax.argsort` 同值时顺序不一致。
- 把 `clock`、`ready_time` 的 rounding 改了。
- 先重构了 JF1-H 再做 regression，导致“参考本身被改掉”。

## 1.6 严谨开发策略

一个 PR 只做：

```text
add legacy mode + regression test
```

不要同一个 PR 同时：

```text
改 candidate semantics
+ 改 pair feasibility
+ 加 FleetHead
```

否则一旦 24.5019 复现失败，没有办法知道是哪一层造成的。

# Step 3. Pair Feasibility false-negative audit

## 3.1 为什么必须审计

[LOCKED]

当前 `safe_pair` 把 24.50/100% 变成约 24.68/99.2%，说明某些 hard filter 可能不是 sound necessary condition。

所谓 sound hard mask：

> 被 mask 的 `(vehicle, customer)` 必须真的不可能形成任何合法 suffix。

否则它就不应该是 hard mask，而只能作为 soft feature。

## 3.2 先把“判定结果”从 bool 升级成结构化对象

推荐：

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class PairDecision:
    feasible: bool
    reason: str | None
    anchor_node: int
    anchor_time: float
    anchor_load: float
    arrival: float | None = None
    service_start: float | None = None
    tw_slack: float | None = None
    cap_slack: float | None = None
    return_slack: float | None = None
```

不要继续只有：

```python
return False
```

因为 false-negative audit 必须知道“为什么被拒”。

## 3.3 第一版允许作为 hard mask 的条件

### A. Causal / ownership

```text
future
served
committed-to-other
locked tail of non-replanned vehicle
```

### B. Vehicle state

```text
returning
closed
invalid anchor
```

### C. Capacity necessary condition

对 ready/idle：

\[
load_k + d_j > Q \Rightarrow mask
\]

对 committed：必须用 anchor completion load。

### D. Direct-arrival TW necessary condition

\[
arrival=t_k+travel(a_k,j)
\]

\[
start=\max(arrival,a_j)
\]

若：

\[
start>b_j
\]

则即使 j 作为该车 suffix 的**第一个 mutable customer**都不可能准时，因此可 hard mask。

### E. Return depot

当前阶段**默认只做 feature，不做 hard mask**，直到 oracle audit 证明 zero false-negative。

## 3.4 oracle check 的关键

被 approximate pair check 拒绝后，oracle 不能再调用同一个 approximate check，否则是循环自证。

正确 audit：

```text
rejected (k,j)
  ↓
构造“j 必须归 k”的临时 mutable assignment
  ↓
调用正式 per-vehicle resource-feasible route planner
  ↓
检查是否存在完整合法 suffix
```

若正式 planner 找到 suffix，则：

```text
false_negative = True
```

该 reject reason 不能成为 production hard mask。

## 3.5 输出表

`pair_feasibility_audit.csv`：

```text
instance_id,event_id,clock,replan_reason,
vehicle_id,customer_id,
status,anchor_node,anchor_time,anchor_load,
arrival,start,tw_end,tw_slack,cap_slack,return_slack,
reject_reason,oracle_feasible,oracle_route,oracle_cost
```

聚合：

| Reason | Reject N | Oracle feasible | False-negative rate | Production action |
|---|---:|---:|---:|---|
| capacity | | | | hard mask only if 0 FN |
| direct TW | | | | hard mask only if 0 FN |
| return | | | | keep soft until proven |
| ownership | | | | invariant |

## 3.6 [GATE]

production hard-mask reason 必须：

```text
false-negative = 0
```

若样本量有限，仍按“未证明 sound → 不 hard mask”原则处理。



## 4.2 正确状态机

```python
unresolved = []
for j in customer_order:
    candidates = build_candidates(j)
    if not candidates:
        unresolved.append(j)
        continue
    assign(j)

if unresolved:
    repair_result = repair(unresolved, current_assignment)

```

# Step 6. 新增 FleetAssignmentHead

## 6.1 最重要的工程风险：旧 checkpoint 兼容

[RISK]

当前 `DynamicColdChainModel` 的 checkpoint loader 对模型结构不匹配会 hard error。若你直接在类里新增带参数的 `FleetAssignmentHead`：

```python
self.fleet_head = FleetAssignmentHead(...)
```

旧 MaskCO checkpoint 的参数树里没有该 head，`nnx.merge(...)` 很可能失败。

### 推荐实施顺序：wrapper-first

第一阶段最稳妥：

```text
先原样 load 旧 DynamicColdChainModel checkpoint
→ 再创建独立 FleetAssignmentHead
→ 组合成 JF2 runtime wrapper
```

伪代码：

```python
class JF2Runtime:
    def __init__(self, base_maskco_model, fleet_head):
        self.base = base_maskco_model
        self.fleet_head = fleet_head

    def encode(self, *args, **kwargs):
        return self.base.encode(*args, **kwargs)
```

这样：

- 旧 ckpt 加载行为完全不变；
- `alpha=0` 更容易 faithful regression；
- Fleet Head 可以单独训练/保存；
- 等 JF2 有效后再决定是否迁移成统一模型 checkpoint。

**不要为了代码“看起来漂亮”在 Gate-0 前重构 checkpoint schema。**

## 6.2 Fleet Head 的输入输出

固定 shape（推荐 JAX 友好）：

```text
node_embeddings H     : [B, N, D]
vehicle_anchor_ids    : [B, K]
vehicle_dyn_features  : [B, K, Fv]
pair_features         : [B, K, N, Fp]
candidate_mask        : [B, K, N] bool
output residual       : [B, K, N]
```

canonical：

```text
N = 51（depot + 50 customers）
K = 25
D = 256
```

不要为每个 event 改成 ragged Python list 输入 JAX 网络，否则会造成频繁 recompilation。

## 6.3 Vehicle representation

\[

\]

建议第一版 `f_k`：

```text
anchor_time / T
anchor_load / Q
remaining_capacity / Q

```

status embedding 必须按运行时五态定义；但 `returning/closed` 通常直接 candidate mask 掉。

## 6.4 Customer representation

\[

\]

`x_j` 至少包含当前 visible 的：

```text

tw_start normalized
tw_end normalized

```

不要重新输入真实 `reveal_time` 的未来 realization 信息。

## 6.5 Pair scorer 推荐第一版

\[
\phi_{kj}=[v_k;c_j;pair_{kj};global]
\]

\[
r_\theta(k,j)=MLP(\phi_{kj})
\]

接着：

\[
S_{kj}=S_H(k,j)+\alpha r_\theta(k,j)
\]

### Flax NNX 风格伪代码

> 这是建议 skeleton，需按服务器实际 Flax 0.10.4 API 做小幅适配。

```python
class FleetAssignmentHead(nnx.Module):
    def __init__(self, embed_dim=256, veh_dim=5, pair_dim=12,
                 hidden_dim=256, rngs=None):
        self.vehicle_proj = nnx.Linear(embed_dim + veh_dim, hidden_dim, rngs=rngs)
        self.customer_proj = nnx.Linear(embed_dim, hidden_dim, rngs=rngs)
        self.pair_mlp1 = nnx.Linear(hidden_dim * 2 + pair_dim, hidden_dim, rngs=rngs)
        self.pair_mlp2 = nnx.Linear(hidden_dim, 1, rngs=rngs)
        self.alpha = nnx.Param(jnp.array(0.0, dtype=jnp.float32))

    def __call__(self, H, anchor_ids, veh_feat, pair_feat, base_score, candidate_mask):
        B, K = anchor_ids.shape
        D = H.shape[-1]
        h_anchor = jnp.take_along_axis(
            H[:, None, :, :],
            anchor_ids[:, :, None, None],
            axis=2,
        ).squeeze(2)  # [B,K,D]

        v = jax.nn.silu(self.vehicle_proj(jnp.concatenate([h_anchor, veh_feat], axis=-1)))
        c = jax.nn.silu(self.customer_proj(H))  # [B,N,H]

        v_expand = jnp.broadcast_to(v[:, :, None, :], (B, K, H.shape[1], v.shape[-1]))
        c_expand = jnp.broadcast_to(c[:, None, :, :], (B, K, H.shape[1], c.shape[-1]))

        z = jnp.concatenate([v_expand, c_expand, pair_feat], axis=-1)
        z = jax.nn.silu(self.pair_mlp1(z))
        residual = self.pair_mlp2(z)[..., 0]

        score = base_score + self.alpha.value * residual
        score = jnp.where(candidate_mask, score, -1e9)
        return score, residual
```

[RISK] `take_along_axis` 的 shape 很容易写错，必须写 shape unit test。

先把 M0 的可归因性做干净。

# Step 8. 实现 residual score

## 8.1 base score 必须复用 JF1-H 的同一实现

不要重新写一个“看起来等价”的：

```python
base = -distance / distance.max()
```

因为 normalize 范围、candidate subset、tie-break 的任何差异都可能改变 JF1-H。

正确方法：把 JF1-H 的 score 抽成共享函数：

```python
def jf1h_base_score(state, candidate_set):
    ...  # 原样迁移，不改数学语义
```

JF1-H 和 JF2 都调用它。

## 8.2 alpha 初始化

```python
alpha = 0.0
```

不是 0.01，不是小随机数。

Gate-0 的意义是：

\[
\alpha=0\Rightarrow JF2\equiv JF1-H
\]

## 8.3 alpha 的训练策略

推荐 M0：

- Fleet Head 参数训练；
- `alpha` 可训练，但监控其数值；
- 可以先让 alpha 固定为一个小正值做稳定性 screening，但正式主实验必须明确版本。

更稳妥的两阶段：

```text
warmup：训练 residual head，alpha 固定 1（loss only，不跑 production）
production fine-tune：alpha 可训练，score = base + alpha*residual
```

但无论怎样，Gate-0 必须在 `alpha=0` 独立完成。

# Part XVII. JF2-M0 Pair Features 的严谨实现

## 17.1 Motion

\[
travel_{kj}
\]

\[
ETA_{kj}=t_k+travel(a_k,j)
\]

\[
wait_{kj}=\max(0,a_j-ETA_{kj})
\]

## 17.2 TW

\[
start_{kj}=\max(ETA_{kj},a_j)
\]

\[
TWSlack_{kj}=b_j-start_{kj}
\]

\[
RelativeUrgency_{kj}=\frac{TWSlack_{kj}}{TWWidth_j+\epsilon}
\]

\[
DeadlineGap_{kj}=b_j-t_k
\]

## 17.3 Capacity

\[
CapSlack_{kj}=Q-(anchorLoad_k+d_j)
\]

## 17.4 Return

先作为 soft feature：

\[
ReadyAfterService=start_{kj}+s_j
\]

\[
ReturnSlack=b_0-(ReadyAfterService+travel(j,0))
\]

只有 audit 证明 sound 后才进入 hard mask。

## 17.5 Customer scarcity

\[
m_j=|\mathcal V_j^{feasible}|
\]

建议归一化：

\[
m_j / \max(1,n_{candidateVehicles})
\]

[RISK] `feasible` 必须指**sound candidate mask**，不能把 learned top-k 当 feasibility。

## 17.6 Vehicle coverage

\[
n_k=|\mathcal C_k^{feasible}|
\]

## 17.7 Travel regret

\[
d_1(j)=\min_k travel_{kj}
\]

\[
d_2(j)=2ndmin_k travel_{kj}
\]

\[
TravelRegret_j=d_2-d_1
\]

只有一个 feasible vehicle 时，不要让 `d2=inf` 进入网络。推荐：

```python
travel_regret = clipped_large_value
single_vehicle_flag = 1
```

同时显式加 `single_vehicle_flag`。

## 17.8 Slack regret

同理比较最佳/次佳 TW slack；要定义“best”方向一致。

建议：slack 越大越好，因此：

```text
best_slack - second_best_slack
```

不要一处用 slack，一处用 negative slack，导致符号混乱。

## 17.9 global context

```text
n_pending / N
n_candidate_vehicles / K
mean feasible_vehicle_count / K
min feasible_vehicle_count / K
progress = clock / horizon
```

所有统计只基于当前 filtration。
