## 0.1 当前已经确认的核心事实

### R1.7：MaskCO learned preference 有独立价值

| 方法 | Cost | 关键结论 |
|---|---:|---|
| NN (H1) | 27.66 | heuristic incumbent |
| H2 raw | 28.20 | real learned logits |
| H3 raw shuffle | 30.19 | shuffled control |
| H2-G | 27.10 | learned + guarded |
| H3-G mean | 27.69 ± 0.07 | shuffled + guarded |

关键机制证据：

- `H2 < H3`：真实 learned logits 比 shuffled 好约 6.6%
- `local_first_divergence = 61.3%`：模型强烈进入决策
- `H2-G < H1`：guarded learned system 比 NN 改善约 2%
- `H3-G ≈ H1`：beam + guard 单独没有检测到正增益
- 因而当前 2% practical gain 主要来自 learned structured preference

### R1.7-4：Guard 安全，但 cost-myopic

当前已知：

- `accepted service_worse = 0%`
- cost-myopic 显著
- rejected opportunity 显著
- 当前 guard 可以继续作为 service-first safety net
- 但不应被当作最终 value-optimal selector

### B0：主瓶颈是 fleet allocation，不是 sequencing

| Policy | Cost | Complete |
|---|---:|---:|
| NN | 27.41 | 96.1% |
| OR-fixed | 27.76 | 96.5% |
| OR-joint | 22.79 | 100% |

当前主结论：

- `G_seq ≈ 0`
- `G_fleet ≈ 17.9%`

即：

> 冻结 customer→vehicle ownership 后，精确 sequencing 基本没有收益；释放 mutable ownership 后，fleet-level reallocation 带来巨大收益。

> **注意**：如果 B0 的 return-depot TW 语义一致性修复尚未正式重跑，应在最终归档前再做一次 clean rerun。该修复预计不会改变“fleet allocation 主导”的方向，但正式论文数字必须以 clean rerun 为准。

# 1. 当前方法主线重新定义

从现在开始，不再把项目理解为：

```text
MaskCO
→ per-vehicle edge score
→ Resource Beam
→ Guard
```

而重新定义为：

```text
Visible Dynamic Instance
        │
        ▼
Causal MaskCO Encoder
        │
        ├── Route Reconstruction Head
        │      └── 保留原 MaskCO masked reconstruction
        │
        └── Fleet Assignment Head
               └── S(k,j | FleetState)
        │
        ▼
Sound Feasibility Candidate Generation
        │
        ▼
Joint Mutable-Request Assignment
        │
        ▼
Per-Vehicle Feasible Routing
        │
        ▼
Fleet Feasible Candidate
        │
        ▼
Service-First Guard
        │
        ▼
Commit Before Next Recourse Event
        │
        ▼
StrictOnlineEnv
```

核心决策函数：

\[
S_\theta(k,j\mid \mathcal F_e,FleetState_e)
\]

回答：

> 在当前严格可见、不可预知未来的 FleetState 下，客户 `j` 应该由车辆 `k` 接管吗？

---

# 2. 为什么仍然必须使用 MaskCO

当前证据不是“MaskCO 不行”，而是：

> **原 MaskCO 的 edge decoder 语义不适合 fleet assignment。**

原始 head 学的是：

\[
L_{ij}
\]

语义近似：

> 节点 `i` 后面应不应该接节点 `j`。

Joint Fleet 要解决的是：

\[
S_{kj}
\]

语义是：

> customer `j` 应不应该分给 vehicle `k`。

因此正确路线是：

> **保留 Causal MaskCO Encoder，新增 Fleet Assignment Decoder。**

而不是放弃 MaskCO。
