## 4. 待命与密度杠杆的解释边界

standby=100 当前只在影子估算的 est_used 上加 `100*cooling_share`（约 372.09 kWh）；不是实际一次待命操作，也不直接进入效用的货币成本。真实已耗能耗已累加，再加全天常数预留，可能重复覆盖已经发生的制冷。需记录时钟、已耗、剩余待命、两分支未来接单量与 margin，才能判断是未来资源机会成本被修正，还是粗糙阈值改变了接单。

S3-2 的 density 在抽样场景内部按 `REV/边际能耗` 排序，属于场景内带后见之明的近似续策；外部真实在线决策仍仅用抽样场景，因此不是读取真实未来。但该顺序不是严格未来逐揭示策略，不保证分布排序在部署中保留，也不是完整利润密度（未纳入拒绝罚和增量燃油）。先按原声明报告，再另立机制对比，不看收益后改排序公式。

S3-2 的单因素效果应对照 **同修订版 C1 reveal**；不能对比 R3 前的 L2b2 来归因密度。这是身份/归因修正，不修改 cond−uncond 的主判据。S3-1 未稳健，不把 standby=100 自动合并进 S3-2。

S3-3 应准确描述当前代码：终局真实影子能耗超预算目前不扣罚，未来选单用 est 硬门槛；未来拟加的是终局超额量连续价格。不得恢复全场景 −1e6 的预算惩罚。S3-4 若 K 固定为 10，不应声称“廉价搜索能多试场景”，应检验在同 K/时限下的质量与耗时。

## 6. MaskCO 方法的最低交付与论文证据

建议方法闭环：**可见历史与资源状态 → MaskCO 表征 → 数量与联合未来场景建模 → 部分掩码迭代重构 → 同下游接/拒决策 → 冻结承诺与 C0 硬认证 → 实际效用**。

原 MaskCO 的核心是从参考解学习结构依赖，并在推理时通过反复掩码和再生成改善解；MaskGIT 的迭代机制则令后续生成条件于前轮结果。当前脚本一次前向并独立采样不能替代这些部署机制。[MaskCO 官方论文摘要](https://proceedings.iclr.cc/paper_files/paper/2026/hash/d85816bf41e54d9b0847e02249f4fcc6-Abstract-Conference.html)、[MaskGIT 原论文](https://arxiv.org/abs/2202.04200)。这是对当前迁移设计的要求，不是已实现成果。

最低实现包：

- 可变数量建模及合法未来时间支持；数量不能在采样后靠丢弃过去 token 任意变化。
- 训练使用部分掩码未来集合，推理按冻结可见历史、多轮生成/保留/重掩码推进；集合槽的对称性、NULL 和计数联合分布要验证。
- PAD 与 MASK 分开，注意力隔离 padding；每样本槽数与推理一致；连续需求严格服从 token 需求桶。
- 输入时钟与公开资源状态，并区分总预算和剩余预算；未来需求分布不能被本方资源状态错误解释为外生需求变化。若做决策感知场景选择，须显式区分分布预测与价值导向选样。
- 同架构、同冻结状态的预训练/随机对照；当前 EncoderMLP 不是随机 CVRP encoder。冻结 hash 已实现，但不能取代架构公平。
- 训练前说明资源状态的来源：历史需求切片没有车队标签，若需资源条件则用训练日的因果策略回放采集，不引入开发/最终测试状态。
- 比较经过开发选择的强条件历史采样器、读取当天可见前缀的显式预测器；当前 explicit_feat 主要只按时钟取均值，强度不足。
- 主报相同下游、K 与时间预算下 MaskCO−最佳条件非学习方法；再报告预训练/随机、单步/迭代、资源条件消融。生成分布拟合改善与在线效用改善分别展示。

系统优势还应包含一个信息与决策规则更匹配的强基线，例如相同场景下的可部署强路由 rollout 或成熟动态接单策略。当前 OR/PyVRP 是 myopic、距离目标、完整覆盖后认证，公平物理约束不等于已经覆盖最强随机决策对手；PyVRP 较差不能无证据归因“约束更严”。

当前 v2 品质在合法时域内不绑定，论文冷链机制宜围绕多温区制冷能耗与不可撤销动态接单。品质驱动结论另需有业务依据的独立任务与证据，不能为了正结果调整当前合同。
