## 1. 唯一假设（可证伪）

```
H_C2M:  四方（M1-a / M1-b / C0 / 安装方）的**实际消费数据**均可由
        同一份**合法 strict-online 冻结状态**经**可重算投影**导出，
        且拒绝路径不需要读取任何未揭示订单的属性。
```

**可证伪条件**：若任一方在隔离环境中**必须**读取未揭示订单属性才能完成该方认证，
或必须修改冻结历史对象，或投影的**内容**无法被独立重算 ⇒ H_C2M 被推翻。

> **主对照 = 现有 C1"四方报告摘要相同"判据。**

## 3. 判据

| # | 判据 | 通过条件 |
|---|---|---|
| **M-C1** | 冻结状态合法性 | 冻结体的可见集合由**权威 `visible_ids`** 决定；投影中不出现未揭示订单的任何属性（坐标/需求/时间窗/温区） |
| **M-C2** | 身份不摄入未来 | 可见身份**只**覆盖可见订单；不得"先用未来属性生成身份，再隐藏明文" |
| **M-C3** | P-a…P-d | 来源标签、内容自洽、**独立重算**、strict-online 可见性四项全过 |
| **M-C4** | 容差有据 | 揭示容差必须等于**事件引擎自身的比较式**（`reveal_time <= clock + 1e-6`，`strict_online_env.py:490/:514/:538`），不得自造 |
| **M-C5** | 真实认证逻辑 | M1-a / C0 用**真函数**；M1-b 若不可达则保留 `NOT_EXECUTED_REAL_CERTIFIER`，**不得**声称四方已验证 |
| **M-C6** | C0 非空执行 | 至少一次**非空车队 + 非空待服务路线**，动态记录真实订单索引 |
| **M-C7** | 未声明依赖 | 经 helper/回调的传递读取必须被报告；声明不得只列直接属性 |
| **M-C8** | 合法同内容 | 内容相同、对象不同 ⇒ 不得误拒 |
| **M-C9** | 资格阻断 | G-2 未合格 ⇒ `JOINT_NOT_CERTIFIABLE`；身份一致不产生物理资格 |
| **M-C10** | 安装方 mock | 只 mock，无真实写入；归档绑定安装前身份 |

## 4. 负控（**先登记，后运行**）

| 编号 | 注入 | 预期 |
|---|---|---|
| **N1** | 四方报告摘要相同，一方实际消费不同状态 | C1 `PASS`，绑定判据 `REJECT` |
| **N2** | 投影来源正确、内容篡改且自报摘要同步更新 | `REJECT`（P-c） |
| **N3** | 未揭示订单被错误加入可见集合 | `REFUSED: HIDDEN_FUTURE_ATTRIBUTE_REQUESTED` |
| **N4a** | 揭示时刻 **= clock + 5e-7**（引擎容差内） | **允许**（依据 M-C4 的引擎比较式，**不是**自造容差） |
| **N4b** | 揭示时刻 **= clock + 2e-6**（超引擎容差） | `REFUSED`（P-d） |
| **N5** | 认证前后冻结状态被改 | `REJECT`（复算不一致） |
| **N6** | C0 非空路线实际索引未揭示订单属性 | 记录并 `REFUSED`；**不得**为完成认证而放行 |

| **N9** | 内容相同、对象不同 | 允许通过 |
| **N10** | G-2 资格缺失 | `JOINT_NOT_CERTIFIABLE`（不产生可安装联合认证） |

## 6. Go / No-Go

| 结论 | 条件 |
|---|---|
| **GO** | 四方实际消费均有可信冻结来源与可重算投影证据；不存在未说明的必需读取路径；全部负控符合预声明；不产生生产安装资格 |
| **NO-GO** | 任一方无法证明实际消费对象来源；出现隐藏未来读取；必须修改冻结历史；或 M1-b 不能完成**所需真实入口验证**（"所需"= 若 C2 主张四方一致性则其绑定必须可验） |

**NO-GO 不触发自动增补开发，不得追加测试直到通过。** 交付裁决后停止 C2 扩张。
