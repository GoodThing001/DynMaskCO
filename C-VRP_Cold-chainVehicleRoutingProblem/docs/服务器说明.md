## ⚠️ 关键问题 & 修复建议

### 🔴 问题 1：JAX 没有 GPU 支持（最严重）

JAX 检测到 GPU 但 **没有安装 CUDA-enabled jaxlib**，所有计算回退到 CPU。

```bash
# 当前状态：JAX CPU-only
JAX version: 0.6.2
Devices: [CpuDevice(id=0)]    # ← 应该是 [CudaDevice(id=0), CudaDevice(id=1)]
Default backend: cpu           # ← 应该是 gpu
```

**修复**：
```bash
# 卸载当前 JAX，安装 CUDA 版本
pip uninstall jax jaxlib -y
pip install "jax[cuda12]"==0.6.2

# 验证
python -c "import jax; print(jax.devices())"
# 应该看到: [CudaDevice(id=0), CudaDevice(id=1)]
```

> ⚠️ CUDA 13.1 + JAX 0.6.2 的兼容性需要验证。如果 `jax[cuda12]` 不兼容 CUDA 13.1，可能需要安装 CUDA 12.x 工具包或降级 JAX。

### 🔴 问题 2：NumPy 2.x 破坏性变更

NumPy 2.2.6 有大量 API 变更，MaskCO 原始代码基于 NumPy 1.26.4。

**修复**：
```bash
pip install numpy==1.26.4
```

### 🟡 问题 3：pybind11 未安装

`lib/Makefile` 编译需要 pybind11。

**修复**：
```bash
pip install pybind11
# 验证
python -m pybind11 --includes
```

### 🟡 问题 4：版本升级兼容性风险

JAX/Flax/Optax/Triton 版本均高于原始要求。Flax 0.10.4→0.10.7 的 NNX API 可能有变化。建议：
1. 先尝试用当前版本运行（大多数 API 向后兼容）
2. 如果出问题，再降级到原始版本

### 🟡 问题 5：GPU 显存紧张

两台 GPU 同时被其他进程大量占用。建议：
1. 训练前用 `nvidia-smi` 确认显存空闲
2. 用 `export XLA_PYTHON_CLIENT_MEM_FRACTION=0.5` 限制 JAX 预分配（两台 GPU 各分一半）
3. 必要时与 `cxp` 环境用户协调 GPU 使用
