## 2. 阻断性缺陷清单（NUM-01）

> 判定标准：**该缺陷不修，则该包的要素①/② 无法成立**，与"写得不够细"不同。

### N-B1 ·（阻断）证明对象未分层 —— 实数物理 / 参考语义 / 执行器 / 认证链

草案说"用独立的**新数值合同** C′ 建立完整认证"，但从未说明 C′ 的**证明落点**。仓内事实要求分成四层：

| 层 | 定义 | 仓内可证性（实测） |
|---|---|---|
| **L_real** | 精确实数下的热模型递推 | ✅ 可证。`q3_strict_float_experimental.py` L34-36 的 **L-A**：`1/(L_K + tail) ≤ exp(-x) ≤ 1/L_K`，纯 `Fraction`，**"assumes NOTHING about the platform's libm"**（L15-16） |
| **L_ref** | 参考语义（有理括区 + 精确舍入模型） | ✅ **已实现**（同上模块，`_TAYLOR_TERMS=32`，域 `h*dt ≤ 4.8`） |
| **L_exec** | 生产执行器 `coldchain_state.transition_segment`（float64 + 平台 `math.exp`） | ❌ **不可证**。该模块 L25 自述其输入要求是"a bound on how far the EXECUTOR's `math.exp` is from the true"——**即 κ** |
| **L_cert** | 决策时刻的认证链（只用可见信息） | ⚠️ 可对 L_ref sound；对 L_exec 需 κ |

**结论（阻断）**：在不修改执行器字节的前提下，C′ **只能证明 L_ref**。
草案 §0 写的"S3 的核心引理只约束'对所有分段成立'"这一论证**是正确的，但不够**——即使不接受全分段，**只要有任何一个分段经 L_exec 求值，就需要该分段的执行器误差界**。因此"改变问题"并不自动消除 κ，只把它从"全局"缩小为"计划内分段"，而后者仍无界可得。

**必须改写为**：C′ 明确声明为**参考语义层的认证**，并把"参考语义 → 执行器"的残差登记为一个**显式未证明项**（不是省略、不是用 0.4963 ulp 的实测值顶替）。S3 row[2] 的 `reading` 已经把这个禁忌写死：*"a finite grid can FALSIFY a kappa claim; it can never establish one"*。

### N-B2 ·（阻断）唯一主对照 `C_restrict` **没有独立成立的安全保证**

草案把 `C_restrict`（"拒绝一切含短 gap 的计划"）当作"不投数值投入也能安全"的基线。**这不成立**：

短 gap 只对应 S3 的**一项**误差（`T-skip`，`t_skip_budget_c = 5.7097e-05`）。
而误差预算**共六项**（`controls.json` row[10]：`sum_of_parts_equals_total = true`，总计 `5.7101e-05`），其中
**`T-kappa` 是绑定项**——row[7] 明确：删掉 `T-kappa` 后同一计划会从 `NOT_CERTIFIABLE` 变成 `PROVED_CONDITIONAL_F`（`drop_effects/T-kappa = 1.9099e-10`）。

⇒ **拒绝短 gap 只消掉 `T-skip`，不消掉 `T-kappa`。** `C_restrict` 因此**不是**一个对 L_exec sound 的认证器，它只是"少了一类未建模分支的 R-level 检查"。

**这使草案的整个比较框架失效**：若 C_restrict 不 sound，则 `Δ_rate = rate(C′) − rate(C_restrict)` 比较的是"两个不同强度的不安全检查"，不能支撑任何关于"新数值合同有无价值"的结论。

**必须改写为**：`C_restrict` 也要**显式声明其证明落点**。合法版本只有两种：
- `C_restrict(ref)`：对 L_ref 的受限域认证——但它与 C′ 的差别就只剩"是否接受短 gap"，而 L_ref 层本来**根本不需要**短 gap 限制（有理括区对任意正长度都成立）。⇒ **该对照在 L_ref 层是退化的**；
- `C_restrict(exec-free)`：只认证**求值路径不含 `exp` 的计划**——这是一个真正可能对 L_exec sound 的域（见 §4 的候选清单），**但它的域极窄，且必须逐条证明"无 exp 求值"**。

**建议**：把主对照改为 `C_restrict(exec-free)`，并把"短 gap 拒绝"从对照降级为一个**敏感性旋钮**。

### N-B3 ·（阻断）"独立的新数值合同"语义含混，可能被误读为改物理合同

草案 §0 写"通过独立的新数值合同 C′"，未限定其**改动范围**。本仓 `objective_profile.json` 的 `contract_hash`、`coldchain_contract.py` 的物理参数、`eps_f_c = 0.001` 都是**冻结值**。若 C′ 被理解为"换一组物理/品质/能耗参数"，那就是**放宽约束**——正是用户明令禁止的。

**必须改写为**：C′ 是**认证语义层（certification-semantics）** 的合同，**不改**：物理参数、`eps_f_c`、温度上下界、品质阈值、能耗预算、`_EPS` 跳段阈值、`n_max` 公式。C′ 只规定**如何判定与如何记账**。

### N-B4 ·（阻断）认证范围未声明

草案从未说明 C′ 认证的是哪种范围。三种互不等价：

| 范围 | 含义 | 代价 |
|---|---|---|
| **S-1 有限计划集** | 只对这批评审过的计划 | 最弱；不可外推到"某个决策规则总能被认证" |
| **S-2 策略类** | 某一**声明过的决策规则**产生的所有计划 | 中等；需要对该规则的输出域给出刻画 |
| **S-3 全计划** | 任意合法计划 | 最强；S3 已证明此路 NO-GO |

**必须改写为**：明确选 S-1 或 S-2，并声明**不得**把 S-1 的结果表述为 S-2/S-3。默认建议 S-2（对 `C0ReserveReplanner` 风格的声明规则），因为 S-1 无法支撑"可行"这个包名。

### N-B5 ·（阻断）证书没有收件人

`compose_certification` 目前**只有测试调用**（`CERTIFIER_WIRING_GAP`），生产安装入口不消费任何证书。因此即使 C′ 完全成立，其结论也只能是 `DIAGNOSTIC_ONLY`。

**必须改写为**：要素⑦ 增加 `certificate_consumer` 项，取值为 `DIAGNOSTIC_ONLY`（当前唯一合法值）或指定具体的生产消费者（需另立预声明）。**不得**用"完整认证链"这种措辞暗示已有消费者。

### N-B6 ·（阻断）三条路线的证明义务未分解，且其中两条**塌缩**

草案把 A/B/C 当三条独立路线。实读后的真实关系：

| 路线 | 草案的设想 | 实读后的真实义务 |
|---|---|---|
| **A 有理区间** | 认证全在 `Fraction` 里做 | ✅ 可行，**但只到 L_ref**；要接 L_exec 仍需 κ ⇒ **A 单独无法给出执行器保证** |
| **B 双执行器一致** | 证明 ref 与 exec 差异 ≤ 可计算界 | ❌ **塌缩为 A + κ**：差异的 `exp` 部分正是 κ |
| **C 受限域** | 只认证"门后无短 gap" | ❌ **等价于 `C_restrict`**，因此继承 N-B2 的全部问题 |

**必须改写为**：不再把 B/C 当"替代路线"，而是当作 **A 的两个附加条件**：(i) 需要一个 κ 或一个 exec-free 域；(ii) 需要声明范围。**A 是唯一有实质内容的路线。**

### N-B7 ·（阻断）S3 复用边界未写明

草案多处引用 S3，但没写明**哪些可复用、哪些禁止**。实读后应固定为：

- **可复用（已证、可 import 逻辑而不改字节）**：L-A 括区；`T-skip` 修正式；六项预算分解；S2 的"Ast 证明判定路径无 `exp/log/pow`"；`n_max = 1 + 2*max_iter + 2`（运行时重算）；S1 的实值括区。
- **禁止复用**：S3 的 24 个计划作为通过证据；`f_level_established`；任何"实测 ulp"作为界。

## 3. 阻断性缺陷清单（OPP-01）

### O-B1 ·（阻断）唯一主对照选错

草案把"同等预算的随机掩码重构 `M_rand`"当**唯一主对照**，把 `distance+SGBS` 降为"强制并列报告臂"。
这使得**"相对强非学习方法是否有贡献"这个问题从未被主对照检验**——而它恰恰是包名的字面意思。

**按用户裁决修订**：

| 角色 | 臂 | 用途 |
|---|---|---|
| **主对照（贡献层）** | **`distance + SGBS`** | 决定 H/U 两层以及 M 层的**贡献**结论 |
| **机制消融（机制层）** | 同等预算的**随机掩码重构** `M_rand` | 只用于回答"增量是否来自**掩码选择**" |
| 参照臂 | `R`（regret-2）、资源机会成本规则臂、clairvoyant（**上界参照，不得在线**） | 强制并列报告 |

`M_rand` **不得**再被称为"唯一主对照"；它是 `M_learnt` 的**配对消融对照**。

### O-B2 ·（阻断）**历史终局实验的对照不是 `distance+SGBS`，而是 `distance-greedy`**

草案 §1.1 用 D1 的 `gap_exh_vs_dist_sgbs = +0.003245` 作为"强非学习对照"的依据。实读：

- `run_terminal_headroom.py:121` 用的是 `_dist_greedy_repair`（`run_headroom_census.py:138`），其实现是**按 `incremental_distance` 排序后取第一条合法动作**（L145-147）——**没有 beam、没有 SGBS**。
- `run_terminal_headroom.py` 的 row 里只有 `terminal_gap_exh_vs_dg`，**没有** `vs_dist_sgbs` 的字段（L134-158）。
- `headroom_census` 的 `gap_exh_vs_dist_sgbs` 之所以存在，是因为它支持 `--ref-per-state`（L202-203）**合并外部 SGBS 结果**——即它需要额外输入，而终局脚本没有这个输入。

⇒ **"终局无头腔"这个历史结论，是在一个比当前最强非学习基线更弱的对照下得到的。**
它的否证范围因此**窄于**草案的表述。**这恰好构成本包重新测量的正当理由**，而不是重复劳动。

**必须改写为**：§1.1 的读数表逐行标注**该行实际使用的对照**（`dist_greedy` 还是 `dist_sgbs`），并写明"终局层尚未在任何强对照下测量过"。

### O-B3 ·（阻断）`exhaustive` 优化的是**可见目标**，不是终局目标

`_exhaustive_repair`（`run_headroom_census.py:152-177`）在叶子节点调用 `_eval_plan(vis, P, ...)`（L165），
即在 **`J_vis`（仅可见信息）** 上取最小值（L167-169）。
`_eval_plan` 又用 `evaluate_visible_plan`（L132）。

⇒ 历史"terminal headroom"测的是 **"`J_vis`-最优修复计划的终局后果"**，
**不是** "终局最优计划"，也**不是** "完全信息 oracle"。

草案 §1.1 / 要素① 把它写成"完全信息枚举修复"，**措辞误导**：它既不完全信息，也不以终局为目标。

**必须改写为**：统一命名为 **`J_vis` 最优修复（近视 oracle），终局评估**。并补一条限制：
该量**不是**终局乐观上界，因此 `terminal_gap` 为负时**不能**推出"终局没有更好计划"。

### O-B4 ·（阻断）符号约定未写公式

草案只说"−0.0055 表示近视头腔不存活"，未给定义式。实读（`run_terminal_headroom.py:141-146`）：

```
terminal_headroom_exh = J0_terminal − J_exh_terminal      # 正 = 该修复改善了终局
terminal_headroom_dg  = J0_terminal − J_dg_terminal
terminal_gap_exh_vs_dg = J_dg_terminal − J_exh_terminal   # 正 = exhaustive 更好
myopic_gap_exh_vs_dg   = J_dg_myopic − J_exh_myopic
```

`J` 越小越好（`heldout` 里 J0 1.1594 → R 1.1237 被记为改善）。因此：
- `terminal_headroom_exh = −0.005502` ⇒ **修复使终局变差 0.0055**（不是"零"，是**负**）；
- `terminal_gap_exh_vs_dg = +0.003876`（CI [−0.001124, 0.012038]）⇒ **方向上 exhaustive 更好，但未建立**。

**必须改写为**：要素③ 里给出上述四式与"越小越好"的声明；`headroom` 与 `gap` 两个名字**不得混用**。

### O-B5 ·（阻断）"CI 跨零"被当作统计学否证

草案要素① 写"终局差 ≤ 0，或 CI 跨越 0 → `H_FALSIFIED`"。
**CI 跨零只是"未建立"，不是"证明为零"。** 要在统计上主张"不存在改善"，需要**等价性检验**（TOST），即需要一个**事前声明的等价界 `δ_eq`** 与足够功效。

**必须改写为**：五值判定

| 判定 | 条件 |
|---|---|
| `ESTABLISHED` | 点估计 ≥ δ 且 CI 下界 > 0（δ 为事前登记的效果门） |
| `NOT_ESTABLISHED` | 未满足上一条（**含 CI 跨零**）；**不**允许表述为"不存在" |
| `FALSIFIED` | 仅在**事前声明 `δ_eq`** 且 CI **完全落在** (−δ_eq, +δ_eq) 内时使用 |
| `INCONCLUSIVE_UNDERPOWERED` | CI 宽于 2·δ_eq，既不能建立也不能否证 |
| `BLOCKED` | 未能运行 / 身份不符 / 数据缺失 |

### O-B6 ·（阻断）U 层捕获率的零/负分母未定义

草案：`捕获率 = (J(dist+SGBS) − J(R)) / (J(exhaustive) − J(R))`。三个未定义情形：

| 情形 | 后果 | 必须的处理 |
|---|---|---|
| 分母 = 0（`J(exhaustive) == J(R)`） | 除零 | 记 `NOT_APPLICABLE_NO_HEADROOM`，**留分母**，不进均值 |
| 分母 < 0（exhaustive 比 R 差） | 率 <0 或无意义 | 记 `HEADROOM_NEGATIVE_NOT_APPLICABLE`，**不得**计算率 |
| 用臂的均值相除 | 与逐状态配对的率不一致 | **必须逐状态**算率，再按实例聚类聚合 |

此外还需定义**裁剪**：率 > 1 时是否记为 1。建议**不裁剪**，而是单列"超捕获"计数。

### O-B7 ·（阻断）16 个实例的 bootstrap 不可靠，历史 CI 宽度大于效应本身

`run_terminal_headroom.py:173-181` 的 `_ci` 对**每实例均值**做 2000 次 bootstrap，而实例数 = **16**。
`terminal_gap_exh_vs_dg` 的 CI 宽度约 **0.0132**，而点估计只有 **0.0039**；`terminal_headroom_exh` 的 CI 宽度约 **0.0165**，点估计 **−0.0055**。

⇒ 用这种 CI 做"等价性"主张**在结构上不可能**。任何 `FALSIFIED` 判定都必须先说明功效，否则只能落在 `INCONCLUSIVE_UNDERPOWERED`。

**必须改写为**：要素③ 增加"功效与最小可检测效应（MDE）"一节；实例数不足时**只能**用 `NOT_ESTABLISHED` / `INCONCLUSIVE_UNDERPOWERED`。

### O-B8 ·（阻断）容量容差造成可行域混杂（实测三分裂）

| 家族 | 判据 | 位置 |
|---|---|---|
| A-v1 四臂（`C0ReserveReplanner`） | **`l > capacity − 1e-4`** | `run_exp_energy_c0.py:253`、`:574` |
| 旧四代（`ReserveReplanner` / `AcceptRejectReplanner`） | **`+ 1e-6`** | `run_exp_reserve.py:165`、`run_exp_energy.py:319`、`run_exp_capacity.py:309`、`run_causal_accept_gate.py:218` |
| H/P/U 的可行判定（`evaluate_visible_plan`） | **`+ 1e-6`** | `visible_state.py:177` |
| 路线级 certificate（`action_contract`） | **`+ 1e-6`** | `action_contract.py:190` |

**含义**：`distance+SGBS` 与历史 headroom 家族工作在 **`+1e-6`** 域（**包含**恰好满容量的计划）；
A-v1 的滚动臂工作在 **`−1e-4`** 域（**排除**它们）。
若 P1 把这两族放进同一比较，**算法质量差与可行域大小差会被混在一起**。

**必须改写为**：要素② 增加"容量口径统一"条款，三选一并全臂统一，同时报"恰好满容量计划"的接受计数作为诊断：
(a) **全部统一到 `−1e-4`**（最保守，推荐）；
(b) 全部统一到 `+1e-6`（需接受边界载重执行期风险）；
(c) 两口径都跑、声明一个主口径。
**并且**：历史对照数字的容量口径须标为 `CAPACITY_CONVENTION_UNVERIFIED`（`run_sgbs_fixed_state.py` 内**没有** capacity 判据，判定发生在 `visible_state`/`action_contract`，实际口径为 `+1e-6`）。

### O-B9 ·（阻断）P 层数据隔离与"样本外决策价值"未定义

草案只有一句"实例级留出"。缺三项：

1. **三段隔离**：train（拟合）/ calibration（选阈值）/ **confirmation（只看一次）**，且三段**实例种子不相交**；
2. **历史状态不得进 confirmation**：D1–D7 的 32 个状态只能作开发；
3. **"样本外决策价值"必须与"相关性"分开**：
   - 预测指标：Spearman / MAE；
   - **决策指标**：按探针分数做选择后，confirmation 上的 `accepted` / `closed_loop` 实现增益。
   **相关性为正不蕴含决策价值**（历史 `myopic_gain_vs_terminal_gain` Spearman 只有 **+0.1363**，且 `structural_only` 为 **−0.0733**）。

另外必须继承历史限制：`value_predictability_cal` 的自述是 *"instance-level split, NOT independent-sample split"*（`value_predictability_cal__summary.json` 的 `split.note`）——**不得**把它当作独立确认。

### O-B10 ·（阻断）M 层未做因子分解，四项贡献混在一起

草案只对比 `M_learnt` vs `M_rand`。需要分离**四**个来源：

| 因子 | 水平 |
|---|---|
| `mask_selector` | learned / uniform-random / distance-guided |
| `decoder` | MaskCO decoder / greedy（同架构） |
| 资源特征 | on / off |
| 搜索预算 | 等墙钟（不变量），另设离线敏感性 |

**主对比**固定 decoder、资源特征、预算，只变 `mask_selector`；其余因子各出一个**边际效应**表。
否则"M 层过"无法归因到"掩码生成"。

### O-B11 ·（阻断）1×/2×/4× 预算的在线合法性未标注，且 1× 须用最坏值

strict-online 决策时钟是 **10 s**。因此：

| 预算档 | 是否在线合法 | 允许的用途 |
|---|---|---|
| **1×（≤10 s，最坏值）** | ✅ | 唯一可用于在线结论的档 |
| **2×（20 s）/ 4×（40 s）** | ❌ **超出时钟** | **只能**作 `OFFLINE_SENSITIVITY_ONLY`，**不得**称为在线结果、不得用于部署表述 |

并且 1× 的达标判据必须是**最坏值**，不能是中位值——S3 `G-T2` 已把这条写进 `reading`：
*"a median of isolated timings is not a worst-case guarantee; the honest status of G-T2 is UNMEASURED, not PASS"*。

## 4. NUM-01 最小修订方案

### 4.1 要素① 重写（证明对象分层）

把 H1 拆成**两条互不蕴含**的命题，分别可独立否证：

### 4.2 要素② 重写（主对照）

  4. 地板钳制到 0 之后的段。
- **短 gap 拒绝**降级为敏感性旋钮，不再作为对照定义。
- 若"无 exp 域"为空或极窄 ⇒ **C_restrict 退化 ⇒ 本包 NO-GO**（见 §6）。

### 4.3 要素③ 重写（判据）

### 4.4 要素⑥/Go-No-Go

| 前置 | 适用于 H1-A？ | 适用于 H1-B？ |
