## 9. Verdict 后的冻结分支

- `GO`：确认当前单客户动作空间具有正式 sequential headroom，不进入 lookahead；冻结本次报告与动作合同。下一阶段为**独立 O0-CC VAL**（VAL GO 后才进入 M0），而不是直接开始 M0 teacher 构造。该结论仍不等于 learned method 优于基线，VAL/TEST 保留给冻结后的 M0/M1。
- `EVIDENCE_INSUFFICIENT`：先按预声明方式报告效应量和 cell 异质性，不在 DEV-GATE 上调参；若 local 可靠且 GO，进入独立数据上的 depth-2 lookahead 开发，否则转入动作空间诊断。
- `NO_HEADROOM`：若 local GO，判为局部动作存在但 greedy composition 失败，进入 depth-2 lookahead；若 local 也无 headroom，才检查 two-customer relocate/exchange 或 batch mask action。
- `SERVICE_GATE_FAIL / PROTOCOL_ERROR`：不解释 cost，保存现场并定位协议；任何影响 baseline、objective profile 或计算身份的修复都要重新冻结并从空目录重跑。
