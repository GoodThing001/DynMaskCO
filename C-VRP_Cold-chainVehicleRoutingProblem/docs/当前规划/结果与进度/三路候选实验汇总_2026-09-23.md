## 三路结论

1. **容量感知接受**：过度承诺可修——接受判据加"车队能否贪心服务该单"（collective 容量/TW oracle）后，违约 9→4、feasible 0.85→0.933、利润增量保住。残单仍是晚揭示单（collective oracle 是贪心非精确）。
2. **物理路由能耗**：头腔存活（+247.8），但 accept-time 的 dwell 估计（历史 mean_dwell）与终局路由能耗不匹配 → myopic 预算违约 36/40（"贪便宜常温单"在物理能耗下回火，常温单在舱最久）。需距离感知的 dwell 估计。
3. **冻结 encoder**：冻结-H 状态 k-NN 小胜 3 维计数 k-NN（+12.2），几乎打到 clairvoyant；随机投影 +6 说明部分增益只是维度，encoder 结构独立贡献 ~+6。**学习头失败**（MLP 学 rem→λ 过保守，利润 1105），与 D6"终局增益不可预测"一致。

## 诚实边界

- ① 已复跑验证；②③ 是并行 agent 自述（脚本+结果文件已核对存在，未独立复跑）。
- 能耗除②外仍是逐单 E_class 简化；物理能耗/高维状态/掩码生成未合并成一条完整管线。
- 冻结 encoder 增益小（+12，n=40 无配对 CI），需更大 n 确认。

## 对主方法的判断

主方法（掩码生成器）核心风险未消除：**冻结表征增益小、学习生成难**（MLP 失败）。但"容量感知接受"和"物理能耗"两个方向是实的、可写的。下一步候选：①把容量感知接受 + 物理能耗合并成一条完整管线；②上真正的掩码生成（而非 MLP 回归）；③加大 n 复验冻结 encoder 的 +12 增益。
