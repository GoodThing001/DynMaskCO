## 4. padding、预算与复现边界

1. 本次 M-pre/M-trained 是固定容量 Nv_max=51、M_max=2048 的实际运行版本。它们的 J 是该版本执行轨迹的评价结果，不能未经对照直接扣除某个“近似误差”来还原另一个版本。
2. 约 1e-5 的局部分数差可能在近并列处改变 argmax，继而改变整个后续状态和轨迹。没有已核实的配对轨迹证据，不能推出终局 J 的误差一定限于 0.01–0.02，也不能宣称当前结论已对这一扰动稳健。现有 diag_padding_lossless.py 仅比较固定状态分数，不能给出闭环 J 的误差上界。
3. 无 padding 不是精确真值，也不保证字节级可复现；其输入形状、编译与耗时变化还可能影响限时搜索机会。若未来确需核查，应另立固定 checkpoint/实例/策略/预算的数值敏感性对照，并区分固定动作机会的数值差异与限时部署差异。目前不启动该对照。
4. B/R 可以表述为本次产物及已回传对照中的数值复现，不能称统计意义上的“精确结果”；它们仍是有限开发实例的估计。
5. 当前源码在候选之间检查 budget_s，并不意味着每次重规划严格不超过 4 秒。保存 summary 缺少各方法完整事件耗时、编译、超时及停止原因记录；本次不据此声称严格全链路等墙钟或速度优势。记录中的 M-trained 累计 replanner 用时 CAL=870.6279s、DEV=790.0312s，不能当作单事件时延。
