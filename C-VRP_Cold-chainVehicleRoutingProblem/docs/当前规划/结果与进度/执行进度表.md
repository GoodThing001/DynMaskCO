## 2.1 历史启动路线与后续论文路线

> **适用范围（2026-09-18）**：以下 R1–R3 及 [R2→M1 执行计划](../工程实现/R2到M1执行计划_2026-09-14.md)保留为已有实现背景，不再决定当前启动批次；其中旧“待④通过”限制已由 E0–E4 取代。R4（文献参数化）与 R5（正式比较）仍是并行/后续方向，不自动启动全矩阵。

旧接口与训练配置可参考 [R2→M1 执行计划](../工程实现/R2到M1执行计划_2026-09-14.md)，不得把旧单动作 schema/标签无版本地复用于完整计划评价。

### R1：先跑通学习数据，不做大规模 oracle

1. 建立全新的 TRAIN-TEACHER / DEV-TEACHER。先查所有既有 split 的基础实例种子与内容；换目录、改 split 名或换 root seed 都不能单独证明不重叠。
2. 起步建议 8 个 TRAIN、4 个 DEV 基础实例，50-node、R1、EDoD=0.5；每实例确定性抽取最多 4 个决策上下文。实例数与上下文数仅是计算试运行配置，不是论文样本量。
3. 对选中的上下文保存全部枚举候选、KEEP/DEFER、证书与共同 continuation 终局 D/Q/E/J。限制上下文数量，不偷偷只导出获胜动作。单上下文过大先计时报告；若采用候选截断，应记录规则，标注 regret 相对于截断集合。
4. teacher 的隐藏未来只参与离线标签。训练张量由可见字段白名单生成；完整恢复快照不能直接喂给模型。
5. 验证同状态 KEEP parity、无跨 split 泄漏、有效合同一致、无非法/非有限标签参与损失。记录 CPU 时间，再决定扩量。

### R2：小规模 M0，与 M1 骨架并行

- 先过拟合一个小训练子集验证 loss 与动作评分接线，再用独立 DEV 检查泛化。
- 首轮比较 frozen pretrained MaskCO + utility head、feature-only head、context 内表征 shuffle（只打乱 embedding 分支，显式特征/标签不动）；Real/表征 shuffle 架构和预算一致。标签 shuffle 另列可选 sanity，只打乱 TRAIN 标签、DEV 保持真实；两种 shuffle 不混称。generic/random encoder 对照在接线跑通后加入。
- 首轮 1–2 个训练 seed 仅作诊断，不算多 seed 稳健性。
- 重点看 normalized regret、相对 KEEP 的决策错误、实际动作分叉和完整在线 D/Q/E/J；不能只看 pair accuracy。
- M0 是短诊断，可并入 M1 工作包。无需等待 M0 显著性 GO 才写 M1 代码，也不能用一次小样本无改善断言“不可学”。

### R3：最小完整 M1

- 在同一开发合同上增加 fleet/thermal tokens、event/risk mask、masked action decoder。
- 从 K=1 开始，再比较 K=2/4 的重构；K 是开发起点，实际在线预算和耗时都要报告。
- 首先只训练 head/adapter/decoder；是否部分微调 encoder 由 DEV 决定。
- 加入在线 replanner 与证书/fallback。不能在部署时使用 teacher 的真实未来终局 rollout 挑动作。
- 与 JF1-H-F、冷链增量启发式、预算匹配的强求解器做完整 rollout 比较。M1 有真实行为/效用信号后再扩矩阵。

### R4：并行收敛路线 B 的仿真设定

助手负责文献、公开数据和参数表；用户负责实现与运行。
优先沿用 coldchain-contract-v1 开发，不自动升级 v2-light。
最终设定可包含有文献依据的参数和明确披露的仿真假设；不得将未核实值标成实测标定值。
参数/单位或 objective 改变后，生成新 contract/profile，在独立开发数据重做受影响的 service/scale 检查及小 oracle/teacher parity；相关旧标签不能混用。
这不要求重复跑旧 9×128 正式 DEV-GATE；需要多少复验由实际改动和论文主张决定。

### R5：正式比较与论文

固定任务、最终模拟合同、主目标、比较方法、预算、开发选择规则后，重做最终版本训练与评估。
优先主动态矩阵与关键消融；随后 100-node、热压力、权重/参数敏感性。
正式计划以 5 个学习 seed 为目标，预算不足时在最终评测前记录调整依据并报告所有运行，不能按显著性增删 seed。
最终 TEST 同时评价锁定主模型、核心对照和必要消融；不把消融只留在调过参的 DEV 上。
显著性、实际收益、速度代价和失效场景一起报告，不能保证胜出或录用。
