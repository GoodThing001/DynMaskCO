### 结果 D：强规则对照门（隔离「筛选」vs「条件信息」）

`run_exp_rule_control.py`（C0 任务，200 训练 / 40 测试，同日配对）。加两个因果、无条件的强规则：
fixed_threshold（训练集校准 τ*=1.238 的固定 value/e 阈值）、class_priority（τ=1.0 先验）。

| 臂 | 利润 | 能耗 | 类别构成(常温/冷藏/冷冻) |
|---|---|---|---|
| myopic（无筛选） | 808.6 | 447.3 | 16.5 / 16.0 / 11.6 |
| class_priority（τ=1.0） | 898.6 | 440.7 | 23.2 / 22.3 / 8.4 |
| fixed_threshold（τ*=1.24） | 1097.8 | 416.8 | 57.9 / 28.4 / 0.0 |

**+349 的分解**（count_knn − myopic）：
- fixed_threshold − myopic = **+289.2 [246.5, 326.3]** → 「无条件 value/e 筛选」，规则可捕获（**83%**）
- count_knn − fixed_threshold = **+59.6 [36.6, 87.6]** → 「条件信息」，k-NN 捕获（**17%**），显著（CI 不跨零）

**结论**：count_knn 相对 fixed_threshold 有 +59.6 的显著增益，但这 +59.6 **混了两个因素**：
①「无条件动态门槛」（λ 随时钟/剩余预算变化）②「条件匹配」（按当天早期计数选邻居）。
两者不能用 +59.6 单独归为「当天计数的条件预测」——见结果 E 的修正对照。**「学习增量空间 < +59.6」
不成立**（+59.6 是两种现有策略的差，不是 k-NN 上方的上界）；**「5.4% 偏边际」也不能作为收束理由**
（对运营利润 5.4% 可能很有意义）。真正收束理由 = 未检测到 *MaskCO 特有的* 正增量 + A-v0 是
截断严重、单一机制的合成数据。

**结论**：+59.6 **完全**来自「无条件动态门槛」，不是「当天计数的条件预测」；「条件匹配」不仅无价值，

## 四、A-v1 方向与开工门（2026-09-24 后续）

### 决策（用户定）
- **收束 A-v0 的「冻结 H 做 k-NN 匹配」具体假设，不换「MaskCO + 动态 + 冷链」课题。**
- 决策 1：**拒绝惩罚**（保留 accept/reject）。`p_c` = 收入**之外**的补偿/合同/服务损失，不与失去收入重复计算；
  已接受未服务仍是**硬失败**；`p_c` 无业务依据时列为**预先固定情景参数 + 敏感性**，不在测试集挑档。
  不选「每天服务率硬约束」（在线未知未来单数/物理可达性）；各温区服务率/拒绝原因/可售率列为**报告指标**，
  有真实 SLA 可另设跨天期望服务水平。
- 决策 2：**C0 货物轨迹品质**（Arrhenius）替换 `K_EFF` 代理。主效用 = 已服务收入 − C0 品质损失 − 行驶成本 − 已揭示未服务惩罚；
  硬约束 = C0 能耗预算 + 时间窗 + 容量 + 承诺兑现。品质时钟 pickup-to-depot（`service_finish`→`return_arrival`），
  报告返仓品质 + 不可售比例。接受能耗预测需保守认证（est/true≈1.5 只是经验余量，非硬保证）。

### 开工门第 1 件（品质敏感性）— 判定：当前 pilot 参数不通过，需先校准
当前 pilot `reference_rate=(0.001,0.002,0.0035)/h`，5.4h dwell 品质损失占收入 **0.05%–0.2%**，不改变决策。
放大 ×50（rate 0.1/h）class0/1 才到 6–8%、class2 仍 2%。→ 需校准品质参数（文献 Arrhenius），
**但不能把「找到参数」当通过、不能为显效调大速率。**

### 三个纠正（用户提出，我核实成立）
1. `0.1/h` ≠ 保质期 10h：10h 是 1/k 时间尺度；按可售阈值 0.80/0.85/0.90，触阈时间 2.23/1.63/1.05h（数学验证）。
2. 金额占比小 ≠ 无决策改变：要同事件同预算直接比较有无品质项的接受/分配/路由；金额还受 `product_value` 经济权重影响。
3. 开工门测**在线目标**，非孤立 C0 输出；`run_exp_energy_c0.py` 利润品质仍 `K_EFF` 代理；
   C0 loss/salable 都除以 `initial_quality`，设低初始品质不自动体现「临近不可售」的绝对风险。

### 文献核查（商品/温区实测，用户提供，精确值待全文复核）
- 樱桃番茄（常温 18°C）：番茄红素/可滴定酸一阶，3h 下降 ~1.0%/0.55%（营养指标，非售价）。
- 鲻鱼（冷藏 4°C）：感官评分零阶 ~0.452 点/天，3h ~0.057 点。
- 冷冻鱼（-18°C）：可接受期限 ~580–623 天（由 -5~-15°C 外推）。
- **结论**：几小时 pickup-to-depot 中，品质可能不是主要优化杠杆；MaskCO 动态冷链方向可保留，
  但论文不能把未经证实的品质收益当主效果。

### 品质→价格：主实验不货币化品质损失
三篇动力学论文无「品质→价格」曲线，现有 `product_value` 是 pilot 假设。**主效用 = 服务收入 − 行驶成本 − 预先固定拒绝损失**，
s.t. 承诺/时间窗/容量/能耗/**可售**。品质变化与各温区可售率**独立报告**，画「服务收入—品质」权衡。
若后续取得合同折价/等级价格数据，再加货币化品质损失；在此之前只做预先固定的折价敏感性，不称实证校准。

### 品质状态语义修正（改完才能填参数）
现有 C0 对三类货物统一一阶 `exp(-kt)` + 损失/可售相对 `initial_quality` 归一化（`coldchain_state._advance_manifest_quality`
与 `_delivery_record`），**不能**表示两种鱼的零阶线性评分、也不能表示「返仓绝对评分 < 5 不可售」。需改：
1. per-温区动力学阶数（零阶 `score -= k·dt` / 一阶 `q *= exp(-k·dt)`）。
2. per-温区阈值类型（绝对评分 / 相对比例 / 无）。
3. 番茄 18°C 无阈值的隐患：需明确其服务/品质要求（或明确其为常温非瓶颈、仅连续报告），避免算法滥用无约束温区。

## 二、收紧的结论（核查后）

1. **（已解决）步骤 4 已完成 C0 接入**（`run_exp_encoder_v3.py` 所有臂共用 C0 合同/预算/完整认证）。
   原 v2 的 `coldchain_contract=None` + 逐单 `E_CLASS` 已废弃。
2. **「预算/预测/终局完全同口径」是错的，已收回。** 接受时是逐单估计
   `cooling_power_kw[c]·mean_dwell[c] + door/COP + precool`（只算单温区）；真实终局是整车**全温区**
   `active_zone_mask=(True,)*3` 持续运行。**实测 est/true ≈ 1.5（逐单估计高估真实 ~50%）**，
   因为 `mean_dwell` 从「全接」训练校准（每车多单、dwell 长），myopic 实际每车更少单、dwell 短。
   → myopic 终局真实能耗 ≈443 vs 预算 B≈675，**~34% slack 未用**。40 天 0 违约是「保守估计 + ρ=0.6 大 slack」
   的**经验结果**，不是接受规则天然保证预算可行，也不代表预算约束已紧绑定。
3. **C0 统一的是能耗，不是完整利润物理口径。** 利润里品质损失仍用固定 `K_EFF` 指数式
   `pval·dem·(1−exp(−k_eff·dwell))`，非 C0 的 Arrhenius cargo trace 品质损失；合同是
   `default_pilot_contract` 改的。正式表述应为「**C0 能耗约束下的代理利润实验**」。
4. **（已解决）步骤 4 v3 已有逐日配对输出**（各臂逐日利润+能耗+可行率、frozen−count / frozen−random /
   count−myopic 同日配对差）。
5. **「k-NN 几乎吃满头腔」不能当结论。** clairvoyant 是贪心 value/energy 启发式，**不是最优上界**
   （k-NN 1158 > clairvoyant 1152 恰好说明它量化不了剩余空间）。且 H 状态 3h 后不再更新、随机 encoder 单初始化——
   即使冻结 H 失败，也只否证「这个特定匹配方案」，不能判死学习型生成。
