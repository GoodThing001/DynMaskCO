## 2. 当前接入位置：先确认已有什么

当前前向是 `H0=冻结的CVRP编码器(raw_3d)`，`H=H0+C(node_feats)`，随后调用 MaskCO decoder 和边输出，再用有序插入残差头 δ 结合目标车辆状态给动作评分。依据：[模型模块](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/models/mpre_trained.py:114)、[状态提取](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/data/repair_state.py:55)。

- `C` 当前吃节点级 TW、温区、初始品质、状态标记；不直接吃全车队状态。
- 目标车辆的时间、余量、温度、温区载重和品质摘要进入最终 δ；本地当前 `F_ACTION_EXPLICIT=20`，不是早期汇报的 17。
- `incremental_distance` 已是动作特征。加入显式距离先验改变的是模型使用该信息的方式，不能声称首次加入距离。
- cargo 明细表被提取，但当前训练／部署评分接口未消费 `cargo/cargo_valid`。这不等于模型没有货物品质信息。
- [在线策略](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/simulation/mtrained_replanner.py:143)在每次重构内部使用确定性逐步 argmax；外层已经有多个 mask 请求和完整计划接受。因此“只有一次搜索”不准确，潜在缺口是**每个 mask 内部的分支探索**。
- 训练已有同状态多采样与 leave-one-out baseline。简单改叫 POMO 或改用组内均值，并不会凭空增加一种新的学习信号。

还需区分两类固定状态统计：[当前聚合函数](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/evaluation/run_fixed_state_quality.py:333)只把失败替换为 J0，成功但变差的候选仍计入均值。它衡量的是带失败兜底的候选质量，尚不等于在线“只接受改善”的输出质量。应保留原表，并用已有逐状态记录补 `J_accepted=min(J0,J_candidate)`；认证失败仍返回 J0。该重算不是新训练，也不能代替动态闭环。

## 3. 第一优先：SGBS 式完整补全搜索

### 借鉴什么

[SGBS 原论文](https://arxiv.org/abs/2207.06190)用策略提出有限分支，再通过补全 rollout 的完整解质量选择保留分支。本地 [CVRPTester](D:/PyCharm_/MASKCO-Main/CC_Compare/SGBS/CVRP/2_SGBS/CVRPTester.py:523)可直接看到扩展、贪心补全和按 rollout reward 排序。它与单纯按累计 log-prob 保留 beam 不同。

适配到我们这里：

1. 保持事件时公开快照、同一合法 mask、同一部分计划。
2. MaskCO 给合法 `(客户, 目标车, 插入位置)` 动作排序，提出少量不同分支。
3. 每个分支在副本中补完剩余 masked 客户。
4. 对完整方案执行当前认证和唯一 J_vis 评价，按完整修复质量保留分支。
5. 始终保留原计划 P0，只有认证通过且改善时写回；继续沿用外层事件掩码重构。

这里的 rollout 是**补全当前已知订单的计划**，不能调用含未揭示订单的真实未来轨迹来选分支。它也不是保证最优的穷举。

### 为什么排第一

当前已有“trained 明显优于 pre，但 greedy 仍输 R”的信号。先检验现有策略分布中是否藏着更好的完整方案，比重新设计 teacher 或再训练大型模型更便宜，也能区分“候选不够好”和“解码没有利用候选”。MaskCO 仍负责提出分支，学习职责明确保留。

### 一次小范围验证如何设定

先读取已有 clean 固定状态的 samples，计算每状态最佳合法采样相对 greedy、R 的差异和重复方案比例。若每状态已有 8 个采样，则做 best-of-8；若没有，不虚构这一统计。这个结果仅作为候选空间诊断：8 次采样胜过 1 次 R，不构成公平性能胜出。

如果有值得探索的信号，再预固定一个小配置，例如 beam 宽度 2、每父分支最多 2 个动作、每状态最多 8 次完整补全尝试，不做参数网格。所有 rollout、失败尝试和完整评价均计入预算；重复完整方案可缓存，但必须记录缓存命中与实际工作量。对照至少包括：

| 对照 | 排除的解释 |
|---|---|
| M-pre greedy、M-trained greedy | 原模型表现 |
| M-trained 独立采样，最多相同次数 | 收益是否仅来自多采样 |
| M-pre + 相同补全搜索 | 是否需要目标训练 |
| M-trained + 补全搜索 | 待验证的方法 |
| 距离启发式提议 + 相同补全／评价 | 是否只需普通搜索而不需网络 |
| 冻结的可部署 R，在相同实际时间预算运行 | 能否胜过现实强参照 |

固定补全次数用于解释算法；**部署比较仍以相同事件墙钟时间为准**，包含特征提取、推理、认证与评价。报告预热／编译策略、实际完成候选数和稳态延迟。不能限制 R 只能产生一个候选，却让模型搜索 8 个后宣布学习更好。

若只有搜索带来收益，换成非学习提议仍一样好，则是搜索贡献，不是学习增量。若模型提议有增量，再进入干净闭环、多个训练 seed 和新留出实例验证。此项借鉴名称应为“SGBS-inspired repair search”，不是原 SGBS 的严格复现。

## 4. 网络结构首选：车辆—部分路线条件化

### 来源与真实机制

- [JAMPR](https://arxiv.org/abs/2006.09100)：车辆编码、路线摘要、车队上下文，联合选择车辆与客户。当地 PDF 第 5–6 页给出对应关系。
- [Vehicle-as-Prompt](https://arxiv.org/abs/2604.05195)：车辆／节点交互表示和多视角解码。当地 PDF 第 5–6 页给出车辆—节点交叉注意力。其原始车辆类型 token 动作不能直接替换我们的物理车辆插入动作。
- [DVS-AM，多温区冷链配送](https://www.mdpi.com/2227-7390/13/13/2039)：车辆状态编码器、车辆与全局上下文融合、逐步更新车辆表示。当地 PDF 第 8–10 页可核查；其配送、异构分舱语义不等于我们的同构共享容量取货协议。
- [RouteFinder](https://arxiv.org/abs/2406.15007)的资源条件 decoder context，以及 [CaDA](https://proceedings.mlr.press/v267/li25bi.html)的约束提示，提供相关实现参考。CaDA 本地实现是全局提示分支与稀疏分支，不应简化成已实现“冷链双注意力”。

### 建议的最小改动

保留 CVRP512 编码器、MaskCO decoder、原边评分、有向 δ 和原动作空间。新增一个小的车辆—路线条件残差模块，而不是整体换成另一论文的模型：

`车辆表示 = f(公开车辆状态, 当前部分路线的有序表示)`

`H_new = H_current + zero_output(节点查询车辆／路线表示的交叉注意力)`

订单节点在进入 MaskCO decoder 前获得车队条件；动作头继续读取**目标车辆对应**的表示，不能只加一个全车平均向量后丢掉车辆归属。路线表示必须保留顺序及 anchor／committed 边界，不能用客户集合代替完整路线。物理车辆 ID 只关联，不学 ID embedding。

零初始化新增模块出口，使加入模块时继承原 clean 模型输出。随后如开展训练，原模型和新模型在相同数据、更新数、采样预算下比较；不能只给新模型追加训练，再将全部收益归因于结构。

这是“更早建模车辆—订单—部分计划关系”的假设，**不是已经证明当前 δ 表达能力不足**。当前 δ 本身已经能建模部分条件关系；新增注意力是否值得，需要用效果和预算证明。原文方法多为 PyTorch，本项目为 Flax NNX，适合借机制，不能直接拷权重或拼一个不兼容层。

### 不默认接入 cargo 明细注意力

依据 [C0 品质状态](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/coldchain/coldchain_state.py:144)，同温区采用共同衰减率时，固定未来温度／时长路径下，当前在舱货物新增加权品质损失可写为：

`ΔQ_z = value_z × (1 − exp(−K_z)) × Σ_i(quantity_i × quality_i / initial_quality_i)`。

当前 `zone_quality` 已包含这个加权和。因此，对该加性品质项，未读取逐订单表并不自动意味着丢了必要信息。订单级可售阈值、异质衰减参数或其他非线性目标需要另论；不能为证明新模块必要而临时改变物理合同。

若以后确需用 cargo 表，还要单独定义无截断的容量和字段语义。目前表有每车最多 8 笔的截断，`exposure_time` 读取也需与实际 lot 字段核对。这些未消费字段不是本次开启另一轮纠正训练的理由。

## 5. 次选：RRNCO 式显式几何先验

[RRNCO](https://arxiv.org/abs/2503.16159)在 [decoder](D:/PyCharm_/MASKCO-Main/CC_Compare/RRNCO/rrnco/models/decoder.py:183)中使用距离／时长偏置。我们可借鉴为：

`s_new(action) = s_current(action) − λ_D × incremental_distance / scale_TRAIN`。

首先只引入距离这一项。λ=0 应复现当前模型；尺度只来自训练或公开合同。加入车辆时长、品质、能耗项均应视为新增变量，尤其不能把旧静态 energy_mat 当作当前 C0 制冷代价。

价值是给模型一个明确的廉价几何偏好，让残差有机会纠正它；不是宣称神经网络此前不知道距离。固定 λ 的有限校准可不重训；可学习 λ 则需要新训练协议。必须保留“仅几何偏好”“M-pre+先验”“M-trained+先验”的对照。如果几何偏好就达到相同性能，则不能归功于 MaskCO。

该公式也不等于 regret-2：后者还通过最佳与次佳插入之差决定先插哪个客户。避免将它包装成“零初始化就继承 R”。本项与 SGBS 分开测试，不同时改变。

## 6. 应先做的工程优化：缓存冻结编码

[Attention Model](https://arxiv.org/abs/1803.08475)将静态编码与逐步 decoder context 分开，本地 [attention_model.py](D:/PyCharm_/MASKCO-Main/CC_Compare/AttentionModel/nets/attention_model.py:151)提供缓存实现参考。

当前 [mtrained_score_fn](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/simulation/mtrained_replanner.py:84)逐步调用完整 `score_actions`，会重复进入冻结编码器。可按同一事件、同一可见节点映射／归一化／padding 形状／encoder 权重缓存 H0。

**只缓存 H0，不缓存所有 H。** 每步 mask、节点状态和部分邻接变化时，需要重新算 C 和 decoder；现有 `score_from_H` 可作为接入点。训练时同样只能复用冻结部分，不能因此切断 C／decoder 梯度。

验收应包括相同形状下分数误差、近并列动作、完整计划与接受行为、实际 encoder 调用次数和墙钟延迟。它是工程效率改进，不是论文核心创新；既往“440 倍慢”的测量混有编译等因素，不能承诺缓存后自动接近 R。

## 8. 推荐的执行顺序与停止条件

1. **冻结当前 clean 模型作为参照。** 保留候选质量表，用已有记录补接受后统计及采样分布诊断。不再使用有状态引用／mask 越界缺陷的旧结果判断当前模型。
2. **原模型证据与新机制评估分别记账。** clean 版本的 bounded 闭环已由执行端回传，见第 9 节，结论为固定状态收益未稳定转化。无需重跑这一包；后续新搜索结果另列。固定状态早期 mask=2 结论也不覆盖在线 mask=4/8。
3. **工程上先减少重复冻结编码。** 用同一计算形状和输出一致性验收，测清可用搜索预算；不改变模型、训练、奖励。
4. **算法上只试一项 SGBS 式搜索。** 先用既有样本判断候选潜力，再进行预固定小配置及公平对照。候选本身缺少改善机会且小搜索无效时，不自动扩大 beam、加 EAS 或延长训练。
5. **只有证据支持表示仍值得改时，才开展车辆—路线条件化结构实验。** 在相同训练与推理预算下与原结构比较，保留零初始化继承和协议验收。不要同时加入距离先验；后者是独立备选。

下一轮判定重点是两个问题：**相同资源下能否优于可部署 R；把 learned 提议换成非学习提议后，优势是否消失。** 仅比 M-pre 好，或比 greedy 好，都不足以回答这两个问题。

有希望的论文主张是“当前公开冷链状态条件下，MaskCO 提议的受约束重构分支，在有限预算内更有效地找到完整计划改善”。这仍是待验证假设。SGBS、车辆注意力、距离偏置本身都有先例，组合这些模块不自动构成新颖性。最终需要明确任务中特有的设计差异、同预算非学习／学习强对照、组件消融、多个 seed、新留出实例及动态闭环，才能讨论方法贡献与投稿。

### 9.2 对“解码是唯一瓶颈”的修正

核查 [上游 cvrp_searching_decode](D:/PyCharm_/MASKCO-Main/MASKCO_code/decoding/cvrp.py:99)：它输出边 logits，按配置加 Gumbel 噪声，再 softmax／排序，由 `CVRPPartialInsertion` 生成方案，并调用 2-opt；后续循环保留部分边再重构，多 run 取较低成本。Gumbel 可关闭或取零尺度，不能把随机性视为每次调用必有的语义。

核查 [扩展搜索循环](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/simulation/mtrained_replanner.py:143)：已有 `2,2,2,4,4,4,8,8 × 2` 的外层 mask 请求和完整方案接受；每个 mask 内使用确定性逐步动作。这不是“一次单趟构造完全替代所有迭代”，也不是原 AM 的逐节点构造实现。

因此，准确的研究假设是：**单个 mask 内增加有限分支探索，可能更有效地利用当前模型的提议。** SGBS 是一种适配搜索，不是逐项恢复上游算法。当前证据不能证明边热图单独已经学对：训练同时改变 decoder、C 和 δ，收益可能来自其组合。尚未排除训练／在线 mask 范围差异、状态分布变化、预算内候选吞吐和 J_vis 与动态终局效用不一致等解释。

### 9.3 下一包顺序：同意继续，但不预设成功原因

**① 读取现有采样。** 对 M-pre、M-trained 同一批状态分别统计 greedy、固定样本顺序下 best-of-1/2/4/8、接受后质量、胜 R 比例、失败率、去重方案数；按实例聚合配对 CI。采样失败算入抽样预算，部署返回 P0，不删状态。记录温度／种子／checkpoint／采样数。已有数据不到 8 个时按实报告。

`best-of-8 + P0` 是已评价候选中的最好结果，不是可达最优解，也不是同成本超越 R 的证据。如果 8 个样本中没有好方案，只能说明这份有限样本未发现，不能据此证明整个分布没有好方案或必须更换表示。若只在 TRAIN 有机会，在 CAL 无一致信号，则暂不扩展搜索或重训。

**② 缓存 H0。** 同一公开事件快照、可见节点及顺序、归一化、padding 形状和冻结权重下复用；动态 C、邻接和 decoder 重算。M-pre 与 M-trained 都使用对应优化，避免实现效率不对称。记录缓存前后分数差、完整动作／计划／接受差及近并列情况；JIT 拆分可能带来数值误差，不能只验 logits 容差就假设 argmax 一致。没有通过行为核对前，不将新结果归因于搜索。

**③ 一个预固定 SGBS 配置，先固定状态。** beam=2、每父最多 2 个动作、每次 mask 最多 8 次完整补全尝试；始终保留 P0，并将原 greedy 方案作为计入该上限的候选。独立采样对照同样保留 greedy，另外最多 7 次采样，使实际新生成候选的总上限相同。分支补全用原 greedy 策略，按完整 J_vis 排序；记录所有分支、失败、重复与评价调用。其与原始 SGBS 的实现差异须明示。

固定状态至少比较：R、M-trained greedy、M-trained 同预算采样、M-pre+搜索、M-trained+搜索、非学习距离提议+同一搜索。SGBS 与独立采样都含 greedy 后，忽略时间上限的单状态“不劣于 greedy”由候选包含关系直接保证，不能把这一点当作学习成功。真正要看同成本相对 R 及非学习提议的增量。

先保持既有干净 mask=2 状态作配对诊断；若出现开发信号，再用预先固定的有限后期状态／mask=4、8 覆盖检查进入在线场景的范围差异。扩大覆盖是新的诊断分层，不与原 mask=2 表混合为一个均值，也不同时修改训练分布。固定状态有信号且延迟可部署，才开展相同 4s／事件的闭环；不能将固定状态改善直接称为“收益已转化”。

主部署比较以 4s／事件为总预算，不是每个 mask 各 4s。所有补全成本包括在内，过期候选不接受，保留最好已及时完成的合法方案。报告预算内候选数、总推理时间及每事件 p50/p95/max 延迟；“超时候选不接受”和“函数能在4s内返回”是两件事。执行端报告的约 689s／16实例不能直接除以实例数后与4s／事件比较，也不足以判断速度优势。编译约64s单列，说明预热覆盖和运行中额外编译。

本包冻结模型、训练数据、奖励、学习率、接受规则与物理合同。结构改动、辅助 CE、EAS、更多训练步数均不自动启动。辅助掩码重建若将来讨论，须首先定义高质量合法目标计划的来源；蒸馏原 R 或自生成低质标签不能只因损失更密集就预期获得增量。小搜索无效也不唯一指向需要 CE。

### 9.4 论文归因

收益需同时回答“是否优于强参照”和“学习贡献多少”。相同搜索下 trained 优于 pre、非学习提议，说明学习具有可测增量；不要求换掉学习后所有搜索收益都消失。反之，如果只有搜索有效而 learned 提议无额外贡献，不能包装为 MaskCO 学习创新。即便消融成立，仍需相对 SGBS／神经局部搜索已有工作的明确设计差异与独立验证，不能自动推出可发表性。

### 10.2 三项影响结论范围的实现事实

**A. 搜索深度未对齐。** [run_sgbs_fixed_state.py](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/evaluation/run_sgbs_fixed_state.py:76)先生成 greedy，再分别对 top-2 首动作做 greedy completion，没有第二层动作扩展、按 rollout 分值保留 beam 的循环。排序和 tie-break 一致时 greedy 与第一分支相同：至多三次完成构造、至多两个不同方案；相同质量的并列顺序或不同构造路径仍需用完整 plan hash 实测。它可称“首动作 top-2 rollout 探针”，不能称 mask=2 下已经覆盖完整两层分支。第二个被插入客户的次高分位置可能对应更好完整 J，本脚本不会尝试。

**B. 预算与失败计数没有完整落盘。** 该脚本不含墙钟截止参数／检查；`_eval_best` 返回的补全计数在调用处丢弃，失败方案也在部分路径中被提前滤掉。采样对照生成8次，而 top-2 探针只生成至多3次，不能写成两者实际投入相同。距离探针与 learned 探针共享控制流，质量比较仍有意义，但其提议和后续 greedy completion 都随方法改变，所以不是只隔离了首动作提议的消融。

神经 greedy 先于同模型搜索运行，可能先承担新形状的编译；因此429s／101s等总时长受编译和执行顺序影响。不能在未测稳态时又断言“即便预热仍慢几个数量级”。这项未知不必单独触发性能实验；可在唯一纠正包内一并记录。

**C. 缓存验收范围窄于部署。** [verify_cache_equiv.py](D:/PyCharm_/MASKCO-Main/C-VRP_Cold-chainVehicleRoutingProblem/scripts/evaluation/verify_cache_equiv.py:51)对固定 padding 容量51/2048的合成输入比较分数与 argmax；搜索脚本调用缓存接口却不传 padding 容量。回传的零差异是已测条件下的有效证据，但未覆盖此次 unpadded 真实状态的完整动作／计划／接受等价，也未覆盖保持 raw 不变而改变动态特征的缓存命中过程。

缓存键当前只比较 raw_3d。若 raw 相同而 node_valid 改变，encoder 输入实际上不同；接口复用应将有效位纳入缓存身份，模型权重变更则重建缓存。当前真实提取通常是裁剪后全有效节点，尚无证据证明此遗漏影响已回传实验，不能把它直接称为新一次训练污染。

| trained搜索在局部任务相同预算下优于非学习搜索，并对简单采样显示优势，且相对单次R有质量信号 | 出现搜索利用学习信号的开发证据；再安排有限后期状态／mask范围覆盖及完整事件预算的R对照、闭环 |

| 神经搜索质量有信号但当前时限无法利用 | 记录质量与效率矛盾，不宣称部署优势；是否重新设计轻量推理另立任务 |
| 数据身份／缓存行为／预算仍无法对齐 | 记录实现未完成，不能升级为方法学否定，也不继续无限纠正 |

若当前路线收束，先前的车辆—部分路线条件化仍只是一个新架构假设，并不会因搜索失败就自动被证实或获得训练许可。保留MaskCO核心的后续研究必须说明：相对已有δ，新增关系表示解决哪个可观察的决策缺口；原结构与新结构如何同数据／同训练预算比较；怎样以更强的非学习搜索为参照。提出这一页设计后再决定投入，不立即串行试MoE、CE、换teacher等多个配方。

当前成果能够支撑严谨的实现、迁移适配和负结果分析；尚不足以声称MaskCO方法性能创新成立。论文可行性取决于后续是否产生新的、可归因且独立验证的学习价值，没有可靠的“再跑几次必然成功”估计。
