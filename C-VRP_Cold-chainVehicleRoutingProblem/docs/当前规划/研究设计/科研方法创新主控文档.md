# DynMaskCO 科研方法创新主控文档

> 版本：2026-09-18 · 路线 B / 方法论文优先；本轮落地 event_plan_v1 开发假设，尚无该版本的新实现或性能结果。
> 本文件决定论文问题、最终方法、创新贡献、证据链与 Go/No-Go。  
> 核心原则：锁定动态冷链主线，只把已通过测试的 C0 层写成实现；pilot 参数与历史代理口径不得写成论文效果。

## 0. 主线与当前判断

论文研究问题固定为：

> **如何把 MaskCO 面向静态解的掩码生成与迭代重构，扩展为面向动态冷链物流的因果、车队级、约束可行且终局效用对齐的在线优化方法？**

最终方法暂命名为：

> **DynMaskCO-CC: Utility-Aligned Causal Masked Generation for Dynamic Cold-Chain Vehicle Routing**

Cost-aware preference learning 是解决“结构可学但部署无效”问题的内部监督机制。最终论文方法不能停在 frozen MaskCO encoder + MLP；必须让事件掩码、重构和迭代改进真实参与在线决策，并通过 MaskCO 身份消融证明其必要性。

当前阶段是算法研发，不是论文收尾。P0/C0 底座、pilot oracle、teacher 与 M0/M1 原型已有实现和运行记录；④接口与⑤两轮归因已有结果，但 learned 方法仍未建立稳定正效用。当前进入 [event_plan_v1 执行协议](../工程实现/event_plan_v1执行协议.md)：从同一 incumbent 生成完整候选计划、评价最终方案并选择一次计划。新增实现、训练和实验由用户执行；助手维护重要文档。

### 0.1 本轮假设与论文成立条件

本轮要检验的是“完整计划评价与选择能否改善连续局部接受的闭环效果”，不是已经确认必须改监督时域。旧标签本来就是单动作干预后的终局差；新版本改变监督与选择的对象，baseline continuation 仍是有限代理。

F_R 的 FULL−EVENT-ONE 对照支持限制事件内继续修改可减少该配置退化，尚不能证明新计划评价器会有效。部分后段动作在 reveal 清尾中失效不能推广为“只准改首段”；候选生成和部署选择不能读取真实下一次 reveal。对 baseline 共用的未来存在性规则须明确披露，不能仅凭 learned 特征不读未来就宣布更强的信息契约已通过。

首轮固定小预算、一个训练目标与简单选择对照；MaskCO 生成器适配可并行，先取得闭环证据再决定扩大 refinement/微调/场景。迭代机制、冷链目标和 MaskCO 身份的增量各须实验支持；若某部分无增量，应简化方法或收窄主张，不能只因组件名字存在便写成贡献。

文献参数化与公平 baseline 适配并行，不要求实车注册、v2-light 或独立 oracle VAL 才能训练。路线 B 研究文献支持的动态冷链仿真，不声称真实设备标定；现有工程检查不构成方法性能证据。学习式修复和邻域选择已有先例，本轮相关工作起点及论文证据清单见执行协议 §9，不宣称新颖性已经完成论证。

## 1. 问题定义：动态冷链车辆路径优化

事件 \(e\) 到来时，订单逐步揭示。部署策略仅能访问 filtration：

$$
\mathcal F_e=\sigma(
\text{revealed orders},
\text{executed trace},
\text{fleet state},
\text{committed legs},
\text{observable cold-chain state},
\text{public parameters}
).
$$

策略必须满足 \(a_e=\pi_\theta(\mathcal F_e)\)。未揭示订单不得通过坐标归一化、节点/边特征、候选集、温度统计、future cardinality 或缓存泄漏。

### 1.1 运营语义

主实验固定为 **dynamic cold-chain pickup-to-depot**。车辆从中心仓库空载出发；动态订单表示客户处待取的冷链货物；服务完成时货物进入对应温区并使载重增加；返仓时统一卸货并关闭车辆。每车单次行程，不允许 multi-trip 或 depot reload。

订单状态为：

```text
unknown → revealed → planned/committed → picked → delivered_to_depot
```

主设置假定客户处货物在取货前由外部合规冷库保管，取货前品质变化不受本策略影响；策略相关品质计时从 `service_finish` 开始，到所属车辆 `return_arrival` 结束。这样，在途插入新揭示订单不需要假设车辆预先装有未来货物，也与现有容量状态转移一致。若另做 depot-to-customer 配送，必须建立新的装货/ownership/reload 协议，不能沿用本论文主结果。

### 1.2 决策对象

事件状态包含：

- 已揭示客户、需求、时间窗、服务时间和温区；
- 每车位置、时间、容量状态、已执行前缀、committed leg 和有序 mutable suffix；
- 每车或每温区的可观测温度状态、累计能耗、分温区载重和订单级 cargo manifest；
- 在途订单的取货完成时刻及当前剩余品质；实际返仓品质仅属于终局评价或离线监督，不得作为在线输入。若使用基于当前可见计划的预测返仓品质，须单独命名、说明计算信息边界。
- 当前 incumbent full-fleet plan；
- 事件、随机性和 evaluator 的可恢复元数据。

最小可部署动作仍为 \(a=(j,s,p)\)：将当前已揭示且未取货的客户 \(j\) 放入置换感知 route slot \(s\) 的位置 \(p\)。M0 可固定客户顺序以验证表示；最终 M1 通过事件掩码决定需要重构的客户/路线变量，并顺序或成组地产生动作。

### 1.3 约束

硬约束至少包括：

- 所有订单恰好取货一次，所有货物最终运回仓库且终局 cargo manifest 为空；
- 时间窗、容量和返仓；
- executed prefix 与 committed leg 不可改变；
- 未揭示订单不可进入当前动作；
- 冷链车辆/温区兼容约束；
- C0 明确冻结的温控阈值约束。

“feasibility-preserving”只指当前动作经完整 route/fleet replay 后满足已定义硬约束；未知未来的全局 completion 仍由完整 rollout 和 fallback 经验验证。

### 1.4 双目标口径

历史兼容指标保持：

$$
J_{dist}=D,
$$

其中 \(D\) 是所有已用车辆含返仓的纯行驶距离，工程字段始终为 `distance_cost`。

论文冷链目标定义为：

$$
J_{CC}
=
\widetilde D
+\lambda_Q\widetilde Q
+\lambda_E\widetilde E,
$$

令 \(q_i^{0}\) 为订单初始品质，\(q_i^{dep}\) 为返仓卸货品质，\(w_i\) 为由货量与产品价值确定并在合同中冻结的权重，则主品质分量为：

$$
Q=\sum_i w_i\left(1-\frac{q_i^{dep}}{q_i^0}\right).
$$

\(E\) 是从车辆 dispatch 到 return 的 trace-level 制冷能耗（kWh）。归一化基准、权重、不可售阈值和单位在 C0 用 train/dev 冻结，工程字段为 `coldchain_cost`。主表同时报告原始 \(D,Q,E\)、不可售订单数和温度越界，禁止只报一个复合分数。

服务与硬约束先按 lexicographic vector 比较：

$$
H=(n_{\mathrm{unpicked}},n_{\mathrm{duplicate}},n_{\mathrm{not\text{-}depot\text{-}delivered}},n_{\mathrm{TW}},n_{\mathrm{cap}},n_{\mathrm{return}},n_{\mathrm{temp\text{-}hard}}).
$$

只有 \(H\) 相同且为零，才比较 \(J_{CC}\) 或 \(J_{dist}\)。

## 2. 为什么仍然基于 MaskCO

已有负结果给出的是监督错位，而不是 MaskCO 范式失效：

- JF2 表明 physical vehicle ID 受同质车辆置换歧义影响；
- HFR 表明 route/partition 结构可学，但静态 adjacency/structure target 与实际 insertion utility 不一致；
- B0 与 factorial 表明 fleet allocation 主导且 partition×sequencing 存在耦合；
- 因此应重构“被掩码变量”和“重构目标”，而不是放弃掩码生成。

原始 MaskCO 的核心是“掩码部分解变量—重构缺失变量—迭代改进”。DynMaskCO-CC 对应改进为：

| MaskCO | DynMaskCO-CC |
|---|---|
| 静态完整实例 | 事件时刻的 causal visible state |
| 掩码静态解边 | 掩码受事件影响的 mutable fleet–route variables |
| 重构参考解结构 | 重构冷链终局效用更优的可部署动作/计划片段 |
| 无执行历史 | executed/committed 部分永久冻结 |
| 静态可行性 | 车队、时间窗、容量、返仓与冷链状态 certificate |
| 结构 CE | 由反事实 \(J_{CC}\) 产生的 listwise/pairwise utility target |
| 多轮 refinement | 每次 reveal 后的 event-conditioned masked recourse |

## 3. DynMaskCO-CC 方法结构

### 3.1 因果动态编码

使用现有 DynamicColdChainModel 的 visible-only normalization 与 visibility-gated attention 作为底座。输入增加当前可观测的 fleet/thermal tokens，但未来订单相关冷链信息必须同样被遮蔽。

节点表示 \(H_e\) 与 fleet/thermal state 共同形成状态表示。MaskCO 预训练权重可先冻结作 M0 探针；M1 只通过 adapter 或分阶段 fine-tuning 接入，避免一次改变过多变量。

### 3.2 事件影响掩码

每个事件构造 \(M_e\)，只覆盖：

- 新揭示客户；
- 因新客户而失去余量的 route suffix；
- 温度、品质或能耗风险越过预警阈值的 mutable segment；
- 明确由 replan reason 标记的 route slots。

executed prefix、committed leg 和 future orders 永不进入可写掩码。必须保留 full-mask、random-mask、no-mask 和 shuffled-mask 消融。

### 3.3 置换感知的车队—路线动作

route slot 定义为 anchored slots 与匿名 NEW_ROUTE。只有 anchor、可用时间、温度、分温区载重和 cargo manifest 都等价的同质车辆才能匿名折叠；物理车 ID 只在动作选定后确定性匹配，不作为监督标签。

候选 action token 至少包含 customer、slot、predecessor、successor、局部余量和冷链状态差分。所有候选必须经同一 Action Contract 与冷链 certificate；模型仅在 certified set 上重构。

### 3.4 冷链效用对齐的掩码重构

> **版本边界（2026-09-18）**：本节动作分布 KL/pairwise 是完整方法设计候选，以下公式保留理论背景。当前 event_plan_v1 首轮采用完整计划收益回归，具体以执行协议 §4–5 为准；不同时启用多套损失，不将下述设计写成已实现或已有效。

对同一 state 的候选动作进行 common-continuation rollout，得到：

$$
Y_{CC}(z,a)=(H,J_{CC},D,Q,E).
$$

成本标签只使用终局 service/hard 全通过的候选子集：

$$
\mathcal A^{pass}(z)=
\{a\in\mathcal A^{cert}(z):service\_ok(Y_{CC}(z,a))\}.
$$

再用开发中确定的温度 \(\tau_T\) 将该子集转成效用软目标；其余候选概率为零。集合为空时不参与成本损失并报告 coverage；部署时不能读取真实未来标签来获得这一过滤集合：

$$
p^*(a\mid z)
=
\frac{\exp[-J_{CC}(z,a)/\tau_T]}
{\sum_{b\in\mathcal A^{pass}(z)}\exp[-J_{CC}(z,b)/\tau_T]},
\quad a\in\mathcal A^{pass}(z).
$$

Masked action decoder 输出 \(p_\theta(a\mid z,M_e)\)。核心损失为：

$$
\mathcal L
=
\lambda_{list}\,\mathrm{KL}(p^*\Vert p_\theta)
+\lambda_{pair}\,\mathcal L_{pair}
+\lambda_{inv}\,\mathcal L_{future\text{-}inv}.
$$

这里重构的是**效用优选动作**，不是 OR 路线 adjacency。若标签尺度不稳定，M0 先使用 state-normalized pairwise loss；M1 再加入 listwise masked reconstruction。

> **损失版本说明（2026-09-17）**：当前已运行的 M1-edge/compact 原型采用的是**连续效用 Huber 回归**（`y_a=-(J_a-J_keep)/s`），D 组额外使用 teacher 动作所得计划的可变邻接重构损失。它**不同于**本节提出的动作分布 KL + pairwise + future-invariance 方案。当前负结果仅适用于已运行版本，**不代表动作分布重构方案已经得到验证**。后续更换损失须单独记录版本，不得追溯改写已有实验。
>
> **口径与状态区分（2026-09-17 补充）**：已有监督标签是**「单动作干预 + 固定 continuation 下的终局成本差」**（不是即时 δ，`counterfactual_teacher` 已跑到终局）。m0_scale 补跑的 sequential（逐客户写回后完整轨迹终局差）与 local（baseline 轨迹上局部机会平均）是**不同统计对象**，比值不是迭代增益倍率，local≈0.016 也不是 K=1 在线策略的整条轨迹收益上限。已有 M1 原型包含掩码／重构及 K 轮在线循环的相关实现，但其与本节完整方法设计的一致性、实际闭环收益及组件增量尚未验证。是否必须更换监督时域、采用多轮重构须由因果闭环诊断单独验证；on-policy aggregation 不因本次 oracle 结果自动进入实施。

### 3.5 约束认证与迭代补救

在线推理：

```text
事件触发
→ 构造 causal snapshot 与冷链状态
→ 标记 affected mutable variables
→ 掩码并枚举 certified actions
→ MaskCO decoder 重构/排序动作
→ 应用完整 fleet action
→ 更新温度、品质、能耗与计划
→ 必要时继续下一轮 masked refinement
→ 无安全候选则恢复 complete incumbent
```

最终评价前固定轮数、预算和 fallback。共同 teacher 的候选共享 continuation；受控消融控制候选与搜索，整方法 baseline 可以不同搜索设计，但共同任务、信息、evaluator 与预算必须公平。

## 4. 当前研发顺序与历史路线

当前顺序为执行进度表 E0–E4：接口与版本 → 20 点 TRAIN 先导 → 有限完整计划标签/训练 → CAL/DEV 闭环 → MaskCO 机制及论文证据。详细预算、对照和两轮开发边界见 [event_plan_v1 执行协议](../工程实现/event_plan_v1执行协议.md)。下列 1–3 步保留为历史启动路线和可复用实现背景，不重启旧 M0 批次，也不再等待已完成的④/⑤许可。

1. 复用已完成 C0/teacher 原语，在新 TRAIN/DEV 导出完整候选标签；先小上下文计时。
2. M0 冻结 encoder 做短可学习性诊断，同时实现 M1 的 token、mask、decoder 与 replanner。
3. M1 从 K=1 到少量 iterative reconstruction；adapter-first，是否微调由 DEV 比较决定。
4. 并行收敛公开数据来源、模拟参数和强基线。开发用 pilot，最终版本统一 contract/profile 和标签。
5. 在最终模拟设定下完成模型/对照训练与 DEV 选择；锁定后做 TEST 主比较、关键消融与泛化。

M0 不是最终论文模型，也不是必须先显著通过的行政门槛。M2 仅在 offline/online 分布偏移时尝试，首轮预算 1–2 次聚合；追加研究记录依据，不从 TEST 回流。
O0-CC 仍可作动作诊断；无 headroom 要区分样本不足、候选限制与学习失败，不能把一次不显著解释为数学不可能。独立 ORACLE-VAL 是可选确认，不再挡住主模型研发。

## 5. 科研判断点，而非保证通过的 Gate

| 观察 | 下一步 | 结论限制 |
|---|---|---|
| 单位/因果/恢复错误 | 修受影响实现，做针对性回归 | 受影响性能暂不解释 |
| teacher 候选无差异或低 coverage | 查 KEEP、尺度、动作和采样 | 不立即扩大网络 |
| M0 训练可拟合、DEV 无信号 | 查泛化/标签噪声/表征，允许比较 adapter | 不称不可学习 |
| M1 有动作分叉、无在线收益 | 查错误接受、状态偏移和预算 | 不只报离线 accuracy |
| 某组件无增量 | 简化方法或调整主张 | 不能编造必要性 |
| 强基线更优或 seed 不稳定 | 查公平性、范围和效用–速度权衡 | 不宣称全面 SOTA |
| TEST 不支持主要优势 | 如实报告，重新定义后续研究 | 不循环换 TEST 直到赢 |

## 6. 待证实的论文贡献

- 因果的事件掩码重构：将静态 MaskCO 范式接入动态可见性与不可回滚执行。
- 冷链资源感知的车队—路线补救：thermal/fleet state 与置换感知 route slot 参与可执行计划重构。
- 反事实终局效用对齐：同 continuation 标签监督可部署动作，比较结构模仿、距离目标和冷链目标。

这是拟研究的贡献，不是已证明的新颖性或有效性。文献相关工作对照和组件消融仍需补齐。
物理模型本身无需创新；“比其他方法好”需明确是哪种任务、目标和预算，并由结果支持。

## 7. 历史结果的位置

JF2/HFR 负结果、B0/factorial 和旧 DynMaskCO 结果保留为动机/诊断。
pilot DEV-GATE v4 sequential GO（ΔJ=−0.2771，95% CI [−0.2848,−0.2696]）支持当前有限动作空间值得学习，不是主模型效果。
旧 committed-tail O0-D、旧品质减少 96% 和历史 distance 数字不能混入当前冷链主表。历史详细数值见实验结果总表。

## 8. 必要证据如何安排

核心消融：pretrained vs generic/feature-only；event vs no/random mask；iterative vs one-shot；thermal state true vs removed；joint vs distance labels。
扩展消融按疑问安排：quality/energy 分解、slot/position、shuffle labels、on-policy aggregation、候选覆盖。
整方法可以不同搜索设计；单组件归因控制候选、预算、fallback 和配对实例。
归因结果不支持冷链感知或 MaskCO 增量时，不保留未支持的强主张；可继续改进或据实简化方法，不把结果不好视为必须强行“修到显著”。

## 9. 现在允许做什么、不能声称什么

允许：开展冻结评分器接口审计（④）与正常 DEV 选择、检索公开资料、建立透明假设与敏感性、在新版本下改进模型；⑤闭环诊断在④通过且运行协议固定后执行。M0/M1 训练、K 搜索与 on-policy aggregation 另立协议与预算，不作为当前执行授权。
不能声称：event_plan_v1 已经实现/有效、已有原型已优于强基线，certificate 保证未知未来全部完成，仿真等于实车验证，文献引用自动完成物理标定。既有 M0/M1 原型已实现并运行的事实仍保留。
不覆写旧归档/结果；开发变更保留版本，不为改文档重新冻结全部源码。
论文主要对象仍是动态冷链算法，不是数字孪生、食品实验或生产平台建设。

## 10. 论文定稿的依据

最终可复现方法、明确模拟设定/来源和局限、强 baseline 公平对比、可解释归因、跨场景/规模/seed 结果、未用于选择的 TEST、全部运行/失败与统计材料。
正式以 5 个学习 seed 为目标，样本量和实际预算在最终评测前确定，不按显著性增删。
是否足以投稿取决于新颖性、证据质量和贡献范围；不存在“做完工程清单必然发论文”的保证。
