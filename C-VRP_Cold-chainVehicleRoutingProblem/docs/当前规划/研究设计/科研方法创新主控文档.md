> 本文件决定论文问题、最终方法、创新贡献、证据链与 Go/No-Go。  
> 核心原则：锁定动态冷链主线，只把已通过测试的 C0 层写成实现；pilot 参数与历史代理口径不得写成论文效果。

## 0. 主线与当前判断

论文研究问题固定为：

> **如何把 MaskCO 面向静态解的掩码生成与迭代重构，扩展为面向动态冷链物流的因果、车队级、约束可行且终局效用对齐的在线优化方法？**

最终方法暂命名为：

> **DynMaskCO-CC: Utility-Aligned Causal Masked Generation for Dynamic Cold-Chain Vehicle Routing**

Cost-aware preference learning 是解决“结构可学但部署无效”问题的内部监督机制。最终论文方法不能停在 frozen MaskCO encoder + MLP；必须让事件掩码、重构和迭代改进真实参与在线决策，并通过 MaskCO 身份消融证明其必要性。

当前阶段不是论文收尾。P0-R/S/A/U/P0-M/C0 已完成；C0 功能/口径 20/20、pilot sensitivity 7/7，旧物理已退役或显式降为非权威代理。O0-D（旧 scope sanity）与 O0-CC DEV-GATE v4（verdict GO）已完成；当前进入 **CAL-PHYS 现实校准**，之后才是新 DEV 重确认 → 冻结 O0-CC VAL → M0 和 M1。P0-M/C0 工程 Gate 不构成方法性能证据。

## 1. 问题定义：动态冷链车辆路径优化

事件 \(e\) 到来时，订单逐步揭示。部署策略仅能访问 filtration：

$$
\mathcal F_e=\sigma(
\text{revealed orders},
\text{executed trace},
\text{fleet state},
\text{committed legs},
\text{observable cold-chain state},
\text{public parameters}
).
$$

策略必须满足 \(a_e=\pi_\theta(\mathcal F_e)\)。未揭示订单不得通过坐标归一化、节点/边特征、候选集、温度统计、future cardinality 或缓存泄漏。

### 1.1 运营语义

主实验固定为 **dynamic cold-chain pickup-to-depot**。车辆从中心仓库空载出发；动态订单表示客户处待取的冷链货物；服务完成时货物进入对应温区并使载重增加；返仓时统一卸货并关闭车辆。每车单次行程，不允许 multi-trip 或 depot reload。

订单状态为：

```text
unknown → revealed → planned/committed → picked → delivered_to_depot
```

主设置假定客户处货物在取货前由外部合规冷库保管，取货前品质变化不受本策略影响；策略相关品质计时从 `service_finish` 开始，到所属车辆 `return_arrival` 结束。这样，在途插入新揭示订单不需要假设车辆预先装有未来货物，也与现有容量状态转移一致。若另做 depot-to-customer 配送，必须建立新的装货/ownership/reload 协议，不能沿用本论文主结果。

### 1.2 决策对象

事件状态包含：

- 已揭示客户、需求、时间窗、服务时间和温区；
- 每车位置、时间、容量状态、已执行前缀、committed leg 和有序 mutable suffix；
- 每车或每温区的可观测温度状态、累计能耗、分温区载重和订单级 cargo manifest；
- 每个在途订单的取货完成时刻、当前剩余品质与最终返仓品质；
- 当前 incumbent full-fleet plan；
- 事件、随机性和 evaluator 的可恢复元数据。

最小可部署动作仍为 \(a=(j,s,p)\)：将当前已揭示且未取货的客户 \(j\) 放入置换感知 route slot \(s\) 的位置 \(p\)。M0 可固定客户顺序以验证表示；最终 M1 通过事件掩码决定需要重构的客户/路线变量，并顺序或成组地产生动作。

### 1.3 约束

硬约束至少包括：

- 所有订单恰好取货一次，所有货物最终运回仓库且终局 cargo manifest 为空；
- 时间窗、容量和返仓；
- executed prefix 与 committed leg 不可改变；
- 未揭示订单不可进入当前动作；
- 冷链车辆/温区兼容约束；
- C0 明确冻结的温控阈值约束。

“feasibility-preserving”只指当前动作经完整 route/fleet replay 后满足已定义硬约束；未知未来的全局 completion 仍由完整 rollout 和 fallback 经验验证。

### 1.4 双目标口径

历史兼容指标保持：

$$
J_{dist}=D,
$$

其中 \(D\) 是所有已用车辆含返仓的纯行驶距离，工程字段始终为 `distance_cost`。

论文冷链目标定义为：

$$
J_{CC}
=
\widetilde D
+\lambda_Q\widetilde Q
+\lambda_E\widetilde E,
$$

令 \(q_i^{0}\) 为订单初始品质，\(q_i^{dep}\) 为返仓卸货品质，\(w_i\) 为由货量与产品价值确定并在合同中冻结的权重，则主品质分量为：

$$
Q=\sum_i w_i\left(1-\frac{q_i^{dep}}{q_i^0}\right).
$$

\(E\) 是从车辆 dispatch 到 return 的 trace-level 制冷能耗（kWh）。归一化基准、权重、不可售阈值和单位在 C0 用 train/dev 冻结，工程字段为 `coldchain_cost`。主表同时报告原始 \(D,Q,E\)、不可售订单数和温度越界，禁止只报一个复合分数。

服务与硬约束先按 lexicographic vector 比较：

$$
H=(n_{\mathrm{unpicked}},n_{\mathrm{duplicate}},n_{\mathrm{not\text{-}depot\text{-}delivered}},n_{\mathrm{TW}},n_{\mathrm{cap}},n_{\mathrm{return}},n_{\mathrm{temp\text{-}hard}}).
$$

只有 \(H\) 相同且为零，才比较 \(J_{CC}\) 或 \(J_{dist}\)。

## 2. 为什么仍然基于 MaskCO

已有负结果给出的是监督错位，而不是 MaskCO 范式失效：

- JF2 表明 physical vehicle ID 受同质车辆置换歧义影响；
- HFR 表明 route/partition 结构可学，但静态 adjacency/structure target 与实际 insertion utility 不一致；
- B0 与 factorial 表明 fleet allocation 主导且 partition×sequencing 存在耦合；
- 因此应重构“被掩码变量”和“重构目标”，而不是放弃掩码生成。

原始 MaskCO 的核心是“掩码部分解变量—重构缺失变量—迭代改进”。DynMaskCO-CC 对应改进为：

| MaskCO | DynMaskCO-CC |
|---|---|
| 静态完整实例 | 事件时刻的 causal visible state |
| 掩码静态解边 | 掩码受事件影响的 mutable fleet–route variables |
| 重构参考解结构 | 重构冷链终局效用更优的可部署动作/计划片段 |
| 无执行历史 | executed/committed 部分永久冻结 |
| 静态可行性 | 车队、时间窗、容量、返仓与冷链状态 certificate |
| 结构 CE | 由反事实 \(J_{CC}\) 产生的 listwise/pairwise utility target |
| 多轮 refinement | 每次 reveal 后的 event-conditioned masked recourse |

## 3. DynMaskCO-CC 方法结构

### 3.1 因果动态编码

使用现有 DynamicColdChainModel 的 visible-only normalization 与 visibility-gated attention 作为底座。输入增加当前可观测的 fleet/thermal tokens，但未来订单相关冷链信息必须同样被遮蔽。

节点表示 \(H_e\) 与 fleet/thermal state 共同形成状态表示。MaskCO 预训练权重可先冻结作 M0 探针；M1 只通过 adapter 或分阶段 fine-tuning 接入，避免一次改变过多变量。

### 3.2 事件影响掩码

每个事件构造 \(M_e\)，只覆盖：

- 新揭示客户；
- 因新客户而失去余量的 route suffix；
- 温度、品质或能耗风险越过预警阈值的 mutable segment；
- 明确由 replan reason 标记的 route slots。

executed prefix、committed leg 和 future orders 永不进入可写掩码。必须保留 full-mask、random-mask、no-mask 和 shuffled-mask 消融。

### 3.3 置换感知的车队—路线动作

route slot 定义为 anchored slots 与匿名 NEW_ROUTE。只有 anchor、可用时间、温度、分温区载重和 cargo manifest 都等价的同质车辆才能匿名折叠；物理车 ID 只在动作选定后确定性匹配，不作为监督标签。

候选 action token 至少包含 customer、slot、predecessor、successor、局部余量和冷链状态差分。所有候选必须经同一 Action Contract 与冷链 certificate；模型仅在 certified set 上重构。

### 3.4 冷链效用对齐的掩码重构

对同一 state 的候选动作进行 common-continuation rollout，得到：

$$
Y_{CC}(z,a)=(H,J_{CC},D,Q,E).
$$

先选 terminal hard outcome 最优的候选子集

$$
\mathcal A^{bestH}(z)=
\{a:H(z,a)=\operatorname*{lexmin}_{b\in\mathcal A^{feas}(z)}H(z,b)\},
$$

再用冻结温度 \(\tau_T\) 将该子集转成效用软目标；其余候选概率为零：

$$
p^*(a\mid z)
=
\frac{\exp[-J_{CC}(z,a)/\tau_T]}
{\sum_{b\in\mathcal A^{bestH}(z)}\exp[-J_{CC}(z,b)/\tau_T]},
\quad a\in\mathcal A^{bestH}(z).
$$

Masked action decoder 输出 \(p_\theta(a\mid z,M_e)\)。核心损失为：

$$
\mathcal L
=
\lambda_{list}\,\mathrm{KL}(p^*\Vert p_\theta)
+\lambda_{pair}\,\mathcal L_{pair}
+\lambda_{inv}\,\mathcal L_{future\text{-}inv}.
$$

这里重构的是**效用优选动作**，不是 OR 路线 adjacency。若标签尺度不稳定，M0 先使用 state-normalized pairwise loss；M1 再加入 listwise masked reconstruction。

### 3.5 约束认证与迭代补救

在线推理：

```text
事件触发
→ 构造 causal snapshot 与冷链状态
→ 标记 affected mutable variables
→ 掩码并枚举 certified actions
→ MaskCO decoder 重构/排序动作
→ 应用完整 fleet action
→ 更新温度、品质、能耗与计划
→ 必要时继续下一轮 masked refinement
→ 无安全候选则恢复 complete incumbent
```

最终接受策略应冻结轮数、预算和 fallback；不能在不同方法间使用不同 candidate 或 continuation。

## 4. 分阶段方法，而不是一次堆叠

### C0：冷链契约

运营抽象已冻结为 pickup-to-depot、同构多温舱、共享总容量、单次行程且无 reload。C0 实现订单级 cargo manifest，统一时间、距离、功率、能量、温度和品质单位，建立唯一状态转移与 trace evaluator，并修复当前 J→kWh、温度依赖品质、trace 返回零值以及 normalized temp_class 等问题；物理参数和硬/软温控边界仍须用 contract 冻结。

### O0-D：距离动作 oracle

在现有 Action Contract 上验证 distance-only sequential oracle。它是协议与动作空间 sanity check，不是最终科学目标。

### O0-CC：冷链动作 oracle

同一 candidate、transition 和 continuation 下改用 \(Y_{CC}\)。若 sequential oracle 在 100% service 下不能改善 \(J_{CC}\)，先扩 lookahead、two-customer 或 batch action；禁止直接训练更大网络。

### M0：MaskCO 表征探针

冻结 causal MaskCO encoder，仅训练冷链 utility head，回答“现有 MaskCO 表征能否预测 \(J_{CC}\)”。M0 可以 Go/No-Go，但不能作为最终论文方法。

### M1：DynMaskCO-CC 最小完整方法

接入 event mask、masked action decoder、utility target 与 1–K 轮重构；先训练 adapter/decoder，主 Gate 正后才允许部分解冻 encoder。

### M2：按需 on-policy 聚合

最多 1–2 轮，收集 first-divergence、高 regret、fallback 和高冷链风险状态，重新生成相同合同的标签。若 M1 状态覆盖充分则可以不做，但须用数据说明。

## 5. Go/No-Go

| Gate | Go | No-Go 后动作 |
|---|---|---|
| C0 | pickup/manifest 生命周期、单位、单调性、snapshot/resume、trace evaluator parity 全 PASS | 修运营/物理/状态合同，不进入 oracle |
| O0-D | 100% service，distance 有可解释 headroom | 检查/扩 action |
| O0-CC | 100% service，paired \(\Delta J_{CC}<0\)，CI 不跨 0 | 扩冷链相关 action/lookahead |
| M0 | Real label regret 优于 shuffle/generic，on-policy 有信号 | 查标签、特征或 MaskCO 表征 |
| M1 | 100% service，\(J_{CC}\) 优于 JF1-H-CC，距离退化在预注册预算内 | 查 mask/action/训练分布 |
| A1 | MaskCO、masking、cold-chain state、joint action 四类归因均成立 | 收紧贡献或重构方法 |
| E1 | 多场景与多 seed 稳健 | 收窄适用范围，不夸大 |

## 6. 三项论文贡献

1. **面向动态冷链的因果 MaskCO 扩展**：把静态掩码重构改造成可见性门控、事件触发、冻结执行前缀的动态生成过程。
2. **冷链资源感知的车队—路线联合掩码补救**：使用携带温度、分温区载重和 cargo manifest 的置换感知 route slots 与完整 fleet action，在容量、取货时间窗、返仓与冷链约束下重构可执行计划片段。
3. **面向终局冷链结果的反事实效用对齐**：使用共享 continuation 的 counterfactual rollout 监督 masked action reconstruction，直接学习距离、品质和能耗的长期影响。

温度动力学本身不必宣称为新的物理理论；创新在于它与因果 MaskCO、动态动作、完整轨迹监督和严格评价形成闭环。

## 7. 历史结果在论文中的位置

- JF2：作为 vehicle-symmetry 与 label ambiguity 诊断；
- HFR：作为 structural learnability 与 online utility 不一致的诊断；
- B0/factorial：作为选择 coupled fleet–route action 的实证动机；
- 旧 Phase-3c 结果：仅作历史演进，不进入修复协议后的主性能表；
- P0-R/S/A/U：作为方法可靠性与可复现基础设施。

不能声称 G 已有独立 downstream 正效用，也不能说所有 route signal 本质无用。

## 8. 必要归因

### MaskCO 身份

- pretrained MaskCO vs random/generic encoder；
- real event mask vs no-mask/random-mask/shuffled-mask；
- masked iterative reconstruction vs one-shot utility scorer；
- frozen encoder vs adapter/partial fine-tune。

### 冷链机制

- \(J_{CC}\) labels vs distance-only labels；
- true thermal state vs removed/shuffled thermal state；
- quality-only、energy-only、distance-only 与 joint；
- 温度压力、温区分布和权重敏感性。

### 动作与监督

- joint \(slot,p\) vs slot-only/insertion-only；
- real counterfactual labels vs shuffle；
- offline-only vs on-policy aggregation；
- candidate/lookahead coverage。

如果 MaskCO 相关消融不成立，论文不能使用“基于 MaskCO 方法改进”为核心贡献；如果冷链消融不成立，暂停主论文并修复 C0/M1，不能退回 generic CVRPTW 后沿用 DynMaskCO-CC 标题。

## 9. 当前允许与禁止的主张

当前允许：

- 论文目标已锁定为基于 MaskCO 的动态冷链优化；
- strict-online P0-R/S/A/U 与新目录兼容 P0-M 已完成；

- O0-D/O0-CC 完整通过前不得进入 M0/M1。

当前禁止：

- pilot quality/energy 已形成论文可用的最终参数闭环；
- DynMaskCO-CC、M0 或 M1 已实现/有效；
- action-level certificate 保证所有未来订单完成；
- 只用 frozen MaskCO encoder 即证明方法是 MaskCO 改进；
- 用复合成本掩盖距离、品质或能耗单项退化；
- 使用旧“品质减少 96%”作为当前论文证据。
