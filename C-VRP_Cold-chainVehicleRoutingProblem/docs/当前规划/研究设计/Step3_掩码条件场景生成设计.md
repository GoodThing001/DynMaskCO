## 2. 改后的论文主张（verifier 1 的救法 + GPT6.sol 收紧 2026-09-23）

**不称"场景生成是文献空白"**（条件事件生成 AAAI、多场景动态规划 Bent & Van Hentenryck 2004 已存在）。诚实主张：

> **预训练 MaskCO 表征改善动态冷链承诺的条件场景前瞻**——复用冻结 encoder 的表征带来可复现的闭环决策增益。

证明方式 = 四对照（冻结 H / 随机 H / 显式特征 / 基于 H 的 k-NN），在同一完整决策器（路由 + TW + 冷链轨迹）下比 k-NN 配对差值。**"k-NN 捕 89%"是简化逐单能耗+背包门的启发式数字，不是完整任务增益上限，真 3b 先重测。**

### 三处实验细节（GPT6.sol，采纳）
1. **先采未来订单数，再掩码生成订单 token**（避免 200 槽 + null 主导训练；每单再采桶内坐标/需求/TW）。
2. **同刻可见状态**：模型条件随订单揭示更新，k-NN 查询同步，否则比较解释不清。
3. **单独检验冻结表征**：同生成头、同训练预算，比较冻结 H / 随机 H / 显式特征 + H-kNN。
4. **坐标扰动两阶段**：先离散 token（时间桶×温区×spot），采样后从历史同桶经验分布取连续坐标扰动；模型若赢再测学习连续残差。

## 3. 为什么必须 3b（verifier 2 的硬条件）

要 material 赢 k-NN，必须同时满足：

1. **高维状态**（让 k-NN 方差爆炸）→ 条件用完整可见订单多重集（time×class×location），不是 3 计数。
2. **策略消费结构**（让学到的联合场景变现）→ accept/reject 评估完整冷链目标（路由 + Arrhenius 衰减 + 能耗），不是 class 计数。

两者都指向 3b。

## 4. 3b 设计

- **场景** = 未来订单多重集（每单 time×class×location×window）。
- **条件** = 完整可见状态（已揭示订单多重集 + 时钟 + 车队）。
- **目标（绿色低碳作约束）** = `最大化 服务收益 − Arrhenius 品质衰减 − 距离`，**约束 = 制冷能耗 ≤ 绿色预算 E_budget**（+ 容量）。
- **策略** = 每场景贪心插入路由 + C0 物理（`coldchain_state`）评估（收益/腐损/距离 + 能耗约束可行性）→ opportunity cost → accept/reject。
- **模型** = 集合不变掩码生成（DeepSets / set-attention，**禁位置编码**）；每单 token = (time×class×location 离散桶)；**按天内多决策时刻切片**训练（非每天一例）；复用 MaskCO 冻结 encoder 作订单/状态编码器；leave-one-day-out。
- **基线** = myopic / 无条件 bootstrap / k-NN 条件 bootstrap（同状态同预算、CV 选 k）/ oracle。
- **统计** = 按天聚类配对 bootstrap；报告 per-class 计数校准；MaskGIT softmax 采样（非 argmax，避免欠离散）。

## 5. 冷链 material 如何保住

3b 里 accept 决策依赖"已接订单的联合路由 + Arrhenius 衰减成本 + **能耗预算约束**"——冷冻订单晚送的凸爆炸代价、以及能耗预算在不确定需求下的分配，使决策价值函数冷链接专属 + 绿色 load-bearing（物理是决策的绑定资源，不是评估器装饰）。此点仍需在 3b 中演示（不是断言）。

## 6. 落地顺序（无训练先行）

1. **全订单 DGP**：扩展 step2 的 DGP 到每单 (time, class, location, window)，location 影响路由成本（纯 NumPy）。
2. **策略评价器**：给定场景 → 贪心插入路由 + C0 物理 → J（复用 `coldchain_state` + `visible_state` 的贪心补全逻辑）。
3. **无训练再验证**：先用 k-NN 条件 bootstrap 跑通 3b 的完整策略，确认"高维状态 + 结构变现"下仍有因果头腔（承重假设在 3b 语义下的复验）。
4. **才训练**：集合不变掩码生成器 + 复用冻结 encoder，对比 k-NN。
