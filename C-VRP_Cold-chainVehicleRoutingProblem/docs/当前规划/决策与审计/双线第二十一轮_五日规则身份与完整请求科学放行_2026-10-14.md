# 双线第二十一轮：五日规则身份与完整请求科学放行

本轮没有重采、重训或重跑旧失败。新增只读独立核查脚本 `tools/audit_dual_science_release_r19.py`，对已封存登记、结果、审计和配送真实请求时钟重新计算并写入 `research/review_3080_20261010/goal_round_20261014_r19_science_release/RELEASE_AUDIT.json`。脚本核实取货五个逐日配对差、原登记与执行规则的机制身份、配送两个真实请求的最后完整阶段；所有输入均记录 SHA-256。**至少一线稳定、可归因的 MaskCO 核心在线正向增益仍未建立。**

取货五日同期对照的差值为 `[0, 102.92300423234701, 24.755533065646887, 0, 0]`，均值 `+25.53570745959878`。这是预算接拒**非学习规则**的开发线索，只有2/5日活跃。以两个非零差作条件符号翻转，单侧描述性尾概率为 `0.25`；五日并非随机抽样的正式确认集，不能把这个数当预登记显著性结论。原独立审计仍为61项中2项FAIL，失败分类附录维持原样。

发现更严格的方案身份问题：最初 `A1_BUDGET_RESERVING_ADMISSION_PREREGISTRATION.json` 冻结的接拒条件是 `e_lower(i) <= B_remaining - reserve_for_future(clock, history)`，而实际五日 v4 采用 TRAIN 标定网格的最小影子价格，并以 `REV(i) - lambda(clock) * e_lower(i) > 0` 决定放行。这两个条件不等价。v4 自有登记在其面板执行前固定，故同期差值仍是可审计的探索性信号；但原“正均值即另扩到40个旧日”的条款不能把**变更机制后的旧40日**自动升级为原规则的确认实验。不能悄悄改旧登记或把这40日称作新鲜独立日。下一科学投入应先就具体候选动作、TRAIN/新鲜研究日隔离、同期已训CE/随机及独立强动态接拒作新的数据前登记，再评估增益；现在不派发40日生产。

配送真实分段头两臂均在stage6完成25步插入链与C0选择，但距8秒子请求截止只剩 `1.2212045`、`1.1643939` 秒，随后均未形成合格响应、发布数0，且旧独立分段审计51项中50项FAIL保留。此前旧8903文件源哈希单独耗时5.618649秒，四分片合成负载也只2/4在截止前完成；这些测量不能相加成正式请求下界，却明确显示继续把同一源门塞在stage6之后没有已证实的预算余量。下一配送工程须事前设计**真实完整请求**的源/参数/动态闭包与发布门位置，满足8秒执行加2秒回收，再做独立严格核查。合成分片和初始头不满足此门；科学第3族不启动。
