# 双线第十四轮：独立接拒后学习提议与分段评分头

本轮仅闭合两个固定旧状态上的工程接口和算术身份，不产生新研究日或在线效用估计。两线稳定、可归因的 MaskCO 核心在线正向增益仍未建立。取货权威旧终局 callback80/pending 空未再推进；配送第2科学族 FAIL 保持封闭，第3族未开始。

## 取货：独立接拒后的模型提议

输入固定为第十二轮自然到达的订单77、独立接拒已接受后的公开 `scoring_packet`。两臂分别加载原 CVRP checkpoint 参数和同架构 seed42 随机参数；同一掩码 seed、0.3 掩码比例、历史条件采样 K10、C0 认证及10秒请求窗。模型初始化和预热形状3–13在请求钟外，提议、共用场景评分、认证及源检查在钟内。注册文件和输入 SHA 在执行前保存；没有按订单成本或输出选样本、权重或头。

首次 `learned_after_strong_root_v1` 原件两臂均因共用评分器把当前 `SaaReplanner` 不接受的 `anytime_vote` 传入构造函数而异常退出；父端约0.9秒回退原计划。保留原 `RESULT.json`、两个 `RAW.json`、源码和失败返回，不写成超时合格。新 v2 仅在评分器新副本删除这个不被当前签名接受的关键字，其他固定输入、模型、种子和 K10 不变；事前 `PICKUP_RECOVERY_REGISTRATION.json` 绑定原失败和两份新源码。

v2 两臂模型初始化分别53.651和52.895秒，请求实际2.621和2.450秒，均按时返回、worker回收、源与checkpoint始末哈希一致、原完整 C0 证书及10条影子分支合格。两臂各实际调用 encoder/decoder 一次、参数哈希及 logits 哈希不同，但**产生完全相同的路线候选**：车0 `[77,40,32,30,69]`、车1 `[25]`、车2空。原计划车0是 `[77,40,25,32,30,69]`。同一历史场景下原计划影子均值544.3634805、候选550.9520251，故两臂都选择候选；这只是影子差约+6.5885，且两臂同动作，不能归因于学习，也不是实际在线效用。新进程独立保存原件审计24项0失败，旧v1失败仍保留。

这项闭合了“独立接拒先行后，模型能提出并由共用认证选出计划”这一旧状态的组件路径。它没有现场公开提取、私有所有者完整安装与回滚、全请求10秒、正式同初始化已训CE/同任务已训随机、连续独立强动态接拒或多日收益资格。当前 checkpoint 身份字段 `checkpoint_step=0`，不把此臂称为正式训练控制。

## 配送：分段评分头的严格算术身份

第十三轮的一个固定保存输入已定位：原动态516行与定形750行的动作特征、第一层线性与激活逐位相同，末层3个分数不同。本轮在旧生产34份保存输入**执行前**固定一个新候选：第一层始终算到750行，取原动作数 `n` 行后再调用原末层。源、原头、34份输入各 SHA、seed20261012、750行和逐位门均登记；无主干前向、解码器、C0、训练或旧编译候选复跑。

新候选在两初始化臂各17步、总34输入/21,148个动作上与原动态头 float32 位模式全等（34/34，差0）；独立另进程按原层实现重算及逐文件哈希审计141项0失败。旧“整头750行”的34/34严格 FAIL 保持，不能把它改成 PASS。本候选只通过**已保存评分输入算术**；尚未在3080完整主干、真实逐步部署或8秒执行+2秒回收内测得完整链，发布前参数/依赖检查和硬C0、所有正式控制仍待。不得据逐位等价推断运行更快或有效用增益。
