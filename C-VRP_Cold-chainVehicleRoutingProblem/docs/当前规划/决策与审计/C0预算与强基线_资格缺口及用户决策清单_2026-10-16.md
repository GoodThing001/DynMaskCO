## 1. 认证器入口与调用链（静态事实）

### 1.1 `certify_plan` 的实际位置与签名

**唯一定义**：`C-VRP_Cold-chainVehicleRoutingProblem/scripts/evaluation/run_exp_energy_c0.py:154`

```python
def certify_plan(env, inst_idx, clock, vehicles, served_mask, plan, contract, B):
    """硬预算认证：完成当前 plan 的真实 C0 能耗 ≤ B（含 committed leg + WAIT 到 booking_end + 返仓）。
    plan = {vid: 未执行订单 route}。返回 (feasible, total_energy_kwh)。"""
```

**关键事实**：`certify_plan` **没有** `certifier` 参数——**它本身就是能源认证器**，且**只认证能源**。

**调用点**（各调用方传入的预算来源）：

### 1.2 "认证器"是两层，不是一层

源码自述（`simulation/d3_composed_certifier.py:9`）：

> `certify_plan (run_exp_energy_c0.py:154-199) certifies the C0 ENERGY BUDGET ONLY and is a pure function. It does not check time windows or capacity (action_contract.certify_route), ownership or commitment ... or plan reconciliation`

| 层 | 位置 | 检查内容 |
|---|---|---|
| (a) 能源认证器 | `certify_plan`（`run_exp_energy_c0.py:154`） | **仅能源预算** `total <= B + 1e-9`（`:199`） |
| (b) **组合认证器（真正的门）** | `compose_certification`（`d3_composed_certifier.py:55`） | `CERTIFICATION_CHECKS = ('repair_plan', 'full_partition', 'route_feasible', 'energy_budget')`（`:38`）；`installable = bool(ok and not blocking_gaps)`（`:298`） |
| (c) 可注入 `certify_fn` | `d3_geo_adapter.py:405`（默认 `None`）、`d3_l1_two_arm_protocol.py:310,385`（默认 `None`） | 身份被记录；**"没传" ≠ "通过"** |

**🔴 关键负面事实（必须记录）**：全仓库检索 `certify_fn=certify_plan` / `certify_fn=compose_certification` / `certify_fn=*certif*`
—— **没有任何生产调用点注入真实认证器**。唯一的非 `None` 注入都是**测试用假认证器**
（`_test_only_deterministic_certifier` 自述 `It is NOT certify_plan, it certifies nothing physical`）。

L1 正式运行传的是 `certify_fn=None`（`d3_l1_l1_formal_run.py:469`），
理由字符串：`'L1 V3 is NOT_RUN by pre-registration: no certifier, no install'`。
**这正是 L1 的 V3 全为 `NOT_RUN` 的代码级原因。**

⇒ **L2 若要做"完整 C0 认证"，必须先解决"生产路径上没有一个被注入的真实认证器"这一事实。**
这不是预算问题，是**接线问题**，且**必须先于预算裁定或与之同时解决**。

### 1.3 各项检查的路径

| 检查 | 位置 | 行为 |
|---|---|---|
| **时间窗** | `action_contract.py:184-187` | `arrive > tw_end + 1e-6 → (False, 'tw')` |
| **容量** | `action_contract.py:188-193` | `load > capacity + 1e-6 → (False, 'capacity')`；接单侧更严：`capacity - 1e-4`（`run_exp_energy_c0.py:253-254`） |
| **返仓** | `action_contract.py:198-202` | `return_slack < -1e-6 → (False, 'return')` |

| **品质/可售** | `d3_composed_certifier.py:283-289` | **不是可执行的决策期检查**：返回 `QUALITY_CAPABILITY_GAP` 并把 `quality_salability` 放进 `blocking_gaps` ⇒ `installable=False`（`:280-282`：`A PASSING PROJECTION therefore changes NOTHING here`） |

**🔴 已记录的静默行为（源码自述）**：`c0_completion_energy` **不会**拒绝时间窗违规——

该行为在 `d3_composed_certifier.py:17-19` 被记为 **F1**。⇒ 时间窗必须由 `route_feasible` 把关，
**不能**依赖能源认证器。

### 1.4 组合认证器的顺序（事实）
