## 0. 继承自 S-8 的两项资格修正（按独立审查意见，登记而非重启 G-2）

### 0.1 `k` 的措辞更正：**有**源码结构上界，**没有**已认证的实用紧上界

我在 S-8 勘误里写"`k` **没有**源码上界"，**该措辞不准确**，就地更正：

| 表述 | 正误 |
|---|---|
| `k ≤ n_edge_perturb = max(1, int(N²·p·0.3))` | **成立**（`generate_coldchain_data.py:103-106` 的显式计算）⇒ 存在**有限的源码结构上界** |
| "`k` 无源码上界" | **撤回** |
| "存在**已认证、足够紧、可直接用于生产**的逐边重复次数上界" | **不成立**（N=51,p=0.1 时上界 78 ⇒ `5^78`，解析界空转） |

登记结论：**`K_HAS_STRUCTURAL_BOUND / NO_CERTIFIED_TIGHT_BOUND`**。
`long_tail_perturbation` 模型仍要求**声明的 k**（未声明 ⇒ `PERTURB_MULTIPLICITY_UNDECLARED`），
这一点不变。

### 0.2 浮点裕量：`4·2^-52` **不足以**覆盖执行器的数值误差

仓库的数值链**不是全程 binary64**（已实测，见下表）：

| 事实 | 证据 |
|---|---|
| 坐标是 `np.float32` | `generate_coldchain_data.py:74` |
| 欧氏距离矩阵由 float32 运算生成 | `:76-78`（`diff/sqrt` 均为 float32） |
| 非对称分支在此之上乘以 float64 噪声 | `:84-89`（结果 float64） |
| 扰动分支逐条 `*=` float64 | `:141-143` |
| 批量落盘统一转 float32 | `:324`（键名含 `dist_mat` ⇒ `np.float32`） |
| env 读入后仍转 float32 | `strict_online_env.py:187` |
| **实测**：npz 中 `dist_mat.dtype = float32`，且 `max|dm − euclid_float32| = 0.0` | 本机 `data/m0_scale` 三份 |
| **实测**：`float32 / python float → float64`；`python float + np.float32 → float64` | numpy 1.26.4 |

因此：

- **存储值**只有 float32 精度：相对误差 ≤ `2^-24 ≈ 5.96e-8`；
- **运算**在 promotion 之后是 float64：相对误差 ≤ `2^-52 ≈ 2.22e-16`；
- 我给出的 `(1 + 4·2^-52) ≈ 1 + 8.9e-16` 比覆盖**一次 float32 舍入**所需的量小约 **6.7×10⁷ 倍**。

**这不推翻 K-1…K-8 的反例**，也不否定 96 个实例的测量；它意味着**新的条件化解析上界
不能升级为覆盖 float32 执行器的已证明浮点上界**。登记两个标签：

```
ANALYTIC_REAL_BOUND_CONDITIONAL
FLOAT_EXECUTOR_OUTWARD_BOUND_NOT_ESTABLISHED
```

**影响量化（诚实说明）**：在登记域最大边 1.2763 处，一次 float32 舍入的绝对量约 `6e-8` h；
而 L1 slack 是 `1.07e-9` h —— 也就是说**缺口的绝对量比 slack 本身还大一个数量级**。
这不改变任何已记录的 slack 数值（slack 只经 `ulp_ceiling(T_clock_sup)` 的 binade 取值，
`T_clock_sup` 变化 1e-7 **不会**跨 binade），但它证明"外扩上界已建立"这句话**不能写**。
若要建立，需要：逐路径枚举 float32 舍入点 + 以 float32 尺度（`2^-24`）外扩 + 与执行器
dtype 身份绑定；本轮**不做**（用户意见：不重启 G-2）。

## 1. 已核实的源码事实与主反例

### 1.1 `plan_hash()` 绑定什么

`action_contract.py:301-309`：

```python
def plan_hash(plans):
    h = hashlib.sha256()
    for vid in sorted(plans):
        p = plans[vid]
        h.update(str(vid).encode())
        h.update(str(p.anchor_node).encode())
        h.update(repr(tuple(p.suffix)).encode())
    return h.hexdigest()[:16]
```

绑定了 `vid` / `anchor_node` / `suffix`；**未绑定** `anchor_time`、`anchor_load`；
返回**截短 16 hex**（64 bit）。而 `VehiclePlan`（`:67-73`）**有**这四个字段。

### 1.2 `plan_identity_v2()` 绑定什么

`m1b_immutable_snapshot.py:47-53`：包含四字段，但

```python
round(float(getattr(p, 'anchor_time', 0.0)), 12),
round(float(getattr(p, 'anchor_load', 0.0)), 12),
```

返回值是**完整** sha256。在 24.0 处 `ulp ≈ 3.55e-15`，而 `round(x,12)` 的舍入半径 `5e-13`
⇒ **≈ 141 ulp** 的漂移被吸收（实测 `ulp / radius = 0.0071`）。

### 1.3 主反例（只读实测，`G3_DEFECT_REPRODUCED` 9/9）

同一 `vid=0`、`anchor_node=7`、`suffix=(3,5,0)`，只改 `anchor_time` 与 `anchor_load`：

| | 认证计划 A | 实际安装计划 B |
|---|---|---|
| `anchor_time` | `24.0` | **`30.0`**（晚 6 小时） |
| `anchor_load` | `12.5` | **`25.0`**（翻倍） |
| `action_contract.plan_hash` | `6c83833a6d143f50` | **`6c83833a6d143f50`（相同）** |
| `m1b_immutable_snapshot.plan_identity_v2` | `e7c9df932e82cd55…` | `7c018ac2d2949697…`（不同） |

**"认证 A、安装 B，旧身份相同"已确立。** 缺陷到达安装边界：
`d3_geo_adapter.py:151-152` `from action_contract import plan_hash; return plan_hash(plans)`，
全文件 21 处引用，`certified_plan_hash` / `installed_hash` 两侧都由它算出。

### 1.4 边界（保持发现窄且可否决）

`plan_hash` **确实**能分辨：suffix 变化、`anchor_node` 变化、车辆集合变化（G-08）。
所以 G-3 要做的是**绑定缺失的两个字段并给出唯一来源**，不是推翻现有编码。

### 9.1 新缺陷：跨字段拼接歧义（确定性，非概率碰撞）

`action_contract.py:303-308` 把三个字段**首尾相连**地喂进同一个 `sha256`，**没有长度前缀或分隔符**：

| 字段 | 计划 A | 计划 B |
|---|---|---|
| `vehicle_id` | `1` | `12` |
| `anchor_node` | `23` | `3` |
| `suffix`（合法，无尾 0） | `(5, 6)` | `(5, 6)` |
| **拼接字节** | `b'123(5, 6)'` | `b'123(5, 6)'` |

| **S-13** | **独立证据替代**，不是改名：认证器对**实际审核的冻结对象**产出身份并回报逐字段；安装方**独立复算**；`certified_plan_hash` 仅交叉核对 |
| **S-14** | 四个标签原始字符串已在勘误 §5 逐字抄录，待用户核对 |
| **S-15** | 两条边界行为只在受控合成中用 mock 安装回调验证 |
| **S-16** | 生产替换须**单独预声明 → 回归 → 冻结 → 身份比对 → 授权**；不得改历史 helper 或冻结证据 |

### 9.7 结论

G-3 的研究方向更明确了：**"计划身份"要解决的是三类正交缺陷**，其中 D-3 是**不能靠更强哈希**
修复的编码问题。**G-3 仍未建立实施资格与生产资格**；本轮只完成独立规格勘误与小规模负控。
