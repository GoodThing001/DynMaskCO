## 1. 通用裁决词表（事前固定）

| 词 | 含义 |
|---|---|
| `PASS` | 该用例的**预期**成立 |
| `FAIL` | 该用例的**预期不成立**（缺陷） |
| `SETUP_FAILED` | 合成夹具未能建立（不得当作 PASS） |
| `NOT_RUN` | 未执行（本轮**不允许**出现在最终交付中） |

**任何 `FAIL`/`SETUP_FAILED`/`NOT_RUN` 都必须保留在证据中，不得删除或改写为 PASS。**

## 2. 各用例的输入、预期、失败条件

### T-Q2-1 Ω10 初始化门

| 用例 | 输入 | 预期 | 失败条件 |
|---|---|---|---|
| T-Q2-1a 正控 | manifest 内鱼类 lot，`initial_quality = 9.0 = initial_value[1]` | `OMEGA10_OK` | 返回非 OK |
| T-Q2-1b 容差边界（内侧） | `initial_quality = 9.0 − 1e-9`（恰在 `ε_init` 内） | `OMEGA10_OK` | 被拒 |
| T-Q2-1c 容差边界（外侧） | `initial_quality = 9.0 − 2e-9` | `OMEGA10_INITIAL_VALUE_MISMATCH` | 被放行 |
| T-Q2-1d 负控（关键反例） | `initial_quality = 1.0`（Q1 §4.1 的逻辑反例） | **在调用 `quality_check_fn` 之前**拒绝 | 放行**或**先调用了品质函数 |
| T-Q2-1e 未来订单隔离 | 存在未揭示订单且其数据初值被刻意改为 1.0 | 门**不读**它，仍返回 OK；且 `read_order_ids` 不含未揭示订单 | 门访问了未揭示订单真实初值 |
| T-Q2-1f 保守初值 | 通过时输出 `Q0_safe = Q0_contract − ε_init` | 等于 `9.0 − 1e-9` | 用了 9.0 |

**失败条件（统一）**：任何一条使"初值不符的鱼"进入品质实现，即 `FAIL`。

### T-Q2-2 Ω11 返仓可行性门

| 用例 | 输入 | 预期 |
|---|---|---|
| T-Q2-2a 正控 | 候选后缀使 `return_arrival ≤ T_end + 1e-6` | `OMEGA11_OK` |
| T-Q2-2b 负控（越界） | 人为把某车 `ready_time` 推后使返仓 > `T_end + 1e-6` | `OMEGA11_RETURN_DEADLINE_EXCEEDED` |
| T-Q2-2c 在途段 | 车辆 `status='returning'`、`return_finish` 已知 | 用**真实** `return_finish` 判定，不重算 |
| T-Q2-2d WAIT | 车辆 `ready@customer` 且 `mutable_suffix=[]`（WAIT 语义） | 必须按"之后仍需返仓"处理，**不得**当作已返仓 |
| T-Q2-2e 强制返仓边界 | 构造 `_force_return_all` 会超出 `T_end` 的时钟状态 | 门**拒绝**（不得依赖 `_force_return_all` 的存在） |
| T-Q2-2f 时钟越界 | `clock > T_end` | `OMEGA11_CLOCK_BEYOND_HORIZON`（不可认证，不伪造证书） |

**失败条件**：任何使 `return_arrival > T_end + 1e-6` 的计划被判 `OK`。

### T-Q2-3 Ω5′ 公式与单位

| 用例 | 输入 | 预期（`abs tol 1e-9`） |
|---|---|---|
| T-Q2-3a | `T_end=24.0, t_min=0, hpu=1.0` | `H_max = 24.000001` |
| T-Q2-3b 单位换算 | `hpu=2.0` | `H_max = 48.000002`；**不是**把下界减半 |
| T-Q2-3c 阈值两侧（温区 1） | `H=200` / `H=230` | `Q_LB=5.234000` 可售 / `4.669100` 不可售 |
| T-Q2-3d 阈值两侧（温区 2） | `H=14000` / `H=15000` | `Q_LB=5.108000` 可售 / `4.830000` 不可售 |
| T-Q2-3e 临界值（文档用，不判定） | `H_crit=(Q0−θ+1e-9)/k` | 温区 1 `212.426978279`、温区 2 `14388.489212230` |
| T-Q2-3f `t_min` 非零 | `t_min=2.0` | `H_max` 相应减少 2.0 |
| T-Q2-3g 非法单位 | `hours_per_time_unit ≤ 0` 或非有限 | 拒绝认证 |

**失败条件**：容差被忽略；或单位变化被当作线性缩放。

### T-Q2-4 双门互不替代

| 用例 | 输入 | 预期 |
|---|---|---|
| T-Q2-4a | 品质达标 + 温度越界（构造 `hard_temperature_bounds_c` 收紧到不可能满足） | `QUALITY_LB_OK=True`、`THERMAL_HARD_OK=False`、**复合=拒绝** |
| T-Q2-4b | 品质不达标（`Q0=1.0`）+ 温度合规 | `QUALITY_LB_OK=False`、`THERMAL_HARD_OK=True`、**复合=拒绝** |
| T-Q2-4c | 两者皆达标 | 复合 = 工程层通过 |
| T-Q2-4d | 任一为 `None`/未知 | 复合 = 拒绝（fail-closed） |

**失败条件**：任一门的结果被用来替代另一门。

### T-Q2-5 温度包络反例与段内峰值

| 用例 | 输入 | 预期 |
|---|---|---|
| T-Q2-5a 连续开门 | 合成：同一车连续多次 service，无充分冷却间隔 | 段内多次开门累积增温被检出；若越界则拒绝 |
| T-Q2-5b 短间隔 | 相邻两次开门间隔极小 | 峰值被记录，不只看端点 |
| T-Q2-5c 初始舱温 | 车辆未 dispatch（`coldchain_state is None`） | fail-closed 拒绝（`THERMAL_REPLAY_STATE_MISSING`） |
| T-Q2-5d 端点 vs 段内 | 构造端点合规但中间峰值越界 | **必须检出**（若当前模型结构上不可能，则记录为资格缺口并给出理由） |
| T-Q2-5e 时间错序 | `depart > arrival` 或 `arrival > service_finish` | fail-closed 拒绝 |
| T-Q2-5f 既有累计违规 | 车辆已有 `thermal_violation_count > 0` | 拒绝（不以本轮重放"洗白"历史累计） |

**失败条件**：仅在端点检查；或缺失状态被当作合规。

### T-Q2-9 缺失值与异常类型 fail-closed

（收据中标注 `budget_is_synthetic=True`）。
