## 1. 两处源码事实（已逐行核实）

### 1.1 安装回调收到的是**被核对的那个可变对象**，归档拷贝在回调**之后**

`d3_geo_adapter.py:666-696`：

```python
installed_hash = _plan_identity(plan)     # :666  先算身份
if why is not None: ... return False      # :668-688  门控
self.install_fn(plan)                     # :689  把原始可变对象交给安装回调
self.n_installs += 1                      # :690
stored = _copy_plan(plan)                 # :691  回调之后才值拷贝
self.installs.append({... 'plan_hash': installed_hash, 'plan': stored})   # :693
```

| # | 事实 |
|---|---|
| **C-1** | `install_fn` 收到**原始 `plan`**，不是调用前建立的不可变快照 |
| **C-2** | 账本条目把**回调前**的 `plan_hash` 与**回调后**的 `plan` 拷贝配对存档 |

`_plan_identity` 委托给 `action_contract.plan_hash`（探针 T-0 以源码检查确认），
即**不含** `anchor_time` / `anchor_load` 的那个。

## 2. 为什么这**不是**第四种哈希缺陷

D-1（字段遗漏）、D-2（截短）、D-3（跨字段编码非单射）都是**编码**问题：换个编码就能修。
本节两点是**对象生命周期**问题：`被核对的对象` 与 `被使用/被归档的对象` 在时间上可以不同——
**再强的哈希也不解决"核对了 A、装了 B"**。

**归类**：C-2 与 §1.2 都记为 **D-1 的下游证据影响**，不新增缺陷类别、不重复计数。

## 3. 规格补充（先登记于 `q3_g3_preregistration_amendment_02.md` §2/§4）

| 编号 | 要求 |
|---|---|
| **L-1** | 安装方在调用 `install_fn` **之前**取不可变快照，并对**该快照**复算身份 |
| **L-2** | `install_fn` 只接收只读视图；回调结束后**再次**复算，不一致 ⇒ `REFUSED: PLAN_MUTATED_DURING_INSTALL` |
| **L-3** | 归档条目绑定**安装前快照**的身份，不得把回调后状态与回调前哈希配对 |
| **L-4** | 认证器回报**逐字段值**，不只摘要 |

TOCTOU 负控 T-1…T-4 的注入与预期拒绝码已在勘误 02 §4 登记（**先于**本探针运行）。
