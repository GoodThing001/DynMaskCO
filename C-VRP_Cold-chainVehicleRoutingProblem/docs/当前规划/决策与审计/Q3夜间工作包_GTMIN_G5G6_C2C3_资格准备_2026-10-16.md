## 1. 阶段 4：G-TMIN 资格修复准备

### 1.1 现状（逐行核对，非转述）
`scripts/m1b_adapter/m1b_q2_certifier.py:122-139` `_resolve_t_min()` 的实际语义：
仅当 `verified_t_min is not None` **且** `self.env is not None` 时，把该值转 float，
检查 `v == v`（非 NaN）、`v >= 0`、`v <= 1e9`，然后**直接把 `t_min_source` 标为
`VERIFIED_AGAINST_SUPPLIED_ENV` 并返回该值**。**全程没有读取 `env` 的任何字段**，
也没有推导任何时间下界。故该标签名不副实：**"提供了 env"≠"对照 env 验证过"**。

**危害已由 Q3 设计文档记录并复现**：`verified_t_min = 1e6` + 任意非空 env ⇒ `t_min = 1e6` ⇒
`H_max` 塌缩为 0 ⇒ `q_lb` 抬升到初始值 8.999999999（保守 `t_min = 0` 时为 `H_max = 24.000001`、
`q_lb = 8.54807998017`）。这是**与已封堵的裸 `t_min` 覆盖同型**的旁路。

### 1.2 最小安全修复（代码级规格，**本轮不实施**）
**F-TMIN-1**：**拒绝而非接受**。把 `_resolve_t_min` 改为三态：
`t_min = 0.0`（唯一被接受的计算输入）→ 标签 `CONSERVATIVE_CLOCK_ORIGIN`；
任何非 None 的 `verified_t_min` → 标签 `UNVERIFIED_T_MIN_REFUSED` 且 **`return 0.0`**
（而不是返回该值）。即：**在出现可信见证之前，非零 `verified_t_min` 不得改变任何数值结果**。
**F-TMIN-2**：移除 `VERIFIED_AGAINST_SUPPLIED_ENV` 这个字符串本身（或改为
`SUPPLIED_BUT_UNVERIFIED`），使旧名**不可能**再被引用；同时把该名加入拒绝清单，
**任何**在收据里出现该标签的路径都应 `REFUSED`。
**F-TMIN-3**：`env is not None` **不得**作为任何判定的依据；env 只允许出现在
"见证提取器"里（见 1.3），且提取失败必须是拒绝。

### 1.3 可信见证（若将来要启用非零 `t_min`）
必须提供**可独立复核**的见证，而不是一个数字：
1. **来源身份**：见证文件/字段的路径 + sha256 + 生成它的程序身份；
2. **语义**：它声明的是"某节点/某事件的**最早可能发生时刻**"，且需说明**为何**是下界
   （例如：`reveal_time` 的物理下限、总时长下界、发布时刻的下界）；
3. **单调性/紧性**：该下界对**所有**被认证的计划都成立（不得只对某条路线成立）；
4. **可重算**：第三方仅凭仓库内文件即可重算该下界；
5. **绑定**：与 `contract_identity` / 状态身份绑定；任一变化即失效。
**未满足 1–5 者，`t_min` 只能取 0。**

### 1.4 正控/负控设计
| 编号 | 输入 | 期望 |
|---|---|---|
| TMIN-N-01 | `verified_t_min=None`，env 有/无 | `t_min=0`，标签 `CONSERVATIVE_CLOCK_ORIGIN` |
| TMIN-N-02 | `verified_t_min=1e6`，env 非空 | **拒绝**：数值仍按 `t_min=0`；`q_lb` 与保守基线**逐位一致** |
| TMIN-N-03 | `verified_t_min=24.0`，env 非空 | 同上（不得出现 `H_max=1e-6` 那一类塌缩） |
| TMIN-N-04 | 收据中出现 `VERIFIED_AGAINST_SUPPLIED_ENV` | 组合判定 **REFUSED** |
| TMIN-P-01 | 完整见证（1.3 的 1–5 齐备） | `t_min` 取该值；`q_lb` 可复算；收据记录见证 sha256 |
| TMIN-P-02 | 见证存在但 sha256 不匹配 | **拒绝**（fail-closed） |

**兼容性分析**：`certify_quality_lb(..., horizon_hours)` 以 `H_max = T_end − t_min` 为上界；
`t_min` 变小 ⇒ `H_max` 变大 ⇒ `q_lb` 变小（更保守）⇒ **只可能拒绝更多、不可能放宽**。
故 F-TMIN-1 是**方向安全**的：它只会让认证更难通过，不会让任何不合格计划通过。**这一点必须写进修复规格。**

## 2. 阶段 5：G5/G6 + C2/C3 联合认证准备（静态审查）

### 2.1 现状要点（来自本轮 grep 与既有负控记录）
- **G5（注册表信任）**：`m1b_q2_certifier.py` 的注册表是**进程内 dict**（`self.receipts = []`），
  `conservativeness_proof_ref` 只是**一个字符串**；没有任何机制验证被引用的"保守性证明"存在或匹配。
- **G6（收据持久化）**：M1-b 收据**仅在内存**；仓库另有 `scripts/simulation/d3_install_receipt.py`
  （D8 持久收据 + 独立读回，已有 R1–R6 验收），但**它不在 F 执行路径上**
  （`d3_l1_v121_dependency_closure.py:83-85` 明确记录"不被 F 执行路径导入"）。
- **C2（身份共享）**：`test_m1b_q2r_negative_controls.py:429-431` 已记录
  "**没有**生产路径调用 M1-b 认证器，且 M1-b 收据**不被**生产消费"，
  生产安装入口是 `d3_geo_adapter.py:708 run_repair_transaction`。二者**不共享状态身份**。
- **C3（联合门）**：M1-a 的四项检查与真实 `certify_plan` **不在**当前复合判定内
  （复合只覆盖 M1-b 的十一道门）。

### 2.2 四类风险与最小设计
| 风险 | 现状 | 最小设计要求 |
|---|---|---|
| **R1 错误计划被安装** | 生产安装路径不消费 M1-b 收据 | 安装入口必须**要求**一个由**单一身份**签发的收据，且该收据绑定 `candidate_plan_identity`；无收据即拒绝 |
| **R2 认证后状态改变** | 收据记录 `state_identity_before/after`，但无人**重新核对** | 安装前重算状态身份并与收据比对；不一致即拒绝（不得只信收据自述） |
| **R3 超时/写入失败** | 内存收据无失败语义 | 持久收据必须**原子落盘**（写临时文件 + `O_EXCL` 重命名）、失败即拒绝且**不留半写文件**；参考 D8 的既有实现而非新造 |
| **R4 重试改变已接受订单/前缀** | 未定义 | 收据必须绑定 `committed_order_ids` 与执行前缀身份；重试时前缀变化 ⇒ 新收据、新身份、旧收据作废 |

### 2.3 静态调用图（本轮只读核对所得的边界）
```
生产安装：  d3_geo_adapter.run_repair_transaction  ──►  InstallLedger.install
M1-a 检查：  certify_route / action_contract.certify_route      （独立）
M1-b 认证：  m1b_q2_certifier.M1bQ2TrustFixCertifier.certify    （收据仅内存）
D8 收据：    simulation/d3_install_receipt.install_with_receipt （不在 F 路径）
```
**结论**：三条链路目前**互不引用**，因此 C2/C3 不是"接线"问题，而是**身份统一**问题。

### 2.4 最小实施顺序（建议，未实施）
1. 先统一**身份对象**（contract / state / plan / projection 四元组的一次性摘要），
   由 M1-a、M1-b、`certify_plan` 三方**各自计算同一摘要**并**互相核对**（C2）；
2. 再把 D8 的持久收据**复用**为 M1-b 的落盘层（G6），**不新建**收据格式；
3. 然后让安装入口**要求**该收据（R1/R2）；
4. 最后把三方判定合成**单一联合门**（C3），并规定"任一方 REFUSED ⇒ 整体 REFUSED"。
**每一步都必须带负控**（错误计划、状态漂移、半写失败、重试前缀变化）**才允许进入下一步**。

### 2.5 负控清单（设计，未实现）
`G5-N1` 注册表缺失/被替换 ⇒ 拒绝；`G5-N2` `conservativeness_proof_ref` 指向不存在对象 ⇒ 拒绝；
`G6-N1` 断电语义（临时文件残留）⇒ 拒绝且可识别；`G6-N2` 收据字节篡改 ⇒ 拒绝；

`C3-N2` 仅 M1-a 通过而真实 `certify_plan` 失败 ⇒ 整体拒绝。
