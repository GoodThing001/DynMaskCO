|---|---|---|
| **Q2-1 合同身份（G2）** | `m1b_contract_identity.py` | 用仓库既有的 `quality_config_class` + `contract_schema_version` + `is_v2` 语义，**并绑定 `contract_hash`**；缺字段 / 类型不符 / 非 v2 / 哈希不符**全部 fail-closed**。AST 断言 `getattr(contract,'version',…)` 与 `.version` 在 m1b 中**零出现** |
| **Q2-2 不可变快照（G3/G4）** | `m1b_immutable_snapshot.py` | `FrozenVehicle`/`FrozenPlan` 为**真正隔离**的副本（`__slots__`，容器逐项复制）；`detect_aliasing` 检查共享可变对象；`plan_identity_v2` **纳入 `anchor_load`**（补 G4）；`verify_state_unchanged` 认证前后机械比对，变化即拒 |
| **Q2-3 Ω10 初始化门** | `m1b_quality_certificate.check_omega10_initialization` | `ε_init = 1e-9` **事前固定**；**保守初值** `Q0_safe = Q0_contract − ε_init`；只读 manifest 载货、候选涉及的已揭示订单、已承诺可见订单；**不扫描未揭示订单**；`check_boundary_initial_value` 给出"揭示/接受/取货"边界的等价校验；**不符即在调用品质函数之前拒绝** |
| **Q2-4 Ω11 返仓门** | `m1b_return_feasibility.py` | 覆盖执行前缀（`returning` 用**真实** `return_finish`）、在途 committed 段、各车当前状态、候选完整后缀、**WAIT**（空后缀离库 ⇒ 判"仍需返仓"，按最早返仓即"现在返仓"处理）、`> T_end + 1e-6` 拒绝、`clock > T_end` 拒（**不伪造证书**）；`replan_invariant_statement()` 说明**每 commit 重新认证、证书不复用** |
| **Q2-5 解析品质认证** | `m1b_quality_certificate.certify_quality_lb` | `H_max = max(0, T_end + 1e-6 − t_min) · hours_per_time_unit`；`Q_LB = max(0, Q0_safe − k·H_max)`；`salable ⇔ Q_LB ≥ θ − 1e-9`（与 `_delivery_record_v2` 一致）；仅 v2 零阶 + 绝对阈值；v1 拒绝**不静默回退**；**番茄 `salable=None`、OUT OF SCOPE，绝不计为不可售** |
| **Q2-6 G7 温度硬门** | `m1b_thermal_gate.py` | 从**可信车辆当前冷链状态**出发，用**真实** `coldchain_state.transition_segment` 重放候选后缀；**在每个段端点与每次开门事件之后**采样温度包络（针对"只查端点"的缺口）；检查 `hard_temperature_bounds_c`；检查**既有累计** `thermal_violation_count/duration`；缺状态 / 时间错序 / 无法完整重放**一律 fail-closed** |

**两门分列（红线）**：收据含**互不替代**的 `QUALITY_LB_OK` 与 `THERMAL_HARD_OK`；
复合通过要求**每一门独立为真**，任一失败**或未知**即不通过。
`non_substitutable` 字段显式记录该规则。

**推导链**：`m1b_q2_certifier.py` 固定顺序
合同身份 → 快照/别名 → Ω11 → **Ω10（先于品质阶段）** → 温度重放 → 品质认证 → 事后状态一致 → 复合。

## 6. 结论（按任务第五节要求的 A/B/C/D 分列）

### A. `Q1_PROVEN_UNDER_REVISED_DOMAIN` 的适用范围与剩余假设

**适用范围**：v2 合同、**零阶 + 绝对阈值**温区（本次为温区 1 冷藏鱼、温区 2 冷冻鱼）；
在 **Ω1–Ω9 + Ω10 + Ω11 + Ω5′** 下，`Q_LB(c) = max(0, Q0_contract − ε_init − k·H_max)`。

**剩余假设（逐条列出，均为已识别的条件而非隐含前提）**：
1. **Ω10 成立**：每件鱼的**实际**入库初值 = 合同 `initial_value[c]`（`1e-9` 内）。
   本轮只在**决策期**对 manifest 载货建立该门；**数据装载管线**的不变量仍**未被运行时强制**，
   依赖 `add_v2_initial_quality` 的调用约定（60+ 处）。
2. **Ω11 成立**：存在独立于 `_force_return_all` 的提交前返仓认证；本轮**提供了实现**，
   但**尚未接线到生产 commit 路径**。
3. **Ω5′ 的 `t_min`**：取 0（时钟原点）；若未来能从公开数据验证更早的 `t_min`，可收紧而非放宽。
4. **`k(c)` 为常数且与舱温无关**：这是 v2 实现的结构事实（`_advance_manifest_quality_v2`
   不接收温度），**不是**假设。若未来合同引入温度相关动力学（v3），本证明**不可继承**。
5. **温区 0（番茄）不在覆盖范围**；本证明**不主张**番茄连续品质。
6. **温度硬界与品质下界相互独立**；Ω 不含温度项，故品质下界**不因**温度合规而更强或更弱。
