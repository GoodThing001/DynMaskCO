# DynMaskCO-CC 风险与解决预案

> 版本：2026-09-03 v4  
> 诊断顺序：目录/导入 → 协议 → 冷链合同 → 状态 → 动作 → oracle → 表征 → 掩码重构 → 轨迹 → 统计 → 论文。

## 1. 风险分级

- P0：会使结论无效；未修复禁止进入下一阶段。
- P1：会使主方法或主张不成立；正式实验前处理。
- P2：影响完整性和竞争力；论文定稿前处理。

### 2.1 P0-00 目录迁移风险

原始 MaskCO 已移入 `MASKCO_code/`，而静态扫描识别出至少 22 个扩展 Python 入口仍按旧根目录布局构造路径。预案是新建唯一 `project_paths.py`，按 `__file__` 解析根目录，核对关键导入的真实 `__file__`，并从多种 cwd 运行 smoke。禁止通过复制上游包、在根目录创建兼容副本或修改 `MASKCO_code/` 来暂时绕过。

## 3. 冷链建模风险

### 3.1 参数看似真实但未校准

症状：代码注释引用真实单位，实际又用任意 `HOURS_PER_UNIT` 或有效功率缩放。

预案：

1. 参数区分 literature、calibrated、pilot；
2. 单位尺度单独保存；
3. 主值和 sensitivity 范围在 train/dev 冻结；
4. 不把简化模型宣称为真实车辆数字孪生。

### 3.2 单舱、多舱、异构车语义混用

症状：同一代码既把车辆设为 frozen capability，又对各温区独立恒温。

预案：主实验已冻结为同构多温舱、共享总容量。route slot 等价性必须包含 thermal/manifest state；若以后增加异构能力或独立舱容，升级 schema 并重做置换测试，非等价车不能匿名合并。

### 3.3 pickup manifest 生命周期错误

症状：取货前就累计订单品质；客户服务后载重未增加；返仓后 manifest 未清空；只访问客户就判 complete。

预案：订单在 `service_finish` 入舱并开始品质计时，在 `return_arrival` 记录返仓品质后卸货。终局 complete 同时检查 all-picked、all-returned、all-delivered-to-depot 和 empty manifest。

### 3.4 预计算 quality 被误作方案真值

症状：换路线后 quality_loss 不变。

预案：数据中的历史 `quality_loss` 只作参考/feature ablation；它使用到达客户的累计时间，属于旧配送式口径，不适用于 pickup-to-depot。主结果按每单 `service_finish → return_arrival` 的在途温度轨迹重新计算，并用“高易腐订单后取可缩短车内暴露”的解析算例检查方向。

### 3.5 目标权重任意

症状：只有某个 \(\lambda_Q,\lambda_E\) 才赢。

预案：冻结归一化；报告原始分量、主设置、邻域 sensitivity 与 Pareto curve；不得在 TEST 后改权重。

### 3.5 品质改善只是距离缩短副作用

症状：distance-only 与 joint 相同，true thermal state 与 shuffle 相同。

预案：必须有 distance-only、thermal removed/shuffled、quality-only、energy-only 消融。无独立增量时不能写冷链感知贡献。

## 4. 状态与动作风险

### 4.1 v2 snapshot 不能恢复热状态

预案：新建 v3_cc；保留 v2 历史 reader，不在 C0 后 teacher 中静默补默认温度。

### 4.2 同质车判断忽略热状态

症状：交换不同温度/能耗/舱室状态车辆后 action 不变却结果不同。

预案：slot semantic signature 加 thermal/capability equivalence；仅完全等价空闲车合并为 NEW_ROUTE。

### 4.3 当前 \(slot,p\) 太局部

症状：O0-CC 无 headroom，或只在个别 early states 改善。

预案顺序：

1. 冷链风险 lookahead；
2. two-customer relocate/exchange；
3. batch/event-mask action；
4. 每次扩展后先 oracle，不先扩网络。

### 4.4 局部 certificate 被写成未来保证

预案：论文只写 action-level feasibility；完整 episode 由 terminal rollout、complete incumbent 和 fallback 验证。

## 5. Counterfactual teacher 风险

### 5.1 不同 action 使用不同 continuation

预案：固定 continuation object、预算、seed policy、合同 hash；失败也按统一 lexicographic outcome 保留。

### 5.2 热状态没有随 force action 改变

症状：不同 route plan 的 plan hash 不同，但 cold-chain trace 相同。

预案：force full-fleet action 后从同一 snapshot 逐段推进；保存首段、温度和 Q/E trace 以审计。

### 5.3 clairvoyant supervision 被误作部署输入

预案：明确真实未来只生成 offline label；policy feature、mask 和 candidate 均只能依赖 \(\mathcal F_e\)。

### 5.4 solver noise 造成错误偏好

预案：重复求解、common random numbers、tie margin、label agreement；按 state 保存全候选，不丢困难 state。

## 6. MaskCO 身份风险

### 6.1 最终只是 MLP scorer

症状：frozen embedding + MLP 有效，但 mask/no-mask、iterative/one-shot 完全相同。

预案：

- M0 明确标 representation probe；
- M1 必须让 event mask 改变 decoder 输入；
- 重构目标必须是 utility-aligned action distribution；
- iterative reconstruction 必须进入真实 action trace；
- 执行 MaskCO identity Gate。

### 6.2 重新引入无效 structural CE

症状：为保留 MaskCO 名称又训练 adjacency/G/A，但 \(J_{CC}\) 下降。

预案：重构目标是由 counterfactual utility 产生的 action distribution，不恢复旧 exact-ID/adjacency CE。历史结构信号可作辅助表示，但不得成为主 loss。

### 6.3 Mask 对当前决策无作用

症状：Real/no-mask/shuffle 的 score 与 selected actions 相同。

预案：记录 mask IDs、candidate logits、rank flip、first divergence；检查 decoder 是否实际消费 mask token。

### 6.4 MaskCO 不优于 generic

预案：先查 checkpoint/edge-mode/输入一致性；再试 adapter/partial fine-tune。若仍无增量，返回方法设计，不能只保留 DynMaskCO 名称。

## 7. 学习与轨迹风险

### 7.1 高离线准确率、低终局效用

预案：主指标使用 normalized regret、high-advantage recall 和 final \(J_{CC}\)，不以 pair accuracy 决策。

### 7.2 状态分布偏移

症状：M0/M1 dev 好，strict-online 后逐事件恶化。

预案：收集 first-divergence/high-regret/fallback/high-thermal-risk states，最多 1–2 轮 state-balanced aggregation。

### 7.3 Score 未进入动作

预案：保存 selected action、incumbent rank、accept/reject、fallback 和 full-fleet plan hash；Real/Shuffle 必须产生非零行为差异。

### 7.4 冷链目标改善、距离失控

预案：预注册 distance degradation budget；报告 Pareto curve。超过预算即 Gate FAIL，不用 \(J_{CC}\) 平均值遮盖。

## 8. 统计与 baseline 风险

### 8.1 Pseudoreplication

正式单位是 instance 与 training seed；state/action 仅作机制分析。

### 8.2 只在 R1/EDoD=.5 或单一热设置有效

预案：9-cell dynamics + thermal stress + 100-node；若失败，收窄适用范围，但不改变论文研究对象。

### 8.3 Baseline 不具冷链能力

预案：同时提供 JF1-H-CC 与 OR-RH-CC；distance-only 方法只进入距离参考表，不与 \(J_{CC}\) 主排名混排。

### 8.4 多次筛选产生假阳性

预案：dev exploratory、VAL confirmatory、TEST one-shot；权重、热参数、mask 和统计计划预先冻结。

## 10. Stop Rules

- C0 任一 blocking test 失败：停止 O0-CC/M0/M1；
- P0-M 未通过：停止 C0/O0/M0/M1 和正式复现实验；
- O0-CC 无 headroom：停止当前 action schema 的学习；
- service 或硬约束失败：不看成本；
- Real 不优于 Shuffle：停止大规模实验；
- event mask/iterative reconstruction 无增量：M1 不算 MaskCO 方法完成；
- true thermal state 不优于 removed/shuffled：冷链机制 Gate FAIL；
- DynMaskCO-CC 不优于 JF1-H-CC：不进 TEST；
- 多场景复现失败：收紧范围并说明，不夸大；
- C0 未完成：暂停动态冷链论文主实验，不把同一项目改名为 generic dynamic CVRPTW 规避问题；
- TEST 已运行：后续修改属于新研究轮次。
