## 要素① 可证伪假设

> **H1**：在同一固定状态、同一 `P0`、同一 B 池与有序 legal、同一 `tie_break`、同一合同下，
> 经**完整 C0 认证**后，F（恢复的 MaskCO 权重）产生的**可执行完整计划**
> 在**决策质量**上**优于** D-Geo（`-Δd`）产生的计划。

**唯一主要实验变化因素**：`scorer_id`（`DECLARED_VARYING_FIELDS = ('scorer_id',)`）。

**否证条件（事前固定）**：满足以下**任一**即 H1 被否证，并如实记录为负结果：

1. 主判据的**均值门未过**；或
2. 主判据的**CI 下界门未过**（CI 跨越 0）；或
3. F 的**认证通过率**显著低于 D-Geo（即 F 更常产生不可认证计划），
   即使其通过认证者的质量更高——该情形记 `cert_fail_asymmetry` 并单列，
   **不得**用"仅比较通过认证者"的方式掩盖。

**H1 不是**"动作是否不同"（那是 L1，已执行）；**不是**"在线效用是否更高"（那是 L3）。

## 要素② 唯一主对照

```
F:      s_F(a) = restored MaskCO logits          a_F = first argmax_{a in legal} s_F(a)
D-Geo:  s_D(a) = -incremental_distance(a)        a_D = first argmax_{a in legal} s_D(a)
```

| 项 | 冻结值 |
|---|---|
| `mask_scope` | `B`（`mask_candidate_pool` 既定作用域） |
| `eps_rel` / `eps_abs` | `0.0` / `0.0`（`EPS_D_PRIMARY_REL` / `_ABS`） |
| `tie_break` | `legal_order_first`（F 的历史 first-maximum argmax 语义）；`canonical_key` 仅作审计列 |
| 分叉语义 | 首步不同后各自 legal 可自然不同；**只在首步检查输入身份**，分叉后指纹逐条记录、永不判 FAIL |

**两臂必须共享（机器可检验）**：初始 strict-online 可见状态、`P0`、B 池、**有序 legal**、
可变车辆集合、合同、信息边界、**初始已接受承诺与冻结前缀**、
**同定义的墙钟与六项候选工作量预算**、**同一认证规则与同一接受规则**。

**机械检查（沿用 L1/V1.18，不新造）**：①两臂收到**同一个 state 对象**；
②state 摘要运行前后三处相等；③首步 legal 指纹两臂相等且等于共享值。

**强对照的冻结集合**：D-Geo 是**唯一主对照**，但**不是**全部在线强基线。
按 `A1强动态对照规格_2026-10-01.md` 与 `A3在线比较预声明_2026-10-01.md`，
**最强条件非学习基线的登记身份是 `cond_hist`（单步 SAA，K=10，10s）**。
L2 的**主对照**保持 D-Geo（与 L1 连续、单因素最纯）；
**`cond_hist` 作为强制并列报告臂**，以免"F 胜过一个弱贪心规则"被误读为方法优势。
（详见附件 4 §4 强基线清单与信息公平性核查。）

## 要素③ 主判据与统计方法

### 3.1 三口径必须分列（沿用升级预登记 §2.2，不得混用）

| 口径 | 定义 | 使用限制 |
|---|---|---|
| `candidate` | 臂提出的计划质量（**未认证**）；失败按 `J0` 计 | **不得**称"部署" |
| `accepted` | 经 `min(J0, J)` 接受规则后的质量 | 与 `candidate` 分开报告 |
| `certified` | **仅通过完整 C0 认证**的计划质量 | **本轮 L2 的主口径** |
| `closed_loop` | 共同 JF1-H-F 延续下的终局质量 | **仅 L3 允许**作为在线口径；**L2 不得提前使用** |

### 3.2 主判据

- **配对单位**：`state`（= 冻结的 `inst × event`），**配对**同状态的两臂。
- **主统计量**：认证后质量差的**按实例聚类**均值差 `Δ`。
- **不确定度**：**bootstrap 按实例（day/inst）聚类重采样**；
  **严禁**把同一天的多个状态当作独立日样本（升级预登记 §2.4 明文）。
- **双门（同时满足才算通过）**：
  1. **均值门**：`Δ ≥ δ_L2`；
  2. **CI 下界门**：`Δ` 的 95% CI **下界 > 0**。
- **`δ_L2` 的取值只能来自用户裁定**，见附件 4 §5 的候选；
  **本文件不填数字**，因为**不存在已登记的 L2 阈值**——
  A3 的 `δ₃=20` 是**A3 的**登记值，**不得**默认移植到 L2（见附件 3 §4）。

### 3.3 分母保留规则（事前固定）

| 情形 | 处理 |
|---|---|
| 认证失败 `cert_fail` | **留在分母**，单列；**不剔除** |
| 超时 `timeout` / `censored` | **留在分母**，单列；**不剔除、不追加运行** |
| 空池 `no_legal` | 记 `NOT_APPLICABLE_EMPTY_MASK`，**留在分母** |
| 臂异常 `FAILED_EXCEPTION` | **留在分母**，记 `UNANSWERED_*` 并给根因；**不插补** |
| 缺失状态 | **留下显式记录**；分母**不得**静默缩小 |

**不得**事后调整判据、追加状态、挑选结果、剔除失败。

### 3.4 必须单列的报告项

`candidate` / `accepted` / `certified` / `cert_fail` 与其他失败 / 经认证的完整计划质量 /
**比较所花费的墙钟与候选工作量（六项分别实测）**。

## 要素⑤ 预期方向和失败条件

**预期方向（事前声明）**：基于 L1 已观察的 48/63 首步分歧，
**若**这些分歧确有决策价值，则 F 的**认证后**质量应优于 D-Geo。

**必须同时声明：L1 的分歧不蕴含质量优势。** 因此 **H1 被否证是完全可能的、并且是有价值的结果**。

**明确的失败条件**：
1. 主判据双门任一未过；
2. `cert_fail_asymmetry`（F 认证通过率更低）；
3. 身份不符、认证器缺失、共同状态无法物化 → **不启动**，记 `BLOCKED`（不是 FAIL，更不是 PASS）；
4. 任何"为提高通过率"的判据/种子更换 → 该批次**作废**。

## 要素⑥ 资源门、时间上限与停止条件

**等预算（六项分别实测，同定义）**：
`n_actions_enumerated` / `n_actions_scored` / `n_candidate_plans_certified` /
`n_action_applications` / `n_solver_calls` / `wall_seconds`。

- 两臂**同一上限**；**不因 D-Geo 更快而给 F 额外额度**；
- 工程阶段观测的最大值**只作容量规划**，**不作为正式上限**（升级预登记 §3 明文）；
- **单决策墙钟上限**：沿用既有 10.0 s 口径**或**由用户另行裁定；**不得**在结果产生后放宽；
- 认证器调用**计入**同一预算。

**停止条件（fail-closed）**：
- 首次不可恢复的协议错误 → 停止并**保留原件**，不重跑、不调参；
- 超时按 `timeout` 记账，**不剔除状态、不追加运行直到有利**；
- 身份漂移 → 立即停止，需要**新身份**（不得静默沿用）。

### 7bis.3 旧规则是否明确要求 L1 PASS？

**不要求。** 逐证据：

1. §1 ② 的原文是"**已签署**且已执行"，**没有任何一处**出现 L1 必须 PASS；
2. **在整个仓库中检索 L1 的 PASS 判据，未找到任何一条**——
   L1 的七要素（`A1_D3_L1_L1_FORMAL_EXECUTION_PREREGISTRATION_V2.md`）与

3. 机制诊断预登记要素③明文："L1 **不要求**统计 CI 或效用胜出门槛"；
4. 因此 L1 在本体上更像**诊断产出**而非**门**；把 `BLOCKED` 读成"L1 未通过因而 L2 无资格"
   是**加入了原文没有的判据**。

### 7bis.4 仅"执行完成但 `BLOCKED`"是否满足原文？

- **按字面**：**满足**（②只要求已签署 + 已执行）。
- **但存在一个实质性张力**，必须如实提出：
  L1-v2 的 `BLOCKED` 起因是 1 个状态因冻结 F 路径的 `M_max` 缺陷（26 vs 27）抛异常，
  即 **L1 的 64 状态分母中有 1 个状态从未被回答**。
  §1 ② 的文字无法区分"干净执行完毕"与"执行完毕但有一状态未回答"。
- **结论**：原文**支持**推进 L2；但**这个解读必须由用户显式裁定**，
  因为它决定了一个**实质性的科学判断**（63/64 是否足以作为 L2 的前置），
  **不是**一个可以由执行端自行作出的文字解释。
