## 3. 数学命题、适用域、证明

### 3.1 记号

- `T_end := tw_end[0]`（depot 返仓截止；`hours_per_time_unit = 1.0` 时为小时）。
- `Q_0(c)`：温区 `c` 的入库品质。`k(c)`：温区 `c` 的零阶速率。
- `θ(c)`：温区 `c` 的绝对阈值；`ε_θ = 1e-9`（源码容差）。
- 对某订单 `i`：`t_pick(i)` = `pickup_finish_time`；`t_ret(i)` = `return_arrival_time`。
- `D(i) := t_ret(i) - t_pick(i)`（该订单货物在车上的总时长）。

### 3.2 适用域 Ω（**不含任何品质假设，故无循环论证**）

Ω = 满足下列**全部**条件的执行轨迹集合：

| # | 条件 | 依据 |
|---|---|---|
| Ω1 | 车辆从空载发车（`dispatch_vehicle` 拒绝非空发车） | `coldchain_state.py:107-108` |
| Ω2 | 单趟、不中途卸货（`single_trip=True, allow_reload=False`） | `coldchain_contract.py:630-631` |
| Ω3 | 每个被接受订单**恰好被服务一次**并在返仓时产生 `DeliveredCargoRecord` | `coldchain_state.py:256-257`；`coldchain_evaluator_a1.py:106-108` |
| Ω4 | 客户到达 `arrival ≤ tw_end[c] + 1e-6` | `action_contract.py:185-187` |
| Ω5 | 返仓 `t_ret ≤ T_end + 1e-6` | `action_contract.py:198-202`；`coldchain_evaluator_a1.py:84-85` |
| Ω6 | 容量 `≤ capacity + 1e-6`（共享总容量） | `action_contract.py:190-193` |
| Ω7 | 温区受支持（`temp_class ∈ supported_classes`） | `action_contract.py:179-183` |
| Ω8 | 能源 `≤ B`（`certify_plan`） | `run_exp_energy_c0.py:154, 199` |
| Ω9 | **首趟在 `t ≥ 0`、`t_ret ≤ T_end` 的冻结时钟上执行**（`tw_start[0]=0`，`horizon = max(tw_end) = T_end`，`_force_return_all` 在地平线处强行返仓） | `strict_online_env.py:454, 506-508, 658-664` |

**Ω 定义中没有任何一条引用"品质合格"**，故 §3.3 不构成循环证明。

### 3.3 命题与证明（v2 零阶、绝对阈值）

> **命题 P(c)**：设温区 `c` 的 `dynamics_order[c] = 'zero'`、`threshold_type[c] = 'absolute'`，
> 且 `k(c) ≥ 0`。令
> **`Q_LB(c) = max(0, Q_0(c) − k(c)·H_max)`，其中 `H_max = T_end · hours_per_time_unit`**。
> 则对任意 `ω ∈ Ω`、任意温区 `c` 的订单 `i`：
> `delivered_quality(i) ≥ Q_LB(c)`，且若 `Q_LB(c) ≥ θ(c) − ε_θ` 则 `salable(i) = True`。

**证明**（五步，每步对应源码）

1. **（损耗精确式）** 零阶分支给出 `new = max(0, q_old − k(c)·duration_h)`（`:484-486`）。
   `_advance_manifest_quality_v2` 是 `transition_segment` 中对该 lot 唯一修改品质的调用
   （`:220-222`；`delivered_quality` 直接读 `lot.quality_remaining`，`:512`），
   故对同一 lot 的连续推进按 `q_{n+1} = max(0, q_n − k·Δt_n)` 递推。
   由归纳得 `delivered_quality(i) = max(0, Q_0(c) − k(c)·Σ_n Δt_n)`。
2. **（在车时长 = 段时长之和）** pickup 事件把 lot 以 `pickup_finish_time = service_finish`
   入册（`:274`），返仓段在 `arrival_time` 结算（`:208`、`:286-289`）。
   lot 仅在其**已入册之后**的段的 `duration_h` 上被推进，故
   `Σ_n Δt_n = t_ret(i) − t_pick(i) = D(i)`。
3. **（`D(i)` 上界）** 由 Ω9：`t_pick(i) ≥ 0` 且 `t_ret(i) ≤ T_end`（`tw_start[0] = 0`；
   `horizon = max(tw_end) = T_end`，`_force_return_all` 在地平线处返仓；Ω5 独立复核）。
   ⇒ `D(i) ≤ T_end − 0 = T_end`。
4. **（单调性与单位）** `k(c) ≥ 0`（契约 `validate` 强制 `rate_per_hour >= 0`，`:596-597`），
   故 `k·D ≤ k·T_end`；时间单位由 `hours_per_time_unit` 换算（`:518-521`）。
   `max(0, ·)` 单调不减 ⇒ `delivered_quality(i) = max(0, Q_0 − k·D(i)) ≥ max(0, Q_0 − k·H_max) = Q_LB(c)`。
5. **（可售）** `salable(i) = True` iff `delivered_quality(i) ≥ θ(c) − ε_θ`（`:501-502`）。
   由第 4 步与 `Q_LB(c) ≥ θ(c) − ε_θ` 得结论。∎

**推理链**：该证明只依赖 **(a)** v2 线性零阶更新、**(b)** `k(c) ≥ 0`、**(c)** Ω9 的时间界、
**(d)** 单位换算。**它不依赖温度、不依赖 Arrhenius、不依赖热违规判定、不依赖路线结构**，
因此 v1 的 A2/A3（温度上界与单调性）在 v2 下**全部不需要**。

| 1 | 冷藏鱼 4 °C | 9.0 | 0.01883 | 24.0 | **8.548080** | 5.0 | **是** | **+3.548080** |

### 3.5 敏感性：证明在什么条件下**不再成立**

| 条件 | 后果 |
|---|---|
| `H_max > 212.427 h ≈ 8.85 天` | 温区 1 的 `Q_LB < 5.0` ⇒ **不可认证**（温区 2 要到 599.5 天才失效） |
| `hours_per_time_unit ≠ 1.0` | 必须按 `H_max = T_end · hours_per_time_unit` 换算；**不得**直接用 `T_end` |
| 契约换成 v1（`QualityConfig`） | 命题**不适用**：v1 是 Arrhenius + 比例阈值 |
| `dynamics_order[c]` 改为 `'first'` | 命题**不适用**：需改为 `Q_LB = Q_0·exp(−k·H_max)` |
| `threshold_type[c]` 改为 `'none'` | `salable = None`，无可售性可认证 |
| Ω5 被放宽（允许 `t_ret > T_end`） | 证明**失效**；`H_max` 必须重新推导 |
| Ω9 的 `T_end = max(tw_end)` 关系被破坏 | `horizon = max(tw_end)` 仍是合法上界，但须逐实例重算 |
