## 1. 接口审计结果（机械提取，不是叙述）

AST 静态分析三个入口 + 生产安装入口，得到下表。**"身份参数"= 该函数签名里是否接受 state/plan 摘要；
"复算身份"= 函数体内是否调用任何身份计算函数。**

| 层 | 入口 | 签名接受的**身份参数** | 是否**复算**身份 | 直接读取的状态字段数 | 恒为真的字面量 |
|---|---|---|---|---|---|
| **M1-a** | `action_contract.certify_route` | **无** | **无** | 6（`capacity`/`demands`/`service_time`/`temp_class`/`tw_end`/`tw_start`） | **`manifest_consistent: True`** |
| **M1-b** | `M1bQ2TrustFixCertifier.certify` | **无** | **有**（`verify_state_unchanged`、`validate_contract_for_quality_certificate`） | 3（`committed_next`/`mutable_suffix`/`status`） | `claim_supplied`、`counts_as_failure` |
| **C0** | `run_exp_energy_c0.certify_plan` | **无** | **无** | 10（含 `dist_mat`/`coldchain_state`/`booking_horizon`/`reveal_time`…） | 无 |

**关键测量（A-3）**：**没有任何一个状态字段被三方同时读取** —— 交点 **0**，并集 **14**。
所以"共享状态"必须**定义**，不能**发现**。

**关键测量（A-6）**：生产安装入口 `d3_geo_adapter.py` 导入 `action_contract.plan_hash`，
但**从不构造 M1-b 认证器、从不调用 `certify_plan`** ⇒ 今天**不存在**任何"三方比对"的落点。

**关键测量（A-4）**：M1-a 的 `manifest_consistent` 是**字面量 True**，`projected_energy/quality/thermal`
恒为 `None`。这不是说 M1-a 错（它本来只做可行性重放），而是说**消费方无法区分"算出来的通过"
与"写死的通过"**——C2 必须让这种常量可见（判据 C5 / 负控 N-10）。

## 2. 由此得到的 C2 定性（与 10-16 工作包一致，但现在是实测）

`Q3夜间工作包_GTMIN_G5G6_C2C3_资格准备_2026-10-16.md §2.3` 的结论是"三条链路互不引用，
所以 C2 不是接线问题而是身份统一问题"。本轮把它**机械确认**为四条：

1. **签名层面无共享位**（H-1）：三方都不收身份参数 ⇒ 透传 digest **不可能**；
2. **复算不对称**（H-2）：只有 M1-b 复算 ⇒ 若由调用方给摘要，M1-a 与 C0 会**无条件接受**；
3. **字段层面无交集**（H-3）：并集 14 个字段、交点 0 ⇒ 共享状态要**新定义**；
4. **无消费落点**（H-6）：生产安装路径不碰任何一方 ⇒ C2 的"共同身份"目前**没有地方用**。

⇒ **C2 的最小可行形态是"新契约 + 四方独立复算"，而不是"接线"或"更强的哈希"。**

## 3. `C2_SHARED_IDENTITY_V1` 的三项固定（按你的要求）

### 3.1 统一身份内容

`contract / state / plan / projection` 四元组，外加五项绑定：**执行前缀**、**不可取消的接单承诺**
（`committed_order_ids`）、`instance_id`、`event_id`、**源码身份**（blob 摘要）。摘要取完整 64 hex，
逐字段定界、位型浮点、`null` 与 `0.0` 区分。

### 3.2 统一验证责任

三方**各自声明**"我读了什么、我认证了什么"，且**禁止共用未核验摘要**（判据 C4 / 负控 N-9）。
特别地：`certify_plan` **只能**被读作"总能耗 ≤ B"，**不得**被读作可行性/质量/热/身份认证；
M1-a 的常量字段要标 `declared_constant`。

### 3.3 严格负控（10 条，已登记）

时间漂移 1 ulp、计划变更、合同变更、状态漂移、旧收据跨事件复用、G-2 资格缺失、
调用方自报摘要、隐藏未来字段、三方共用未核验摘要、恒真常量被计为通过 ——
**全部不得**获得可安装的联合认证资格。

## 4. 唯一主对照

**四方独立复算**：同一冻结状态由 M1-a / M1-b / C0 消费方 / 安装方**各自独立**计算摘要，
四份必须逐字相同；任一绑定字段 1 ulp 变更，四份必须**同时**改变。
这条判据直接对应"不同认证层是否在证明同一个对象"，不需要第二个对照。

## 9. 下一步建议（C2 资格审查）

**C2 具备"隔离规格已成、进入资格审查"的条件，但不具备实现资格**，因为：

1. 主对照（四方独立复算）需要一个**冻结状态导出器**，而它必须与 G-2 的时间上界绑定；
2. G-2 未合格前，C2 只能做到 `JOINT_NOT_CERTIFIABLE`，无法产出可安装结论；
3. C3 联合门必须等 C2 契约定稿，否则会重演"三方各自为政"。

**建议顺序**：C2 资格审查（只读，验证契约本身可机械实施）→ 若通过再谈 C2 隔离候选实现 →
最后才谈 C3。
