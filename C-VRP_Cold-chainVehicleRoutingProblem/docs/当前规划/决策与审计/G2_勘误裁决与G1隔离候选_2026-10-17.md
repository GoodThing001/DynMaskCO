## 3. G-2 **仍条件成立**的部分（第二份独立结论）

### 3.1 距离模型域（新，S-8）

`travel_bound = √2 · Π(倍率上界) / tw_speed`，向外膨胀 1 ulp：

| 模型 | 倍率上界 | 见证 | 控制 |
|---|---|---|---|
| `euclidean` | 1.0 | **逐实例离线**：`dist_mat` 对称 ∧ `max|dist_mat − euclid(coords)| ≤ 1e-6` | **D-1：96/96 通过**（实测最大偏差 `1.1e-7 ~ 1.2e-7`，`max edge 1.2407/1.2763/1.2658 < √2`） |
| `asymmetric_transit` | **2.090741** | 域级声明（生成器区间） | D-2：`√2` 被 2.594 超过，模型上界 2.9568 覆盖 |
| `long_tail_perturbation` | **5.0** | 域级声明 | D-3：`√2` 被 1.500 超过，模型上界 7.0711 覆盖 |
| `external_undeclared` | **无界** | 无 | D-4：`DISTANCE_MODEL_UNBOUNDED`，**拒绝近似** |
| `tw_speed ∈ {0,−1,nan,inf,None,'fast'}` | — | — | D-5：`TW_SPEED_INVALID`（6/6） |

**重要限定**：登记数据 `dist_mat` 键**存在**且等于欧氏矩阵，因此 `√2` **在登记域内成立**——
但这是**逐实例见证**出来的性质，**不是**仓库级不变量；换域（asymmetric / perturb / 外部矩阵）
即失效。**在线阶段不得**读取完整距离矩阵求最大边权（`require_offline` 拒绝 `stage='online'`）。

### 3.2 `T_clock_sup` 的完整成立前提（补全）

```
T_clock_sup = horizon + travel_bound
前提 P1   horizon 已按 G-2 逐实例见证判定为公开量（max(tw_end) == tw_end[0]，96/96）
前提 P2   返仓完成推进 ≤ horizon + travel_bound（E-01 的机制）
前提 P3   travel_bound 由 §3.1 的模型 + 见证给出，tw_speed 合法
前提 P4   浮点向外膨胀 1 ulp（生成器在浮点里相乘倍率）
前提 P5   n_max = 20003（max_iter 单界）**且**有 clean 监视器收据
判据      slack = [1e-9 + ulp_c(T_clock_sup)/2] + [n_max·ulp_c(T_clock_sup)/2]（hpu 必须 = 1.0）
```

**数值结论仍未变**（登记域 `24` 与 `25.4142` 同 binade）：`slack = 1.0710684844307253e-09` h。
**但推导已被替换**：跨 binade 时旧基准会低估一倍（E-02：`2.3298e-06 → 4.6585e-06`）。

### 3.3 推进次数

`n_max = 1 + 2·max_iter + 2 = 20003`（`max_iter` 单界，采用）；
`n_iter ≤ 1 + floor(T_max/eps_event)` 的收紧 **`NOT_ADOPTED`**（缺"每迭代时钟前进 > eps_event"的证明）。

## 7. 是否可以进入 G-3 的建议

**建议：可以进入 G-3 的隔离规格阶段，但不得进入任何联合认证/安装链路。** 理由与前置：

1. **可以**：G-1 的身份对象已能把"时钟 / 锚点 / 单位 / 合同 / 实例 / 前缀 / 时间预算 / 监视器"
   一并绑定，并在缺失前提时 fail-closed；G-3 的候选计划身份可以直接沿用同一编码与拒绝码体系。
2. **不可以**：G-3 若要把"计划身份"与"时间上界"联合起来，需要一个**已获资格**的 `T_clock_sup`；
   当前它仍是候选（跨距离域即失效）。
3. **建议顺序**：先做 G-3 的**隔离规格 + 负控设计**（与 G-1 同一种隔离形态），
   把"计划前缀/候选计划身份"接入现有拒绝码；**不要**在 G-2 上界获资格前做任何联合认证。
4. **不建议**再扩大 G-2 的随机诊断——按用户意见，把已发现的适用域限制带进 G-1/G-3，
   而不是继续堆控制数量。
