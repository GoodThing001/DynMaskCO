# S3-5 λ-margin 双计审计（2026-09-29，预声明批次内审计先行）

> 预声明问题：L2「accept iff acc_u − rej_u > K·λ·est(o)」是否与既有机制重复计入
> 预算机会成本？若已计入则不实现 L2，或改为净额门槛。

## 1. 审计路径（代码实读）

- **影子场景已内化预算稀缺定价**：`scenario_saa.py::_sim_scenario` 对未来订单按
  `est_used + e > B + 1e-9` 硬门槛拒单（L676–678），拒单计入
  `rej_loss += reject_penalty[tc]`（L677）；场景价值 = `plan_rev − fuel − rej_loss`
  （L694–696）。「未来订单因预算不足被拒」的机会成本**已通过未来 rej_loss 进入
  acc_u / rej_u 的差**——accept 挤占预算 → 未来少接的损失，天然被两分支差分吸收。
- **接单侧真实预算**：`certify_plan` 对计划做真实 C0 完成能耗硬认证（WAIT 到
  booking_end + 返仓），超 B 拒单——这是最终强制层，不是定价层。
- **系统性低估存在**：影子 `est_used` 只含（已耗累计 + 计划订单边际 + 待命预留，
  L654–662），**不含完成阶段 WAIT/返仓的待命制冷能耗**；`_complete_u` 计算的终局
  真实能耗 `energy` 超 B 时目前**不扣罚**（L685–693 注释）。历史证据：影子 est≤B
  而真实 certify 恒超 B、certify_budget 拒绝主导（C1/OR-Tools/PyVRP 拒绝原因唯一）。

## 2. 结论

1. **双计风险结构性成立**：在接单规则上再叠加 `K·λ·est(o)`，会在「影子未来
   rej_loss 已定价机会成本」之上重复计同一项成本 → **不实现 L2 原方案**。
2. **正确修复点 = 场景内终局超额连续价格（S3-3）**：把完成阶段被低估的能耗差额
   在影子场景内以连续超额价格扣罚（不恢复全场景 −1e6），低估在影子内部被修正，
   acc/rej 差分自然吸收，无需在接单规则外再挂一层 λ。
3. **残余校验**：S3-3 之后可用「影子终局 est/真实 certify 逐决策超额残差」度量
   残余低估；若仍显著，另立**净额门槛**（λ 作用于 shadow−certify 残差，而非 est 全额）
   并重新预声明——不是原 L2 式。

## 3. 落档

- 本审计替代 S3-5 行「未实现」结论；L2 行（附录）标「双计风险成立，不实现；
  缺口由 S3-3 场景层修复，残余另立净额门槛预声明」。
