# S3-4-D3 anytime 部分投票 —— 正式规格预声明（2026-10-03 登记）

> 触发：S3-4 v2 低负载复测（`a1_s3_4_smoke_v2_low_1003_033620`，2 天 p_c=0、ls+incr、10s）
> 三臂超时 171.5–177.0 次/天（~86% 决策），0 超时资源门未达，S3-4 v2 按规格 §5/§9 判负。
> 按 S3-4 规格 §9 顺序：**按序评估 D3（anytime 部分投票）**。本文件为该候选的正式启动登记；
> 启动实施与正式 40 天运行均在本登记之后。文献锚与候选草案见

## 1. 假设

现行超时降级把已完成场景的投票信息**全部丢弃**（保旧计划 + 拒单 + 计 timeouts，`scenario_saa.py`
L262/L946-980）。v2 低负载实测表明 ls 单决策收敛本身 >10s（anytime 型搜索，吃满预算），
且 ~86% 决策撞时限。若把语义改为 **anytime 部分投票**：
**(a)** 场景顺序随机化（固定种子，cond/uncond/三臂同序，保持 CRN）；
**(b)** 逐场景累进接/拒投票，**先验早停**（已完成 m≥4 场景且累计 |Δ| 边际置信远离 0 时停）；
**(c)** 时限到时按已完成场景的多数投票提交（接受 ⇒ 该订单插入 + 共用 C0 `certify_plan` 认证，
认证失败 ⇒ 拒单；拒绝 ⇒ 保持计划拒单）；
**(d)** 预算更足的事件自然全投票——部分投票结果在 deadline=∞ 路径上必须与全投票逐位一致；
则超时损失从「全丢」降为「部分信息」，密集决策日接单质量提升，且不再有「丢投票」式超时。

> ⚠️ 这是**超时回退语义变更**：现协议（保计划+拒单+计次）为 A2 锁与 rr3/S3-3 冻结批次口径，
> 本变更**不得回改任何已冻结/已锁定批次**；正式启用前必须写明与原语义的关系（§3 计数口径）。

## 2. 唯一主对照与判据

- **唯一主对照**：与现行 `shadow_mode='ls'`（同修订版、`--incr-eval` 开）按天配对，唯一差别 =
  超时语义（部分投票 vs 丢弃）。若同版旧 ls 无 40 天基线则对照同修订版 greedy 影子并如实标注。
- **判据（沿用 S3-4 预声明主判据，不因语义变更放宽）**：cond−uncond 按天配对 mean≥20 且日聚类
  CI 下界>0 且 hard=1.0 且全日可裁决 + 质量对比（影子路线质量 vs 旧 ls 逐场景差 ≈ 0，T 系列口径）
  + **0 丢弃式超时**（§3 新计数口径）+ 同 K=10/10s；1×40 天三档。
- 不得把「超时语义改变使超时计数清零」单独当成功——主判据不过即判负。

## 3. 参数、计数口径与次数

- 无自由参数：场景乱序种子固定 1 个；早停阈值固定 1 种（m≥4 且累计 |Δ| > 2×边际标准误时停）；
  部分投票提交 = 已完成场景多数票（平票按拒绝，与旧「保计划」同向保守）。
- **计数口径（新，与原协议关系声明）**：`timeouts` 保留原义（提交复查时无任何已完成场景 ⇒
  保计划+拒单+计次，即「0 信息丢弃」）；新增 `partial_commits`（时限到时按部分投票提交的事件数）；
  资源门 = `timeouts == 0`（每事件至少完成 1 场景投票才计入合格）且 `partial_commits` 如实报告。
  deadline=∞ 时部分投票与全投票逐位一致（回归测试，见 §7）。
- 2 天 p_c=0 烟测（0 崩溃 + deadline=∞ 一致性 + 早停率/部分投票率/与全投票动作一致率 +
  逐日效用与旧 ls 对比 + 超时观察）→ ≤1 次 40 天三档（工作目录实现 → 本地全绿 → 服务器烟测 →
  新建 S3-4-D3 冻结源码树 → 正式运行，沿用冻结链纪律）。

## 4. 预期方向

0 丢弃式超时；部分投票动作与全投票在无超时路径一致；影子质量与旧 ls 逐场景差 ≈ 0；
cond−uncond 按主判据裁决（不预设方向）。

## 5. 失败条件

- 动作一致率低于预定阈值（部分投票系统性偏拒/偏接，烟测报告），或主判据恶化，或早停率≈0
  （无收益），或 deadline=∞ 一致性回归失败 → 判负回滚，正式批次不启用。
- 主判据未过 → 按预声明顺序推进下一杠杆（S3-6 场景工程规格已备），不把「超时清零」单独当成功。

## 6. 资源门

0 丢弃式超时（新口径）、40 日全日可裁决、hard=1.0、身份合格（source_stable、共享源码/合同/数据
hash 与冻结口径一致）、同 K=10 同 10s、`partial_commits` 与早停率如实入报告。

## 7. 代码身份

- `scenario_saa.py` 的 `_saa_decide` 投票循环改造 + 场景乱序（CRN）+ 早停 + 部分投票提交；
  旧行为保留为对照开关（默认关闭保证旧行为不变），驱动加 `--anytime-vote` 透传并同步
  `run_identity.py` 封存清单（若入 `SOURCE_FILES_STEP2`）。
- 新增回归测试（T 系列续号）：① deadline=∞ 时部分投票与全投票逐位相等；② 场景乱序后各臂
  CRN 保持（同种子同序）；③ 提交前复查路径的超时计数不变；④ 平票拒绝与旧「保计划+拒单」同向。
- 实施完成后按冻结链纪律新建 S3-4-D3 冻结源码树（逐文件 `sha256sum -c` + 只读 + import 证据），
  正式运行只从冻结树启动。

  等 A3 落盘后执行**（避免争抢；v2 低负载教训：超时测量必须在空载窗口）。
