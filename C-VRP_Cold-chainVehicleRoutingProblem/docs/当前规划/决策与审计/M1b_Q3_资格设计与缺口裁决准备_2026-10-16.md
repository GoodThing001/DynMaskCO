## 2. 任务二：连续时间温度数学证明规格（**只读**）

**不实现新的证明钩子；不将有限样本诊断升级为连续时间保证。**

### 2.1 分段热动力学与实际数值执行器的关系

执行器（`coldchain_state.py`）在**每个事件段**上按固定顺序推进：

| 步 | 代码 | 公式 |
|---|---|---|
| 段时长 | `:208-211` | `end_time = arrival`（返仓段）或 `service_finish`；`duration_h = time_to_hours(end − depart)` |
| 传热 | `:366-372` | `natural = ambient + (T − ambient)·exp(−h·Δt)`（`h = heat_transfer_per_hour[z]`） |
| 制冷 | `:373-379` | 活跃温区：`updated = max(target, natural − c·Δt)`（`c = cooling_rate_c_per_hour[z]`）；非活跃：`updated = natural` |
| 门事件 | `:413-430` | `warmed = T + door_heat_kwh[z] / thermal_capacity_kwh_per_c[z]`（**瞬时**，仅开启温区） |
| 派车 | `:109-111` | `T ← target_temperature_c`（**初始条件**） |

**关键结构事实（本轮复核）**：

1. `max(target, ·)` 使 **target 成为温度下限**，故活性温区 `T ∈ [target, ·]`；
2. 各温区平衡点 `ambient − c/h` **均低于 target**（实测 15.0 / −6.25 / −41.667 vs target 18 / 4 / −18），
   故在无门事件时 `natural − c·Δt ≤ target`，`max` 取 target ⇒ **界内为常数 target**；
3. **唯一突破 target 的机制是门事件**，其增量恰为 `door_heat/thermal_capacity`（每温区 0.0333 / 0.0875 / 0.1200 °C）；
4. 段内温度是"指数衰减 + 线性降温"的复合，**被 max 截断**；极值**只可能**出现在
   (a) 段首、(b) 段首之后即刻（门事件瞬时跳变）、(c) 段尾——但 (b) 与 (c) 之间仍存在未采样区间。

### 2.2 段内极值候选、边界与门事件

对活性温区 `z`，设段首温度 `T0`：

- 段首：`T0`；
- 门事件后（若该段服务某订单）：`T0 + Δ_door`；
- 段尾：`max(target, ambient + (T0 − ambient)·e^{−hΔt} − c·Δt)`，其中门事件发生在段内**服务完成时刻**。

⇒ **段内极大值的候选集** = `{T0, T0 + Δ_door}`（因为随后的函数在 `max(target, ·)` 下单调不增）；
**段内极小值的候选集** = `{段尾值, target}`（下限由 `max` 强制）。

**因此"段内连续极值"在解析上可归约为有限候选集**——这正是可证明性的入口，
**但**该归约依赖：(i) 服务完成时刻之后不再有门事件；(ii) 冷却速率与传热系数在段内为常数；
(iii) `active_zone_mask` 在段内不变；(iv) 执行器确实按上式取值。**这四条须逐条冻结并独立审核。**

### 2.3 适用域

| 维度 | 必须明示 |
|---|---|
| 活跃温区 | `active_zone_mask` 的取值集合；`_coldchain_active_mask()` 当前为**全开**（`:196-199`） |
| 初始状态 | 派车后 `T = target`；**未派车 ⇒ 无状态 ⇒ 不适用**（E6） |
| WAIT | 空后缀离库：按"最早可返仓"计时（Ω11），温区在等待期间**持续按段推进** |
| committed | 从 `committed_finish` 续放后缀（Ω11） |
| returning | 使用**记录**的 `return_finish`，不重算 |
| closed | 无可执行任务 ⇒ `THERMAL_NOT_APPLICABLE`；历史返仓由 Ω11 closed-history 审计 |
| 时间单位 | `hours_per_time_unit` 必须为 1.0 或显式换算 |
| `t_min` | **保守取 0**（G-TMIN） |

### 2.4 可证明的命题 / 尚不能证明的命题

**可证明（在冻结适用域内）**：

- **P-1（温度下限）** 活性温区 `T ≥ target`，由 `max(target, ·)` 构造性成立；
- **P-2（无门时段上界）** 无门事件时 `T ≤ max(T0, target)`，因复合函数单调不增且被 `max` 截断；
- **P-3（门事件有界增幅）** 单次门事件增幅**恰为** `door_heat/thermal_capacity`，为合同常量；
- **P-4（段内极大归约）** 段内极大值 ∈ `{T0, T0 + Δ_door}`（§2.2）。

**尚不能证明**：

- **N-1** 多段累计（一日多次开门、无充分冷却间隔）的**全局**上界与 `hard_temperature_bounds_c` 的关系；
- **N-2** 极值归约所需四条前提在执行器中的**逐条机械核验**（尚未做）；
- **N-3** 温区**下界**突破 `hard_lower` 的可能性（当前 `max` 只保证 ≥ target，而 `hard_lower < target`，
  故需证明 target 到 hard_lower 之间不可达——例如持续过冷）；
- **N-4** 与**数值浮点**实现的一致性（解析归约 vs `float64` 逐段运算）。

### 2.5 数值实现与解析模型不一致时如何 fail-closed

**规则**：解析归约**只**能用于**收紧**判定；一旦出现下列任一情形，必须**回退到采样级并拒绝上升为连续级**：

1. 执行器与规格公式不符（任一步骤被修改）→ `THERMAL_CONTINUOUS_NOT_ESTABLISHED`；
2. 段内存在未建模事件（例如未来新增的除霜/预冷段）→ 同上；
3. `active_zone_mask` 在段内改变 → 同上；
4. 浮点与解析在**同一段**上的差超过冻结容差 → 同上并记录；
5. 缺少 `t_min` 或 `t_min` 非 0 且未独立验证 → **保守取 0**（G-TMIN）。

### 2.6 最小反例与独立审核要求

**已构造（Q2-R T-Q2-5a）**：同一车连续 9 次开门、间隔 0.01 h，观测到 z1 峰值 `4 + 9×0.0875`
量级的累积增温——**证明"只看端点"会漏掉段内峰值**，是该规格必须存在的原因。

**要求新增的最小反例（待 Q3 执行，本轮不实现）**：

| 编号 | 构造 | 预期 |
|---|---|---|
| CT-1 | 单段内一次门事件 + 段尾恰好回落到 target | 解析 `{T0, T0+Δ_door}` 与采样一致 |
| CT-2 | 连续开门使累计超过 `hard_upper` | 采样级**必须**拒绝 |
| CT-3 | 持续过冷逼近 `hard_lower` | 验证 N-3 是否可达 |
