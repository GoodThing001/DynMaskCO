## 2. A：受信投影来源（**3 处旁路，已关闭**）

### 2.1 修复前：三例全部通过投影门与 Ω10/Ω11，并读取了未揭示节点

| 例 | 最小输入 | 修复前实测 |
|---|---|---|
| **A1** | `TrustedPublicProjection(... revealed_nodes=(7,9) ..., snapshot_identity=None)` | `projection_gate = PROJECTION_OK`、`projection_binding = PROJECTION_BOUND_TO_SNAPSHOT`、`omega11 = OMEGA11_OK`、`omega10 = OMEGA10_OK`、`QUALITY_LB_OK = True`、`THERMAL_SAMPLED_OK = True` |
| **A2** | `projection_from_revealed_maps(..., snapshot_identity=None)` | 同上：门通过、绑定门"通过"、Ω10/Ω11 接受 |
| **A3** | 旧 callable（`temp_class_of`/`quantity_of`/`service_time_of`/`initial_quality_by_node`） | 同上：`clone` 路径构造 `tw_start=0` 且 `snapshot_identity=None`，门仍通过 |

**根因（两处，均已定位）**：
1. `m1b_q2_certifier.py` 原第 226 行 `if projection.snapshot_identity is not None and ...`
   —— **`None` 使绑定校验被静默跳过**；
2. `isinstance(projection, TrustedPublicProjection)` 是**唯一**资格判据，而
   `TrustedPublicProjection.__init__` 与 `projection_from_revealed_maps` 都是**公开构造入口**，
   任何调用者都能自行声明可见集与 `source_identity`。

**关键限定（按任务要求）**：三例的 `composite` 均为 `False`，**但原因是后续的连续温度门
（设计性 fail-closed）**。**不得**因此把更早的投影/Ω10/Ω11 错误误判为已解决——
本报告正是按"分层记录"处理的。

### 2.2 修复内容

| 要求 | 实现 |
|---|---|
| 只接受可验证出处的环境事件投影 | 新增模块级 `_FACTORY_TOKEN` 与 `_ISSUED` 登记；**只有** `build_projection_from_env` 铸发的投影能通过 `PP.is_certifiable` |
| diagnostic / legacy 构造器不得创建有生产资格的对象 | `projection_from_revealed_maps` 返回 `_data_trusted=False` + 外来 token ⇒ 认证器拒绝（`PROJECTION_TOKEN_INVALID` / `PROJECTION_DATA_NOT_TRUSTED`）；`_legacy_projection` 改走该诊断构造器，故**旧 callable 路径完全不能认证** |
| 快照身份/实例/事件/时钟/合同必须绑定且校验 | `snapshot_identity is None` 在**构造期**即拒绝（`PROJECTION_UNBOUND`）；认证器改为**无条件**比较 `projection.snapshot_identity == snap['state_identity']` |
| `snapshot_identity=None` 不得静默跳过正式绑定 | 已删除 `is not None` 短路 |
| 受信身份覆盖所用属性内容及来源 | `source_identity` 仍由 `(实例, 事件, clock, 可见集, contract_hash, snapshot)` 计算；新增 `projection_challenge()` = 对**全部受信字段与绑定**的摘要，认证前后各算一次，不一致即拒 |
| 真实未揭示属性不得进入算法 | 认证器**自行**用环境重验可见集：`assert_visible_set_matches_env` ⇒ 任何声明超出 `env.reveal_time` 的节点被拒（`PROJECTION_VISIBLE_SET_NOT_REVEALED`） |
| 投影构造后不得替换受信字段 | `MappingProxyType` + challenge 摘要（构造后篡改导致 `PROJECTION_CHALLENGE_MISMATCH`） |

### 2.3 修复后：6 项控制 **0 FALSE_PASS**

`A0` 正控（工厂绑定、可见集与环境一致）**通过全部门**；`A1` 直接构造被拒（构造期报错）；
`A2`/`A3` 在 `projection` 门被拒，**Ω10/Ω11 从未被评估**。

**`projection_challenge` 的诚实说明**：它是**同进程内**的篡改探测，不是密码学承诺；
`_FACTORY_TOKEN` 也不是对恶意代码的隔离。这是 **strict-online 软件协议边界**，与既定口径一致。

## 5. 残留限定（**如实列出**）

1. **`_FACTORY_TOKEN` / `_ISSUED` 是同进程的协议约束**，不构成对恶意代码的密码学隔离；
2. **旧类型 `QC.PublicOrderAttributes` 仍存在**且自述可变（标 `NOT_ESTABLISHED_FOR_THE_LEGACY_TYPE_ONLY`）；
   **无法进入认证**（T3-7 证明），但仍是可被误用的接口；
3. **`m1b_quality_certificate.check_omega10_initialization`** 仍保留修复前 per-lot 语义作导入兼容，
   带 `LEGACY_SHIM_WARNING`，**不在认证路径**；
4. **认证器仍接受旧 callable 参数**并翻译为**诊断投影**（故不认证）。这是刻意的兼容层，
   已在 `A3` 与 `X8b` 中验证其**不能**产生证书；
5. `M1bQ2TrustFixTestOnlyCertifier` 产出的收据带 `test_only` / `not_consumable_as_production_certificate`。
