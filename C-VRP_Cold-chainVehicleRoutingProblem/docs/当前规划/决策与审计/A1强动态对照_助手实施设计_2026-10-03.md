## 1. 合议臂（Arm 1）—— `ConsensusReplanner(SaaReplanner)`

- 每揭示事件：K=10 条件历史场景 → 逐场景投票 `d_i = u_acc(i) − u_rej(i) + pc_o > 0`
  （与 SAA 主统计同构的单场景边际；「建议接受」= 该场景下插入后影子边际为正）；
  **多数票接单，平票拒绝**（与旧「保计划」同向保守）。
- 插入可行性 = 共用 `_try_insert_certified`（贪心插入 + `certify_plan` 硬预算认证，越限不提交，
  异常回滚 A-01）；冻结已承诺订单不变；超时语义沿用协议（保计划+拒单+计 timeouts）。
- 新增计数：`scen_completed_sum`（逐事件已完成场景数累计）→ SAA 完成率 =
  `scen_completed_sum / (K × 决策事件数)`，与 timeouts 一并入逐日行。

## 2. Rollout 臂（Arm 2）—— `RolloutVReplanner(SaaReplanner)`

- 场景影子 = **h=2 截断**：未来池只取 `reveal ≤ clock+2h` 的单，接单顺序/门槛/局部搜索与
  SaaReplanner 同口径（density 顺序时同样只在截断池内打包）；截断后**不**跑 `_complete_u` 全终局，
  改算终端 `V(s_after)`。
- `u = plan_rev − fuel − rej_loss + V(s_after)`；rej 侧 `− pc_o`。不可行场景仍
  `INFEASIBLE_SCENARIO_PENALTY`。
- **V 特征（固定 14 维，登记即冻结）**：
  - 每车：`rem_time_v = tw_end[0] − cur_time_v − dist(cur_v,0)/speed`（截 ≥0）；
    `rem_cap_v = capacity − load_v`（截 ≥0）；
    `geo_v = Σ_{剩余可服务单 o} [可达_v(o)] / (1 + dist(cur_v,o))`（可达 = 揭示已发生、
    未服务、非本车 committed_next、arrive ≤ tw_end[o]；不查容量——时间可达口径）。
  - 车队：三量的 mean/max/var（9 维）+ `B − est_used`（剩余能耗 slack，车队级标量，
    「每车能耗余量」按预算为车队级预算如实实现为标量并注明）、`n_active`（有路线或已 dispatch
    的车数）、`n_remaining`（剩余可服务单数）、`total_remaining_demand`、`clock`（5 维）。
  - 跨车方差 = 三量 var 维度（显式含）；特征全为确定性纯计算，无模型侧随机。
- **V 模型** = 岭回归（λ 由训练日留出选）；权重文件 hash 入运行 identity；模型预载不入 10s
  决策时限（规格允许，如实声明）。

## 3. V 训练（因果回放）与先行探针

- 回放日志：训练日（20260925 流）逐事件，OFFLINE（无限时）：acc/rej 两状态 × K 场景，
  各跑**全影子**与 **h2 截断影子**；目标 1 = 续程价值 `full_u − h2_u`（V 的训练目标）；
  目标 2 = 边际差 `g = (full_acc − full_rej)`（探针风险预判目标，对应清单 §0）。
- 探针：训练日留出（按天分折）Spearman/MAE × 两目标；负信号如实记录、不豁免判据，
  结论口径注明（历史 D6 Spearman≈−0.04 是主要风险）。
- 训练/评估日按天隔离：V 训练只用 20260925 流；20260926/20260930/20261001 及
  20260927/28 不入训练。
- 探针规模（本地）：20260925 流前 2 天 × 每事件 K=10 × 20 sim（~2.4k sim，CPU 分钟级）；
  正式训练规模（服务器，A3 落盘后）：≥60 训练日采样事件。

## 4. 驱动与身份

- `run_a1_step2_gate.py` 增 `a1_consensus`/`a1_rollout` 两臂（与 uncond/cond/explicit 同批、
  同日、同 p_c 三档、同逐日配对口径）；臂由 `(sampler, replanner_cls, extra_kwargs)` 描述，
  A1 臂共用 `CondHistoricalSampler`。
- identity 增：V 权重 sha256（rollout 臂）、臂类型、h=2、特征向量版本号。
- **provider 声明**：两臂无任何外部求解器/服务调用（纯本地 NumPy 计算），故无 provider
  调用/fallback 记录（清单 §0 该条 = 空声明）。
- 三层对比口径：系统优势（vs myopic/greedy 影子同驱动）/ 条件优势（cond−uncond，A2 门）/
  MaskCO 独立优势（vs 最强条件非学习 = cond_hist 或本两臂胜者，A3 启动时锁定）——分开报告，
  不合并、不重复记账。
- **系统优势层（vs myopic 求解器）口径**：旧 myopic OR-Tools/PyVRP 对照为历史背景结果
  （`run_exp_rule_control.py` 系），不在 A1 批次内重跑；A1 批次内「同下游 greedy 影子」
  即 uncond/cond 基线臂提供批内背景——如实标注引用关系。
- **自查边界（诚实标注）**：清单为「助手只核身份与判据」设计；本次用户授权助手实施，
  验收由助手按清单逐项自查，核验独立性与执行端交付口径有结构性差异，全部如实标注于交件。
