**必须写明的解释**：`R2` 命中的是"整行恰好是 64 位十六进制"——本仓库大量**证据 JSON 的摘要值**在 pretty-print

**这套规则是为"一次交付的暂存差异"设计的，不是为"全历史内容"标定的**：把 433 当作"暴露数"是错的，
反过来把"扫过历史"当作"历史干净"也是错的。**这 433 条需要人工判断，本报告不作暴露认定。**

## 3. 结果二：锐化判据 —— 全历史只有 **2** 个真正的裸令牌 blob，且都是已知件

启发式命中多不等于有真东西。真正的判据只有一个形状：**`secrets.token_hex(32)` 写进文件后，文件内容就是
64 位十六进制**。因此对全部 17272 个 blob 先按尺寸筛出**唯一可能承载该形状的类别**（≤200 字节，共 **4092** 个），
再要求**整个 blob 体**匹配 `^[引号/空白]*64-hex[引号/空白/逗号]*$`：

| 项 | 数值 |
|---|---|
| 历史中的 blob | 17272 |
| 尺寸上可能承载裸令牌的 blob（≤200 B） | 4092 |
| **整块内容就是裸 64-hex 令牌的 blob** | **2** |
| 其中位于 `execution_secret_*` 路径 | **2 / 2** |
| **位于任何非密钥文件路径的** | **0** |

两个命中即 `research/.../l1_v2_execution_run/guard/execution_secret_12adf7457768bfb5.txt` 与
`research/.../v122_evidence/run_v122/guard/execution_secret_b3e36be45ceb6bb4.txt` 的**原始值 blob**——
这就是**已登记、已裁决**的那次公开事件（当时的处置是修复与脱敏，**明确选择不重写历史**；见
`l1_gates/L1_EXPOSED_SECRET_REDACTION.json` 与 `A1_D3_L1_EXPOSED_SECRET_CLEANUP.md`）。
**本次复查没有发现第三件**，也没有在任何非 ASCII 路径上发现裸令牌。

## 4. 结论与边界（不得外推）

1. **可以说的**：全历史可达 blob 100% 被读过；历史中不存在第三个 `execution_secret_*` 路径；不存在位于
   非密钥路径上的裸 64-hex 令牌 blob；因此**覆盖缺口没有掩盖一个"原始密钥文件"**。
2. **不可以说的**：**不能**说"历史里没有凭据"。433 条启发式命中里有 431 条是规则与合法形态相遇，**需要人工
   逐条判断**，本报告**未**逐条裁决，也**未**据此认定任何一次暴露；"密钥从未被提交（除已知两件）"**不在**本
   报告的结论范围内。
3. **本次复查不改变的事实**：已知的两个原始值 blob **仍然在历史里**（因为当时决定不重写历史）。这是既有裁决，
   本报告不重开、不建议改写历史、也不主张现在改写。
4. **与前一份报告的关系**：§3.3 的"留给用户裁决"现在**收窄**为"是否需要人工审阅那 431 条启发式命中"，
   而不是"是否需要先做一次全历史扫描"。扫描已经做完，覆盖已满。
