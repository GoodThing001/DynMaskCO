## 3. C：三级裁决与确定性数值规则

### 3.1 顺序及统一距离算法

第一级为§2整包证据有效性；第二级按原唯一主对照和1%条件裁决；第三级独立报告穷举参考。第二级结果不得被第三级追认或改写。第一级不通过时不得开展正式主质量比较；也不计算或解释任何几何差异。

在全部目标身份门通过后，沿用原 `ref.public_env(view).dist_mat` 的公开欧氏距离、单位和缩放。按 vehicle_id 升序展平各车 `anchor -> suffix -> 0` 的边，车内按路线顺序，将矩阵边值转为 Python binary64 float，使用**一次 `math.fsum`**得到车队 D_res；不把各车已舍入小计再次相加作为总值。空后缀仍计 anchor->0，closed 车不计；已执行段和在途承诺腿仍不计。路线小计可单独以 fsum 作描述，不改变总值算法。

固定公开视图、矩阵构建源码、Python/NumPy/平台与浮点环境于未来T2；独立复核使用同一计算规则。每个结果保存十进制及 `float.hex()`，不得先四舍五入再比较。最短候选如数值完全相等，以完整结构的确定性序列顺序选报告代表，最小距离值不变。

DeltaD、ratio、g及相对gap的减除运算各按上述已冻结binary64结果直接计算；不加任何容差或epsilon。非有限值、矩阵缺失、负距离、算术异常均无效，不以零或近似值插补。临近浮点精度的差异另报 `g`、两距离的 `math.ulp` 与 `abs(g)/max(ulp(D_MaskCO), ulp(D_reference))`，仅作数值尺度说明，不改变正负/相等或1%判据，不解释为可靠优化优势。

### 3.2 穷举报告四字段

| 字段 | 冻结规则 |
|---|---|
| `closure_status` | `EXHAUSTED / CAPPED / TIMEOUT / INVALID`，互斥；未启动单元取 INVALID，并以独立失败码说明未尝试；所有触发原因另存列表 |
| `distance_relation` | 仅在第一级有效且该单元EXHAUSTED时，以 `g = D_MaskCO - D_min_enum` 判定：g>0为 `ENUM_STRICTLY_BETTER`；g=0（含有符号零）为 `ENUM_TIE`；g<0为 `CONSISTENCY_ERROR`；其余为 `NOT_EVALUATED` |
| `relative_gap` | D_min_enum>0时为 g/D_min_enum；为零时为 N/A，仍保留g；另列描述性 `within_one_percent = (0 <= relative_gap <= 0.01)`，N/A时该字段也为N/A |
| `enumeration_cost` | 实测枚举wall秒数、展开状态数、生成完整计划次数、不同完整结构数、合法完整结构数、峰值内存及停止原因；未启动wall为N/A，实际展开量为0，不冒充已执行零成本 |

closure_status的终态按§4首次触发规则确定：触顶为CAPPED；单元/整包超时为TIMEOUT；身份、资源、异常、缺目标等失败为INVALID；仅无失败且全部分支结束为EXHAUSTED。缺目标单元同时保留真实 `closure_exhausted=true` 与失败码，不能因INVALID丢失已经穷尽的事实。

CONSISTENCY_ERROR意味着闭包、身份、集合包含或计算存在不一致，触发整包无效并停止质量解释。1%以内的严格差异仍是STRICTLY_BETTER，绝不写成精确TIE。主ratio与这里的relative_gap分母不同，不得互换。

部分枚举最小值只能称 `D_min_visited`，在非空合法已访问集上是完整闭包最小距离的上界，不能称完整最优。只有模型计划身份已唯一认证且差异计算门满足时，才可能报告“已访问合法候选更短”的结构化见证；它仍不证明最优。本包默认触顶会使全局门失败，因此仅保存候选/恢复账，distance_relation=NOT_EVALUATED，不为取得见证绕过§2与R0.1的先恢复后比较纪律。

即使第二级出现跨两个开发根日的1%改善，第三级也不能证明学习搜索不可替代；必须同时披露穷举真实wall与展开量，保留“小beam未覆盖不等于独立优化优势”的解释边界。

## 4. D：资源、计时和失败保全

### 4.1 待签署固定上限

| 项目 | 上限 |
|---|---|
| 计算worker / 计算线程 | 1 / 1；底层数值库线程也为1；监督器仅做控制与记录，不并行搜索 |

| 整包wall | 1800秒 |
| 单元wall | 120秒 |
| 每单元完整计划CAP | 5000个不同完整结构，达到即停止该单元枚举 |
| 单元与次数 | 原19单元、原顺序、唯一一次限定评价；不补抽、不自由重跑 |

CAP按**全部已生成的不同完整结构**计数，包括最终检查拒绝的结构；合法完整结构数另报，不能借拒绝或短哈希碰撞规避上限。同结构多条路径计入生成次数和展开量，不重复占结构CAP。第5000个结构产生后，只有已有的全部分支均已处理、无待展开状态时才可认定EXHAUSTED；否则记CAPPED，不再展开以探测第5001个。闭包实际规模只有穷尽时才可报告为精确值。

### 4.2 计时、内存与终止优先级

以单调墙钟计时。整包从监督入口开始、在输入核验和worker启动**之前**计时，到worker全部退出且结果/失败账最终持久化为止；涵盖加载、恢复、距离、检查和运行内记录。文档准备、未来实施/合成回归及事后独立只读复核另计，不得在正式窗口外继续搜索或算正式距离。整包最后5秒保留用于终止与封账：到1795秒停止计算和启动新单元，到1800秒必须完成退出/封账；该保留不增加1800秒预算。

单元采用**受监督工作区间的累计wall**：每个区间从监督器持久化该单元START/RESUME并允许读取状态前开始，到该区间PAUSE/终态持久化结束；包括加载、枚举、检查、距离和写盘等待，不以CPU时间替代。原19单元先完成身份恢复，全部身份门通过后才进入距离阶段；两阶段之间该单元完全无活动的全局门等待不计入其累计wall，但始终计入整包wall。每个区间起止与累计值必须落账，不能在区间内暂停计时或因阶段切换清零。单元累计计算截止为115秒，另留5秒用于终止/封账，累计wall不得超过120秒；达到累计截止后不再恢复该单元计算。

整包截止高于任何单元剩余额度，任一硬限先到即停止相应工作：单元时间/CAP终止该单元，按原顺序记录其余单元直到整包停止；进程树内存失败、整包超时、身份漂移或无法安全监督则停止整包。所有失败使主评价无效，继续记录其他恢复单元不构成重跑，也不得计算质量差异。同时触发时完整保留原因，主原因固定优先级为：整包超时 > 内存/监督/进程异常 > 单元超时 > CAP > 正常结束；不根据结果选择原因。

RAM范围为监督器、worker及全部后代，含原生数值库，不只测Python对象。记录进程树汇总RSS峰值和平台提交/私有内存计量，二者均不得超过6 GiB；共享页按各进程RSS保守重复计数。监督器须在进程树层实施可验证内存硬限制和死亡联动，不仅依赖worker自报；运行环境不支持时，在正式数据处理前以RESOURCE_MONITOR_UNAVAILABLE拒绝。不得只靠可能跳过长调用的循环内检查保证超时；监督器必须能强制终止worker进程树，监督器退出时worker不得继续运行。任何观测越限即资源失败，不以采样未捕获为零峰值或资格已证。

### 4.3 原子记录与故障后的19单元失败账

未来获授权后，监督器在计算开始前创建原19槽位清单（初始NOT_ATTEMPTED），持久化T1/T2/输入身份；未落盘成功不得启动worker。每单元START必须先于工作许可持久化。worker在同目录临时文件写候选/恢复记录，flush并fsync后原子替换已完成记录；记录带单元身份、序号与内容摘要。事件账本追加后flush并fsync，读取只接受完整且校验通过的记录；残缺尾部按中断登记，不能视为成功。
