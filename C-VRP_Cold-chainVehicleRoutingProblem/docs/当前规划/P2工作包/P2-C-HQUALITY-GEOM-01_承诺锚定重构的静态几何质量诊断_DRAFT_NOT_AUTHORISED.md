## 0. 唯一主假设

> **H-GEOM-01**：在相同公开状态、冻结锚点、固定 mask 与共享合法动作空间下，`MaskCO-greedy` 产生的完整车队计划，其**剩余行驶距离**是否低于**冻结 distance-SGBS 候选集合中距离最短的计划**？

**唯一主对照**：`min_{P ∈ S_distance-SGBS} D_res(P)`（同一单元内）。
不再以 `distance-greedy` 为唯一对照——`S_distance-SGBS` 本身已包含它（`completions[0]` 就是无分支贪心补全），因此取集合最小即已包含更强对照。

**唯一主指标**：

```
ΔD(unit) = D_res(P_MaskCO) − min_{P ∈ S_distance-SGBS} D_res(P)
```

- `ΔD < 0` → MaskCO 的静态几何剩余距离更低；
- `ΔD = 0` → 相等；
- `ΔD > 0` → 距离搜索集合中存在更短方案。

**次级诊断（不替代主判据）**：`D_min^enum` 与 `D_res(P_MaskCO) − D_min^enum`，见 §5。

## 2. 数据问题与恢复规则（本轮只读核对已确认）

**冻结工件不保存完整车队路线。** 已核对 `pass_a_run*.json` / `pass_b_run*.json` 的全部字段：

| 文件 | 每单元可用的计划信息 |
|---|---|
| Pass A | `sides.{model,distance}.plan_hash`（16-hex）、`cvid_suffix`（**只在途车**的后缀）、`anchor`、`suffix_first_after_anchor`、`status` |
| Pass B | `sides.{mode}.valid_plan_hashes`（哈希列表）、`n_unique/n_total/n_fail/n_valid`、`set_intersection/union`、`uncovered_model_plans` |

⇒ **单凭哈希无法计算全车队距离**，必须恢复完整计划。

### 2.1 恢复方法（严格限定）

从**保存的公开视图**出发，用**冻结的共享合法动作枚举器**（`camr_shared.legal_actions_shared`，T2 已冻结哈希）重建与 CAMR-STATIC **完全相同的重构关系**，再以 `plan_hash` 匹配冻结工件。

1. **仅**使用原 19 个注册单元，不新增样本。
2. **不加载** MaskCO checkpoint、**不做**模型评分、**不重跑** SGBS 或源日。
3. 对每个已记录哈希要求**唯一恢复**完整计划，并复核锚点三元组、`committed_next` 不在后缀、exact-once、`route_check` 全通过；**不能唯一恢复则登记阻断**（§6），不得用近似计划替代。
4. **在完成全部计划身份匹配之前，不计算、不解释任何几何差异。**
5. 所有距离使用**同一公开坐标**（`ref.public_env(view).dist_mat`）与**同一返仓规则**，**不使用未来订单信息**。

### 2.2 本草案补充的三条硬性约束

6. **同一关系**：恢复必须使用 `camr_shared` 的 mask-移除→逐单插回关系（与产生记录哈希的那条路径一致），**不得**改用 ANCHOR-01 的 relocate 枚举。
7. **闭包完整性**：恢复集合必须是该关系的**完全闭包**；若设置了枚举上限而未达完全，登记 `ENUMERATION_CAPPED`（§5 说明其逻辑方向）。
8. **模型无关**：恢复与距离计算**全程不需要模型**。计划身份已冻结为哈希，匹配是纯查找。因此本包可以完全落在"禁止模型加载"的授权边界内。

### 2.3 恢复身份必须按 `(unit_id, plan_hash)` 绑定（R0.1 修订）

**`plan_hash` 不编码几何。** 源码核对（`action_contract.py:301-309`）：哈希只喂入

```
vid,  anchor_node,  repr(tuple(suffix))
```

**不含** `anchor_time`、`anchor_load`、也不含任何公开坐标。因此两个不同公开状态可以产生**相同哈希而几何距离不同**的计划。

**由此冻结三条：**

9. 恢复任务的计数单位是 **`(unit_id, plan_hash)` 对**，共 **123 个**（各单元 `set_union` 之和），**不是** 107 个可复用的完整计划。
10. **禁止**建立以 `plan_hash` 为唯一键的全局物理计划缓存；任何跨单元复用都是错误。107 只可作为"哈希字符串互异数"的统计量报告。
11. 每个 `(unit_id, plan_hash)` 必须在该单元**自己的公开坐标与锚点时间/载重**下恢复并计算 `D_res`；`ΔD` 只能单元内比较。

**已观察到的现实例子**：SAA `d1 ord6` 与 MYOPIC `d1 ord7` 两侧的计划哈希分别完全相同（model `799e9894`、distance `d308f77e`），但两者 `public_identity` 不同、锚点 finish 不同（3.807 vs 6.222）——同哈希、不同物理计划与不同几何。

## 3. 距离指标

```
D_res(P) = Σ_{v ∈ P} D( anchor_v → suffix_v → 0 )
         = Σ_v [ dist(anchor_v, s₁) + … + dist(s_n, 0) ]
```

冻结口径（逐条对应裁定）：

- **计划来源**：`build_vehicle_plans` 语义——`closed` 车不进入计划（无剩余距离）；`committed` 车 `anchor_node = committed_next`；其余车 `anchor_node = current_node`；`suffix` 不含 `0`。
- **空后缀**：计入 `dist(anchor_v, 0)`（假设返程）。**这是一个几何完成约定，不代表引擎已决定返仓**；措辞见 `NOTE_L1A_SUFFIX_SEMANTICS.md`。
- **不计入**：已执行行程与在途承诺腿（`current_node → committed_next`）。它们在全部候选间**完全相同**，是常数平移，不影响 `ΔD`。
- **不引入**：燃油成本、制冷能耗、鱼类品质、拒单损失、`coldchain_cost`、任何效用权重。**距离减少不等于 utility 增加**，本轮不为此编造数值。
- 距离单位与缩放沿用公开视图的 `dist_mat`（Euclidean，公开坐标），**不做**任何归一化或与历史结果口径混用。

## 4. 观测清单（主 / 派生 / 描述性）

| 指标 | 回答的问题 | 地位 |
|---|---|---|
| `D_res(P_MaskCO)`、`min_{S_SGBS} D_res` | 跨车重分配是否减少总体绕行 | **唯一主指标** |
| `ΔD` 与相对变化 `ΔD / min_{S_SGBS} D_res` | 几何幅度是否值得关注 | 主指标派生量 |
| 后缀非空车辆数 | 是否调用更多车辆承担后续任务 | 描述性 |
| 由 depot 新增出发的路线数 | 工作是否被转给原本空闲的车 | 描述性 |
| 每车 `tw_slack / cap_slack / return_slack`（`ac.certify_route`） | 新计划是否更贴近已检查的约束边界 | 描述性 |
| `D_min^enum` 与 `D_res(P_MaskCO) − D_min^enum` | 距离静态可达最优还有多远 | **次级止损诊断** |

描述性指标一律**不得**改写主判据。

## 5. 穷举几何参考（次级止损检查）

### 5.1 定义

```
P_legal(unit) = 在共享合法动作集合下、以 mask 移除→逐单插回完全枚举得到的全部合法完整计划
D_min^enum   = min_{P ∈ P_legal} D_res(P)
```

`P_legal` 包含 `P_MaskCO` 与 `S_distance-SGBS`（两者都由同一关系产生），因此在同一距离目标上 **MaskCO 不可能严格优于 `D_min^enum`**。

### 5.2 为什么它比 L1-B 更要紧

**"固定双订单 + 小队列"意味着合法空间可能非常小。** 若廉价穷举就能轻易得到更短距离计划，那么"distance-SGBS 未覆盖"只说明**小 beam 的覆盖不足**，不说明学习评分具有独立的几何搜索价值。这是一项**刻意的科学止损检查**。

### 5.3 关于"152 个候选"的更正提示

ANCHOR-01 记录的 152（13 相位 × 8 + 2 相位 × 24）来自 **relocate 语义 + `allowed = mutable ∪ {committed}`** 的枚举；CAMR-STATIC 使用的是 **mask 移除→逐单插回**。中间状态的可行性剪枝不同，**最终可达集合可能不同**。因此：

- **不得**把 152 当作本包的闭包规模；
- 闭包规模必须在执行时**实测并报告**（`|P_legal|` 逐单元）；
- 若两者恰好相等，也只是经验巧合，不是先验结论。

### 5.4 枚举上限的逻辑方向（必须冻结）

设枚举设上限 `CAP`（拟 `|P_legal| ≤ 5000`/单元）。若某单元触顶：

- `D_min^enum(capped) ≥ D_min^enum(true)`；
- ⇒ 由 `D_res(P_MaskCO) > D_min^enum(capped)` 可安全推出 `> D_min^enum(true)`（**"MaskCO 不如穷举"的结论在触顶下依然成立**）；
- 但 `D_res(P_MaskCO) ≈ D_min^enum(capped)` **不能**推出"MaskCO ≈ 穷举最优"（触顶下最优可能更低）。
- 触顶单元一律标记 `ENUMERATION_CAPPED` 并单独列出；**不得**计入"MaskCO 达到几何最优"的计数。

| 代码 | 含义 | 处置 |

| `RECOVERY_NOT_FOUND` | 记录哈希在闭包中不存在（关系不一致或闭包不完整） | 该单元 `INVALID`，**保留在 19 内**；先修关系再谈差异 |

## 7. 裁决顺序（有优先级，不是五档并列）

按顺序判决；前一级未通过则不进入下一级，**不得**把两级结论合并成一个"通过/不通过"。

### 第 1 级 · 证据有效性

19 个单元的全部 **123 个 `(unit_id, plan_hash)` 身份**都唯一恢复、锚点/ exact-once / `route_check` 全通过、且距离在各自单元的公开坐标下算得有限值 → 进入第 2 级。
否则该单元 `INVALID`（保留在 19 内）并停止质量分析，不得用近似计划替代。

### 第 2 级 · 相对唯一主对照的改善（唯一主判据）

- `n_improve` = 满足 `ratio(unit) ≤ −0.01` 的单元数（`ratio` 定义见 §7.1）。
- **无任何单元达到阈值** → **H-GEOM `NO-GO`**：停止以静态距离收益支持 CAMR 扩张。
- **仅个别单元达到、且集中于单一开发根日** → 保留探索性结果，**不扩张**。
- **day 0 与 day 1 各至少一个独立物理状态达到阈值** → 记录为"**跨两个已观察开发实例出现改善**"，**不得**称为稳健性通过，**不自动授权**后续工作。

### 第 3 级 · 穷举参照（独立报告，不参与第 2 级判决）

报告 `|P_legal|`、**枚举实际耗时（wall）**、**展开节点数**、以及 `D_res(P_MaskCO) − D_min^enum`。第 3 级只能给出以下三种之一：

- `ENUM_STRICTLY_BETTER`：存在更短的合法计划 → 至多建立**有限搜索预算下的几何改善线索**，**不得**建立"学习搜索不可替代"的贡献；
- `ENUM_TIE`（差距落在 1% 内） → 至多称为"接近静态可达最优"，仍不证明冷链质量优势；
- `ENUM_CAPPED` → 只允许上界方向推断（§5.4），**不得**计入"达到几何最优"。

**同时为真的处置**：若第 2 级通过而第 3 级为 `ENUM_STRICTLY_BETTER`，结论只能是"**小 beam 未覆盖 ≠ 独立优化优势**"，优先级高于第 2 级的任何措辞。**必须**报告穷举的实测成本，否则"廉价穷举"只是猜测。

### 7.1 1% 阈值的正式定义与边界

- `D_SGBS,best(unit) = min_{P ∈ S_distance-SGBS} D_res(P)`（同一单元内，含其 `completions[0]`）；
- `ΔD = D_res(P_MaskCO) − D_SGBS,best`；
- `ratio = ΔD / D_SGBS,best`；`improve ⟺ ratio ≤ −0.01`。
- **分母为零**（`D_SGBS,best = 0`）：保留绝对 `ΔD`，相对比例记为 **`N/A`**，该单元**不计入** `n_improve` 并单独列出；**禁止**事后加任意小常数、换分母或作其它变换使比较成立。
- 报告必须同时给出**绝对 `ΔD` 与相对 `ratio` 两种口径**，以及逐单元明细。
- 该 1% 是**事前研究筛查门槛**，不是统计显著性、不是效果量；正式阈值在创建 `registration.json` 前由项目负责人确认后冻结。
- 样本性质：19 个单元是相位–mask 暴露量，来自 **2 个**已观察开发实例，**不是**独立样本；任何"稳健性/总体优势"表述均不成立。

1. **完整车队路线确实不在冻结工件里**，恢复是必要的，且只能通过"同关系重建 + 哈希匹配"完成。
