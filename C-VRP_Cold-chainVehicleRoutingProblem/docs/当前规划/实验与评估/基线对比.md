# DynMaskCO-CC 基线对比

> 2026-09-19 · 目标是可信的算法比较，而非建立最多的适配/门控框架。最新资产审读见[项目内基线核查](MaskCO新主线基线核查_2026-09-19.md)。

## 1. 先做最有信息量的比较

| 层次 | 对照 | 回答的问题 |
|---|---|---|
| 必做研发 | JF1-H-F；同协议冷链增量 heuristic | 学习是否优于当前稳定规则和直接冷链规则 |
| 必做强参考 | OR-Tools-RH / PyVRP-RH 中已可公平运行者 | 相同预算下优化质量与速度是否有竞争力 |
| 必做 learned | 选择一个具备源码/权重、可公平适配的强方法 | 是否优于同类学习方法，而非只胜弱启发式 |
| 必做归因 | one-shot、no/random mask、generic/feature-only、distance-only labels | 改善来自哪些组件 |
| 辅助 | O0-CC；旧 DynMaskCO；JF2/HFR | 有限动作潜力、方法演进和负结果 |
| 按需扩展 | 第二个 learned、冷链 solver 代理、更大规模 | 加强竞争性或回答审稿问题 |

不要求首次运行把 CC_Compare 所有仓库都复现。源码克隆、原方法跑通、DCC 适配、同口径正式可比是四种不同状态。
本轮只读核查CC_Compare源码/既有运行产物，未运行方法或完整复验冻结身份，不更改其源码/冻结证据。OR/PyVRP已有迁移记录；RRNCO新RH适配已有真实模型R0.5 smoke，尚不能视为正式性能矩阵。

## 2. 两类结果表与共同 evaluator

距离兼容表报告纯 distance_cost；冷链表报告 J_CC 与原始 D/Q/E、服务/硬约束、runtime。
所有可在同一任务下执行的方法都可列入冷链结果表，包括 distance-only objective 的强方法，必须标明其优化目标与可用特征。
同时提供冷链感知 heuristic，避免主方法只占目标函数信息优势。不能把 baseline 不读取热状态当排除它的理由。
oracle 单独标“离线有限预算参考”，不是在线方法、全局最优值或严格上界。

历史 JF1-H 24.50、JF2 25.91、HFR g_only 24.97 等只在原 distance 协议中解释，不能直接拼入新 coldchain 表。当前开发底座使用 JF1-H-F，别混淆与旧 JF1-H。

## 3. 冷链对照怎样做

JF1-H-CC（计划名，不能冒充已实现）：在可见状态下用 projected ΔJ_CC 排 certified action，使用相同服务规则、fallback 与在线预算；不读取真实未来。
OR-RH-CC 若需线性化/代理冷链目标，明确公式、预算与代理误差，最终仍用共同 trace evaluator。不是开启一个名称就视为已具备冷链能力。
首轮先做冷链启发式与已有强 solver；若主张接近冷链 solver 的最优权衡，再投入更强代理/搜索适配。

最新提案的关键组件对照为**CC-LNS-RH（待实现）**：与MaskCO共享公开冷链状态、目标、mask合法范围、认证/接受，用非学习联合修复生成计划。先检验这一可部署目标的闭环收益，再研究学习重构增量；具体目标与停止条件见[新工作包](../研究设计/MaskCO职责重定与下一阶段工作包.md)。旧S_proxy未建立收益，不可无验收直接复用为可靠选择器。

## 4. 外部 learned 的选取与适配

优先将已有真实模型smoke的**RRNCO-Ordering-RH-D**形成正式比较，明确真实网络排序器与确定性车队协调器的职责。RouteFinder作为第二候选（已有源码/权重，当前DCC适配待做）；CaDA旧一次性适配不直接冒充当前RH对照。CO-enriched-ML的动态派车波次与当前在途pickup语义不同，适配须另评估。
必须核对 future visibility、frozen/committed、capacity/TW、多车辆、完整服务以及训练数据与预算。
naive future masking 不是天然公平的 rolling-horizon baseline；不能故意采用弱适配制造优势。
若只实现了 distance objective，照常报告共同 J_CC，但不得据此单独证明主模型的冷链表征优越。
不改第三方原始源码，适配仅在其独立 adapter 目录，本规划不授权改动它们。

## 5. 预算和消融

整方法可以不同候选、不同搜索，但共享任务、信息、evaluator；给可比 wall-clock/硬件预算和至少几个质量–时间点。具体预算由 DEV 实测设定。
模型在线成本包含编码、候选生成/认证、重构循环、fallback；离线 teacher、训练和超参搜索成本单独报告。
不能只计网络前向并把昂贵搜索隐藏到计时之外，也不能给 solver 极短预算再宣称 SOTA。
组件消融固定候选/预算，random mask 匹配 mask rate，generic 控制容量与调参资源；报告必要差异。
所有主方法、对照与核心消融在锁定后的 TEST 上一起评价，不只展示 DEV 上筛选过的消融。

## 6. 可复用公开入口

[SINTEF Solomon](https://www.sintef.no/projectweb/top/vrptw/solomon-benchmark/)用于静态 VRPTW 基准核查；其原始车辆数优先目标与本项目目标不同，不能直接引用其 BKS 为本任务最优值。
[EURO Meets NeurIPS 官方 quickstart](https://github.com/ortec/euro-neurips-vrp-2022-quickstart)提供动态 VRPTW 环境与 baseline；其 epoch dispatch 任务不直接等同在途 pickup-to-depot。
具体下载版本、license、转换与结果必须后续实际核查。本轮只确认入口，不把候选来源当已复现数据集。

## 7. 论文结论

目标是有证据地优于强对照或建立清晰的质量–速度/适用域优势，不保证所有方法、所有 cell、所有指标均获胜。
若强 solver 更优，应诚实报告其优势，并检验学习方法是否有速度或特定条件价值；若没有，不宣称 SOTA。
