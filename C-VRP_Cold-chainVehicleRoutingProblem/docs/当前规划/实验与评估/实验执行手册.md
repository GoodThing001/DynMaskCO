# DynMaskCO-CC 实验执行手册

> 版本：2026-09-03 v4  
> 用途：从当前源码到论文证据的唯一实验 DAG。代码文件/API 以 `代码实现蓝图.md` 为准，指标以 `评估口径.md` 为准。

## 0. 总执行图

```text
P0-R/S/A/U 已完成
       ↓
P0-M project layout/import compatibility
       ↓
C0 cold-chain contract/state/trace evaluator
       ↓
O0-D distance action oracle
       ↓
O0-CC cold-chain action oracle
       ├─ No-Go → 扩 action/lookahead → 重跑 O0
       └─ Go
            ↓
M0 frozen-MaskCO representation probe
            ↓
M1 DynMaskCO-CC event-masked utility-aligned reconstruction
            ↓
M2 optional on-policy aggregation
            ↓
A1 identity/mechanism attribution
            ↓
E1 dynamics × thermal stress × scale × 5 seeds
            ↓
T1 one-shot TEST
```

P0-M 先按 path/import/entry smoke → P0 regression 推进；科学阶段按 unit/synthetic → VAL16 → VAL32 → VAL128 推进。上一 Gate 未通过，不进入下一阶段。

## 2. P0-M 与 P0 回归

任何实验前先验证：

- 上游根目录唯一为 `MASKCO_code/`，扩展根目录唯一为 `C-VRP_Cold-chainVehicleRoutingProblem/`；
- 从不同当前目录运行时解析结果一致；
- 上游和扩展代表模块导入到预期文件；
- 训练、解码、仿真和评估代表入口 smoke 成功；
- `MASKCO_code/` 无扩展侧修改；
- `results/p0m/project_layout_tests.json` 存在且 Gate PASS。

C0 及之后每次更改 event state、snapshot、action 或 evaluator，都必须重跑：

- P0-R 18/18；
- P0-S 7/7；
- P0-A 7/7；
- P0-U 4/4；
- distance-only JF1-H no-op/incumbent parity。

任何回归失败先修复，不允许用新冷链结果覆盖。

## 3. Phase C0：冷链评价闭环

### C0.1 冻结建模合同

先写清并序列化：

- 已锁定的 pickup-to-depot 状态机：空载出发、`service_finish` 入舱、`return_arrival` 卸货、单次行程、无 reload；
- 已锁定的同构多温舱与共享总容量；
- cargo manifest、`picked`/`delivered_to_depot` 和品质计时语义；
- normalized coordinate/time 到 km/hour 的尺度；
- 环境温度和目标温度；
- 热传递、制冷功率、COP、dispatch 预冷能耗和开门过程；
- 温度依赖品质函数；
- 不可售阈值与硬温控边界；
- \(J_{CC}\) scales/weights；
- 参数来源、校准数据和 sensitivity 范围。

未冻结前不跑模型实验。

### C0.2 单元与解析算例

解析算例至少包含：

- 静置零时长；
- 取货前品质不计时、服务完成后订单入舱；
- 返仓卸货后 manifest 与载重归零；
- 恒温行驶；
- 无制冷自然升温；
- 制冷开启；
- 等距离不同 waiting；
- 有无开门；
- 同路线不同温区；
- 同一批取货订单换序：高易腐订单更晚取货时，其取货后至返仓暴露不得更长；
- 返仓能耗；
- 温区不兼容；
- snapshot 中途恢复。

每个算例给出手算或高精度参考值。输出 `results/c0/unit_cases.csv` 和 `coldchain_contract_tests.json`。

### C0.3 Trace parity

对同一真实 execution trace 比较：

1. 环境在线逐段累计；
2. trace evaluator 回放；
3. route/batch evaluator（仅在时间语义相同的静态 case）。

原始距离、订单级返仓品质、能耗、温度越界和 manifest 生命周期必须一致；动态 dispatch case 不得错误地把车辆起点时间设为 0。

### C0.4 Pilot 与冻结

只用 train/dev：

- 检查 \(D,Q,E\) 量纲和数量级；
- 冻结 scales；
- 选择一个主 \(\lambda_Q,\lambda_E\)；
- 预注册邻域 sensitivity；
- 冻结 distance degradation budget；
- 生成 `coldchain_contract_final.json`。

Gate C0：评估口径 §5 全部通过。

## 4. Phase O0-D：距离 oracle

目的：确认 P0-U 动作空间与 sequential rollout 没有协议问题。

依次运行：

1. 2–5 customer analytic cases；
2. VAL16 smoke；
3. VAL32 candidate/advantage diagnosis；
4. VAL128 sequential oracle。

必须同时输出 local baseline-state oracle 与 on-trajectory oracle。记录 hard outcome、distance、candidate coverage、NEW_ROUTE/anchored/position、fallback、first divergence 和 runtime。

Go：100% service/hard feasibility，且 distance 对 JF1-H 有可解释 headroom。若不通过，先扩 action。

## 5. Phase O0-CC：冷链 oracle

只将 outcome 从 distance 改为 \(Y_{CC}\)，其余完全继承 O0-D。每条 action 记录：

```text
state/action/plan/contract hash
hard outcome
distance_cost
quality_loss
energy_kwh
num_unsalable
thermal violations
coldchain_cost
delta against incumbent
continuation/runtime/failure
```

先做固定权重主设置，再做预注册邻域 sensitivity。只有 sequential oracle 在 100% service 下显著改善 \(J_{CC}\)，才进入 M0。

若 No-Go：

1. 增加 1–2 step lookahead；
2. two-customer relocate/exchange；
3. batch/event-mask action；
4. 每次重新编号 action contract 并重跑 O0-D/O0-CC。

## 6. Phase M0：frozen MaskCO 表征探针

### 数据

- state 来自 JF1-H 与 O0-CC 行为轨迹；
- 同 episode 的所有 states/actions 位于同一 split；
- 一个 state 的全部候选先保存 listwise outcome；
- batch 先采 state，再在 state 内采 pair；
- tie margin 来自重复求解/数值容差。

### 模型

冻结 causal MaskCO encoder，只训练 route-slot/cold-chain utility head。固定 customer order、candidate、continuation、evaluator 和 mask metadata。

### Gate

- Real labels 优于 Shuffle；
- pretrained MaskCO 优于 random/generic/feature-only；
- dev normalized regret 与 high-advantage recall 有效；
- strict-online rollout 100% service；
- \(J_{CC}\) 有非零改善或至少明显低于 heuristic action regret。

M0 是低成本表示诊断，不可直接作为最终论文方法。

## 7. Phase M1：DynMaskCO-CC

### 最小变量

在 M0 已固定的 candidate/teacher 上，只新增：

- fleet/thermal tokens；
- event/risk affected mask；
- masked action decoder；
- utility-aligned listwise target；
- 至多 \(K\) 轮 reconstruction。

第一轮只训练 adapter/decoder，不同时解冻全 encoder、不改变 search heuristic。

### Gate-0

- no-mask/no-residual/incumbent 模式与冻结基线 exact parity；
- real event mask 会改变 action score/trace；
- future perturbation 不改变当前 action；
- accepted action 均通过完整 certificate；
- rejected action 恢复 complete incumbent。

### VAL Gate

- 100% service 和硬可行；
- paired \(J_{CC}\) 优于 JF1-H-CC；
- \(D,Q,E\) 分项可解释；
- distance 不超过预注册退化预算；
- event mask 优于 no/random/shuffle；
- iterative reconstruction 优于 one-shot utility scorer；
- pretrained MaskCO 优于 generic。

## 8. Phase M2：on-policy aggregation

仅当 M1 offline 好但 online regret/结果退化时启动。优先收集：

- first divergence；
- high predicted advantage/high oracle regret；
- fallback 和冷链 hard-risk；
- 新 route composition；
- 高温、高品质风险和高能耗 states。

```text
D0 = behavior/oracle states
D1 = M1 on-policy states
D2 = optional second round
```

每轮保持 C0/O0 合同不变，最多两轮。用 dev 预注册停止条件；不得无限聚合到 VAL 变好。

## 9. Phase A1：归因

先固定主模型和 seeds，再一次只改变一个变量：

1. pretrained MaskCO vs random/generic/feature-only；
2. event mask vs no-mask/random/shuffle；
3. iterative reconstruction vs one-shot；
4. true thermal state vs removed/shuffled；
5. \(J_{CC}\) vs distance-only labels；
6. quality-only/energy-only/joint；
7. joint action vs slot-only/insertion-only；
8. Real vs Shuffle teacher；
9. offline-only vs aggregation；
10. candidate/lookahead sensitivity。

每个消融共享 candidate、fallback、evaluator、budget 和 paired instances。

## 10. Phase E1：正式矩阵

### Dynamics

| 维度 | 设置 |
|---|---|
| Solomon type | R1 / C1 / RC1 |
| EDoD | 0.2 / 0.5 / 0.8 |
| scale | 50；至少一组 100 |
| train seeds | 42 / 123 / 999 / 2025 / 2026 |

### Cold-chain stress

| 维度 | 最低设置 |
|---|---|
| 温区分布 | balanced / chilled-heavy / frozen-heavy |
| 热压力 | normal / high ambient / long service-door |
| objective | distance / quality / energy / joint |
| weights | 主设置 + 预注册邻域 |

### Baselines

NN/EDD、JF1-H、JF1-H-CC、OR-Tools-RH、OR-Tools-RH-CC、旧 DynMaskCO、JF2/HFR、M0 one-shot、DynMaskCO-CC、Shuffle/no-mask/generic，以及至少一个公平 external learned baseline。

## 12. Phase T1

在模型、物理合同、objective、权重、mask、候选、预算、seeds 和统计计划全部冻结后建立 TEST ledger。TEST 只运行一次；若之后修改任何上述项，必须声明新研究轮次。

## 13. 禁止事项

- C0 未通过即训练或宣传冷链模型；
- P0-M 未通过就运行或解释训练、解码结果；
- 将预计算参考路线的 `quality_loss` 当任意方案真值；
- 用三套不同热模型分别训练、解码和评价；
- 用复合成本覆盖旧 `distance_cost` 字段；
- action oracle 前堆大模型；
- 把 M0 frozen encoder + MLP 当最终 DynMaskCO；
- 使用 future 温度/订单信息；
- 改变 candidate/budget 后仍称同一消融；
- incomplete 方法进入成本主排名；
- 多次查看 TEST。
