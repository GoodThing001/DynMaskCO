## 0. 当前批次与执行分工

本轮按 [event_plan_v1 执行协议](../工程实现/event_plan_v1执行协议.md)的 E0–E4 实施：先接口与 20 点 TRAIN 计时，再有限标签/训练和 CAL/DEV 闭环。协议统一维护候选数、生成尝试、seed、阈值、停止条件及回传字段，本手册不复制这些数值。

助手负责重要文档，用户负责代码、测试、提交、上传及服务器运行。本轮文档更新没有执行新实验。以下 §3–5 的旧 teacher/M0/M1 步骤保留实现背景，不重启已完成批次，也不把旧 K=2/4 或聚合建议当当前默认动作。

新版本主对照为 JF1-H-F、同候选简单距离选择与 learned 完整计划选择；MaskCO 生成器就绪后再区分生成器和选择器增量。保持当前环境/合同，不能为了让后段修改存活而只对 learned 方法改变 reveal 清尾。

训练、CAL 及 DEV 的实际运行数和耗时均计预算。CAL 必须按各阈值跑真实闭环，不能过滤旧轨迹代替；DEV 保持开发身份。三 seed 的同实例结果按交叉/配对结构报告，事件数不能充作独立样本。最终确认样本量和分析在访问前固定。

## 1. 实验依赖

已有 P0/C0/oracle 底座 → 新 TRAIN/DEV 的完整候选标签 → M0 短诊断与 M1 原型 → DEV 迭代 → 最终设定下公平比较、归因和独立 TEST。

文献参数化、公开数据复核、外部 baseline 适配并行开展。独立物理实验、v2-light 和 ORACLE-VAL 都不是启动 M0/M1 的前置条件。

## 2. 开发运行最低记录

每次保存：run_id、源码 commit 与未提交 diff、数据文件/实例分组、原始和 effective contract hash、profile、checkpoint、配置、训练/评估 seed、环境、日志、逐实例结果。
保存全部失败，不覆盖上轮目录。不需要每次生成正式 archive 或远端备份。
最终论文 artifact 再统一打包；既有 archive 接口和旧封存包不改。

## 3. Teacher 数据小闭环

- 使用新 TRAIN/DEV 基础实例，先完成重叠检查。
- 选少量上下文保存全候选，不能把 oracle_log 的最佳动作当完整 listwise 数据。
- 使用 scripts/simulation/counterfactual_teacher.py 的现有原语作为底座；完整 exporter（`export_coldchain_teacher.py`）、QC 与训练接线已实现（2026-09-17），服务器已跑。
- 对每个候选从同 snapshot 恢复、同 continuation/预算终局 rollout；保存 KEEP 参照、证书、hard vector 和 D/Q/E/J。
- 协议错误停止该样本批次；service-fail 合法记录但不进成本偏好损失；无有效候选的 context 记录并计 coverage。
- 同 episode 的事件/候选/场景增强不能跨 train/dev/test。
- 按基础实例→context 平衡抽样；事件和 action 数不冒充独立样本量。

第一次建议 8 TRAIN + 4 DEV、每实例最多 4 个上下文；先计时，不立即跑 1152 个完整 sequential oracle。完整导出、训练命令待对应脚本实现后给出，不能调用旧 train_hfr_m0.py 冒充新模型。

## 4. M0：先回答学习链有没有信号

小训练子集过拟合检查 → frozen MaskCO head / feature-only / **Representation-shuffle** → 独立 DEV regret → 少量完整在线 rollout。
首轮 1–2 seed 仅诊断，数据量由 CPU teacher 吞吐决定。
保持候选、特征可见性和预算一致；**Representation-shuffle 在 context 内对候选 embedding 分支按固定置换打乱，显式特征/标签/合法性不变**；**Label-shuffle 仅作可选 sanity（只打乱 TRAIN 有效标签，DEV 保持真实）**，两者分别命名、分别报告，不混称。若节点置换后再做全局均值导致表示不变，则该置换不是有效的表征消融。
不要以“hash 相同”代替行为回归；有接口变化用少量真实实例对账即可，不无限加审计层。

## 5. M1：让掩码重构真正决定动作

先接 fleet/thermal token、event mask、masked action reconstruction 与 replanner。K=1 跑通后比较 K=2/4。
no-op 恢复原计划；拒绝的动作不能部分写回；已执行/committed 区域不变。
评分只能使用当前可见信息；模型不允许调用真实未来 oracle 作为在线验收器。
证书证明当前动作可行，不证明未知未来全部可完成。完整服务仍由完整 episode 实测。
DEV 允许正常架构/超参/微调迭代；M0 不作为必须先显著通过的审批节点。

## 6. DEV 选择与基线

先建立 JF1-H-F、当前可见冷链增量 heuristic、强 rolling-horizon solver 和主模型的小矩阵。
不要只因不会使用热状态而排除表现强的 distance-only 对照；所有方法在共同 evaluator 下报告 D/Q/E/J，并标出目标/输入差异。
机制消融控制候选和 fallback；整方法对比允许不同搜索设计，但总在线预算和调参资源要公平。
在扩大参数搜索前先查未改善来自标签、特征、动作分叉、分布偏移还是预算，不把“不显著”当代码错误。

## 7. 路线 B 并行任务

公开论文/规格提供模型形式、参数或范围；无法转移的参数保留 assumption/pilot 标签。
不要求自有车辆、传感器或真实商品批次，不设仪器 P1–P6。
不以 M1 胜负拟合物理参数；目标权重可作为算法任务设定，但必须公开选择依据与敏感性。
合同变化后重做受影响的标签、scale 和对照。旧模型在新合同上可以作为明确 zero-shot transfer 实验，不能伪装成同合同训练。
来源和数据抽取详见[路线 B 参数清单](冷链参数标定清单.md)。

## 8. 论文矩阵分层扩展

第一层：50-node R1/C1/RC1 × EDoD 0.2/0.5/0.8，主 nominal；5 个学习 seed 为正式目标。
第二层：100-node 与高动态/热压力，验证适用范围。
第三层：权重和参数敏感性，必要的 quality/energy 分解。
核心消融：pretrained vs generic/feature-only、event vs random/no mask、iterative vs one-shot、thermal true vs removed、joint vs distance labels。
JF2/HFR 作为历史负结果，不必在全部新 cell 重跑；M2 仅在明显分布偏移时做，首轮预算最多 1–2 次聚合，DEV 记录任何追加研究。

## 9. 最终 TEST 与统计

在 TEST 访问前锁定主模型/checkpoint 选择规则、主对照、核心消融、场景、全部 seed、样本数、预算、主终点和统计程序。
同场景同实例配对；跨场景共享内部 seed 时成组重采样；多训练 seed 与实例交叉处理，不能复制 baseline 计成独立样本。
正式计划选择一个主比较，其他预声明确认比较做多重性处理或标探索。
不按 TEST 结果增删实例、挑 seed、改权重或只报告获胜 cell。技术失败的恢复可在同冻结身份下按事先规则续跑，失败尝试留痕；这不同于重新选模型后再次测试。
若 TEST 不支持优势，如实报告，不能靠新 TEST 无限试到显著。
