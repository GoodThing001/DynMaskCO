# DynMaskCO-CC 评估口径

> 版本：2026-09-03 v4  
> 本文件是结果准入的硬契约。主线已锁定为动态冷链优化；C0 实现 Gate 已通过，但在 O0-CC、正式校准和方法实验完成前仍不得声称冷链优化效果成立。

## 0. 运营前提

主协议是 **dynamic cold-chain pickup-to-depot**：车辆空载出发，客户服务完成时取货，货物品质从 `service_finish` 累计到 `return_arrival`，返仓统一卸货并关闭车辆。`complete` 不再只表示访问全部客户，而是同时要求全部订单恰好取货一次、全部启用车辆返仓、全部货物送达仓库且终局 cargo manifest 为空。

## 1. 指标命名不可混淆

- `distance_cost`：所有已用车辆含返仓的纯行驶距离；与历史 strict-online 结果兼容。
- `quality_loss`：按订单从取货完成到返仓卸货的真实 execution trace 累计，并按冻结的货量/产品价值规则汇总。
- `energy_kwh`：由统一物理单位计算的制冷能耗。
- `num_unsalable`：按返仓卸货品质与 C0 冻结的分类阈值统计的不可售订单数。
- `coldchain_cost`：由冻结合同计算的复合目标 \(J_{CC}\)。

禁止把 `coldchain_cost` 简写为旧字段 `cost`；历史表中的 `cost` 一律解释为 `distance_cost`。

## 2. 评价顺序

### Layer 1：服务与硬可行性

逐实例报告：

- complete、unpicked/unserved、duplicate pickup；
- all cargo delivered to depot、terminal manifest empty；
- TW、capacity、depot return；
- frozen-prefix 与 committed invariant；
- future leakage 和 silent-drop assertion；
- temperature compatibility；
- C0 明确列为硬约束的温控越界。

主方法任一硬指标弱于对照，主 Gate 自动 FAIL，不再用较低成本补偿。

统一 lexicographic hard outcome：

$$
H=(n_{\mathrm{unpicked}},n_{\mathrm{duplicate}},n_{\mathrm{not\text{-}depot\text{-}delivered}},n_{\mathrm{TW}},n_{\mathrm{cap}},n_{\mathrm{return}},n_{\mathrm{temp\text{-}hard}}).
$$

### Layer 2：动态冷链主目标

仅在 Layer 1 全通过的同实例 paired set 上比较：

$$
J_{CC}
=
\widetilde D
+\lambda_Q\widetilde Q
+\lambda_E\widetilde E.
$$

归一化统计只能来自 train/dev，权重与阈值在 VAL 主模型选择前冻结。主表必须同时列原始 \(D,Q,E\)、不可售订单和温度越界，防止复合指标掩盖单项退化。

### Layer 3：距离兼容指标

`distance_cost` 单独报告，用于与 JF1-H、OR-Tools-RH、JF2/HFR 和外部 routing baselines 公平对比。冷链主方法允许在预注册的距离预算内换取品质/能耗收益；该预算由 C0 pilot 后冻结，不在看到 TEST 后修改。

### Layer 4：效率

分别报告 online model inference、candidate/certificate、masked refinement、offline teacher compute、总 runtime、peak memory 和参数量。

## 3. 数据与选择纪律

- train：teacher/state collection 和模型训练；
- dev：物理参数校准、归一化、权重范围、tie margin、架构和早停；
- VAL：Go/No-Go、方法选择和最终超参数冻结；
- TEST：全部冻结后 one-shot。

同 episode 或同源动态 realization 不得跨 split。正式统计单位为 instance 与 training seed，recourse states 或 action pairs 不能当独立 replicate。

冷链参数校准数据与 TEST 实例必须隔离；温度/品质参数不能通过 TEST 结果回调。

## 4. Manifest

每个正式 run 至少保存：

```text
dataset/split/instance IDs/hash
event engine/evaluator/snapshot/action schema
cold-chain contract version/hash
distance/time/unit scales
thermal/quality/energy parameters and source tag
operation_mode=pickup_to_depot, single_trip, no_reload
cargo-manifest schema and quality-clock semantics
hard temperature policy
J_CC normalization and weights
candidate/continuation/search budget
MaskCO checkpoint and edge-feature mode
mask policy and refinement steps
training/evaluation seeds
code/environment/hardware
```

缺 manifest 的数字只算 exploratory。

## 5. C0 冷链合同 Gate

以下全部 blocking：

1. pickup-to-depot 状态机与代码一致：空载出发、服务完成入舱、返仓卸货、无 reload/multi-trip；
2. manifest 数量之和与总/分温区载重一致，终局为空；
3. 品质计时只覆盖 `service_finish` 到 `return_arrival`；
4. 时间、距离、功率、能量单位闭合；
5. kW×h 和 J→kWh 单元测试正确；
6. 品质速率真实依赖温度；
7. 等温条件下，更长暴露不得产生更低品质损失；pickup 换序算例的计时方向必须正确；
8. 同条件下更高风险温度不得产生更低衰减；
9. 行驶、等待、服务/开门和返仓均进入 trace；
10. snapshot/resume 后 manifest、温度、品质、能耗 exact parity；
11. execution trace 与 batch/replay evaluator 对同一轨迹一致；
12. evaluator 不再固定输出 quality/energy=0；
13. future cold-chain 信息扰动不改变当前部署动作；
14. \(J_{CC}\) 可由保存的原始分量与合同 hash 重算；
15. 参数与敏感性范围有明确来源或 pilot 标识。

任何一项失败，禁止运行 O0-CC、M0/M1 主实验或使用“冷链优化”结果主张。

## 6. 已完成 P0 回归 Gate

- P0-R：比较器无 partial return，service-first；
- P0-S：snapshot/resume parity；
- P0-A：full-fleet action、ownership、certificate；
- P0-U：same-state/common-continuation、incumbent delta=0。

C0/M1 每次修改 strict-online state 或 evaluator 后必须重跑上述回归，不得因旧版通过而跳过。

## 7. O0 Gate

### O0-D

使用现有 `distance_cost` 和同一 Action Contract：

- sequential oracle on-trajectory；
- 100% service/hard feasibility；
- paired \(\Delta D<0\) 与 CI；
- candidate coverage、fallback、action 分布和 runtime。

O0-D 是动作/协议检查，不是冷链论文成立条件。

### O0-CC

与 O0-D 共用 candidate、transition、continuation 和预算，仅将排序 outcome 换为 \(Y_{CC}\)：

- sequential oracle 100% service 与所有硬约束；
- paired \(\Delta J_{CC}<0\)，95% CI 不跨 0；
- \(D,Q,E\) 分项方向和实例贡献可解释；
- 结果在预注册权重/温度敏感性范围内不依赖单一点；
- local baseline-state headroom 与 on-policy final headroom 分开报告。

O0-CC 不通过时，先修改 action/lookahead；不得直接通过加深网络绕过 formulation failure。

## 8. M0 与 M1 主 Gate

### M0 表征探针

报告：

- offline 与 on-policy normalized regret；
- high-advantage action recall；
- calibration；
- pretrained MaskCO vs random/generic/feature-only；
- Real labels vs Shuffle；
- strict-online final \(J_{CC}\)。

M0 只能证明表示/标签可学，不能单独支撑最终 MaskCO 方法贡献。

### M1 DynMaskCO-CC

主比较：

$$
\Delta J_{CC,i,s}
=
J_{CC,i,s}^{DynMaskCO\text{-}CC}
-J_{CC,i}^{JF1\text{-}H\text{-}CC}.
$$

准入顺序：

1. 所有实例 100% service；
2. TW/cap/return/frozen/committed/temperature hard feasibility 均不弱于 baseline；
3. mean paired \(\Delta J_{CC}<0\)；
4. 95% paired bootstrap CI 与预注册 paired test 支持；
5. 距离退化不超过预注册预算，或距离本身同步改善；
6. 5 training seeds 的方向一致性与 seed-level mean±std；
7. Real mask/label 优于 shuffle/no-mask；
8. iterative masked reconstruction 优于 one-shot utility scorer。

## 9. MaskCO 身份 Gate

| 对比 | 必须回答 |
|---|---|
| pretrained MaskCO vs random/generic | 收益是否来自 MaskCO 表征 |
| event mask vs no-mask | 动态掩码是否必要 |
| real mask vs shuffled/random mask | affected-region 选择是否有效 |
| iterative reconstruction vs one-shot scorer | MaskCO 重构循环是否真实贡献 |
| frozen vs adapter/partial fine-tune | 动态冷链适配来自哪里 |

若这些对比均无增量，论文不能宣称“基于 MaskCO 方法改进”；应返回 M1 设计，而不是只保留名称。

## 10. 冷链机制 Gate

| 对比 | 必须回答 |
|---|---|
| joint \(J_{CC}\) vs distance-only | 冷链目标是否改变并改善冷链结果 |
| true thermal state vs removed/shuffled | 状态输入是否被模型使用 |
| quality-only / energy-only / joint | 改善来自哪个分量 |
| 常规 vs 高温/长服务/温区偏斜 | 冷链机制是否在压力场景中稳定 |
| 权重与参数 sensitivity | 结论是否依赖单一人工设置 |

单纯因距离变短而品质同步变好，只能称协同效应，不能证明冷链感知机制有效。

## 11. 正式实验矩阵

### 动态路由矩阵

- 50-node：R1/C1/RC1 × EDoD={0.2,0.5,0.8}；
- 100-node：至少 R1/C1/RC1 × EDoD=0.5；
- 学习方法使用相同 5 training seeds。

### 冷链压力矩阵

至少改变三类因素：

- 温区分布：balanced、冷藏偏重、冷冻偏重；
- 环境/热压力：正常、高温或更长服务/开门；
- 目标权重：distance-only、quality-only、energy-only、joint 以及预注册邻域。

压力场景只改变公开环境参数，不能给部署策略泄露未来订单。

## 12. Baseline 公平性

主表至少包含：

- JF1-H（distance heuristic）；
- JF1-H-CC（相同动作/预算的冷链增量 heuristic）；
- OR-Tools-RH distance quality–runtime curve；
- OR-Tools-RH-CC 或明确能力边界的冷链 rolling-horizon reference；
- DynMaskCO 旧 distance-only 版本；
- M0 one-shot probe；
- DynMaskCO-CC；
- JF2/HFR 完整负结果对照；
- Shuffle/no-mask/generic；
- 至少一个可按 strict-online 协议公平适配的 learned baseline。

所有方法共享 event engine、evaluator、物理合同和服务优先规则。若外部方法无法消费热状态，必须标为 distance-only reference，不与 \(J_{CC}\) 主排名混排。

## 13. 统计

- per-instance paired delta；
- paired bootstrap 95% CI；
- 预注册 paired permutation 或 Wilcoxon；
- win/tie/loss 与 effect size；
- seed-level mean±std；
- scenario/EDoD/temperature 分层结果；
- 多权重结果优先展示 Pareto 或 trade-off curve；
- state-level 结果仅作机制分析。

只看 aggregate mean、单 seed 或 complete subset cost 不足以过 Gate。
