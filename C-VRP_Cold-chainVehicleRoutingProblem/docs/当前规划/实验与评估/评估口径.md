# DynMaskCO-CC 评估口径

> 2026-09-18 · 路线 B 的方法比较合同。区分研发诊断、冻结确认和真实部署主张；不以物理实测或 oracle VAL 审批模型开发。

## 1. 共同任务与指标

主任务为 strict-online dynamic cold-chain pickup-to-depot：空载出发，service_finish 入舱并开始品质计时，return_arrival 卸货终止计时；同构多温舱、共享容量、单次行程、无 reload。
所有方法共享实例、运营语义、事件引擎、可见信息和最终 evaluator。

- distance_cost：含返仓的纯行驶距离，绝不混入 penalty。
- quality_loss：模拟 execution trace 下的数量/价值加权损失。
- energy_kwh：声明模拟模型下的制冷能耗估计，不是车辆实测电耗。
- num_unsalable：合同中品质阈值的派生计数；无商品验证时只能称模拟阈值超限，不代表真实安全/不可售判定。
- coldchain_cost：独立复合指标，不得覆盖旧 cost。

\[
Q=\sum_i d_i v_{c_i}\left(1-\frac{q_i^{dep}}{q_i^0}\right),\qquad
J_{CC}=\frac{D}{s_D}+\lambda_Q\frac{Q}{s_Q}+\lambda_E\frac{E}{s_E}.
\]

s 和 lambda 明确版本；尺度只由 TRAIN/DEV 的预声明规则估计。无业务成本来源时 v 与 lambda 是任务偏好，不是货币成本。
现有 pilot profile v2 仅适用于相应合同，不能将其 raw kWh/品质数值宣传成实车收益。

## 2. 服务优先，不能靠漏单赢成本

逐实例报告 complete、unpicked/unserved、duplicate、TW/capacity/depot return、cargo delivered/manifest empty、temperature hard、ownership/accounting、frozen/committed invariance。
协议错误、非有限值、缺失实例不得静默填零；其结果不进入正常性能结论。

若任何方法服务不完整，仍报告它的失败率和失败实例。完整样本子集的 cost 只能作条件诊断，不能删掉失败实例后宣称主方法更优。
本项目“100% 服务下成本更优”的主张要求全预定评测集合服务/硬约束均通过。不能只比 Layer 1 通过的交集后泛化到总体。
若数据包含不可行请求，必须先明确可行性定义与拒单目标并作为不同任务报告，不能临时改罚分救排名。

## 3. 数据角色

TRAIN：训练和 teacher。DEV-MODEL（也可名 model validation）：开发选择、早停、消融排错，可重复。
DEV-PARAM/SCALE：数值检查、任务尺度规则；不能按哪个方法赢来定物理参数。
ORACLE-VAL：可选冻结 oracle 确认，不用于学习，不阻断 M0/M1。
FINAL-TEST：锁定后的泛化/归因证据，不用于开发选择。
历史 DEV-GATE/VAL128 已被查看，不重新包装为 untouched TEST，也不回填新 teacher。

> **本批 M0/M1 开发数据角色（2026-09-17）**：`TRAIN-64` 用于拟合参数与标签标准化尺度；本批 `CAL-16` 用于选择接受阈值；`DEV-CHECK-16` 用于开发诊断（因结果已用于后续设计，**不能称未见确认集**）；历史 `DEV-CAL` 用于冷链目标 profile 尺度，与本批阈值 CAL **不是同一角色**，勿混用两种 CAL。

按基础实例/instance_seed 分组，同源场景、增强、事件和动作不得跨 split。root_seed 不同只是第一层，仍检查内部 seed、源实例与内容重复。
公开基准只有一组小实例时，可报告公开基准对比，但不把反复查看的集合宣称为未见测试；生成式私有新 split 或独立公开集合可提供补充验证。

## 4. 模拟器有效性与研究边界

保留已有 C0 的单位、生命周期、守恒、温度依赖品质、trace/replay、snapshot/resume、future perturbation 检查。
本轮不要求实车预测精度、仪器证书或物理 holdout。采用文献支持形式和明确仿真假设，报告参数敏感性与局限。
数值测试过关不证明真实有效；论文需有最终参数表、来源/假设标记、适用域和复现说明。
发现单位错、未来泄漏或 evaluator 分叉时，停止解释受影响实验并修复；不因此要求从头重做全部项目治理。

## 5. Oracle、M0 与 M1 分工

- O0-CC：有限动作空间、有限 continuation 下的离线 lookahead 诊断；不是全局最优界，不是可部署方法。local 和 sequential 分开报告。
- pilot DEV-GATE GO 已支持继续做学习。新合同下可用小 DEV oracle 检查标签是否还有信号；不要求先跑正式 ORACLE-VAL。
- M0：可见表征是否学到动作效用。报告 context regret、high-advantage recall、KEEP 错误与在线效果，不能只看 pair accuracy。
- M1：完整模型在相同任务和预算下的在线结果；需证据支持 event mask、重构循环和冷链效用对齐的贡献。

M0/M1 可以现在开发。归因不支持某一组件时，应删减该组件或收窄主张，不能以堆模型/换测试集确保“过 Gate”。

## 5.1 离线诊断指标与接受规则（2026-09-17）

接受规则（带单位）：

\[
\widehat g=s[f(a)-f(\mathrm{KEEP/DEFER})],\qquad
\text{accept iff }\widehat g>\tau_J.
\]

本批阈值网格为 `{0, .002, .005, .01, .02, .05, ∞}`（J 单位），按 CAL 实例等权净收益选择，合格配置平局取较小阈值。`∞` 表示保持 baseline，不算模型取得收益；该网格是已完成批次的记录，后续变化应版本化。DEV 全网格只作探索性附表，不从中挑最优阈值当主结果。

离线诊断指标定义（baseline-state 离线反事实选择，**不是完整在线 episode 收益**）：

| 指标 | 定义 |
|---|---|
| net | context 收益先在实例内平均，再实例等权；正值更好 |
| regret | `g* − 实际选择收益`，未除候选成本范围（`g* = max(0, max_a[J_keep − J_a])`，仅有效监督候选） |
| coverage | 接受次数／全部 context 数 |
| harmful ratio | 有害接受次数／全部接受次数；零接受时未定义 |
| Spearman | 有有效标签变化的 context 内计算，再平均 |
| MAE | 所有有效监督候选汇总平均 |

`net` 与 `regret` 均按实例等权（`regret_instance_mean` 也是实例等权，非只有 net 一列）。另需注意：

- 这些是 baseline-state 离线反事实选择指标，不是完整在线 episode 的收益，不能把 context 收益相加当作实际总节省；
- 有服务失败或被选动作标签缺失时，净收益不能作为完整有效性能结论，必须同时展示失败标志与计数；
- 合法候选监督覆盖率的分母是因果合法候选；另列全部枚举候选覆盖率，不能混称。

## 5.2 local / sequential / hindsight 三者不可混用（2026-09-17）

三种 oracle/诊断量测的是不同对象，报告时必须分开列，禁止用比值或相加互相转换：

| 量 | 计算对象 | 统计单位 | 可否当在线策略上限 |
|---|---|---|---|
| local | baseline 轨迹上，每个客户独立试一次单动作取最好改善，再 customer→event→instance 平均 | 局部决策机会的平均改善 | 否；不是整条轨迹收益上限 |
| sequential | 逐客户选择动作并写回计划、持续执行到终局，相对 baseline 的完整轨迹终局 J 差 | 完整轨迹终局差 | 否；是真实未来辅助评分的参照，非严格上界 |
| hindsight 潜力 g\* | 每个 context 的 `max(0, max_a[J_keep − J_a])`（仅有效监督候选） | 单 context 事后潜力 | 否；离线反事实参照 |

关键边界：

- **local 与 sequential 不可比比值**：17 次相互独立、各改善约 0.016 的动作即可累计到约 0.27，无需任何迭代交互；CI 不重叠也不能消除统计对象不同。
- **local 不是 K=1 在线策略的收益上限**：K=1 已能在一事件内接受多个动作并跨事件继续决策。
- **无 eligible 实例**（某实例没有任何决策点）不计入 local 平均，但须显式报告 `no_eligible` 计数，不能静默当零。
- **service gate 处理**：任何方法服务不完整（complete/hard gate 失败）先报告失败实例与失败率；其 cost 只作条件诊断，不得删失败实例后宣布更优。协议错误实例不进入正常性能结论。

## 5.3 event_plan_v1 的完整计划评价边界（2026-09-18）

当前版本详细规范见 [event_plan_v1 执行协议](../工程实现/event_plan_v1执行协议.md)。完整计划标签为 g_B(z,P)=J(P_0→B)−J(P→B)，正值为改善；闭环主指标 ΔJ=J_method−J_B，负值为改善。旧标签本来就跑到终局，本次改变监督对象，不是首次引入终局奖励。

新版本阈值网格和选择规则只适用于该版本，不追溯修改 §5.1 的旧实验记录。完整计划 baseline-continuation 标签仍是代理目标，不能代替 learned 持续部署的完整 episode 验证。KEEP/候选的实际安装包含 WAIT/RETURN/deferred，不能以两份序列化指令不同代替执行核查。

分清固定状态同候选的选择能力与完整策略效果。不同策略分叉后的候选可以不同，不能把整轨迹差解释成每个局部动作的可加损失。相同首段 dispatch 不意味着计划执行等价，不按真实未来 reveal 过滤在线候选。

使用同一批实例评估多个训练 seed 时，实例与 seed 是交叉结构，3×16 行不是 48 个独立实例。固定 seed 平均后的实例配对区间需同时报告每个 seed，不能声称该区间充分覆盖训练随机性。开发集可重复用于设计，但独立确认/TEST 的样本量与统计必须在访问前固定。

既有 `has_future_reveal` 若在 baseline/写回中使用，须披露信息规则并跨方法一致；不因 learned 输入不包含该字段就宣布完整系统满足更强的非预知主张。改信息规则须另立协议，相关旧结果保留原身份。

## 6. 整方法公平性与消融公平性

整方法对比：允许不同候选/搜索算法，共享任务、数据、评价与可比总预算；报告目标能力、训练数据、调参资源与适配范围。
受控消融：尽量固定候选、fallback、teacher 和预算；如改变搜索覆盖，明确是整策略差异，不作单组件因果归因。
即使 baseline 不使用热特征，也可在共同冷链 evaluator 下列出 J_CC，标 distance-only objective；同时必须加入至少一种冷链感知强对照。
不能仅凭“不消费热状态”排除强 baseline，也不能声称击败它就证明冷链机制。
ORACLE 单列离线参考，不入在线时间/排名。

## 7. 主终点和确认统计

正式模型实验的默认主效应：nominal 下九动态 cell 等权、全实例配对的 mean ΔJ_CC（主模型减预声明主对照），负值为改善。
在 FINAL-TEST 前记录样本数、场景权重、主对照、全部 seed、CI 与失败处理；不能临时按结果挑检验。

- 先对每个训练 seed、每个实例算配对差值，再按预定义场景权重聚合。
- 实例与 training seed 为交叉随机因素。bootstrap 分别重采样训练 seed 和基础实例组，保留每个实例的场景向量和所有方法配对，重算同一主统计量。
- deterministic baseline 不因复制到 5 个 seed 就多了 5 倍独立样本；随机 baseline 保存独立 run seeds，并预先定义配对/平均方式。
- 报告 95% percentile CI、每 seed 效应、seed mean±std、win/tie/loss、各 cell D/Q/E、服务率、runtime。
- 小 seed 数 CI 精度有限；不能以 thousands of actions 代替训练重复。
- 默认一次主比较，以 mean<0 且 95% CI 上界<0 支持平均改善；这是证据判据，不保证每实例/每 seed 都赢。
- 多个确认比较使用预声明 Holm 等校正或同时区间；未预声明消融/子组标探索，不堆多种检验挑显著。
- 可选配对置换检验须说明交换性与重采样单位，不能把相关 cell 当独立。
- 敏感性不能救回 nominal 主比较失败，但其失败也不能被忽略：应收窄稳健性主张。
- distance trade-off 预算若采用，必须在 TEST 前数值化并解释依据；否则报告曲线，不临时声称符合预算。

现有正式 oracle 聚合器只适用于其冻结计划，不能直接冒充多训练 seed 的模型统计器；模型汇总接线属于后续实现。

## 8. 论文证据与复现材料

核心证据：与强 heuristic/solver/learned 对照的公平比较；event mask、iterative vs one-shot、pretrained/generic、thermal/目标消融；多分布/动态程度、规模和参数敏感性。
是否有贡献由效果、效率、适用范围和新颖性共同决定，不把“所有消融显著”当投稿资格证。

最终保存：源码与配置、split 清单、数据生成/变换说明、contract/profile、所有 checkpoint 选择记录、逐实例结果、日志、统计程序及失败清单。
冻结后允许同身份技术续跑并留痕，不允许更换方法继续窥探同 TEST。
没有本轮复算的历史值写 recorded；文档修改不升级实验置信等级。
