# DynMaskCO-CC 实验细节

> 版本：2026-09-03 v4  
> 未由 C0 contract、manifest 或 pilot 冻结的数值统一标 TBD。

## 1. 核心任务

默认 formulation 为 strict-online dynamic cold-chain pickup-to-depot VRP：

- 客户订单按 reveal time 出现；
- 每个订单是从客户取货并运回中心仓库的冷链请求，含坐标、取货量、取货时间窗、服务时间和温区；
- 执行过的 prefix 与已出发 committed leg 不可回滚；
- 策略在当前可见订单、车队和冷链状态上做事件驱动补救；
- 先保证服务与硬约束，再优化 \(J_{CC}\)；
- \(J_{dist}\) 保留为独立兼容指标。

运营语义固定为：车辆从仓库空载出发；客户处货物在取货前由外部合规冷库保管，前置品质不受路线策略影响；在 `service_finish` 时完成取货、载重增加并把订单加入对应温区的 cargo manifest；策略相关品质从此时累计到该车 `return_arrival`；返仓时统一卸货、清空载重与 manifest，车辆关闭。每车只有一次行程，不允许 depot reload 或 multi-trip。客户服务后状态为 `picked`，只有货物随车返仓后才是 `delivered_to_depot`。

这与现有引擎的 `current_load += demand` 一致。若未来研究 depot-to-customer 配送，必须建立新协议：仓库装货后载重随配送下降，且新揭示订单只能由仓库车辆承担或触发显式返仓 reload；不得与当前取货结果混写。

## 2. 数据字段

现有基础字段：

```text
coords, demands, tw_start, tw_end, service_time
temp_class, reveal_time, visible_mask
routes, opt_costs, optional dist_mat
```

现有 `quality_loss` 和 `energy_mat` 是历史预计算/辅助字段，不能作为任意 execution trace 的权威结果。C0 后建议新增：

```text
ambient_temperature_profile
vehicle_thermal_capability
initial_quality (optional; default fixed by contract)
thermal_contract_id
unit_scale_id
product_quality_parameters
```

固定参数可放 contract JSON，不必在每个 NPZ 重复，但 dataset 必须记录 contract hash。

## 3. 因果节点表示

现有 7D：

$$
x_i=[x_i,y_i,d_i/Q,e_i/T,l_i/T,c_i/2,r_i/T].
$$

要求：

- 坐标归一化只用 visible nodes；
- future 节点使用统一占位并在 attention 中屏蔽；
- edge features 对 future rows/columns 同时屏蔽；
- normalized `temp_class` 必须通过统一函数恢复为 0/1/2；
- checkpoint 是否使用 energy edge feature 必须写入 manifest。

冷链动态状态不建议直接塞入固定 7D 节点数组；M1 使用额外 fleet/thermal tokens，避免把 vehicle-level state 伪装成静态 customer feature。

## 4. Snapshot v3

`recourse_snapshot_v3_cc` 在 v2 基础上增加：

```text
coldchain_contract_hash
per-vehicle/per-zone temperature
total/zone load and thermal capability
cargo manifest: order, quantity, zone, pickup_finish, current_quality
cumulative energy
onboard order quality and finalized depot quality
thermal violation duration
door state/count
ambient state
```

snapshot hash 对 route 顺序和冷链状态敏感。resume 后相同 continuation 的 routing trace 与 cold-chain trace 均 exact parity。

## 5. Action Contract

最小 action：

$$
a=(j,s,p),\qquad p=(u,v).
$$

stable ID：

```text
(customer, slot_semantic_id, predecessor, successor)
```

NEW_ROUTE 对同质空闲车匿名；非等价 thermal state 的车辆不能折叠为同一 slot。也就是说，只有 anchor、可用时间、容量和冷链状态都等价的车辆才允许 permutation。

certificate 输出：

- route/fleet hard feasibility；
- capacity/TW/return slack；
- temperature capability、共享总容量与 manifest consistency；
- projected temperature margin；
- projected distance/quality/energy increment；
- full-fleet plan hash；
- reject reason。

projected 冷链值仅作 causal feature，权威 label 始终来自终局 trace rollout。

## 6. 冷链状态与目标

统一 transition：

$$
(\Theta',\mathcal C',E')=\Phi_{CC}(\Theta,\mathcal C,E;\Delta t,c,load,\psi).
$$

其中 \(\mathcal C\) 是订单级 cargo manifest；新订单只在 `service_finish` 加入，返仓在 `return_arrival` 记录最终品质后移除。

单位：

- distance：km 或明确的 normalized unit；
- time：hour；
- power：kW；
- energy：kWh；
- temperature：摄氏度，动力学中 Kelvin 转换显式；
- quality：内部统一保存 0–1 `quality_remaining`；loss 只在 evaluator 按初始/返仓品质计算。

目标：

$$
J_{CC}=D/s_D+\lambda_Q Q/s_Q+\lambda_E E/s_E.
$$

$$
Q=\sum_i w_i\left(1-\frac{q_i^{dep}}{q_i^0}\right).
$$

`s_D,s_Q,s_E,lambda_Q,lambda_E` 由 train/dev 冻结。主输出保留原始分量。NumUnsalable 使用按温区冻结的 threshold，不用任意单阈值在 TEST 后调节。

## 7. Event mask

Mask set 由当前信息决定：

```text
newly revealed customer
route slots marked needs_replan
mutable segments with low TW/cap/return slack
mutable segments with high thermal/quality/energy risk
```

禁止使用真实未来是否会冲突来决定 mask。mask policy 输出 affected customer/slot/edge IDs，并保存在 action trace。

最小消融：

- no-mask；
- random mask（同 mask rate）；
- shuffled affected mask；
- full mutable mask；
- event+risk mask。

## 8. Action feature

每个 certified action 至少包含：

- \(h_j,h_s,h_u,h_v\)；
- route member pooling 和 route length；
- clock、anchor node/time/load；
- TW/capacity/return slack；
- 当前 compartment temperature 与 target/bound margin；
- customer temp class；
- active zone/load、manifest size 与在途订单最差/平均剩余品质；
- projected energy increment；
- projected quality-at-risk；
- distance increment；
- event mask/replan reason；
- incumbent/action-type flag。

禁止 physical vehicle ID、future order features、future thermal demand、teacher objective 或真实未来统计。

## 9. Teacher label

每个 state 保存所有候选的 listwise outcome：

```text
state_hash/action_id/plan_hash/contract_hash
hard outcome
D, Q, E, NumUnsalable, thermal violations, J_CC
delta against incumbent
continuation/budget/seed
runtime/failure/tie
```

同 state 所有 action 共享 continuation。确定性 JF1-H 可用数值 tolerance 定义 tie；随机/OR continuation 先重复 5–10 次估计 noise，再冻结 margin。

## 10. M0 模型与损失

M0：

$$
q_\theta(z,a)=\operatorname{MLP}(
[h_j,h_s,h_u,h_v,f_{route},f_{slack},f_{thermal},f_{cost},f_{mask}]
).
$$

主要指标是 state-level normalized regret、高 advantage recall 与 rollout \(J_{CC}\)。pair loss 按 state 归一。M0 冻结 encoder，只作表征探针。

## 11. M1 模型与损失

M1 增加：

- fleet/thermal token adapter；
- event mask embedding；
- masked action decoder；
- 1–K 轮 reconstruction。

效用软目标：

$$
p^*(a|z)\propto\exp[-J_{CC}(z,a)/\tau_T],
\quad a\in\mathcal A^{bestH}(z),
\qquad p^*(a|z)=0\ \text{otherwise}.
$$

总损失：

$$
\mathcal L
=\lambda_{list}\mathrm{KL}(p^*\Vert p_\theta)
+\lambda_{pair}\mathcal L_{pair}
+\lambda_{inv}\mathcal L_{future-inv}.
$$

超参数 \(\lambda\)、\(\tau_T\)、K、top-k、accept threshold 与 mask rate 先 pilot，再在 dev/VAL 冻结。

## 12. 数据采样

```text
D0 = JF1-H/O0 behavior states
M0 = frozen representation probe
D1 = M1 first-divergence/high-regret/high-thermal-risk states
M2 = train on state-balanced D0 ∪ D1
D2 = optional second round
```

split 单位为 episode/instance。一个 state 的所有 actions 在同一 split；batch 先采 state，再采 actions/pairs。

## 16. 结果解释边界

- 若 distance-only 与 cold-chain joint 都改善：可写协同优化；
- 若 \(J_{CC}\) 改善但 distance 略升：按预注册 trade-off 解释；
- 若品质只因距离缩短而改善、true/shuffled thermal state 无差异：不能写冷链感知；
- 若 M0 有效但 event mask/iterative reconstruction 无增量：只能证明通用 utility learning，不足 DynMaskCO-CC；
- 若 C0 不稳：暂停模型结果，不切回 generic CVRPTW 继续写同一篇论文。
