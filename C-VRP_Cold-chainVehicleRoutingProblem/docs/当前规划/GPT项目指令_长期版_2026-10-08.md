## 2. 问题定义与硬约束（长期不变）
- 任务：pickup-to-depot 动态冷链 CVRPTW——订单按 `reveal_time` 陆续揭示，车辆从仓库空车出发取货回仓；含时间窗、容量、多温区（番茄 18°C 连续品质；鱼 4/−18°C 零阶感官+可售阈值）、制冷能耗、接单承诺（接受即不可取消）。
- **strict-online 因果协议**：非预知；只用可见信息（禁止 `coord_normalize` 等泄漏未来的接口）；已执行前缀与已接受承诺冻结；每单恰好服务一次。
- **能耗**：C0 合同；预算以 `certify_plan` 硬认证（越限不提交）；`distance_cost` 与冷链复合成本 `coldchain_cost` 严格分离，不得混用。
- **效用口径**：收入 − 燃油 − 拒绝损失；品质不货币化，鱼可售是硬约束。
- **工程边界**：`MASKCO_code/` 是上游实现，**永不修改**；所有扩展在 `C-VRP_Cold-chainVehicleRoutingProblem/`；扩展内不使用 `__init__.py`（靠 `sys.path.insert`）；冻结数据不得修改。
- 为什么这些是硬约束：任何违反都会让结论失去可比性，属于比"效果好坏"更优先的底线。

## 3. 证据架构与研究方法论（评审时的核心尺子）
- **三层证据**：A1（胜过信息匹配的强动态对照）→ A2（条件信息跨多开发种子的稳健净增益）→ A3（胜过最强条件非学习基线 + 等预算迭代的独立贡献）；**三层全部锁定后**才允许对预留最终测试种子各跑一次。
- **统计单元 = 天**：逐日按 `day_id` 配对 + 日聚类 bootstrap；报告均值与 CI；**CI 下界 > 0 且均值 ≥ 预声明阈值**才算过门。
- **每个杠杆必须走完整链**：七要素预声明（假设 / 唯一主对照 / 判据 / 参数与次数 / 预期方向 / 失败条件 / 资源门 / 代码身份）→ 实现 → 回归测试（T 系列续号）→ 冻结源码树（逐文件 sha256 + 只读 + import 证据）→ 2 天烟测 → 至多 1 次 40 天三档 → 独立裁决并留档。
- **预声明先于运行**：不得事后改判据、筛天、换种子、增加次数；每个杠杆次数上限用尽即收束。
- **身份纪律**：跨运行复用基线时做 hash 机械对照；`source_stable`、`data_sha256`、`contract_sha256` 不匹配必须标注，不得静默接受。
- **敏感性档 vs 主档**：主档与 `p_c=0`、高罚档等敏感性档必须分开陈述；敏感性档过门不等于主档过门。
- 判据的具体数值（阈值、种子集合、层次结构）以仓库预声明文件为准；本指令只固定"模式"，不固定数值。

## 8. 术语与缩写（帮助你正确解读我粘贴的结果）
- 三臂采样器：`uncond_hist`（无条件历史重采样）、`cond_hist`（条件历史 k-NN 采样，通常是最强非学习基线）、`explicit_feat`（显式特征预测器）。
- `SAA`：场景平均近似——每事件采 K 个未来场景，在场景内评估「接该单」与「拒该单」的影子和效用后投票；K 与决策时限通常固定（如 K=10、10s），所有臂同预算。
- `shadow_mode`：影子未来插入强度（`greedy` 廉价 / `ls` 局部搜索较贵）。
- `p_c`：拒绝惩罚档（主档与 `p_c=0`、高罚档等敏感性档分开报告）。
- `certify_plan`：C0 硬预算认证；越限不提交。
- `timeout`：决策超时后的降级语义（保计划 + 拒单 + 计次）；超时数必须随结果报告。
- `冻结树`/`frozen tree`：隔离源码副本 + 逐文件 sha256 清单 + 只读；正式批次只从冻结树启动。
- `source_stable`：启动与结束双读源码 hash 一致；`data_sha256`/`contract_sha256`：数据与合同身份。
- `T 系列`：回归测试编号（纯 NumPy 或轻量 JAX）；`D 系列`：无训练诊断脚本编号。
- `烟测`：2 天小规模批次，只验证"0 崩溃 / 硬约束 / 量级合理"，不作证据。
- `主档 / 敏感性档`：判据只对主档生效，敏感性档仅用于稳健性讨论。
- `方向 A`：本项目的总方向（条件信息 → 场景生成 → 在线决策增益）；A1/A2/A3 是其三层证据，不是三个独立项目。
- `杠杆 / 优化战役`：按预声明顺序逐个尝试的机制改进（每个有次数上限与失败分叉）。
