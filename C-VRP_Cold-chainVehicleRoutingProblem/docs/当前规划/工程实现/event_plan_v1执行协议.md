## 1. 当前决策与证据边界

进入一个预算有限的事件级完整计划原型。冻结旧 feature-local checkpoint 及其结果作为参照，不再以重复迁移诊断或旧阈值搜索作为默认下一任务。

已有记录见[实验结果总表 §1.5e–f](../结果与进度/实验结果总表.md)：

- 旧 FULL 策略未建立正效用。F_R_s42 的 FULL−EVENT-ONE 为 +0.0675，95% CI [+0.012,+0.124]；F_H 同方向但区间跨零。这是策略限制的整体效果，不能分解成每次修改的独立损失。
- EVENT-ONE 相对 baseline 的区间均跨零，尚未建立正效用，也未确认其剩余退化显著。
- 执行人报告部分后段修改在执行前被 reveal 清尾，解释了已检查案例的零收益；不推广为全部零收益点的机制。
- “只有改变首段 dispatch 才影响终局”不是已证实规律。后段可能在下次 reveal 前执行，也可能影响后续决策；首段相同不等于两个计划执行等价。
- 已接受样本的预测增益为正受到接受规则筛选，不能据此估计全部候选的预测偏差。
- oracle 提供使用真实未来辅助选择时的改善参照，不能证明可见信息足以辨认这些机会。

本轮研究假设：**从同一事件状态产生完整候选计划，评价候选最终计划相对 KEEP 的效用并选择一个方案，有可能减轻局部判断连续应用产生的退化，并获得在线正收益。** 此假设尚未验证。

## 3. 事件状态、完整计划和候选生成

### 3.1 决策起点

记事件状态为 z_e，JF1-H-F 本次规划产生的完整 incumbent 为 P_0。所有候选从同一个 P_0 的独立副本生成，真实环境在候选比较期间保持不变。

保留已验证的时点语义：复用旧 context 字段时仍由 pre-prepare collector 提供；候选状态来自 prepare 后及 baseline 规划后的 incumbent。新特征逐字段标明采集时点，不把 pre/post 字段静默混成同一语义。每个样本绑定 instance、event、clock、snapshot 和 P_0 身份。

完整计划包含所有相关车辆的有序 suffix、anchor 及执行控制语义，并明确 deferred 集合。KEEP 必须保持原有 WAIT/RETURN、非 mutable 车和 committed leg，不能用“只保留客户列表”悄悄改变执行指令。

### 3.2 生成规则

1. 只掩码已揭示、未执行且允许修改的客户/变量；unmasked 客户的归属及相对顺序保持，允许因插入而产生位置偏移。所有方案保持 full-partition 和 frozen/committed 不变量。
2. 每个候选在副本内完成掩码、重构和认证；内部可顺序应用多个合法动作，但不逐个向真实环境接受。
3. 不以旧 70 维评分器判正作为候选准入条件，也不以真实未来终局收益筛选、排序或补齐候选。
4. KEEP 固定保留；用完整计划及 deferred/控制指令身份去重，不能只按下一段 dispatch 去重。相同首段的不同后段计划不是已证明的等价类。
5. 候选不足 8 个时记录实际数量，不复制候选充数。首轮最多尝试 32 次非 KEEP 重构；失败/重复也计入尝试及耗时。内部枚举、模型调用和认证开销另记，不能把 8 个输出误当相同计算量。
6. 生成前固定 mask 选择、采样 seed、重构顺序、tie-break 和尝试上限。例行实现细节由执行人落实并登记，不需要再次请求方法审批；改变研究变量或预算须标版本。

### 3.3 两个生成器的角色

- G_simple：复用现有合法插入/重排原语，用可见信息与固定 seed 产生小型候选集。首轮拟定 7 个非 KEEP 生成请求，mask 大小依次为 1、1、1、2、2、4、4（可变客户不足时取可用数量）；保持单客户和组合修改覆盖。具体 mask 采样及重构规则必须在首批标签前固定。
- G_mask：适配现有 M1/MaskCO 的事件掩码和重构接口。掩码必须实际作用于候选生成，不能只作为日志字段。首轮可冻结已有生成器权重，记录精确 checkpoint；没有完成适配时明确标“未运行”，不能用启发式输出冒充 MaskCO 输出。

最小闭环可先用 G_simple，G_mask 的适配并行开展。G_simple 的结果不构成 MaskCO 的效果证明。更换生成器后记录新的候选分布；是否重训评价器和相应标签预算须明示，不能无记录地混用。

## 4. 计划评价器与在线接受

### 4.1 输入约束

新评价器必须表示完整候选 P 与 P_0 的关系，至少能区分：

- 受影响车辆的下一段行动，以及 WAIT、RETURN、启用车辆的变化；
- 客户归属、后段有序结构和路线余量；
- 当前可见的车辆时间/容量、温区及 cargo 状态，且保留与对应路线的关联；
- 计划相对 KEEP 的变化、缺失数值及其有效位。

可以复用现有节点、路线和车队表示，首轮不规定必须扩大网络。不能只输入最后一个插入动作，不能把路线无序均值当作完整的顺序表示，也不能简单求和旧动作评分来代替完整计划评价。

输入维度、字段顺序、归一化、采集时点、车辆置换处理和网络配置在训练前写入 feature/model schema。物理车辆 ID 不作为学习特征。时间尺度使用公开 depot horizon 等已验证信息；不能因访问完整 NPZ 统计量引入未来信息。

### 4.2 首轮训练目标

完整计划的 baseline-continuation 收益为：

\[
g_B(z_e,P)=J(P_0\to B\mid z_e)-J(P\to B\mid z_e).
\]

其中 B 固定为同一版本的 JF1-H-F continuation。正值为有益；闭环主指标仍是 ΔJ=J_method−J_B，负值为有益，两种符号不能混用。

首轮固定一套归一化收益 Huber 回归：令 y=g_B/s_train，预测为 f_theta(z_e,P)−f_theta(z_e,P_0)。s_train 仅从有效 TRAIN 标签按固定规则取得并检查 finite、正值；全零或近零标签尺度不得静默强行训练。按实例、事件平衡抽样，避免候选多的事件支配训练。

这是监督对象和部署选择单位的版本变更，**不是把已有即时奖励改成终局奖励**：旧 teacher 原本就执行到终局。本轮不同时搜索 Huber、pairwise、KL、soft-label 等多套损失。

### 4.3 部署选择

在线计算 g_hat(P)=s_train·[f_theta(z_e,P)−f_theta(z_e,P_0)]。在当前信息下通过认证的候选中选最高分 P*，仅当 g_hat(P*)>tau_J 时接受；否则 KEEP。KEEP 增益固定为 0，平分优先 KEEP，其余按固定 stable key。

所有分数和尺度必须有限；异常不能变成零分或获胜候选。选择后核对最终 full-partition，并将 P* 与 deferred/控制指令作为整体安装；失败不得留下部分修改。

首轮 CAL 阈值网格固定为 `{0, 0.005, 0.02, ∞}`，单位为当前 J。每个 seed 在 CAL 上进行各阈值的完整闭环，按服务/硬约束通过后实例等权平均 J 最小选择；数值平局取较大阈值，比较容差在 runner 配置中固定。该平局规则只适用于 EP-v1，不追溯修改旧批次。

不能把一个阈值产生的轨迹日志离线过滤后冒充另一阈值的闭环结果。∞ 表示 baseline fallback，不算 learned 正收益。每个 checkpoint 的阈值在进入本轮 DEV 比较前锁定，不从 DEV 阈值扫描挑主结果。

该接受规则依赖估计，不提供终局单调改进或安全收益保证。当前动作认证也不保证未知未来下的完整服务，仍需 episode 检查。

## 5. 反事实标签与信息隔离

对每个候选，从同一恢复状态安装对应完整计划，再接共同 B 到终局。保留实际发生的 reveal 清尾和后续 baseline 行为，不能为让后段修改有效而延长锁定。

- KEEP 分支对应 P_0，一次计算后只在相同状态/合同/continuation 身份内复用。候选分支隔离 env、replanner、deferred、随机状态及冷链轨迹。
- 候选只由可见信息生成；真实未来仅用于离线 rollout 标签。模型输入与恢复用完整 snapshot 分开存取。
- 区分 `causal_candidate_mask` 与 `label_mask`。后者额外要求终局服务/硬约束及标签有效，不得拿它在部署时过滤候选。
- 合法但终局失败的分支保留失败字段，不填造成本标签；当 KEEP 无有效终局参照时，该事件不形成成本回归样本，仍计入 coverage 和失败报告。
- 记录全部尝试、认证拒绝、终局失败、数值/协议错误、有效标签比例；不能只导出获胜计划。
- g_B 是 baseline continuation 下的代理目标。反复部署 learned 策略可能改变后续状态，不能以标签对齐替代完整闭环验证。

关于 `has_future_reveal`：旧 baseline/写回路径的未来订单存在性信号应在运行身份中披露；各策略使用同一信息规则，learned 输入和生成器不得扩用真实未来。共享旧规则下的相对比较不能自动升级为更强的 strict-online 证明。若要移除此信号或改变信息合同，另立版本并重跑受影响对照，本轮不静默改环境。

## 6. 数据、计时和分阶段预算

### E0：版本与接口

登记 contract/profile、候选生成器、表示和训练配置；先完成 KEEP parity、副本隔离、拒绝无残留、真实安装及有限值检查。未来扰动检查保持当前可见状态及声明的信息权限不变，比较输入、候选、评分和当前选择，而不只比较 context。

仅对新接口和实际修改运行针对性回归，不重复开展全项目审计。现有 trace 脚本按事件序号比较哈希不能自动证明物理状态汇合；如本轮保存分支机制证据，要记录 clock、事件类型、实际 dispatch 和必要状态，不把不同时间的“第 n 个事件”当同状态。

### E1：20 个 TRAIN 决策点

原 20 点先导已完成，保留为固定回归和覆盖参照，不按收益替换。EP-v1.1 修正生成/采样后，原 20 点不保证全部属于新的 eligible 训练样本；只能在状态、候选、schema 与合同身份一致时复用产物，不额外冒充独立数据。原 pilot.json 缺完整训练输入，不能直接拼入 E2 数据集。

### E2：有限标签与训练

首轮复用已确认身份的 TRAIN-64，每实例最多 6 个不同 eligible baseline 决策点；eligible 和分层规则以 §0.2 为准，先按可见状态判定，再按公开 clock/horizon 固定抽样。不按候选成功或收益选择；不足时记录实际数量，不复制同一事件。全部派生事件/候选/场景增强与基础实例同 split。

每生成器上限为 64×6×8=3,072 条计划分支（含 KEEP）；这是上限，不含 baseline 轨迹采集、额外核查以及 CAL/DEV 的完整在线策略运行。20 点先导结果用于填写实测 CPU/GPU/墙钟预算，不能把分支数当作训练和评估的总成本。

先完成一个 seed 的运行检查，再固定报告 42/43/44。训练步数、优化器、模型容量和 checkpoint 选择规则在训练前登记；可复用现有稳定设置，例行参数落实不需要再次请求许可。CAL 专用于接受阈值；若要验证集早停，应从 TRAIN 按基础实例另划内部子集并记录实际训练规模，不能挪用 DEV-CHECK 挑 checkpoint 后称其独立验证。

首次以一个生成器的数据完成闭环；增加第二生成器须单列最多 3,072 条标签及训练预算，或明确做冻结评价器的跨生成器迁移。不能把两份预算都算进“总计 3,072”。

### E3：CAL 与 DEV 闭环

沿用本批 CAL-16 选阈值，DEV-CHECK-16 做开发诊断。三个 seed、阈值、简单选择器及生成器组合的 episode 数在启动前列入 run manifest；baseline 和 ∞ 结果仅在身份完全一致时复用。

DEV-CHECK 已多次查看，不是未见确认集。出现值得继续的结果后，再预声明独立确认集的样本量、最小实际改善、预算和分析方法；不在样本量未规划时声称当前 16 个实例“足够发表”。

### E4：MaskCO 机制与论文实验

G_mask 适配可与 E1–E3 并行。正式扩大场景、网络或 refinement 预算前，先评估该版本的候选与 learned 选择是否有实际信号。M0/小评价器不显著不等于 MaskCO 不可学，也不作为结构接线的行政阻断。

## 7. 对照与公平比较

首轮最小在线对照为：

| 方法 | 用途 |
|---|---|
| B：JF1-H-F | 完整轨迹的主参照 |
| G_simple + S_distance | 同候选、按当前完整计划距离选最小者（含 KEEP）；该规则仅使用可见信息，不声称优化完整冷链目标 |
| G_simple + S_learned | 检验完整计划评价器的学习增量 |

S_distance 平分优先 KEEP；任何额外温度/能耗预测启发式若加入，应独立命名并说明其可见预测口径，不能把真实终局 J 当可部署启发式。

G_mask 就绪后，用同样的两个选择器形成“生成器 × 选择器”对照。区分两种估计对象：

1. **固定状态对照**：保存同一状态、同一候选池，比较 S_distance 与 S_learned 的选择与标签收益，用于隔离选择能力。后验最佳候选只作离线参照。
2. **完整策略对照**：从同实例起点跑 episode，比较终局 J。策略分叉后不强求后续候选相同；这时测量的是整策略效果。

比较生成器时记录是同一冻结评价器还是各自训练的评价器。后者包含训练分布改变，不能解释成纯生成器因果效应。方法整体比较报告总在线时间，组件比较控制候选数、生成尝试和模型/认证预算；只相同最终候选数不等于预算匹配。

旧 FULL / EVENT-ONE 留作历史参照，无环境或身份变化时不为每个新批次重跑全部旧配置。

## 8. 主结果、统计与停止条件

主指标：逐实例配对 ΔJ=J_method−J_B，负值为改善。服务/硬约束、协议和 finite 检查优先；不删掉失败实例后宣称成本获胜。

同时报告：D/Q/E 原始差及按 profile 加权的 J 贡献、胜/平/负实例数、接受次数、发生接受的事件数、候选 coverage、推理总时间和分项时间、全部 seed。

实例是主要独立单位，事件/动作是重复观测。对固定三个 seed 的均值，可先按实例求 seed 平均差再做实例配对 bootstrap，同时分别报告每个 seed；该区间是对这组固定 seed 的实例不确定性，不代表已充分估计训练随机性。最终多 seed/多场景实验另行预声明分析，共享基础实例的场景成组处理，不能把 3×16 行当作 48 个独立实例。

开发轮次预设为“一个原型 + 最多一次有明确依据的修改”。这是工程投入边界，不是一次小样本检验就判定方向不可行：

| 观察 | 行动 |
|---|---|
| 正确性或信息边界失败 | 修复受影响部分，再解释结果；不扩展无关审计 |
| 候选改善机会很少 | 查候选覆盖与样本不确定性，优先改生成器，不盲目加大评价器 |
| 有机会但 learned 不如简单选择 | 检查计划表示/监督，第二轮只改变一个明确变量 |
| 固定状态选择有信号，闭环退化 | 检查 continuation/部署分布错位，再决定是否另立有限聚合协议 |
| 只降低接受量、恢复到 baseline | 记录控制退化，未建立 learned 正收益 |
| 多 seed 有实际改善且优于简单选择 | 锁定版本，规划独立确认及 MaskCO 机制实验 |
| 两轮仍无可复现收益趋势 | 收束本配方，保留结果，重新选择方法假设；不循环换阈值/测试集直到显著 |

不要求开发集每个 seed 都显著，也不只看 p 值。扩大投入时综合效应大小、区间、seed 稳定性、实例集中程度及计算代价。正式确认的样本量、最小实际收益、比较和停止规则应在查看确认结果前固定；如追加样本或修改方法，应改变研究身份，不把反复查看后的普通 95% CI 包装成一次性确认。

## 9. 论文贡献与后续扩展

可争取的贡献是：**在动态冷链取货的执行约束下，将事件掩码重构、完整车队认证和终局效用学习结合，并证明该结合带来可部署收益。** 当前不能写“首次”“稳定优于”“保证改进”或“已经可发表”。

| 拟提出的主张 | 必须补齐的证据 |
|---|---|
| 完整计划评价有价值 | 同候选选择对照 + 完整闭环，而不只是离线误差下降 |
| MaskCO 有方法增量 | learned/simple reconstruction、event/random mask、预算匹配的 refinement 对照 |
| 冷链效用对齐有价值 | distance-only 与冷链目标对照、D/Q/E 分解、权重/参数敏感性 |
| 动态机制有效 | 多 EDoD、执行边界与信息规则一致、防泄漏检查 |
| 方法具有适用范围 | R1/C1/RC1、规模变化、多 seed、公平强基线与质量—时间权衡 |

公开相关工作已包含学习式修复和邻域选择，因此“增加评分器/生成多个计划”本身不足以证明创新：

- [MaskCO 原论文](https://openreview.net/pdf?id=psUjNnLhl9)：掩码表示学习及迭代再生成是上游方法来源。
- [Neural Large Neighborhood Search](https://arxiv.org/abs/1911.09539)：学习式修复与路线搜索的已有方法。
- [Learning-Enhanced Neighborhood Selection](https://arxiv.org/abs/2403.08839)：学习选择邻域的已有方法。

这些仅是已查阅的相关工作起点，不构成完整新颖性检索，也不支持本方法已有优势。论文的问题定义、算法、协议及局限可以先写；摘要中的增益和贡献强度随证据更新。

初步收益后再扩场景、强传统/learned 基线和核心消融。最终参数表、信息合同、objective profile、模型和预算锁定后开展 FINAL-TEST。历史纯距离/配送结果不能填入当前冷链取货主表；合同变化后重做受影响的标签与对照。强基线对比仍待当前共同协议下重跑，不能保证全面获胜或录用。
