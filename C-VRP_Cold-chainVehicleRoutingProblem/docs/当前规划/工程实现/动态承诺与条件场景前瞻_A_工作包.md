## 1. 论文主张（一句话）

> 掩码生成作为**随机组合优化的条件场景生成器**：在动态冷链物流里，用掩码生成模型条件于「已揭示订单 + 冻结前缀」生成未来订单场景并做随机前瞻，据此做 accept/reject 承诺决策；在**可预测需求**下以**决策质量**击败历史 bootstrap SAA / ADP。

## 2. 为什么这样能成立（三条，文献锚定）

1. **因果判据**：前瞻有因果价值 iff (i) 未来可从可见状态预测 + (ii) 当前动作不可逆且有机会成本（Bent & Van Hentenryck 2004；Ulmer et al. 2019）。accept/reject 正是不可逆承诺；可预测需求给因果头腔来源。
2. **方法空白**：掩码生成 NCO（MaskCO/DIFUSCO/MDLM）只被用作静态求解器，**无人用作条件场景生成器**——这是新颖性落点。
3. **战场选择**：经典求解器在动态因果决策下最弱；**MaskCO 不赢路由、赢决策**（绕开"学习输 HGS"的死结，路由交 OR-Tools/HGS 滚动重优化）。

## 3. 需求过程（DGP，合成但结构真实）

- **连续潜在日因子** `z ~ N(0,1)` 决定：空间热点权重、峰值小时、总需求。
- **3 个空间热点**（高斯团），权重 `softmax(log(base)+β·z)`，β 使 z 高→热点 0 主导。
- **时间单峰剖面**，峰在 `peak_hour(z)=clip(11+4z, 9, 19)`。
- **订单** = 非齐次泊松（thinning）；每单带 `temp_class`（与热点相关）+ 交付窗 `tw_end = t + lead + width`。
- 历史 H 天训练 + M 天测试。热点/时间峰/提前期都是真实生鲜配送现象；可预测性由构造保证，用于**验证协议机制**，不是真实数据声明（真实数据可预测性需实车数据，超出本工作区）。

## 4. 决策结构

- **事件**：订单揭示（带提前期）→ 决策 **accept/reject（承诺）** + 派车时机。
- **已接订单** → OR-Tools/HGS 滚动重优化路由（MaskCO 不负责路由构造）。
- **目标（绿色低碳作约束，2026-09-23 用户裁定）**：`最大化 服务收益 − Arrhenius 品质衰减 − 距离`，**约束 = 制冷能耗 ≤ 绿色预算 E_budget**（绿色低碳作绑定硬约束，非软目标项 λ_e）。这使 accept/reject = 在不确定需求下**分配能耗预算**——accept 高收益高能耗远单会挤掉未来好单；条件前瞻正是为此，能耗约束成为决策里 load-bearing 的资源。

## 5. 方法：掩码条件场景生成

- **输入**：可见状态（已揭示订单 + 冻结前缀 + 时钟 + 车队）。
- **mask = 未来订单**；采样 K 个未来场景 + 补全计划；在场景上做 SAA；accept 若共识收益 > 拒绝代价。
- **训练**：在历史日上训练掩码生成模型，条件于当天早期模式（REINFORCE 或最大似然），复用 MaskCO encoder/decoder。

## 6. 基线阶梯（弱→强）

1. myopic（来就收）+ 滚动重优化；
2. 点预测 + 滚动重优化；
3. **历史 bootstrap SAA**（从历史重采样未来场景 + 滚动重优化）——主对手；
4. offline ADP / 价值函数近似；
5. 完美信息 oracle（上界，隔离未来信息份额）。

## 7.1 前两步结果（2026-09-23，无训练）

**① 可预测性**：未来总数 out-of-sample R² = **0.69**（CI [0.55, 0.80]）、每热点池化 R²=0.92、L1 误差比边际下降 71%、预测 spread 0.22 → 承重假设成立。

**② 头腔门**（容量 C=100，价值 ambient/chilled/frozen=10/20/30，K=10 场景）：
- 总价值：myopic 1970 / uncond 2370 / cond 2417 / oracle 2662。
- 头腔分解：future_info（oracle−myopic）= 692 [357,990]；causal_cond = **448 [159,665]**（捕获未来信息 64.7%）；causal_uncond = 401 [−103,691]（57.9%）；residual（oracle−cond）= 245 [29,480]。
- **cond 优于 uncond**（64.7% vs 57.9%，且 cond 的 CI 严格为正、uncond 跨零）→ 条件化有增量、且更可靠。

**诚实 caveat**：cond vs uncond 的差距不大（+47）；且 step2 的"cond"本质是 k-NN 条件 bootstrap（强非参数基线）。步骤 3 的掩码生成模型必须以 **k-NN 条件 bootstrap 为下限**，靠「参数化密度估计 + 全历史利用 + 高维状态」取胜——这是步骤 3 的真实风险点。
