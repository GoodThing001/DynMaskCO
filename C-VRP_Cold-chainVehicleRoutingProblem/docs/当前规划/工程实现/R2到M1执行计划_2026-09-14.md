> **适用范围（2026-09-18）**：本计划的启动批次已被 [event_plan_v1 执行协议](event_plan_v1执行协议.md)及执行进度表 E0–E4 取代。④/⑤已有记录，不再等待其许可；以下“立即开始”“拟新增”等是当时计划表述，不代表当前任务或当前文件是否存在。复用现有实现，勿重跑旧批次。

## 5. 任务 4：M0 utility 短闭环

**Files:** 新增 scripts/models/coldchain_utility_head.py、scripts/models/coldchain_maskco_encoder.py、scripts/training/train_coldchain_utility_probe.py、scripts/evaluation/run_coldchain_utility_probe.py、scripts/tests/test_coldchain_utility_probe.py。

**Interfaces:**

```python
score_actions(model, inputs: dict, mode: str) -> object  # 浮点 [batch, candidates]，越大越好
compute_probe_loss(scores, targets: dict) -> object     # 标量，仅同 context 比较
evaluate_probe(model, contexts: list) -> dict           # 离线分组指标
```

- [ ] 先用同一 head 的 feature-only 模式完成一小批可区分合成标签过拟合，测试 loss 有限、目标参数梯度非零、预测有变化、checkpoint 往返相同。

> **验收三查（2026-09-17 强化，三者不可互相替代）**：接线检查=梯度可达、参数实际更新、checkpoint 往返一致；拟合检查=固定小训练集上的损失、候选选择 regret 和相对 KEEP 的行为随训练改善；泛化检查=独立开发实例上的收益与失败率。**「loss 有限、梯度非零」只是接线检查，不构成训练成功。** padding 验收须比较不同 padding 长度与批次组成下的有效候选分数、赢家和接受决策，容差提前声明；**「误差小于阈值网格间距」不构成 τ=0 下的验收依据**（τ=0 无网格间距可依）。
- [ ] 首版 head 建议两层 MLP（128/64，GELU）；这是开发起点而非声称最优配置。沿用现有 JAX/NNX 训练代码风格。
- [ ] 主监督保留连续效用：y_a = -(J_a-J_keep)/s，s 为 TRAIN 有效 |delta| 的 90% 分位数与 1e-6 的较大值；固定后用于 DEV。对 label_mask 内候选使用 Huber loss，delta=1（缩放后单位）。baseline 非有效 service 时不使用该 context 的相对成本监督，保留失败统计。
- [ ] 先按基础实例均衡抽样，再抽 context；候选损失先在 context 内平均，避免候选很多的事件主导训练。不要跨 context 比成本名次。
- [ ] AdamW 初始 lr=1e-3、weight_decay=1e-4、batch=8 context、gradient clip=1；先 200 步合成冒烟，再最多 2000 步开发诊断，每 200 步评估 DEV。记录最优 DEV checkpoint，不能看 TEST 选模型。这些是建议默认预算，可因内存/耗时在运行前统一调整并记入配置。

> **已运行批次的实际配置（2026-09-17 记录，非严格执行旧默认配方）**：
>
> | 项目 | 执行计划 | 当前 compact 实现 |
> |---|---|---|
> | 标签尺度 `s` | TRAIN 有效 `abs(δ)` 的 90% 分位数 | TRAIN 有效 `δ` 的标准差 |
> | 抽样 | 先实例再 context | 直接均匀抽 context |
> | weight decay | `1e-4` | `1e-2` |
> | 梯度裁剪 | norm=1 | 无显式裁剪 |
> | checkpoint | 每 200 步评估并记最优 DEV | 保存最后一步 |
>
> 计划允许提前调整默认配置，以上差异不单独构成违规，但须按实际运行配置登记。服务器运行值以命令、日志与对应源码为准。下一批在运行前固定 scale 定义、抽样单位、优化器、裁剪、checkpoint 选择规则。**训练 context 等权与评价实例等权是不同概念，分别报告。无结构变化但有有效效用标签的 context 仍参加 utility 训练；只有无有效监督的 context 才跳过成本损失。**
- [ ] 接入 frozen pretrained MaskCO，customer/anchor/predecessor/successor embedding 通过可见索引 gather；冻结参数梯度为零。加载现有 checkpoint 时严格核对模型配置、特征维数、edge mode 和归一化。
- [ ] 首轮三组：Feature-only、Real-pretrained、Representation-shuffle。Shuffle 对每个 context 的候选 embedding 分支按固定置换打乱，显式特征/标签/合法性不变；训练和评估都按同一规则生成可复现置换。单候选 context 无法打乱，单列统计。
- [ ] Label-shuffle 另列为可选泄漏 sanity：只在 TRAIN context 内打乱有效连续标签及其派生字段，DEV 保持真实标签；不得将它与 representation-shuffle 混称。
- [ ] Feature-only 是缺少表征的实用对照，不宣称与 Real 参数量相同；Real/Representation-shuffle 的架构与预算完全相同。generic/random encoder 在主链跑通后加入以检验预训练来源贡献。
- [ ] 首轮使用两个预先固定训练 seed（例如 17、29），对所有组一致；它们仅用于研发诊断，不构成最终稳健性论证。
- [ ] 报告：成本回归误差、有效候选上的排序、最优动作集合命中、KEEP 误接受/误拒绝、终局失败候选选中率、近似平局占比。所有指标先 context 汇总，再基础实例汇总。
- [ ] normalized regret 在有效候选集合上用 (J_selected-min J)/(max J-min J)；范围 <= 1e-9+1e-9*max(1,abs(J_keep)) 的 context 单列为平局，不除近零数。预测选择终局 service-fail 候选时记失败，不编造一个有限 regret。

> **离线诊断指标口径（2026-09-17）**：已运行批次的 `regret = g* − 实际选择收益`（未除候选成本范围），与本节 normalized regret 公式不同；当前离线指标的权威定义见《评估口径》§5.1（net/regret/coverage/harmful/Spearman/MAE），其中 `net` 与 `regret` 均实例等权。不要把当前 `regret_instance_mean` 误当作 normalized regret。
- [ ] 诊断报告同时区分“仅有效标签集合内排序”和“部署可见候选全集选取”；前者有离线标签筛选，不能冒充真实在线效果。

**完成条件:** 三组能训练评估，产生可解释的 DEV 表；不要求 Real 显著胜出。M0 最多完成首轮诊断和一次有明确假设的修订，然后进入/继续 M1，不反复停在 probe。

## 6. 任务 5：真正的 M1 最小模型（与 M0 后半程同步）

**Files:** 新增 scripts/models/dynmaskco_cc.py、scripts/training/train_dynmaskco_cc.py、scripts/simulation/dynmaskco_cc_replanner.py、scripts/tests/test_dynmaskco_cc.py。

**Interfaces:**

```python
encode_visible_state(model, inputs: dict) -> dict
build_event_mask(snapshot: dict, visible_inputs: dict) -> dict
score_masked_actions(model, encoded: dict, masked_plan: dict, candidates: list) -> object
reconstruct_plan(current_plan: dict, chosen_action: dict) -> dict
```

- [ ] 首先实现 no-op adapter：返回 incumbent，跑小实例完整 online trajectory，验证与基座一致；此时还不是主模型交付。
- [ ] 加 fleet/thermal adapter 和事件 mask：从新揭示/需要重规划客户及其可变插入范围构造 mask；冻结执行前缀和 committed leg。不以终局风险或未来 reveal 选 mask。
- [ ] mask 必须真的改变 decoder 看到的可变计划边/位置；保留区作为条件，重构区不得含 teacher 目标边。测试“mask 改变 decoder 输入”，不能只检查日志有 mask 字段。
- [ ] 复用 MaskCO decoder 的 masked adjacency 路径，在扩展目录做适配，不把 M0 MLP 简单改名为 DynMaskCO。候选 utility scorer 消费 decoder 在受影响边上的表示/输出及当前资源特征；utility loss 必须能反传到新增 adapter/decoder 参数。
- [ ] teacher action 通过现有 action 原语应用到 incumbent，得到可变区域重构目标；KEEP/DEFER 对应维持计划。输入仍从 incumbent mask 构造，禁止用 teacher 计划未遮蔽边泄漏目标。
- [ ] 首版训练使用 utility Huber + mutable-edge reconstruction loss。重构项只在允许重构边上计算，正/负边各自平均后等权，避免大量零边淹没目标；两个归一化损失初始权重 1:1，记录分项与梯度。目标动作采用已验证 teacher 选择，连续 utility 标签仍保留给效用项。
- [ ] 首版冻结 encoder，训练 adapter/decoder/head；测试 frozen 参数不动、decoder 梯度非零。后续 partial unfreeze 是一次明确 DEV 对照，不作为第一版实现前提。
- [ ] 先 K=1：模型评分→选动作→完整计划 certificate→原子写回；失败保留整个 incumbent。候选全集只按当前 certificate 筛选，不能按 teacher 的 service_ok 筛选。
- [ ] 在线 KEEP 接受规则采用“预测候选分数 > 预测 KEEP 分数 + margin”；首版 margin=0，后续只用 DEV 比较预声明网格。该规则不保证真实终局不变差，必须测量。

> **阈值选择口径（2026-09-17）**：已改用 CAL-16 选阈值、DEV-CHECK-16 评价，不再用 DEV 选 margin。接受规则 `ĝ = s[f(a)−f(KEEP/DEFER)]`，accept iff `ĝ > τ_J`；本批网格 `{0,.002,.005,.01,.02,.05,∞}` 按 CAL 实例等权净收益选择、合格平局取较小阈值，`∞`=保持 baseline 不算收益。
- [ ] 增加 K=2、K=4 refinement：每次从上轮认证后的计划重新编码/构造 mask/评分；保留同一决策时刻和可见集，不执行未来事件。无有效修改、重复 plan hash 或预算耗尽即停止。
- [ ] 测试 frozen/committed/ownership/容量/TW 的写回不变量、失效动作整计划回滚、未来扰动下评分相同、K=2 第二次输入来自更新计划。

## 8. 任务 7：有限迭代，不无期限打补丁

每轮修改前写一条假设、一个主要改动、一组固定 DEV 对照；其他设置不变。先做最多两轮主要方法修订，再总结是否值得扩规模。

| 观察 | 优先检查/实验 | 不做什么 |
|---|---|---|
| 合成可学、DEV 无排序信号 | 增加基础实例/事件覆盖；比较 Real 与 feature-only；检查标签噪声 | 不据 4 DEV 断言不可学 |
| 离线好、在线差 | 记录模型访问状态与 teacher 状态差异；TRAIN-only 收集模型轨迹新 teacher，保留原标签共同训练 | 不给 DEV/TEST 重打标签后回流训练 |
| 模型几乎全 KEEP | 看真实 teacher 改善比例、分数尺度、margin 与 class imbalance | 不强制每个事件修改 |
| 改动作多但 J 变差 | 比较 margin、K=1 与 K=2、效用/重构损失权重；查 decoder 是否真正用状态 | 不用未来 oracle guard 掩盖问题 |
| Real 不如 feature-only | 保留强 feature-only 对照；尝试 adapter 或部分解冻一次 | 不压低对照预算制造优势 |
| K 增大不改善或太慢 | 报收益/时间曲线，选择可部署预算 | 不把更多计算伪装成结构优势 |
| 服务率下降 | 检查当前 certificate、writeback/fallback 和训练状态分布 | 不混入惩罚距离遮蔽失败 |

允许调整学习率/损失等方法超参；物理参数不能按“让我们赢”来调。开发修改记录配置即可，不要求每轮新 archive/seal。

## 9. 任务 8：并行的参数依据、公开数据与公平基线

助手负责公开文献/官方数据来源检索与文档，执行人负责适配、下载权限核对与运行；不要求用户提供真实车辆/仪器资料。本计划不声称已经找到或验证某套新的真实冷链数据。

- [ ] 数据首先分清：公开路线基准、论文附带参数、合成动态揭示/温区扩展、真实冷链测量。公开路线基准加仿真温区不等于真实冷链数据。
- [ ] 记录来源、许可、单位、公式、可复现生成规则；不能从论文图片/表格猜未报告字段并标成原始数据。
- [ ] 开发可用 pilot；最终大训练前收敛 literature-supported/transparent-assumption 的模拟设定及敏感性范围。改变任务/目标语义后重生成受影响标签和对照，不混结果。
- [ ] 基线先做 JF1-H-F、当前信息冷链增量启发式、同目标的强传统求解器；若强求解器暂仅优化距离，明确标记 distance-objective baseline，不能当作已适配冷链目标。
- [ ] 然后选一个实际可复现 learned baseline 做同协议适配，再扩更多方法；不让所有外部仓库复现阻断主模型。
- [ ] 对所有方法计入预处理/修复/搜索时间，比较匹配墙钟预算的质量，同时给多预算曲线；相同 K 或相同迭代次数不等于相同计算预算。

## 10. 任务 9：从开发转入论文实验

**最终锁定发生在开发完成后，而非现在。** 锁定任务/数据生成、contract/profile、架构与 checkpoint 选择规则、基线适配、主指标、预算、失败处理、主要比较与统计单位。

- [ ] 主矩阵沿用 R1/C1/RC1 × EDoD 0.2/0.5/0.8、50-node；先单 cell 开发，不一开始铺开 9 cell 大 teacher。
- [ ] 核心对照：强传统基线、可用 learned baseline、feature-only、random/generic encoder；核心消融：无 utility 对齐、event mask 对随机同预算 mask、K=1 对多轮 refinement。最终结果必须包含用于支持主要主张的对照，不能只展示 DEV 上有利的消融。
- [ ] 泛化/敏感性随后加入 100-node、热压力与目标权重变化；先报告训练分布内，再明确哪些是真正未训练场景。
- [ ] 正式训练以 5 seed 为目标；预算调整须在最终评测前记录。所有 seed 使用同组 TEST 实例，报告全部运行；训练 seed 与实例两层不确定性分开，不能把 seed×context 行当独立样本。
- [ ] 测试实例数量在开发获得实例级变异与最小有意义效果后做精度/功效预算，再一次固定；本计划不随意把 8+4 或任意整数写成足够发表的 N。
- [ ] 主要指标为完整服务约束下的实例级冷链 J，D/Q/E 与时间分开。主矩阵按预先固定 cell 权重汇总；同源基础实例跨场景重复时按实例族成组，做配对比较，不把候选当独立重复。
- [ ] FINAL-TEST 不参与架构、物理参数、seed、超参或停止规则选择。看过后若实质改模型，原 TEST 降为开发证据，不能仍称未见测试；完整报告失败，不能反复抽新的测试直到赢。
- [ ] 写作主张与证据对应：部署收益看在线对照；MaskCO 贡献看表征/随机编码器对照；mask/refinement 看组件消融；冷链贡献看 D/Q/E 与敏感性。仿真结论不写成实车节电或食品安全保证。

## 12. 本计划的完成定义

近期不是“多通过几项测试”，而是交付：**可读 teacher → 因果张量 → 可训练效用模型 → 真正 MaskCO 重构主模型 → 第一张在线比较表**。

论文阶段再回答是否可靠超过强基线、核心组件是否有独立贡献、泛化/速度代价是否可接受。研发推进和最终科学结论是两件事。
