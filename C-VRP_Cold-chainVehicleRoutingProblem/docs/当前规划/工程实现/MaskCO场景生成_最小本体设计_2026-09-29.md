# MaskCO 场景生成最小本体：架构设计（2026-09-29，与运行批次并行推进）

> 依据 [步骤 3 新协议](A-v1步骤3新协议_MaskCO场景生成_2026-09-29.md) §2 最小实现包。
> 本设计只定义「条件未来场景生成器」本体；正式训练与评估在信息门重立后启动。

## 1. 生成器闭环（与协议一致）

```
可见历史(订单/时钟/资源) → 编码器 → 数量头 n̂ + 联合场景 token 分布
  → 采样数量 n → 部分掩码初始化（未来集合槽，冻结可见前缀）
  → 迭代重构（多轮：生成 → 保留高分槽 → 重掩码低分槽 → 再生成）
  → 合法未来场景集（time/温区/位置/窗口/需求，均服从 token 桶）
  → 共享 SAA 下游消费 → 接/拒决策 → 冻结承诺 + C0 硬认证 → 实际效用
```

关键迁移（论文明示）：MaskCO 的「参考解结构依赖 + 掩码重生成改善」迁移为
「条件未来订单集合的结构依赖 + 掩码重构改善」；仅借用 encoder 不构成贡献。

## 2. Token / 槽设计（PAD 与 MASK 分离）

- **槽（slot）**：未来订单占位。**PAD** = 到固定槽数 S 的填充（注意力隔离，-1e9
  bias + 输出置零）；**MASK** = 「该槽尚未生成」的可学习占位（与 PAD 不同向量）。
- **NULL**：数量 n < S 时，剩余槽生成为 NULL（终止语义），与 PAD 区分——数量信息
  由 n̂ 与 NULL 的**联合分布**共同表达，禁止「采样后靠丢弃过去 token 改变数量」。
- **每订单 token**：离散桶。时间桶（相对 clock 的合法未来时间）、温区（3 类）、
  位置桶（空间分桶，可见坐标归一化）、TW 桶（宽/晚界）、需求桶（**连续需求严格
  服从桶解码**，越桶即非法，回退到桶内再采样）。
- **对称性验证**：任意置换未来槽的生成顺序 → 分布不变（槽对称训练 + 对称损失）；
  单测覆盖。

## 3. 数量与联合建模

- 数量头：条件于可见历史的离散计数分布（n ∈ [0, S]）。
- 联合分布：未来订单特征通过自注意力共享上下文（槽对称），NULL/计数联合通过
  「先 n 后槽」或「槽内 NULL 停格」两方案选一，单测验证两者一致。
- 显式预测器对比（新协议 §2.7）也要强化：读当天可见前缀做条件计数+每单特征回归，
  作为强非学习对比。

## 4. 迭代重构（部署机制，非后处理）

- 推理：T 轮。每轮对**低置信槽**（生成熵高）重掩码，保留高分槽；再生成条件于
  可见历史 + 已保留槽 + 当前轮掩码图。
- 轮数与保留比例是超参（预声明网格），单步（T=1）= 消融下限。
- 训练：部分掩码未来集合（随机掩码比例/随机保留轮次），交叉熵逐槽；
  **决策感知目标（L4）另立**：分布拟合损失与在线效用分别报告，不混合。

## 5. 资源条件输入

- 输入通道：clock（当前时刻）、剩余预算 B−已耗、在途车队摘要（车数/载重/位置分布）、
  已接受未服务集合摘要——全部**公开状态**。
- 纪律：未来需求分布是外生的，不得因本方资源状态改变条件需求分布；资源条件只影响
  「生成→决策」路径。若做决策感知选样，显式区分「分布预测」与「价值导向选样」两目标
  （两个头或两步训练，消融）。
- 资源条件的训练标签来源：训练日**因果策略回放**采集（历史需求切片无车队标签）；
  不引入开发/最终测试状态。

## 6. 同架构公平对照与消融

- 编码器：预训练 CVRP encoder（冻结 hash 记录）vs 同架构随机初始化——其余结构逐层
  相同（非当前 EncoderMLP）。
- 消融：单步/迭代、资源条件开/关、数量头开/关（固定 n=均值）、预训练/随机。
- 主报：同下游、K、时间预算下 `MaskCO − 最佳条件非学习`；再报消融。

## 7. 与共享 SAA 的接口

- 生成器输出 = `ScenarioOrder` 列表（现有 `_build_space` 消费格式，含合法 reveal 时间）；
- 每决策时限内完成全部 T 轮；超时降级与 A-02 同语义（保旧计划+拒单+计次）；
- 生成器状态随实例重置，严格因果可见边界（`VisibleSnapshot` 复用，无未来泄露）。

## 8. 交付顺序（与协议一致）

设计（本文档）→ 信息门重立 → 实现 + 不变式单测（槽对称 / NULL-计数联合 / PAD-MASK
隔离 / 需求桶解码 / 因果边界）→ 开发评估（主比较+消融）→ 稳健性 → 锁定+唯一终测。
