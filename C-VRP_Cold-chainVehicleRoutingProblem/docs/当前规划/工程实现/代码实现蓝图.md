## 2. 第一工作包：可训练的 teacher 导出

已新增（进入实际 TRAIN/DEV 试运行）：

- scripts/expert/export_coldchain_teacher.py
- scripts/tests/test_coldchain_teacher_dataset.py

复用现有 snapshot/action/continuation 语义，不直接把最佳动作 oracle_log 转成训练集。
导出 context 与全候选表：基础实例、event/customer、snapshot/state、可见特征、mutable scope、候选 stable ID、KEEP/DEFER、certificate、终局 hard vector/D/Q/E/J、raw/effective contract、profile、预算/seed。

数据合同见[表征探针接口与数据规范](表征探针接口与数据规范.md)。完整恢复快照可含隐藏环境状态，模型特征必须单独白名单提取。
每条 rollout 使用隔离 continuation，不能串候选污染 deferred/repair state。
成本 loss 只读 service_ok 候选；协议错误 fail，不以缺失填零。记录无候选/失败 context，不能默默删掉难样本。
试运行限制基础实例/决策上下文数，保存全部候选；如果截断候选，显式记录覆盖与选择规则。

最小检查：KEEP parity、A→B→A 分支隔离、相同 context 候选排序不敏感、同源 split 不重叠、未来特征扰动不影响输入/当前评分、contract/evaluator 一致。
通过后再扩数据，暂不生成正式 VAL archive。

## 3. 第二工作包：M0 短诊断

已实现（2026-09-17）：

- scripts/models/coldchain_utility_head.py
- scripts/training/train_coldchain_utility_probe.py
- scripts/evaluation/run_coldchain_utility_probe.py
- scripts/training/train_feature_only_local.py
- scripts/evaluation/run_margin_scan.py、run_threeway_eval.py、run_id_sensitivity.py、run_candidate_gain_space.py

冻结因果 MaskCO encoder，取 customer/slot/predecessor/successor embedding，拼接 clock、anchor、route pooling、slack、thermal/manifest 汇总与当前可见增量特征。

> 注：路线/热/ manifest 信息是原设计要求，但当前 compact 原型尚未完整落实「候选—受影响车辆—在途货物剩余品质」的对应关系（全车队平均不能替代目标车辆状态）；标为待补，不写「完整 thermal adapter 已验证」。
先试单小 batch 过拟合，后按基础实例/context 平衡训练。temperature/tie margin 来自 DEV，不从 TEST 估计。
首轮比较 Real、context 内 Shuffle、feature-only；跑通后加入容量匹配的 generic/random encoder。
输出 regret、KEEP 错误、high-advantage recall、逐实例在线 D/Q/E/J、服务率、动作分叉和耗时。
M0 是短诊断，可纳入 M1 开发，不要求独立显著性审批。

## 4. 第三工作包：M1 主模型

已实现（2026-09-17）：

- scripts/models/dynmaskco_cc.py
- scripts/training/train_dynmaskco_cc.py
- scripts/simulation/dynmaskco_cc_replanner.py
- scripts/evaluation/run_dynmaskco_cc_gate.py
- scripts/models/dynmaskco_cc_compact.py
- scripts/training/train_m1_compact.py

最小接口（设计，不是当前可调用 API）：

~~~text
encode_visible_state(visible_nodes, fleet_tokens, thermal_tokens)
build_event_mask(snapshot, current_risk)
score_masked_actions(encoded_state, mask, certified_candidates)
reconstruct_plan(current_plan, chosen_action)
~~~

复用上游权重但不改 MASKCO_code。route slot 使用语义签名，不用 physical vehicle ID 作监督目标；不同 thermal/anchor state 不能随意合并。
mask 同时作用于 decoder 输入/可变计划，不能只记日志。K=1 后比较 K=2/4；每轮新计划完整认证再写回，失败恢复整个 incumbent。
模型的改善判断来自可见估计/网络分数，不能拿 teacher 的真实未来 rollout 在线作 guard。
先 head/adapter/decoder，再用 DEV 决定部分解冻；不要求先击败基线才允许试微调。
no-op/frozen/committed/ownership/causal invariance 是正确性检查，终局收益是实验问题。

## 5. 数据生成和现有 CLI 边界

run_action_oracle.py 现有参数为：

~~~text
--data
--capacity
--num_vehicles
--objective distance|coldchain
--objective-profile
--coldchain-contract
--max_instances
--instance-ids
--role regression|dev_proto|dev_gate|val
--workers
--local
--out
~~~

旧蓝图的 --contract、--trajectory、--split val、--output_dir 不是这个入口的真实参数，不要照旧命令运行。
该脚本是 oracle 评估器，不输出新训练器所需全部数据合同；正式 VAL 仍走 run_o0cc_val.py 的 archive 入口，不用底层角色参数绕过。
generate_dev_split.py 当前生成固定 50-node 九 cell manifest；不要假设仅改 --split-role 就满足新 TRAIN/TEST 的全部身份/去重要求。生成 adapter 先做隔离与字段核对。
本轮不提供不存在脚本的“可直接复制训练命令”；实践完成后再按 --help 和小样本运行输出更新。

## 6. 路线 B 参数变化与代码范围

开发先用 v1 pilot，不自动实现 v2-light。文献设定就绪后：

## 7. 测试与统计实现边界

按变更风险测试：新导出器测 schema/泄漏/标签；新模型测 shape/loss/梯度/掩码；新 replanner 测 no-op、完整写回、strict-online 与小实例 rollout。
改 event/snapshot/action/evaluator 时跑相关 P0/C0 回归；最终统一版本再跑完整关联测试。
禁止以历史 94/94 自动证明新 M0/M1 正确，也不因改文档就再跑三天 oracle。
最终模型需要支持多 training seed 的实例/场景配对汇总；现有 oracle 单次九 cell 聚合器不是现成模型汇总器。具体统计见评估口径。

## 8. 实践边界

全部新实现位于扩展目录，不改 MASKCO_code，不加子目录 __init__.py，不覆盖 data/baseline 或已封结果。
保留 GPU 选择先于 JAX import、visible-only normalization、loader 五元组/模型 edge mode 一致性。
超过 5 分钟服务器运行使用 tmux，先测 CPU teacher 与 GPU 吞吐后扩量，不沿用旧 oracle 时间估算作为承诺。
开发记录 commit/diff、配置、数据/合同、日志即可；正式论文版本再统一封存。源码提交、上传和服务器运行由执行人完成。
