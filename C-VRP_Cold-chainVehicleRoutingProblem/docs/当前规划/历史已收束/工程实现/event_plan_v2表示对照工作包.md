# event_plan 第二轮：可见执行后果表示对照工作包

> 2026-09-19 · EP-v1.2 / representation-r2 · 已有本地运行结果，按预算收束当前实现；源码仍有偏离原计划的限制。本文件保留原实施计划，不表示全部条目已验收或自动授权继续重跑。当前状态见[两轮收束与后续决策](../决策与审计/event_plan两轮收束与后续决策.md)。用户负责代码、实验及提交，助手负责文档与证据审读。

## 1. 决策和证据边界

第二轮选择改变评价器输入表示，保持 g_B 的 baseline-continuation 定义和 Huber 损失。暂不改 pair/listwise、不扩大生成器、不解冻 encoder、不做 on-policy aggregation。先把明确实现偏差修正在两组共用路径中，再一次完成旧/新表示的训练、CAL 与 DEV 对照；不逐个检查回来讨论。

2026-09-19 读取本地脚本及 event_plan_export/data.json、CAL/DEV summary 后确认：

- TRAIN 为 64 实例、384 个抽样事件、1,875 条候选记录；378 事件非空、6 事件无候选，故数量范围为 0–7。正/负/近零为 559/976/340（1e-9 容差）。238/384 点有正收益候选；含 KEEP 的逐事件最佳收益均值 0.026285。
- all_events=4500 是 collector 实际缓存的重规划上下文数，不一定等于全部仿真事件；eligible=1755 是抽样前分母，non_keep=378 是抽样后分母，不能直接混算覆盖率。
- 三 seed 在 CAL 的三个有限阈值下均值 ΔJ 均为正，但部分区间跨零；最终均选择 ∞。DEV 三组 ΔJ=0、accept=0。原 distance 实现 DEV 为 +0.087429，CI [0.042013,0.134470]、accept=141。
- ∞ 的零差是外部选阈拒绝干预，任意 finite scorer 配 ∞ 都如此，不能解释为网络学会安全拒绝或已有 learned 增益。
- 正收益候选来自 TRAIN baseline 状态，标签使用真实未来；不证明部署状态有相同覆盖，也不证明当前可见信息足以辨认好候选。候选分布、信息不足、训练和后续策略分布仍是可能因素。
- 旧输入为 context25 加每车 anchor/N、next/N、截断长度、changed；不是有序完整路线表示。节点编号不能表达地理/时间关系。现有数据有 89 组事件内输入碰撞，其中 2 组标签不同，1 组符号相反：inst42/event5 为 -0.030202 与 0；inst58/event5 为 +0.002604 与 -0.053202。只证明存在表示损失，不证明其为唯一或主要退化原因。

因此，表示增强是有依据的下一假设。候选数增加、训练跑完和 checkpoint 保存不等于评价器已经学会选择；原表 2 缺同状态选择与泛化指标，下一批补齐。

## 3. 单一研究变量：结构摘要 vs 可见执行后果表示

| 项目 | A：旧表示修正版 | B：执行后果表示 |
|---|---|---|
| context | 原 pre-prepare context25 | 同一 context25 |
| 候选表示 | 旧 100 维结构摘要 | 下列可见状态及顺序敏感的计划后果 |
| 生成/标签/抽样 | 同一修正版数据与实例/事件平衡 | 完全相同 |
| 网络/损失 | MLP hidden=(128,64)、同激活、Huber、同优化器和步数 | 完全相同，输入维度按 schema 变化 |
| seed/阈值 | 42/43/44；CAL 网格 0/.005/.02/∞ | 完全相同 |

不得只把 B 与旧历史 checkpoint 比，因为这会混入共同修正效应。两组各三 seed，共六次训练，是本轮上限；训练步数、batch、checkpoint 选择在 manifest 固定，使用当前单一配方，不开超参搜索。输入层参数差异如存在必须报告；如需容量匹配，在训练前固定零填充到同一维度，两组一致执行，不把它变成第三实验。

B 的表示包含以下字段组，字段顺序、有效位和归一化在训练前一次冻结：

1. **当前车辆与控制**：active/mutable/committed/closed 有效位，WAIT/RETURN/首段启用标记；anchor 的真实可见坐标（相对 depot）、ready-clock、载重/容量、当前已知温区状态。客户/车辆编号只作索引，不能当连续地理特征。
2. **实际货物状态**：各温区温度、zone_load、在舱数量、货物年龄及剩余品质的固定聚合。空舱必须有有效位；不能用 load>0 猜 cargo manifest。保留状态与对应车辆路线关联。
3. **有序路线时间与资源**：按真实 suffix 顺序逐段递推的行驶距离（含实际 RETURN）、行驶/等待/服务时长、最小 TW slack、最大载重、预计返仓时间及首段物理变化。首段相同不能把后段直接丢弃。
4. **可见计划冷链代理**：下节预测的增量 D/Q/E 及其按冻结 profile 合成的代理 J，按车及车队汇总；同时提供相对 KEEP 的差值、有效位。仅换路线顺序时，表示应能在时序/物理后果不同的情况下变化；聚合不声称无损表达任意路线。

实现为同一纯函数，以保存的可见状态、P0 和 P 为输入；训练和在线直接共用。固定车辆槽位是本轮工程约定，不声称置换不变；不同时引入新 Transformer 或 GNN。所有尺度来自公开合同/depot horizon 或 TRAIN，禁止全 NPZ 的含未来统计。f(P0) 与 f(P) 必须使用相同物理起点和字段语义。

## 4. 冷链代理怎样计算，怎样防止变成 oracle

这是“当前已知计划的物理投影”，不是终局 g_B，不是调用含真实未来的 StrictOnlineEnv.run 来造特征。

- 从同一事件的当前可见车队和真实 cargo 状态副本出发，候选只替换 mutable 指令。模型 context25 仍取 pre-prepare；计划投影使用与执行一致的 post-prepare 起点，两个时点明确分字段记录，不做 ready_time 反推。
- 已 committed 的余下服务/行驶是当前已知承诺，按现有时间语义推进一次后接 suffix，不能从未来完成态取当前温度，也不能把整段重复累计。
- 沿当前已知 suffix 及 RETURN 递推 travel/wait/service/pickup/return，复用唯一 C0 transition 和合同换算；pickup 在 service_finish 入舱、return_arrival 卸货。增量扣除共同已发生部分。
- 不插入未揭示客户，不读取下次真实 reveal 时间，不猜哪段会被未来清空，不使用真实反事实终局 D/Q/E。KEEP 和每候选使用同一投影约定。
- 对实际 WAIT 或未闭合路线，记录 open/WAIT 位。固定投影终点为公开 depot horizon H：在合同允许的状态转移下推进已知等待至 H，记录 active quality 和能耗；已经返仓关闭的车辆保持关闭。未来新揭示、重新调度、延期客户不在代理中完成，故代理绝不当完整 episode 服务或成本。跨过 H/不可计算情形给明确有效位与有限占位，不利用最终 rollout 是否成功过滤部署候选。
- has_future_reveal 只保留既有写回信息合同，不新增权限；输入中的控制位可能间接反映这项旧许可，须披露。未来扰动测试固定许可的存在性信息，不能一边改变它一边声称应该完全不变。更强信息合同另立批次。

先用几个已知订单的短路线检查投影与 C0 逐段计算一致，再做双路径张量/分数一致、隐藏未来扰动及互不污染检查。检查只针对新增特征/接口，不重审整个冻结环境。时间余量、距离和冷链预测共同构成一个表示改动；不得看 DEV 再逐字段搜索。

## 5. 数据复用与完整工作包

1. **实现共同修正与 B 表示**，保存真实 snapshot 与 schema。恢复既有 384 事件，候选保持七请求规则；核对 full_plan、控制/延期指令、合同和标签身份。
2. **生成一版共用训练数据**。只在恢复状态、实际计划、continuation 和 objective 完全相同且标签有效时复用旧 g_B；元数据修复不必重跑全部标签。身份变化或证据缺失的分支重新标注。最多仍为 TRAIN64×6×8=3072 分支（含 KEEP），不把 A/B 复制成两份标签预算。
3. **训练 A/B 各三 seed**。固定相同标签尺度 s（由共用有效 TRAIN 数据同一规则计算，不强行保持旧 0.0517）、相同训练设置。先小批过拟合，随后正常完成六次训练。
4. **在 CAL baseline 固定状态上补选择表**。每实例最多六个预定 eligible 点，两组共享候选及反事实标签；最多 16×6×8=768 分支。报告相对 KEEP 选择收益、有害/近零接受、含 KEEP 的候选 regret、输入碰撞及覆盖。只作 CAL 诊断，不选择 checkpoint/损失/字段；仍按真实闭环选阈。TRAIN 表不能冒称未见状态泛化。
5. **完成 CAL→DEV 闭环**。A/B 各三 seed，CAL 原网格，锁阈后 DEV。baseline、修正的 S_distance 和下述 S_proxy 同列。所有普通负结果也完成预定比较，不逐项回报许可。

S_proxy 是新表示自带的无学习对照：按同一可见物理投影的 J(P0)-J(P) 选计划，CAL 使用同一 J 单位阈值网格。不读取 g_B，也不拟合参数。它用于判断收益来自物理计算本身还是 learned 终局校正；若 B 只胜距离而不胜 S_proxy，不能声称学到额外价值。这是必要对照，不是额外损失/生成器搜索。

本批预算登记：训练六次；TRAIN 最多3072、额外 CAL 固定状态最多768 标签分支。方法闭环上限为 A/B 两表示×3 seed×(4×16 CAL +16 DEV)=480 episode，S_proxy 为80，修正 distance DEV 为16，合计576；另有 baseline 32 episode及状态收集/局部验收。已证明身份一致的 baseline/∞ 可复用并报告实际节省。计时后再启动全批；明显超出资源约定时暂停，不能暗中扩预算。

## 6. 报告和判读一次完成

仍回传三张表：

1. **正确性/数据**：源代码与数据身份，KEEP/安装/拒绝/分支隔离，完整服务和分区，表示对账与未来扰动；候选/请求一一对应，全部分母，实际组合修改，D/Q/E 与时间记录是否齐全。
2. **同状态选择**：A/B 全部 seed、S_distance、S_proxy、KEEP 及后验最佳参照；TRAIN 与 CAL 分开，实例/事件平衡后的选择收益、regret、有害/无效接受与碰撞。后验最佳使用真实未来，只作离线参照。
3. **闭环**：所有 CAL 阈值、锁定规则、DEV 配对 ΔJ/CI、D/Q/E 贡献、服务/协议向量、实际接受量、运行时间；B−A、B−S_proxy 均以同实例配对汇总。实例为统计单位；三个 seed 不是三倍独立实例，全部 seed 留表。

判读：

- B 比修正 A 好，且多 seed 有可复现的实际接受和闭环改善，再考虑扩投入；不要求每个小样本 CI 都显著，但不能只挑最好 seed。
- B 与 S_proxy 相当：可见物理表示/代理有用，learned 增量未建立。避免把物理启发式包装成 MaskCO 学习贡献。
- 同状态选择改善、闭环仍退化：记录 continuation/部署分布错位的可能性；本批不自动加 on-policy 训练。
- 两组都选 ∞ 或都无稳定收益：第二轮收束，不默认再换 pairwise 做第三轮。保留新接口/物理特征作为研究资产，重新讨论方法假设或论文范围。
- 出现服务/协议/泄漏错误：修复具体实现并重跑受影响结果，普通修复不算新方法轮次；若需更换环境合同或显著扩大预算则统一讨论。

E4 的 MaskCO 生成器、event/random mask、refinement、公平强基线和独立确认仍未完成。第二轮即使有增益，也只是决定是否进入这些论文证据工作，不能据此承诺发表。当前 CAL/DEV 均为开发数据，最终确认另锁方案与独立数据。
