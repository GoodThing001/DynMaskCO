# 直接目标训练后续决策：状态身份与固定状态诊断

> 2026-09-21 · 用户要求由助手给出后续方向决定。本轮交付研究决策与执行边界；执行端负责代码、实验与提交，助手不代跑。此前 Step 5 数值和负结果归档保持不变。本决定将下一步具体化，不启动无 padding 重跑、seed43/44、网络/奖励搜索。

## 1. 决定

保留完整 CVRP512 预训练骨干 + 冷链适配 + 条件联合重构的学习主线。先用不超过三个工作日完成运行身份及训练状态有效性核查；身份和状态可信后，补原工作包缺失的固定状态质量表。当前不宣称动态优化方法已有效，也不因一个受实现限制的配方负结果认定整个方向不可行。

这是有上限的后续诊断，不是继续原训练预算。它只回答两个问题：训练是否确实使用了对应决策时刻的公开状态；训练后的修复分布是否改善了同一固定状态上的完整冷链目标。

## 2. 已有本地源码证据与运行身份边界

2026-09-21 只读核查发现 `scripts/training/train_mpre_reinforce.py`：

- `CollectProbe.plan` 把 `vehicles`、`served_mask` 原对象存入 `self.states`（当前第 162–166 行），没有冻结副本；随后 `env.run(inst)` 继续执行，模拟器会原地修改车辆与 served_mask。训练是在采集结束后才读取这些对象。当前本地实现存在历史状态被后续执行改变的风险：P0、clock、vis 与网络读到的车辆/cargo/served 状态可能不对应同一时刻。
- 采集器只有 `len(self.states) >= max_states` 的全局限制，复用于所有实例；`max_states=4*n_instances` 不实现“每实例最多4个”。因此 n_states=256 不能证明 TRAIN64 各有4个状态。
- 训练 mask 请求固定为2，而在线请求含2/4/8。这是已可见的训练/部署范围差异，只作解释边界，本轮不借此自动扩大 mask 或重训。

这些是当前本地源码事实；尚未证明服务器运行源码与本地相同，不能直接宣布已运行 checkpoint 一定受污染。损失有限、梯度非零和最终服务通过不能替代此项核查。

## 3. 第一交付：最多三个工作日的身份与状态核查

1. 从已有服务器运行文件/上传记录/日志核对当时训练脚本、checkpoint、数据、合同/profile 的身份。列出可核实与无法追溯项，不把事后本地 SHA 当成当时运行 SHA。
2. 有已保存状态池则先统计每实例事件数；没有则在身份匹配的采集器上做最小不训练诊断，记录 instance_id、event_id、clock、mask、车辆/cargo/served 摘要。不要仅按总状态数反推覆盖。
3. 在同一次最小诊断中，保存事件时刻的独立公开状态快照；推进模拟器后，检查原记录的公开字段、提取张量及评价起点是否改变。不得读真实未来构造网络输入。
4. 记录 `capture_before / after_advance / replay` 三份一致性结果，核实输入与奖励来自同一公开快照。只检查上述有源码依据的问题，不扩成全仓审计。

交付：`state_identity_audit.json`（或同等可机器读取产物）+ 一页结论。若三工作日内仍无法恢复运行身份，记“训练有效性未核实”并停止扩大实验，不以无限排查延续原项目。

## 4. 条件性修正预算

若确认当时运行也存在历史状态别名/实例采样偏差，本次 checkpoint 的闭环负结果仍是实际结果，但不能作为预定训练协议已被有效检验的证据。

对此明确允许一次纠正性版本：冻结决策时刻公开状态、落实每实例最多4个状态、保存状态池清单；保持数据划分、网络、奖励定义、优化器/学习率、训练 seed42、1000更新、8×4采样和32000次候选尝试上限。不同时试新网络、新奖励、新 mask 分布或更大预算。实例抽样规则必须在观察候选效果前固定；修复带来的样本变化和按原定义重算的 TRAIN 奖励尺度单列。

先通过一个真实批次的输入/奖励时间一致性、采样/回放、冻结参数和计划认证检查，才运行这唯一一次修正训练。原有结果保留；新运行另目录、另 manifest，不能写成原数值被替换。修正后仍无信号，不追加第二次调参训练。

若运行身份可信且上述问题不存在，不重训，直接用现有模型补固定状态表。身份无法核实不触发该修正训练许可。

## 5. 第二交付：固定状态质量表，最多1216份修复候选

目的为诊断，不是新的主结果或独立测试。使用训练配置 mask=2，不扩大问题。固定 padding，与已归档配置保持明确对应；不做未 padding 敏感性搜索。

- TRAIN 和 CAL 各取16个固定实例，每实例按预定时间顺序取最多2个 eligible 决策点，共最多64状态。不按模型改善、cargo 是否有利或结果正负筛选；缺额如实记录，不根据效果换实例。
- 所有方法使用同一个冻结公开状态、P0、mask、保护集合、可修改范围和完整评价器；候选不写回动态环境。
- 每状态：R一次完整重构；共同策略M-pre和M-trained各一次argmax重构；M-pre和M-trained各8次固定温度采样。上限64×(1+1+1+8+8)=1216候选尝试，失败计入预算，不无限重试。采样seed在运行前冻结。
- 不复用旧 `run_mpre_fixed_state.py` 的历史 regret式 M-pre 作为正式对照；该入口当前不是新共同策略 M-pre/M-trained/R 三方比较。
- 主报训练前后采样期望目标、argmax目标和相对R差值；best-of-8仅作潜力诊断，不能替代单候选结果或宣称公平速度优势。
- 失败率单列，按已冻结失败规则保留所有采样；有效候选条件均值只作辅助，不能删除失败后宣布策略改善。原始候选质量与经P0接受门控后的质量分开。
- 记录D/Q/E、合法动作数、唯一完整计划数、熵/最高动作概率、有效采样数、耗时。实例内先聚合，再做配对汇总；TRAIN结果只回答训练集是否学到，CAL仍为开发诊断。

已有完全同口径产物可直接复用，不为填表重复计算。至少检查删除单个实例后主要改善方向是否稳定；小样本跨零意味着证据不确定，不能当等价性证明。

## 6. 决策出口

| 固定状态结果 | 决定 |
|---|---|
| 输入/奖励身份仍不可信 | 停止结果归因，保留实现局限；不运行后续训练或闭环 |
| 有效训练后，TRAIN上相对M-pre也没有可用信号 | 停止当前512微调+直接修复奖励配方，不以闭环/更多seed找信号 |
| TRAIN改善，CAL不改善 | 记为未建立泛化，停止自动扩训练 |
| 采样改善但argmax不改善 | 记为分布学习与确定性部署不一致；不自动追加采样预算或重跑闭环 |
| CAL相对M-pre改善，但相对R仍无有用信号 | 承认训练增量有限，尚不足以启动论文主矩阵 |
| 固定状态同时支持相对M-pre/R的增量，且服务与成本可接受 | 仅进入一次预先锁定的闭环确认；现有checkpoint已有同实现闭环则复用，不能为换符号重跑 |

固定状态改善而既有闭环不改善，只支持“收益未转化”的定位，不能单独证明J_vis是唯一根因，更不能直接把reward换成真实未来。若仅静态修复成立，可据此重新定义一个明确缩小的研究问题，但不得把动态失败藏掉或将缩小后结果冒充动态优势。

## 7. 论文边界

MaskCO的掩码重构、迭代改进和预训练迁移已有原始论文；RL神经修复用于VRPTW也已有先例。因此本项目需要证明冷链状态与MaskCO条件重构的独立价值，不能仅以组件组合或代码规模主张创新。

- [MaskCO原论文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/d85816bf41e54d9b0847e02249f4fcc6-Abstract-Conference.html)
- [Large Neighborhood Search based on Neural Construction Heuristics](https://arxiv.org/abs/2205.00772)

本决定不保证正结果或录用；它给当前方向一次有明确因果问题、范围和资源上限的判断机会。确认有效训练仍无增量后，应暂停当前投稿主张，利用已有实现与负结果完成研究报告，再另立新课题假设，不能承诺继续投入必然获胜。
