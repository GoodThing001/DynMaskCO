# N1/N2 收束与增强修复验证决策

> 2026-09-20 · 方向决策 + 诊断口径复核 + 下一工作包规格。本文是 N1/N2 结果的收束归档，也是对 [n1n2_maskco条件联合重构结果](../结果与进度/n1n2_maskco条件联合重构结果.md) 判读的更正来源。

## 1. 决策

- **收束当前 N1→N2 配方**，不立即修 padding 重训。
- **下一步只做一次不训练网络的「增强修复是否值得学习」验证**。
- **暂时保留 MaskCO 论文方向，但不启动下一轮模型训练**。

收束是**投入决策**（当前没有明确的质量或速度信号，继续投入需积极证据），**不是**「已证明修复无用」。不修 padding 重跑不能解释成「修复没用」；将来若复用该学习器，padding 一致性仍必须修正和验收。

## 2. 诊断口径复核（新增诊断的过度外推）

新增诊断（`diag_n1_table{1,2}.py`）**没有**证明「学生只能复制 R、永远无法超过 R」。具体纠正：

| 原表述 | 源码实际支持的结论 |
|---|---|
| 384/384 标签回放一致，所以标签没坏 | 表 1 只比较回放后的**客户集合**（`set`）；尚未证明逐车有序路线完整一致 |
| 100 个固定状态证明质量无增量 | 只测了 **s42、前 100 条 TRAIN 记录**；**未计算 `J_vis`**，不能判定不同方案谁更好 |
| 与 regret-2 客户归属一致 100% | 表 2 的 `_ownership` = `frozenset(customer_id ...)`，**只保留客户集合**，丢掉车辆归属、访问顺序与重复次数；「0 额外改动」也不代表没有改变分车或顺序。同一个 mask 的完整修复本来就应该覆盖相同客户 |
| 完整计划一致 60% | 支持「这 60% 记录的 `plan_hash` 一致」；其余 40 质量未知 |
| 修掉 JIT 后仍数量级慢 | 尚未测得；当前耗时未分离编译与稳态，学习器计时不含 encoder |
| padding 6/20 翻转 | 范围 = **s42、前 20 条训练记录的第一步选择**；补齐长度原设为总节点数，需核对是否等于 checkpoint 实际训练 `Nv_max` |

## 3. 可靠结论

> **闭环未建立学习增量；当前实现存在影响动作选择的 padding 不一致；已测运行方式没有速度优势。固定状态质量、完整标签一致性及失败主因仍未充分判明。**

也不能把整体瓶颈写成「不是代码或数据问题」——已确认的实现不一致仍然存在。

## 4. 下一工作包：增强修复是否值得学习（只做一次，不训练）

**选定增强修复方式**（只此一种，不同时尝试多方向）：**R 完整修复后，在本次 mask 客户中加入有限的两客户交换，允许跨车；用完整认证与完整 `J_vis` 选择方案。** 保留未掩码客户的车辆归属与相对顺序，不动 committed、已入舱货物或保护车辆。

选它的理由：改动范围容易界定，能直接检验 R 的插入结果是否留下可利用的联合重排机会。它只是**待验证的候选方法**，不能先称为「强 teacher」。

| 项目 | 本包要求 |
|---|---|
| 训练 | **不训练、不批量生成新监督数据** |
| 信息与合同 | 沿用当前可见信息、冷链合同、保护规则、认证与接受规则 |
| 搜索范围 | 只增加上述一种交换；不同时增加 beam、随机重启或新目标 |
| 开发上限 | 沿用最多 4 秒、最多 64 次完整候选尝试；所有评价计入预算 |
| 固定状态 | 保存可恢复的公开冷链状态，直接比较完整计划的 `J_vis` 和 D/Q/E |
| 闭环 | 比较 B、R、增强修复；R 与增强修复使用相同预算计时边界，报告实际耗时 |
| 数据 | TRAIN 固定实现；CAL/DEV 做一次锁定比较，继续标为开发结果 |

应同时比较 **R@1秒、R@4秒 与增强修复的相应预算结果**，避免把更多搜索时间误认成新增算子的优势。若资源只允许一个预算，先固定 4 秒并对两种方法一致执行。

**回答两个问题：**

1. 在相同公开状态下，是否存在优于 R、且能用合法插入步骤表达的局部完整修复？
2. 这种改善是否在真实动态闭环中仍然存在？（`J_vis` 更低仍可能因提前返仓、资源占用等损害后续动态服务）

## 5. 出口规则（现在就定，避免连续换配方）

- **固定状态和闭环都没有一致改善**：停止这条增强修复—蒸馏路线，进入论文定位调整；不自动追加第三种算子。
- **固定状态改善，闭环不改善**：暂不训练。本包没有建立值得蒸馏的在线参照，不能靠网络掩盖这个缺口。
- **闭环方向一致改善、服务通过**：才考虑一个新的有限学习包。先明确学生能否看到决定这些修复的冷链状态，并修正训练—部署一致性。
- **增强修复本身已足够快且有效**：它必须成为直接竞争对手。学习器需证明进一步质量优势，或以更低成本逼近它；不能只拿旧 R 当对照。

CI 跨零可作为探索性信号，不能称为已确认有效。继续与否结合改善幅度、额外耗时和实例间一致性，不只看均值正负。

## 6. 论文方向（暂时保留，承诺收紧）

现在不能判断 MaskCO 主线已走通，也不能因当前失败断言它不可行。MaskCO 原论文强调部分解条件化与迭代重构；学习修复嵌入搜索也已有先例（NLNS、Learning-to-Delegate、CO-enriched-ML）。因此下一篇论文需证明的是**具体机制的增量**，而不是「神经网络＋搜索」这种组合形式本身。

- 若增强修复验证建立了**可学且有实际价值**的参照 → 继续 MaskCO。
- 若没有 → 研究重点转向「已有冷链在线优化框架能否形成独立的方法或机制贡献」。

调整论文定位也需要证据，不是给负结果换个标题。

## 8. 实施状态与结果（2026-09-20 已跑，负结果）

增强修复验证已实现并跑完（本地 CPU，纯 NumPy）：`scripts/simulation/cc_swap.py`（`swap_two_customers` / `iter_swap_pairs` / `_suffix_tw_ok` / `cc_lns_swap_search` / `CCLNSwapReplanner`）+ `run_cc_lns_swap_{fixed_state,gate}.py`。`cc_lns_swap_search(swap=False)` 与本地冻结 `cc_lns_search` 逐位一致。

**结果（详见 [cc_lns_swap增强修复验证结果](../结果与进度/cc_lns_swap增强修复验证结果.md)，解释已复核）**：

- **Q1 固定状态**（TRAIN-64，4s）：mean Δ(J_S−J_R) = **+0.00584，聚类 bootstrap 95% CI [+0.00477, +0.00689]**（按基础实例聚类，严格为正 = 变差）；交换更好 13% / 更差 20.6% / 持平 66.4%。候选构成：R 平均 16 次重构（全正常结束）；S 平均 ~12 次重构 + ~33 次交换（985 candidate_cap / 770 normal）。交换**穿插**进搜索、共用候选预算，S 的候选集合**不包含** R 的。
- **Q2 闭环**（CAL/DEV）：swap_effect S−R = **+0.0194 (CAL)** / **+0.0454 (DEV)**，均为正（方向变差），CI 跨零；CAL 上 S 仍优于 baseline、DEV 上 S 反劣于 baseline。
- @1s == @4s（两种方法都在 1s 内完成搜索，时间预算不约束）。

**出口落点（修正）**：这个**穿插式交换搜索配方**未建立整体收益，按预算停止。**删除**「优于 R 的局部修复不存在」「R 是部署上限」——228 个改善状态说明前者不成立，S 候选集合不包含 R 说明后者不成立。「先找到更强 teacher 才能继续学习」**只适用于蒸馏路线**，不适用于所有学习路线。下一步另立 [MaskCO 直接目标训练工作包](../工程实现/MaskCO直接目标训练工作包.md)：复用预训练 MaskCO decoder、按完整冷链修复结果直接优化生成策略（RL），不再模仿 regret-2。
