# 合同/任务改动候选与推荐（制造因果可捕获的冷链头腔）

日期：2026-09-22。性质：研究设计建议，非已批准实现。前提：六步负证据链已证明当前合同（50 节点 R1 EDoD=0.5）下 MaskCO 无可因果捕获的头腔——根因是"冷链目标 ≈ 路由时间的确定性函数，无冷链专属决策，头腔 ≈100% 未来信息"。经用户裁定允许"合理改动"（保持 MaskCO 核心 + 动态冷链 pickup-to-depot + 结构改动而非调权重/放宽约束）。

## 1. 根因（机制，已核实到代码）

- **品质 = f(在途时间)**：quality clock = service_finish→return_arrival（`coldchain_contract.py:28`）；车厢恒温在 target_temperature_c，`quality_rate_per_hour` 退化为每温区常数 r[class]；每 lot 品质衰减 `exp(−r[class]·dwell)`，dwell = 返仓−取货，纯路由决定。
- **能耗 = f(时长)**：`power_duration_to_kwh(cooling_power_kw[zone], duration)` = 固定功率×时长 + 固定开门/预冷项，路由时长的线性函数。
- 温区/功率/容量/温度都是冻结合同常数（`capacity_model=shared_total`、`fleet_model=homogeneous_multi_compartment`）→ **除路由外没有冷链专属决策变量**。

## 2. 候选（4 合同改动 + 3 任务改动，附对抗验证结论）

### 合同改动（结构改动，非调权重）

| 候选 | 改动 | 新决策 | 制造信号？ |
|---|---|---|---|
| **① 多温区分舱指派 + 分区容量** | `capacity_model: shared_total→per_zone`；新增 `zone_capacity`、`zone_assignment=flexible`；每订单取货时决定装哪个温区 | 逐订单的**分舱指派**（冷区稀缺、保护高值易腐订单），正交于路由顺序 | **否（最强）** |
| ② 硬货架期截止 | 激活 `unsalable_quality_threshold`（现为被动 flag）→ 不可售=不可行 | 每订单的**内生返仓硬截止**（在途时长上限） | **否** |
| ③ 逐订单异质衰减率/价值 | 衰减率/价值从 per-class → per-order | 仅细化已有品质项的系数，无新决策变量 | **是（拒绝）** |
| ④ 离散温度设定点 | target_temperature 从常量 → per-trip 决策 | 无耦合约束的自由标量 → 塌到角落，等价于 λ 重参数化 | **是（拒绝）** |

对抗验证（读代码核实）确认：① 新增离散指派变量 + 收紧容量（per-zone 替代 shared-total），品质成为 `f(时长, 选定温区)`，不再与距离共线，不碰 λ——审稿人不会说"你只是让品质更重了"；③④ 是信号制造（细化系数/重参数化 λ），排除。

### 任务改动（减少未来信息主导，保持动态）

| 候选 | 改动 | 效果 | 保持动态？ |
|---|---|---|---|
| A 提前需求公告窗口 Δ | 订单在 `max(0, reveal_time−Δ)` 可见（可规划但未 release 前不可服务） | 直接缩小 clairvoyant 的 VoFI（对 Δ 窗口内订单，终局增益应重新可预测） | 是（订单仍按时间到达） |
| B 批量揭示（K 波） | 连续 reveal → K 个固定 epoch | 去掉连续揭示时序通道，转成 K 段离散 DP | 是（但只去时序分量，留身份分量） |
| C 多温区分舱指派 | 同合同候选① | 打根因 F2，引入因果决策 | 是 |

## 3. 推荐

**主改动 = ① 多温区分舱指派 + 分区容量**（合同候选① = 任务候选 C）。理由：
1. 直接打根因：把"温区/温度"从冻结常量变成**决策变量**，品质不再是路由时间的纯函数，产生正交于路由的、**可见且可学习**的冷链接指派决策；
2. 新增真实可行性结构（per-zone 容量是收紧，不是放宽），对抗验证确认**非信号制造**；
3. 与 MaskCO 天然契合：分舱指派可编码为掩码重构里的离散 token/动作，仍是"条件掩码重构"内核。

**可选补充 = A（提前公告窗口 Δ，取小到中等值保持动态）**，用于缓解另一个根因（未来信息主导）。但它单独不产生因果信号，必须与①组合、且先重跑可预测性探针确认信号真的回来。

**排除**：③ 逐订单异质衰减、④ 设定点——对抗验证判为信号制造/λ 重参数化；单独使用会被审稿人识破。

## 4. 改动前验证（D7，无训练，1–2 天）

在花任何 GPU 之前，对**新合同**跑 D7「易腐排序头腔 oracle」（复用现有 Probe/快照脚手架，把"距离键修复"换成"冷链键排序"——pickup-to-depot 下是**易腐订单后取**，因品质钟从取货才开始）：

- **(a) myopic 头腔**：距离贪心 vs 按易腐权重 w(c)=value·qty·rate 重排 suffix，myopic J_vis 差 > 0（CI 下界 >0）——合同是否奖励排序；
- **(b) 终局存活（决定性）**：baseline vs 「每次 committed_next 选最不易腐」的终局 J 差 ≥ 0.02（CI 严格 <0，且 ≥50% 实例改善）——myopic 收益是否进入终局（这一步当年杀了 D3）；
- **(c) 可预测性**：冷链排序特征（per-route 易腐数、suffix 前后半段的 Σw、期望 dwell 分布、温区装载混合…）→ 终局排序增益，留一实例线性探针 Spearman ≥ 0.30——信号是否从可见状态可学。

**GO 仅当 (a)(b)(c) 全过**（任一不过 → 不改训练，回改合同）。参考基线：当前合同 D3 终局 CI 跨零、因果 myopic +0.091（有害）、D6 探针 Spearman −0.037——所以 0.30 明显高于噪声，非制造目标。

成本：写 ~150 行 harness（复用现有脚本，无新评价器），每候选合同 ~15–30 分钟 CPU，无 GPU 无训练。
