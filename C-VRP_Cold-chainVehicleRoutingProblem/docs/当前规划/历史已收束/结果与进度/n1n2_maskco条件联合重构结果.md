## 一、本轮做了什么

| 环节 | 交付 |
|---|---|
| teacher 数据 | 带预留保护的 R 轨迹上，较充分 regret-2 搜索产出逐步插入标签（`P_before→mask→P_partial→steps→P_target`），384 条记录 |
| 模型 | 冻结 `DynamicColdChainModel` encoder + 可训练 `MaskCODecoder` + 插入 `ScoringMLP`；训练目标=条件插入步骤监督（softmax cross-entropy 对齐 teacher 下一步插入） |
| 训练 | 3 seed：s42 loss=0.30 / s43 loss=0.03 / s44 loss=0.007 |
| 在线 | greedy 插入重构（整体移除 mask → 模型打分 → 选最高分插入 → 重复），完整计划层面接受 |
| 闭环 + 诊断 | B / R / MaskCO×3seed 闭环；表 1 正确性 + 表 2 固定状态诊断 |

## 判读（对应工作包出口规则）

1. **学习增量未建立**：MaskCO 三 seed 混杂、CI 全跨零，未稳定胜过 baseline；R 在两个 split 上都更优（CAL CI 不含零）。
2. **固定状态**：学习器在**客户集合 / 部分 `plan_hash`** 层面接近 regret-2，但**未算 `J_vis`，不能据此判定质量无增量**；且明显更慢（~440 倍，计时口径如上限制）。
3. **train/deploy 不一致**：s42 前 20 条训练记录第一步选择 6/20 翻转（补齐长度是否等于训练 `Nv_max` 待核对）。

**可靠结论（已复核口径）**：闭环未建立学习增量；当前实现存在影响动作选择的 padding 不一致；已测运行方式没有速度优势。**固定状态质量、完整标签一致性及失败主因仍未充分判明**；也不能把整体瓶颈写成「不是代码或数据问题」——已确认的实现不一致仍然存在。

新增诊断**没有**证明「学生只能复制 R、永远无法超过 R」。收束是投入决策，不是「已证明修复无用」。

## 收束与下一步

1. **收束本轮**，冻结归档（checkpoint、逐实例结果、参数、源码身份已记录）。
2. **不修 padding 去重训**——这是投入决策（当前无质量/速度信号，继续投入需积极证据），**不能解释成「已经证明修复无用」**。将来若复用该学习器，padding 一致性仍必须修正和验收。
3. **下一步只做一次不训练网络的「增强修复是否值得学习」验证**（见 [决策](../决策与审计/N1N2收束与增强修复验证决策.md)）：R 完整修复后加入有限两客户交换（允许跨车），用完整认证 + 完整 `J_vis` 选择方案；暂不启动下一轮模型训练，MaskCO 论文方向暂时保留但承诺收紧。
