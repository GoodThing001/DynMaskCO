必须区分下列三套模型路径，避免把不同职责或输入维度混成“已有完整模型训练”：

1. **原静态 pilot 路径**：`scripts/delivery/delivery_maskco.py`，上述 3D 预训练/随机完整 CVRP 主干，0 新训练。
2. **冻结特征训练小头路径**：`scripts/research_20261010/delivery_trained_guide.py` + `delivery_traintask_train.py` + `delivery_traintask_data_export.py`。`DeliveryTrainedGuide` 继承上述 3D provider；只训练 frozen encoder 特征上的 `Z @ Z.T` 对称边头。推理为遵守旧 decoder-call 配平，调用原 decoder 后丢弃输出，改用头分数；训练不支付该丢弃调用。训练目标是 realized-cost 驱动的 advantage-weighted ranking，并有动作复算屏障。可借保存/重载、数据核对等工程机制，**不能原样称 MaskCO encoder-decoder 掩码重构任务训练**。
3. **实际动作头/10D 工程路径**：工作区根 `tools/delivery_actual_action_head_v1.py` 与 `tools/delivery_action_tensor_binding_v1.py`，以及 `research/review_3080_20261010/delivery/` 的对应冻结记录。动作头要求完整 10D snapshot features；它不是 `scripts/delivery` 的 3D provider。既有实际执行、方向动作和计时资格各有范围，不据其前向/梯度工程核查声称已完成新静态主干训练或公开数据实验。

`scripts/research_20261010/delivery_equal_schedule.py` 可借用相同掩码日程、P/R/H 归因和保存真实实际调用数的思想，但生成器是固定 50 客户的合成配送快照，协议种子/阶段固定；训练器还会按旧 seed/id 重新生成数据。若接公开实例，必须换成保存的实例身份读取，不能继续依赖旧生成器重建。

`scripts/data/generate_cvrptw_data.py` 明确是 **Solomon 风格生成器**，不是公开 Solomon 原始实例读取器。当前重点配送链中未见可直接完成公开原始数据下载、原文件哈希、许可证/来源、单位与 TW 映射的统一入口。

## 4. 与动态取货耦合的位置

`coldchain_contract.py` 的 `ColdChainContract` 与 `ColdChainContractV2` 验证器明确只接受 `pickup_to_depot`；`coldchain_state.py` 强制空载发车、订单在取货 service_finish 入舱、return_arrival 统一卸货。**不能仅把 mode 改成配送来复用此 transition**。

已有 delivery evaluator 正确另设加载和客户卸货事件，仅借 `_advance_temperatures`、`_advance_manifest_quality_v2` 等底层函数。新线可保留这种语义分离，但新合同必须绑定这些函数所用的动力学、热学、单位和费用参数，明确是否适用于论文的货品与温区。

下列动态功能不应成为新静态线的必需依赖：`simulation/strict_online_env.py`、在线订单 reveal 和接拒、`scenario_saa`、I3未来订单生成、私有状态所有者/共享内存/发布恢复、10秒逐事件事务、sealed final seeds。这些继续作为取货历史证据保留。静态数据应明确全订单在时刻0已知；旧 `ready_time/reveal_time` 字段若保留，应由新适配器统一设定并验证，而不是借用未来屏蔽流程。
