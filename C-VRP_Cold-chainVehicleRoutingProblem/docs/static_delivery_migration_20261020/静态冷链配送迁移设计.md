# 静态冷链配送迁移设计

> 文档身份（2026-10-20同步）：历史已批准设计，首轮单车范围及未来时描述保留，不作为当前待实施状态。该工程已完成，v3时钟/公式和多车按[后续补充计划](../static_delivery_followup_20261020/实施设计与计划.md)实施；当前结果见[总索引](../文档索引与版本状态.md)。

日期：2026-10-20。原设计已获批准并完成对应工程实施；以下为保留的设计基线，后续变更由v3补充计划和当前状态记录明确。

## 1. 本次目标与边界

本次用户已明确改变研究方向：静态订单、仓库向客户配送、业务与物理参数有文献依据、使用公开已有数据，完成后保全取货/负结果要点并清理本地工作区。用户随后明确选择：**“优先完整复现公开RRP冷链基准，再扩展多车”。** 该指令取代以前的动态取货主线及助手只维护文档的旧分工；原版`MASKCO_code/`和第三方原仓库继续不改。

“静态”定义为规划开始前订单、需求、时窗和可用车辆全部已知，不再学习未来订单揭示或接拒，不使用EDoD/SAA/滚动接单。公开确定的日内温度或速度时段可以是已知外生输入；它们不等于动态加入订单。

“配送”定义为车辆从仓库携带该行程全部订单出发，沿途卸货，剩余载量递减，返回仓库时为空。品质从有据可循的装载/出仓时点开始，至客户交付时点结束；若来源模型不包括仓储或装货过程，应写明边界，不能代填装货0.05h，也不能照搬取货的返仓结束计时。

成功标准是获得可执行、来源可核对的新任务链和清晰的历史归档。改为静态**不预设**MaskCO一定胜过强基线，原负结果不被重命名为新结果。

## 2. 数据与任务方案

**已选首轮：作者公开RRP，单车静态冷冻配送。** 依据Ceschia、Di Gaspero、Meneghetti的[*Extending and Solving the Refrigerated Routing Problem*](https://doi.org/10.3390/en13236214)，使用[作者仓库](https://bitbucket.org/sceschia/the-refrigerated-routing-problem/)固定commit `f5c5317a5ecd8fe64df779e79bd0397904bc0f9e`的D1/D2共30份实例与30份参考解，不调用作者生成器或本地生成器。

| 方案 | 能直接回答的问题 | 必须声明的边界 |
|---|---|---|
| 本轮：完整RRP复现 | 同一论文的实例、外生温度/速度表、车辆参数和参考解；复算目标后接MaskCO | 单车tour、没有逐客户时间窗；不是多车CVRPTW，不能把全部参考解自动称为已证明最优 |
| 后续：多车扩展 | 在RRP参数与评价闭合后研究车队分配和路线联合重构 | 需新的任务定义与公开数据协议；Solomon等是候选，不能把普通VRPTW原文件称为原生冷链实测 |

RRP原始输入包含需求、距离矩阵、车辆参数、24行速度时段表和288行月度/小时温度表；不要求它没有的坐标和客户时窗，不凭距离矩阵反造随机坐标。作者实例来自文献发布的生成型算例，包含真实气候/交通依据，不能称30份企业实测业务记录。仓库未单独声明数据许可；保持来源归属，本次不对外再分发。

数据来源与已取得文件见[公开数据集核验](公开数据集核验.md)。原版MaskCO的公开训练数据可用于原任务预训练；官方测试集只用于原任务复现，不当新任务训练数据。原论文参见[ICLR正式论文](https://proceedings.iclr.cc/paper_files/paper/2026/file/d85816bf41e54d9b0847e02249f4fcc6-Paper-Conference.pdf)。距离矩阵输入如何适配原坐标模型必须显式设计，不能仅改字段名。

每份原始文件记录发布者、URL/DOI、版本/commit、许可或未声明状态、文件名、大小、SHA-256、获取日期。原文件只读保存；适配文件另存并记录字段映射与单位换算。原始数据没有的距离—时间—小时换算、温区或商品标签，不得随机添加。药品冷链和交叉转运数据只作为独立候选任务，不把药品温区改成番茄/鱼，也不将交叉转运原问题伪装成单仓配送。

第一阶段复算**全部30份已公开参考解**，这是复现检查，不作模型泛化结论。其后训练/开发/测试按原实例身份分组；先核查D1/D2是否共享距离/需求构造，再固定分组。不同掩码、不同月份或衍生变体不能跨集合泄漏。30份基准量小就如实报告，不能把掩码数当独立实例数；已经阅读的参考成本不能伪装成盲测。另求标签只在固定公开实例上求解并标明来源，绝不重新生成客户。

## 3. 参数与品质模型

所有进入正式运行的业务、物理、品质和成本参数必须有明确来源及单位。数据自带参数保持原值；论文参数标明表/式/页、物种、包装、温域、设备边界；从论文值计算的量注明推导。缺项以未配置状态拒绝使用，不能退回旧pilot。

[参数核验报告](参数论文核验.md)已经区分番茄TA一阶衰减、鲻鱼感官零阶衰减、冷冻海鲈外推寿命和整车模型。**原RRP采用恒定−20°C单舱边界，目标为牵引、传热/渗透制冷燃料和司机成本，不包含番茄/鱼专属品质动力学。首轮忠实复现不擅自新增这些食品标签、品质罚金或阈值。** 这些产品文献留作后续有来源的扩展，而不是新程序中的默认系数。量表上限不充当每批初始品质，拟合温域不充当食品安全温界。

首轮物理边界采用RRP作者实例完整参数，**不继承旧三温舱动态温度状态**，不宣称真实三舱传热、货芯温度或连续温度认证。原文式(13)燃料转换方向与表列单位存在疑点；作者公开表与参考解可用于量纲和数值核验。实现必须记录采用的乘/除方向及来源，不静默修订。全部30解的牵引/传热/渗透/工资/总成本、到离时刻和载量均应逐项复算，未闭合项先报告差异。

2026-10-20进一步核查：D2公开参考成本对应原论文**表7(b)忽略工资**变体，因此不能因其不含工资就判为错误；表7(a)有工资与表7(b)无工资应分别明确评价。首次研究脚本统一加工资的差异只能用作口径诊断，不能作为作者数据错误或正式复现失败的定论。当前还有部分分项残差待排查，原解与原残差不覆盖。正式评价器从路序与等待重算时刻，不直接沿用TXT中的已保存到达/速度；探索性0.1欧筛查阈值不是论文的正式复现验收判据。

部分产品初值/阈值、三舱设备参数与公开VRPTW物理单位映射仍未闭合，归入**后续扩展**，不阻塞原RRP已提供参数的复现，也不以用户批准代替科学出处。

## 4. MaskCO与评价链

新实现放在扩展目录内的独立静态RRP模块，保留`scripts/project_paths.py`解析根路径。先实现原实例读取、作者参考解解析与独立评价器，再接原版MaskCO的掩码—恢复—迭代范式；公开静态输入不再做未来节点屏蔽。原RRP具有方向、载量和出发时刻依赖，不能将正反路线的无向邻接相同误判为目标等价。矩阵输入、方向和等待决策须保留；不可用伪坐标或旧3D模型推理冒称已经学会完整RRP。

监督目标为固定实例、原RRP目标下参考路线及适用的等待决策的掩码恢复；训练、单次恢复、迭代推理和保存重载贯通。训练与推理共享静态配送合同。原论文的**保留比例**与旧代码的**删除客户比例**不同，不能因数值相同而认作相同方法。若先只研究路线、固定等待策略，就单列该受限变体，不冒称原RRP完整决策空间。

RRP结果报告原论文各成本分项与总目标、行程/等待时长、服务完整性、容量/行程上限和运行时间，距离单列。原数据没有客户时窗，不报告伪造的TW通过率；车辆数恒为1，不声称学会多车分配。无最优性证明时称相对参考解差距。原文燃料价格与工资率支撑原目标，不沿用`D+0.1E+Q`。

强传统基线与MaskCO使用相同数据、目标、硬约束和预算；否则单列任务限制。原始MaskCO迁移、同架构随机/未预训练控制、任务训练后模型、单步/迭代消融应区分。JIT/加载和搜索耗时明确分列，所有不完整/失败实例留在结果中；不以事后挑参数或放大衰减速率制造收益。

## 6. 实施验收

1. 原始30实例/30参考解身份、许可记录和字段解析闭合；代码没有随机生成客户实例的路径。
2. 配送初始载量、逐客卸货和返仓空载可复核；矩阵、需求、时段、等待及原容量不被偷改。
3. 正式配置中没有旧pilot兜底；所有启用参数能指向原文/作者实例，单位与适用范围一致。
4. 先逐项复算原30参考解，再真正运行一条公开实例读取→参考解/掩码→训练小步→保存重载→重构→独立评价链；未执行前不写“已完成训练/方法有效”。复算参考解不等于复现原作者LAHC/MIP/CP算法，二者状态分别记录。
5. 新入口从仓库外工作目录也能解析路径；确认上游未变。
6. 关键历史证据按manifest重新核验，完成明确删除清单后再整理目录。归档完整性与方法科学收益分别报告。

本设计批准仅允许进入实现规划与对应代码改造；不能使未查清的参数变成有依据，也不意味着新方法已经取得正结果。
