## 推荐唯一主线协议及其明确边界

命名建议 `rrp_mip_dimensional_v1`，避免宽泛的 `paper` 暗示全文完全一致。主线遵循原始有向矩阵、固定出库时刻、连续秒、每弧出发槽定速、服务开始槽热学、式 (19)–(20) 的 2ψ、MIP 式 (14)覆盖全部等待、式 (15)的客户服务热侵入、表内 0.30 L/kWh 乘法换算，以及式 (1)–(3)年度欧元目标。

对下一节点 j 的预服务等待，清晰实现为：

```text
a_j = d_i + 3600*distance_ij / speed_slot(d_i)
t_j = a_j + wait_j
d_j = t_j + service_j
thermal_slot_i = floor(t_i/3600)
transmission_duration_ij = t_j - t_i
```

热学可复算式（JSON 表列用零基索引）：

```text
E_trans_year[kWh] = sum_i sum_m days_m * table[m,slot(t_i),7]
                       * (t_next-t_i)/3600 / table[m,slot(t_i),8]
E_inf_year[kWh]   = sum_customers_i sum_m days_m
                       * (table[m,slot(t_i),5]
                          + table[m,slot(t_i),6]*(service_i-40))
                       /3600 / table[m,slot(t_i),8]
C_refr_year[EUR]  = (E_trans_year+E_inf_year) * 0.30 * fuel_cost
```

`t_next` 是下一节点的服务开始（已含其预服务等待）；末弧为回库物理到达。仓库 `t_0=d_0=start_time`。总和时间区间从 t_0 连续覆盖到回库，没有漏掉等待，也没有重复计时。

时间可行性必须拆成两种标签，而不是为贴参考解静默放宽：

- `source_day_domain`：严格标明一天时域和固定开工，以公开公式能够确认的域进行评价；9h超限单独报告。此域也不是声称恢复了未公开的作者求解器全部约束。
- `operational_tour_9h`：用户/本地扩展明确采用的“总tour≤9h”运行域；无工资与有工资都同等应用。超过者在此域不可行，但不据此判定作者求解器错误。

若工程暂时维持9h为默认，所有结果要在身份中注明 `operational_tour_9h`；不能再仅引用 Table 1 即称已证明这一筛选在作者全部实验中强制存在。9h总tour和9h驾驶不是同一约束；本报告不以该论文文字提供道路法规合规判断。

对比报告应同时保留原始作者值、统一主线重算值、逐分量残差、profile、objective、时间域、固定SHA。`archive_compatibility` / `archive_pre_service` 是解释归档序列、服务系数的诊断，不作为恢复主线成本的可调参数。

## 多车扩展的科学继承条件

论文 p4 假设全部需求可由单车承运，p23明确把多车列为未来工作。因此多车应称新扩展：每客户恰好分配一车、每车载量≤33托盘、各车从原仓库出发并回库、每车独立重置已卸托盘位置和载重。年度成本按车辆路线求和；服务次数与客户覆盖不能改变。沿用33托盘/7450kg/150m²等车辆参数时，注明同型车假设。

没有一手来源的固定车辆成本、变动出库时刻、额外客户时间窗、产品质量动力学不能凭空加入。车辆数若固定，则显式声明；若只给上限，则报告实际启用数量，不能暗设一套车辆收费来产生期望的车数。保留原始JSON矩阵，不生成坐标或客户；几何同源D1/D2仍按组分割。以上只规定模型身份，不等于多车已有泛化、成本收益或文献基准证明。
