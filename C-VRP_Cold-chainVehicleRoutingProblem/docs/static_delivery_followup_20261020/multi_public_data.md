Escobar出版社地址由保存的Crossref元数据确认，正确文件是`IJIEC_2021_16.pdf`。PDF第12页（印刷146页）已渲染检查：表3的Q未注明千克/托盘；表4柴油热值字段印为W/kg，而式(9)的转换量定义为J/gal，两者不能直接相代。表4发动机字段还印为146.7 cc。本报告保存印刷值，不自行修成其他单位，不将其数值迁入RRP。图证见[表3/4渲染](multi_public_evidence/escobar_table3_4.png)。

Set M是VRP-REP发布的XML版本，不冒称作者原CVRPLIB文件的逐字副本。XML的`quantity`、`capacity`和坐标没有给出物理单位；其README还明确提醒距离取整规则存在历史差异。因此不能把200换成33托盘，不能把需求乘600 kg，也不能默认为坐标单位是km或与某个BKS的取整身份一致。若将来要做“公开路由 + 文献物理层”混合场景，必须先取得需求/容量/距离的来源支持映射并独立标识场景；当前该映射未闭合，不能给出物理欧元能耗结论。

## Split的文献边界与首轮建议

[Prins 2004](https://www.sciencedirect.com/science/article/pii/S0305054803001588)的巨环排列加Split为方法先例；其最优划分以给定客户顺序为条件。[Vidal 2016](https://arxiv.org/abs/1508.02759)及[作者代码](https://github.com/vidalt/Split-Library)给出CVRP线性Split和有限车队扩展；O(n)或O(nm)依赖论文的路段成本结构，不能直接转移到时变冷链成本。

本项目可用一般有向无环图/Bellman划分：一个边代表一段连续客户及仓库出入，由独立RRP评价器计算该车的需求、时钟、等待、可行性和年化分项成本；有限车辆数增加一层标签。给定排列、给定各段成本后，划分的最优性才成立。若等待只由有限候选或启发式确定，不能声称同时得到了连续等待全局最优，也不能把CVRP的线性时间证明当作RRP证明。朴素划分标签可按O(Kn²)计数，分段评价器的时间另计。

首轮保持原客户与原需求，不复制订单，不缩放载量，不缩小33托盘车型来强迫多车；每辆实际装载其所分配需求之和。最大可用车辆数K在实验中显式设置，使用“至多K辆”语义并报告实际用车数。原30例需求总量24–33托盘，所以容量本身不强迫多车；得到单车结果也是合法结果。原资料没有车辆固定启用费，不新增该分项，更不能声称真实固定费为零。各车继续报告原RRP的牵引、制冷和工资年化欧元，距离另报。

这条路线可验证多车分配、连续等待和求和评价是否工作；不能据此证明大规模多车泛化或企业收益。当前单车参考成本残差、D1-n9等待缺项以及历史负结果均不因此消失。
