## 3. 为什么这 8 个文件没有进入 GitHub：**是设计如此，不是事故**

证据在**已提交的**只读验收器 `C-VRP_Cold-chainVehicleRoutingProblem/scripts/tests/q3_package_acceptance.py` 里：


第 165-173 行是验收行 **A-09**，逐字要求：

> `A-09 run records are EXCLUDED from the delivery by the explicit list (root results/ is NOT gitignored, so nothing may rely on .gitignore here)`
> `first_version_of_this_check: 'asserted the directory WAS gitignored and FAILED; the fact is that root results/ is not ignored, so exclusion must be explicit'`

`NIGHT_STATUS.json` 自己也有同样的登记：

> `"excluded_from_the_repository": { "results/_q3_overnight/**": "RUN RECORD, not evidence. Root results/ is not gitignored, so these are excluded by the explicit delivery list only; never force-added." }`

而 `NIGHT_REPORT.md` 第 3-5 行开篇即声明：

> **性质：运行记录，不得冒充冻结证据。** … 是**过程记录**，不是验收工件、不是冻结证据、不改变任何既有裁决。

**所以三层原因叠加，都不是"忘了提交"**：

1. **定性**：这 8 个文件被作者定义为 **RUN RECORD（运行记录）**，不是 evidence。证据是它们派生出的 3 个 l1_gates JSON。
2. **机制**：根 `results/` **未被 `.gitignore` 覆盖**（`git check-ignore` 返回 1），所以排除**必须显式**做——
   交付用显式 `--paths` 白名单（`DELIVERY` 列表 10 条），验收器用 A-09 把这条排除**机械断言**下来。
3. **实际结果**：那 10 条交付路径 **全部已入库且已跟踪**（逐条核验，见 §4），提交为
   `759fe7f docs(q3): archive the Theorem-B refutation, the corrected weaker bounds and the prohibited-use errata`。

- 断言与当前合同**不一致**：合同语义是"没有**生产路径**引用"，而验收器实现是"文件文本里出现该字符串"。

### 6.2 DEV-GATE v4 的 `EVIDENCE_SEAL.json` 不是 UTF-8

```

gbk        OK   len=2053
```
