### 3.2 C++ 扩展（`scripts/lib/`）

`cvrptw_ops.cpp` + `cvrptw_bindings.cpp` + `Makefile` + 预编译 `cvrptw_ops.cpython-310-x86_64-linux-gnu.so`（Linux/py3.10）。
导出 `repair_edd` / `two_opt` / `count_violations` / `quality_two_opt`。
**只有 3 个消费者**：`decoding/cvrptw.py`、`simulation/run_dynamic_sim.py`、`data/generate_self_training_labels.py`——**全部在历史线上**。
**`scripts/tests/` 里 0 处引用 `cvrptw_ops`，因此测试不需要重建它**；且预编译 `.so` 在本地 Windows/py3.12 上根本加载不了，`try/except ImportError` 会静默降级为 Python 实现（不会让测试失败，也不会报错）。
需要时：`cd scripts/lib && make`（需 `pybind11` + `clang++`）。

### 3.3 D3-L1 / `l1_gates` 的边界（新手最容易被它误导）

- `l1_gates` **不是 Python 包**，是**证据输出目录**：`research/review_3080_20261010/d3_g0_evidence_root_v1/a1_d3_l1_prereg_root_v1/l1_gates/`（86 文件）。
- 代码侧共 **89 个 `d3_*.py`**（`simulation/` 28、`tests/` 59、`data/` 2），其中 69 个 `d3_l1_*`。
- 它是**冻结的治理/资格机器**：fail-closed、一次性凭据、42 条 watch 路径、`main()` 拒绝绕过。
- **耦合方向是单向的**：它消费研究主线（`coldchain_contract`、`action_contract`、`mpre_trained`…），**主线不 import 任何 `d3_*`**。
- **规矩**：当只读审计痕迹处理，**不要重构、不要"修红"、不要重跑**。同理 `coldchain/q3_*_experimental.py`、`q3_qualification/`。

## 8. `CC_Compare/` 对照区

- 16+ 个第三方方法树（`Sym-NCO` 占全部跟踪文件的 88%；`OR-Tools` 占字节最大 2.36 GB）+ 项目自有的共享契约层。
