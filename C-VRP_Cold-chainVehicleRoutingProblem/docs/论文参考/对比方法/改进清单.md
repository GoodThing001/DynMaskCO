## 1. 节点类型专属 embedding（typed embedding）⭐

### 改了什么
`temp_embed`（3 类，仅温度）→ `type_embed`（**5 类**）：

| 类型 id | 含义 |
|:-:|------|
| 0 | depot |
| 1 | 常温（temp_class=0） |
| 2 | 冷藏（temp_class=1） |
| 3 | 冷冻（temp_class=2） |
| 4 | 未来订单（`visible_mask=0`，reveal 前不可见） |

### 顺带修复的 bug
旧代码 `raw_features[...,5].astype(int32)` 把归一化的 `temp_class/2.0 ∈ {0, 0.5, 1.0}` 直接截断：
- **冷藏(0.5→0) 被误归为常温(0)**，只有冷冻(2)→1 被区分。

新代码 `(temp_class * 2.0 + 0.5).astype(int32)` 正确恢复 0/1/2。

### 涉及文件
- `models/DynamicColdChainModel.py`（`type_embed` 定义 + `encode` 中 node_type 计算）
- `decoding/cvrptw.py`、`simulation/run_dynamic_sim.py`、`baselines/euro_adapter.py`（`hasattr(model, 'temp_embed')` → `'type_embed'`）

## 2. 不可售产品数 Num 指标

### 最终实现（数据同款公式）
新增 `--quality_salable_threshold`（默认 0.02），解码器在数据含 `quality_loss` 时报告两个口径：

```
[冷链] Num unsalable (预计算 quality_loss > 0.02): 8.10/inst  (参考路线口径)
[冷链] Num unsalable (最终路线): 0.31/inst  (数据同款公式 1-exp(-k·cum_time))
[冷链] Num unsalable (beam 生成阶段): 18.66/inst  (品质感知 beam score 的路线)
```

### 验证结果（阈值 0.02）
- 贪心参考 8.10 vs DynMaskCO 最终路线 **0.31 = -96%**（search+2opt 隐式优化品质）
- beam 生成阶段 18.66（初始路线差）→ search+2opt 后 0.31（优化显著）

### 实现要点（调试后确认）
- **最终路线 Num** 用数据同款公式 `quality_loss = 1 - exp(-K_TEMP·cum_time)`，与预计算口径完全一致（避免 thermal_state 温度模型的数值 bug）。
- cum_time 累积 `dist_mat[prev, node] + service_time[prev]`（FROM 节点服务时间），depot 重置。

## 3. 3 阶段品质模型 + 寿命阈值

### 改了什么
`decoding/resource_beam.py` 的 beam 品质模型从「连续累计 quality_loss」升级为「逐温区品质 + 可售阈值」：

- `BeamState` 新增 `num_unsalable`；`quality_ambient/refrig/frozen` 字段从死字段变为真正逐段衰减。
- 每段行驶：`decay = 1 - exp(-k_T·dt)`，逐温区累乘；剩余品质 < `(1 - quality_salable_threshold)` → 该货物不可售，`num_unsalable += 1`。
- 对应 ESWA 的「新鲜→可见劣化→不可售」三段。

### 参数
- `quality_salable_threshold`（默认 0.1）：可售品质损耗阈值。仅 `--enable_quality` 时参与 beam 决策与 Num 统计。

## 4. 显式边特征（energy_mat → 注意力偏置）

### 改了什么
借鉴 GAT 边特征 embedding，把**边的制冷能耗 `energy_mat`** 作为显式边特征注入编码器注意力偏置（复用 P0-2 可见性门控的 `attn_options['bias']` 通道）：

- 模型新增可学习标量 `edge_weight`（init=0，安全 no-op）。
- `encode(..., edge_feat=None)`：`edge_bias = edge_weight × edge_feat`，加到注意力偏置。
- 训练 `--use_edge_feat` 时，dataloader 产出 `energy_mat` 并传入 encode。

### 涉及文件
- `models/DynamicColdChainModel.py`（`edge_weight` + `edge_feat` 参数）
- `data/ColdChainDataloader.py`（加载 `energy_mat`，`need_edge_feat` 开关，默认 4 元组向后兼容）
- `training/train_dynamic_cc.py`（`--use_edge_feat`，5 元组解包 + 传入 encode）
- `decoding/cvrptw.py`（energy_mat 作为 edge_feat 注入推理）

---

## 5. 新增参数 / 开关汇总

| 参数 | 作用域 | 默认 | 含义 |
|------|------|:-:|------|
| `type_embed` | 模型 | — | 5 类节点类型专属 embedding（替代 temp_embed） |
| `edge_weight` | 模型 | 0.0 | 边特征 → 注意力偏置的可学习缩放 |
| `--use_edge_feat` | 训练 | False | 喂 energy_mat 进编码器（边特征训练） |
| `--quality_salable_threshold` | 解码 | **0.02** | 不可售品质损耗阈值（Num 指标 + beam 决策）——0.1 对本数据偏高 |

## 7. 验收标准

### Smoke（服务器跑 `run_smoke_improvements.sh`）
1. 模型构造成功：`type_embed.num_embeddings == 5`，`edge_weight` 存在。
2. temp_class bug 修复：喂 `temp_class/2.0` 编码不报错，冷藏不再被截断为常温。
3. 训练 200 steps（typed embedding + `--use_edge_feat`）无报错，checkpoint 正常保存。
4. 解码输出 cost/feas + Num 指标行。

### 全量验证（重训后）
5. typed embedding 模型 5-seed 评估，cost/feas 与旧基准（14.77 / 100%）可比，且**不退化**。
6. `--use_edge_feat` 训练后，`edge_weight` 不再为 0（说明边特征学到了信号）；否则说明 energy_mat 对 encoder 无增益，可关掉该路径。
7. `--enable_quality` 下 `searcher.last_num_unsalable` 随 `quality_salable_threshold` 变化，且常温货物的不可售数 > 冷冻货物。

## 8. 已知限制

- **旧 checkpoint 不兼容**：`temp_embed` → `type_embed` 改名 + 参数结构变化，旧 ckpt（causal_v1 / transfer_r1 / frozen_v1）无法直接加载，需重训。
- **edge_weight 训练依赖数据**：只有数据含 `energy_mat` 时 `--use_edge_feat` 才有意义；否则 edge_feat=None，边特征路径不生效（但仍可训练，等价于关闭）。
- **Num 指标双口径**：预计算 quality_loss（参考路线）vs beam 实时品质（`--enable_quality`）。论文中需明确用的是哪个口径。
