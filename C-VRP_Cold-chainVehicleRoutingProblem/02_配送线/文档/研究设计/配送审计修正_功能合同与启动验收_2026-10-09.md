# 配送审计修正：功能合同与启动验收

> **2026-10-10**：商品品质模块与电输入单位检查已独立实现并通过服务器11项回归。旧事件检查器未冒称已整合该物理组件；强滚动优化与迭代收益仍需新科学版本。[商品、来源、范围及假设](../../../docs/当前规划/决策与审计/三线修正_服务器复验与文献参数版本_2026-10-10.md)。透明仿真不要求实测校准作为通用门槛。

D2是已备货、出发前静态路线快照，online_ready=False。其单步主门已失败，不能改用迭代改善作为主门。下表形成具体实现合同，状态均为待实现/待注册验收，未启动新配送实验。

| 功能 | 必须落实的合同 | 必须通过的反例/验收 |
|---|---|---|
| 动态订单 | release_time控制公开；ready_time控制可装货，两时钟分开 | 未公开不可规划；已公开未备好不可装货；迟备货完整计入 |
| 货物生命周期 | 仓库→装货→车载→交付；每货物只归属一个位置；仓库阶段品质计时显式 | 重复装货、凭空生成、在途跨车转移、未装货交付均被拒；数量守恒 |
| 有限车队 | 固定车辆身份、返仓到达/卸装/再出发时刻；禁止隐式加租车 | 忙车不能重复派遣；返回途中不能提早复用；等待计入运营时间 |
| 可修改路线 | 执行前缀与当前承诺行驶段不可变，只改允许后缀 | 在途位置、库存和当前目的地保持；重构不回溯撤销已交付 |
| 温舱容量 | 明确固定分舱或理想灵活分舱，共享总容量不能冒称固定分舱 | 总量和每舱约束按所选合同逐事件认证，不以sum容量代替分舱 |
| 温度与品质 | 空气、产品温度及品质状态分别建模；当前V2固定速率仅作历史 | 零时长不损耗、单位一致、温域与产品匹配；冷冻外推单列不确定性，不称食品安全验证 |
| 强滚动基线 | 同信息、车队、目标、提交截止和认证器；滚动接口实现后才命名HGS/ALNS | 对全新微型例与精确参考核查；日志保留推理、搜索、认证和回退，不拿距离搜索冒称冷链强基线 |
| 迭代归因 | 预训练/随机/非学习使用同初始路线、掩码和尝试日程；另做等墙钟比较 | 执行次数、有效候选、原权重hash与墙钟完整；固定次数与等时间分别裁决 |
