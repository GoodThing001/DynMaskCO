# 机制实验设计：局部改善为何消失（②a 动作执行追踪）

日期：2026-09-22。性质：工作包 ② 的第二项机制实验设计。目的：解释 D3 的核心发现——mask=2 局部修复有 myopic 头腔（D1/D2 ~0.006–0.013），但终局头腔 ≈0（~2/3 状态终局结果与 baseline 逐字节相同）。区分两个机制：

- **M1（动作未执行）**：修改被后续重规划覆盖，客户根本没按候选方案被服务。
- **M2（执行了但无终局收益）**：修改按候选方案执行了，但未来订单把收益洗掉，终局成本仍等于 baseline。

这是"被后续重规划覆盖"从**推断**（成本相等反推）升级为**可验证机制**（路线/动作执行记录）的关键——审读明确要求不能仅从成本相等推断机制。

---

## 1. 做法（复用 D3 的 Probe + 终局 rollout，加执行记录比对）

1. **采集状态**：复用 `run_headroom_census.Probe`（mask=2），得到每状态的 `mask_set`（被移除的 2 个客户）+ `partial` + `mutable_ids`。
2. **候选修复**：复用 `run_headroom_census._dist_greedy_repair` 得 `P_dg`（距离贪心修复）与 `_exhaustive_repair` 得 `P_exh`。
3. **强制 + 终局 rollout**：复用 `_snapshot_with_force` + `run_resumed`，得到终局 `traces`（每车的 `services[].node` = 实际服务顺序）与 `coldchain_cost`。
4. **执行比对**（核心新增）：
   - 候选分配 `cand_assign = {c: vid for vid, suffix in P_dg.items() for c in suffix}`；
   - 实际执行 `trace_assign = {sr.node: vid for vid, tr in enumerate(traces) for sr in tr.services}`；
   - 对 `mask_set` 里的每个客户 c：`persisted(c) = (cand_assign.get(c) == trace_assign.get(c))`。
5. **分类**：
   - `executed`：mask_set 全部客户 `persisted=True`（修改按候选执行）；
   - `overwritten`：至少一个客户 `persisted=False`（被后续重规划改派/改序）；
   - 结合终局头腔 `J0 − J(P_dg)` 交叉制表：executed 组 vs overwritten 组的终局头腔分布。

## 2. 判读

- 若 **overwritten 占主导** 且其终局头腔 ≈0：D3 的"≈0"是"修改被重规划覆盖"，支持"固定状态局部修复在动态续策略下不稳定"。
- 若 **executed 占主导但终局头腔仍 ≈0**：修改执行了但未来订单洗掉收益，直接指向"未来信息主导"（与 ②b、D7-b 同构）。
- 两组的正头腔状态数/均值对比，回答"执行了的那部分修改有没有带来终局收益"。

## 3. 可选扩展（"何时"被覆盖）

在 `run_resumed` 的事件循环里装 hook（`env.snapshot_hook` / `env.oracle_hook`），记录每个决策点的 `mutable_suffix`，定位 mask_set 客户被改派的**第一个事件 id**。先做核心版（executed/overwritten 分类），"何时"作为扩展按需补。

## 4. 验收标准

- 产出逐状态 `{inst, event, persisted_mask, executed/overwritten, terminal_headroom_dg, myopic_gap}` 与交叉制表 summary。
- 明确回答：D3 的终局头腔 ≈0 主要是 M1（未执行）还是 M2（执行了无收益）。

## 5. 实现（新脚本，`negative_result_paper/scripts/`）

`run_execution_trace.py`：复用 `run_headroom_census.Probe` + `_dist_greedy_repair` + `_exhaustive_repair`，新增 `_trace_assignment(traces)` 与 executed/overwritten 分类 + 交叉制表。依赖（只读）：`run_headroom_census`, `run_terminal_headroom`, `counterfactual_teacher`, `recourse_snapshot`, `strict_online_env`, `coldchain_contract`。
