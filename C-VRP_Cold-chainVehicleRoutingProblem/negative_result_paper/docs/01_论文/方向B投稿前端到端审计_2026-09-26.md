## 投稿前必须解决（P0）

1. **预注册总体判定失败，不能表述为“C1 独立确认复现并加强”。** C1 协议 §3 预先要求 (a)(b)(c) **全部成立**，任一失败即回退为 R1 单协议案例；结果中 (b) 的 s42 接受后区间跨零、(c) 的 s43 M-trained−R 区间在零以上。论文摘要、讨论和结论原先违反该规则。本次已把完整初稿改为“联合判据未通过；分项 (a) 成立，其他为部分复现/探索性”。预注册文件原始规则与原始结果应原样保留，不得事后改写。
2. **未来采样器的回退实现与文字说明不一致。** `negative_result_paper/scripts/run_future_sampling_oracle.py` 中 `_sample_future` 先在每次重试改写 `coord/demand/temp/tw/service`；full 模式若 200 次均不满足 `max_reveal > clock`，`coord` 已非 `None`，故 `if coord is None: continue` 不会触发，返回的字典含新属性和 `reveal=None`。`_apply_future` 在 `reveal=None` 时保留原真实 reveal_time。这与“失败保留该客户原属性”不符，也可能在 full 评分中混入真实未来时序。**当前归档没有触发次数或逐场景记录，不能判定该路径实际影响图 3 的幅度。** 执行端需先加失败计数并在原数据/seed 下核查触发率；修复为整单保留或一致的合法重采样，再以同样 N=8、相同数据/目标/候选集重算 ②b 与图 3。若零触发，可把零触发日志与源码修复一起归档；若非零，必须替换正文数值。
3. **在线预算单位原文写错。** `run_step5_gate.py` 每次构造 `CCLNSReplanner`/`PolicyReplanner(budget_s=4.0)`，`cc_lns_search` 在每个重规划调用内重置 `t0`。所以是 **4.0 秒/重规划调用**，不是 4.0 秒/实例。M-trained s43 的 `elapsed_total` 约 1209 秒/16 实例，亦与“每实例 4 秒总预算”不相容。本次已改完整初稿与发布说明；还需给表 2/5 追加每臂每实例总搜索耗时、事件调用数或至少中位数/P95，并明确 JIT 预热另计。
4. **三层口径共用 v1 目标，但源码版本并未完全统一。** 归档审计明确记载：固定状态用六模块 09-22 pin；闭环只 pin v1 物理模块，context/LNS/M-trained 使用后续版本。两层可在各自内部配对，但将候选→接受后→闭环的变化归因于同一策略的在线接受/重规划，尚需同一状态/同一 mask 下的策略行为对账，或明确降为描述性层级比较。本次已在方法节加边界说明。固定状态只评 mask=2，闭环每事件两轮 (2,2,2,4,4,4,8,8)，也是跨层级差异。
   另，R1 固定状态主表主要来自 TRAIN/CAL，闭环来自独立留出；只有 s42 做了留出固定状态，s43 没有同一留出集的固定状态三列。因此现有主表能证明“不同层级出现不同排名/区间”，不能精确识别某个候选收益在哪个事件被抵消。若保留“定位消失位置”的强主张，需同实例逐事件候选→接受→最终执行的联接分析；否则坚持描述性三层评价。
5. **复现包还不是审稿人可从零执行的包。** `release/` 目前无大文件与 `docs/`，训练时 `mpre_trained.py` 源码已丢失，s43/s44 无 `training_identity.json`，step5 原逐实例事件 JSON 未保留。六模块 pin 与闭环 physics-only pin 需两个明确的执行环境；简单用六模块覆盖所有脚本不能重现闭环身份。发布说明路径 `pinned/v1_modules/` 原本不存在，C1 数据也未列入大文件清单/SHA；本次已更正路径、C1 SHA 与文件数。执行端须按发布说明补齐公开下载、源码快照、环境锁定、可执行入口，并让未参与开发的人在干净环境试运行一次；不能承诺逐位重训练。

## 重要修改与待核对（P1）

1. **显著性笔误已修。** R1 留出 M-pre−B：s42 +0.0461 [−0.0147,+0.1026]、s43 +0.0411 [−0.0179,+0.0955]，两者均跨零。完整初稿原称“均显著更差”，现已改。M-trained−M-pre 的显著改善是**配对比较**，不能由各臂对 B 是否显著来代替。
2. **bootstrap 次数原文写错，现已修。** `analyze_fixed_state.py` 与未来采样脚本使用 2000 次；`service_first.paired_bootstrap_ci`（闭环）使用 10000 次，分别以实例为单位。论文原写统一 1000 次。若投稿版本仍采用多比较的逐项 95% 区间，应说明这些是单项/名义区间，不把每个探索性诊断当独立确认。C1 s43 M-trained−R 的 95% 区间下界仅 +0.0020，表述“名义 95% 区间在零以上”比笼统“显著更差”更稳妥。
3. **收益阈值不是双侧等效性。** 1%·J0 来自项目立项门，现有下界可排除固定状态接受后 ≥1% 的平均改善；不能推及闭环或“与 R 等效”。若称“预设”，须在附录给出先于检验的日期化立项门证据。
4. **机制解释应保持线索级。** 动作追踪只测最终车辆归属，未逐事件定位何时改派，更没有证明“只有首客户的改善进入轨迹”。未来评分的 clairvoyant 是同候选集按真实终局成本选最小值，差值非负由构造保证；full 不是已验证的真实条件分布，attr 保留真实 reveal_time。本次已收窄正文，但 ②b 在 P0-2 完成前不应作为论文核心机制定论。
5. **图 1–3 的顶部标题被裁切。** 已直接目检 PNG，长 suptitle 越出画布；图 3 的 “fixed sampler” 也需在 P0-2 完成后再用。执行端按短标题+图注分离重新生成 PNG/PDF，并核对轴标签、字体、留白及黑白打印可读性。图 1 不应凭不同实例集的视觉距离推断层级因果变化。
6. **参考文献已有可核实的硬错误。** [10] 实为 2021 年 IJPE 231:107849；[12] 作者为 Lu Chen、Yang Liu、André Langevin；[13] 为 2026 年四作者正式论文；[14] arXiv 标题及三名作者原文均错；[20] 是 NeurIPS 2025 **workshop**，不是主会论文；[21] 作者顺序、标题、DOI 原文均错。本次已按出版方、会议/机构与 arXiv 页面修改完整初稿。其他条目仍需作者用目标期刊格式逐条核对；相关工作不能写成“学习场景生成只有条件化+小预算才有优势”这样的跨论文普遍结论。
7. **主张范围需坚持“这一适配”。** M-pre 把原 MaskCO 的边 logits 转成确定性逐步插入分数，M-trained 再加 C/δ 和 REINFORCE；这不是上游 MaskCO 原生迭代重掩码解码的原样部署。论文可报告该适配的失效边界，不能证明“MaskCO 在动态冷链普遍无增量”。完整初稿已收窄摘要/结论。
8. **旧导航仍含过期数字。** 根 README 和 2026-09-23 短稿/“锁定主表”保留历史物理口径与 ②b 数字，易被误当唯一主表。本次在根 README 顶部标注阅读顺序；投稿包仍应按执行端归档规则把旧资料清楚标为历史，并确保 release 仅引用统一 v1/C1 数据。
