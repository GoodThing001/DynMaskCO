# 增强修复验证结果：R 完整修复后的两客户交换（不训练）

> 2026-09-20 · 本地 CPU 运行（纯 NumPy，无 GPU/encoder），数据 `data/m0_scale/`。回答 [N1/N2 收束与增强修复验证决策](../决策与审计/N1N2收束与增强修复验证决策.md) 的两个问题。
> 配置：`--n-rounds 2 --max-attempts 64`，budget 1s / 4s，seed 0，guard_reserved=True。R = `cc_lns_swap_search(swap=False)`，S = `swap=True`。
>
> **⚠️ 解释已按 2026-09-20 复核修正**：交换是**穿插进搜索**的（[cc_swap.py:186](../..//scripts/simulation/cc_swap.py)），不是「先保留独立 R 的最终答案再额外搜索」；因此 S 的候选集合**不保证包含** R 的候选集合。下列「S 更差」不能写成「交换算子必然有害」，也不能写成「优于 R 的局部修复不存在」或「R 是部署上限」。

## 一、Q1 固定状态（TRAIN-64，budget 4s）

同一公开状态上 R vs R+交换，比较完整计划 `J_vis`（不写回）。

| 指标 | 值 |
|---|---|
| 状态数 / eligible | 4500 / 1755 |
| mean J_vis (R) / (S) | 1.257184 / 1.263023 |
| **mean Δ(J_S − J_R)** | **+0.00584，聚类 bootstrap 95% CI [+0.00477, +0.00689]**（按基础实例聚类，严格为正 = 变差） |
| 交换更好 / 更差 / 持平 | 228 (13.0%) / 362 (20.6%) / 1165 (66.4%) |
| ΔD / ΔQ / ΔE | +0.1181（差）/ −0.0016（好）/ −0.0443（好） |
| 平均候选构成 | R：**16 次重构**，1755 全部正常结束；S：**~12 次重构 + ~33 次交换**（共 ~45 候选），其中 **985 触及候选上限、770 正常结束** |

**Q1 结论（修正后）**：**这个「穿插式交换」搜索配方在固定状态下未建立整体收益**（均值显著变差）。但 228 个改善状态本身说明「不存在优于 R 的局部修复」不成立；S 的候选集合不包含 R 的（交换消耗共同候选预算、并改变后续 mask 搜索路径），所以 S 可以更差——不能据此断言交换算子本身有害，也不能断言 R 是部署上限。

**Q2 结论**：闭环里这个交换配方同样未建立改善，两个 split 上 S−R 均为正（方向变差），CI 跨零（未达 95% 确认）。与 Q1 一致：这不是「交换无价值」的证据，而是「这套穿插式交换搜索配方没有整体收益」的证据。

## 三、关键观察

1. **@1s == @4s**：两种预算下结果逐位相同——R 在 16 次重构内结束（`normal`），S 在候选上限/正常结束前都不触及 1s 时间预算，故时间预算不构成约束。
2. **实现正确性**：R（`swap=False`）与本地冻结 `cc_lns_n0r_R_1.0s_{cal,dev_check}/summary.json` 逐位一致（CAL −0.0531 / DEV −0.0327）。与 [N1/N2 结果](n1n2_maskco条件联合重构结果.md) 表 3 的服务器数字（−0.0686 / −0.0232）存在差异，**原因未核实**（不能直接认定一定来自数据或 seed），不影响 S−R 同机比较。
3. **穿插 vs 先留后搜**：当前实现把交换插入在每次 R 重建之后、共用 `n_attempts`/`seen`/预算，接受交换会更新 `best` 从而改变后续 mask 选择。因此 S 不是 R 的严格超集；S 更差不能反推「R 的答案无可改进」。这是配方设计，不是交换算子本身的属性。

## 四、出口

**保留结论**：这个交换搜索配方（穿插式）未建立整体收益，按预算停止，不重跑、不扩大解释。**删除**「优于 R 的局部修复不存在」「R 是可部署方法上限」等表述。

「先找到更强 teacher 才能继续学习」这一前提**只适用于蒸馏路线**，不适用于所有学习路线。下一步另立新的有限学习包（见 [MaskCO 直接目标训练工作包](../工程实现/MaskCO直接目标训练工作包.md) 或状态入口），不继续增强 teacher。
