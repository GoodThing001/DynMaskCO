## 判读

对应工作包 §6 的四条分支：

1. **未建立B稳定优于A**。TRAIN较低，CAL混合但均无正选择均值；锁阈闭环两组相同。
2. **B与S_proxy的锁阈闭环相同，但都是baseline fallback**。这不满足原工作包中“物理代理有效而learned无额外增量”的情形，因为两者都未建立正效用。
3. ~~固定状态选择改善、闭环仍退化~~ 部分符合但非泛化。A 的「选择改善」仅出现在 TRAIN（+0.0065），CAL 上归零/略负，不能作为泛化证据；闭环仍选 ∞。
4. **两组都选 ∞、无可复现收益趋势 → 第二轮收束。** ✅

**结论**：在当前样本、实现与2000步训练预算下，A/B均未建立CAL选择与闭环正增益，按约定收束，不默认换pairwise做第三轮。B没有检出样本内冲突，不足以判断“表示损失不是主要瓶颈”。部分共同修正已落实，但源码仍有WAIT未推进到H、committed载重摘要重复加需求、训练seed兼作生成seed等限制，不能称完整表示假设已被干净否证。

**审读补充（不自动重跑）**：WAIT仅设置open_plan，没有等待至公开H的C0转移；anchor_load已含committed客户需求，projection又加一次，影响代理max_load；closed_loop对learned使用生成seed42/43/44，而导出与简单对照为0。A/B同seed仍可配对，但不能把跨seed差异全算训练随机性。closed_loop目录当前仅见汇总JSON，runner没有保存方法逐实例rows，CAL runtime=0是占位。具体代码依据、范围与复用前置见收束记录；不推断这些问题必然解释全部退化。

保留资产：event_plan_projection（可见物理投影引擎）、B 特征提取、S_proxy 无学习对照、修正的候选/导出/训练/闭环链路。这些作为研究接口留存；方法假设（完整计划评价能否带来可部署收益）与论文范围需要重新讨论。
