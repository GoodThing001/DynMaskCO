# N0服务失败后的决定：关闭当前入口，仅做一次预留资源对照

> 2026-09-19 · 当前无保护N0-r1服务Gate失败，不进入N1。下文是单独编号的**方法改动N0-R**，尚未实现或运行，不冒充机械bug修复。用户/执行端实施，助手维护研究文档。

## 1. 决定与投入边界

1. 当前N0-r1按服务失败收束，保留代码、原始结果、未验收项；CAL成本数字仅作审计。
2. 不生成正式MaskCO标签、不训练N1、不扩候选或增加swap/2-opt、不调整冷链权重、不引入未来价值网络或未来订单情景采样。
3. 原§B预冷对照不再阻塞收束，保留条件解析关系即可，不声称已经实测排序翻转。
4. **允许一次且仅一次N0-R方法对照：约束优化层继承JF1-H-F本事件未使用的预留空车。** 保持目标/搜索不变，检验增加这一通用资源保护是否恢复服务并保留可见收益。

为什么值得这一次：JF1-H-F已有明确、可见、无须预测未来的预留机制，LNS当前允许把预留车用于普通改善。可以检验一个具体接口层面的策略假设，尚不需要新value网络。为什么不能无限继续：保护一辆车只保护一种资源，不能保证所有未来紧窗口都可服务；若仍失败，本工作包结束，不继续调预留数/时间阈值直到CAL成功。

## 2. 先纠正因果结论

已经证实的是：当前策略在CAL某实例比baseline少完成订单，违反服务前置。尚未证实“预留车被消费”就是该例唯一原因，也未证明所有近视目标必然失败。

route certificate与完整分区保证当前已知订单的合法分配，不保证任意未来到达流的可服务性。把未来订单排除在模型输入之外是因果性要求，不能因此宣称未来服务能力天然得到保护。

保留基线预留车也不是安全定理。后续仍要靠严格闭环服务Gate评价。仅当全部动作完全沿用baseline时才有轨迹相同的直接依据；局部fallback在已分叉状态上继续baseline，不能撤销此前不可逆的出车或承诺。

## 3. 唯一方法变量：预留资源约束

### 3.1 定义保护集合

在调用本事件JF1-H-F之前，以与其源码一致的规则，从idle车中按确定性顺序提取原有`slack_vehicles=1`个reserved_ids。不得以订单21、实例15、6.88时刻或实际下一揭示时间作条件。

正常调用JF1-H-F得到P0后，保护集合为上述reserved_ids中**仍未派车、仍位于depot且P0没有客户任务**的车辆。若baseline为服务当前已知订单已经启用这辆车，本事件不再将它强行冻结为空。保留baseline自身repair使用预留车的能力。

这一集合只在本事件有效，下次事件按当时公开状态重新计算；不是永久锁死固定车辆。车辆ID只用于复现baseline确定性选择，不作为学习标签/风险特征。

### 3.2 候选与写回约束

- 候选重建的allowed_vehicle_ids排除保护集合；同一集合下的完整候选须保持这些车的P0指令不变，不增加虚拟客户或提前关闭。
- 其他允许重规划车辆仍可做联合移除/插入，不把所有首段dispatch锁死，不扩展到committed或原冻结车辆。
- 最终写回前独立复核保护集合、完整分区及deferred；分区正确不能替代资源保护检查。
- 模型输入与候选选择不读取未来订单。此保护规则只依赖当前车辆状态和baseline当事件的P0。

后续如果进入MaskCO，非学习对照和学习重构必须使用同一保护集合、认证与fallback。保护规则带来的收益属于策略框架，只有此基础上相对非学习重构的增量才属于MaskCO。

## 4. 两个变体共享的必要边界处理

这些是运行口径修正，guard-off/guard-on共用，不能把它们混成资源保护的增量：

- 按逐事件保存并正确累计P0_feasible/finite、reason、已知未补全订单；无效P0评分不得参与标量比较。评分无效时停止本事件可选LNS，保留该状态下baseline输出及其deferred，记录fallback。该动作不保证已经失去的服务可恢复。
- 对有限/可行候选才比较J_vis；已有保护部分不变的检查在两组共用。
- timing区分总replanner与内部搜索。保持原16次尝试、搜索阶段1秒上限；总耗时完整报告，明确不是整方法硬1秒保证。不要为了本轮另换预算策略。
- 对“新车预冷恰好一次”使用能够区分一次与两次的断言；保存已有独立回放的脚本/结果和误差分母。Q约0.07%的单次差异可作为该案例误差，不能写成全局界。不为此新开大规模物理实验。

如这些共同处理改变无保护版本行为，应报告新控制结果，不能直接把历史r1和新guard相减后全部归因guard。

### 必须记录的最小机制信息

对每次计划改变保存：当前clock、保护集合、P0与候选的保护车任务、新增出车集合、每车下一承诺及可用时刻、deferred、P0评价状态、保护拒绝计数、是否有实际写回。对inst15从首次分叉到漏单的区间保留完整方案与车辆状态。

## 7. 对研究主线的影响

本轮没有否定MaskCO，也没有建立MaskCO正效用。阶段结论是：**成本下降、当前可行和完整动态服务是三个不同条件，学习目标前的参照策略必须先满足服务前置。**

若这一有限、公开的资源保护也不能形成有效参照，下一次应重估未来需求不确定性、可保留资源状态与方法范围；不自动进入情景采样、RL/value网络或更大训练。当前只实施以上单变量方法对照，避免无限延长机械纠错链。
