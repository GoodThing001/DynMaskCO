# P2-C-CAMR-STATIC-01：措辞更正——锚点后首动作 `0` 是"后缀为空"，不是"返仓动作"

**性质：只读措辞更正（不改变任何数字）。** 不修改 `REPORT.md`、`ERRATA_L1B_01.md`、任何 T1/T2/`preflight`/Pass A/B 工件；未加载模型、未重跑搜索、未产生新实验；不需要授权。

## 1. 被更正的表述

- `REPORT.md` §3 第 1 点、§5 表格中写作"让在途车**就地返仓**（首动作 `0`）"，以及 §0/§4 的"返仓"措辞；
- 复核意见采纳表沿用了同一表述（"MaskCO 倾向让在途车返仓 13/19"）。

数据不支持"返仓动作"这一读法。

## 2. 数据实际显示

从冻结工件 `pass_a_run1.json` 的 `rows[].sides.{model,distance}.cvid_suffix` 与 `suffix_first_after_anchor` 直接读出（19 单元，与 `pass_a_run2.json` 一致）：

| | 模型侧 | 距离侧 |
|---|---:|---:|
| 锚点车后缀为空 `[]`（`suffix_first_after_anchor = 0`） | **13 / 19** | **0 / 19** |
| 锚点车后缀非空 | 6 / 19 | 19 / 19 |

- `suffix_first_after_anchor` 的取值规则是 `s[0] if s else 0`，所以 `0` 的**唯一**来源是 `suffix == []`。
- `route_check`（`p2_pos01_reference.py:341-359`）在遍历后缀时遇到 `c == 0` 即判非法，因此 `0` **不可能**作为后缀元素出现；"空后缀"是其唯一合法表示。
- 6 个非空单元的模型侧后缀都只有 **1** 个订单（`[40]` `[37]` `[12]` `[44]` `[21]` `[11]`），而距离侧对应单元保留 **2–3** 个（如 `[12,37,40]`）。

## 3. 正确的表述

> 在 13/19 个单元中，模型侧把**在途车在锚点之后的后缀置空**——即在途车执行完已承诺的那条腿之后不再承担任何取货任务；队列订单由**其他车辆**服务（`check_plan` 的 exact-once 与参考检查在该单元通过，可证不是丢弃）。距离侧 **19/19** 都继续给在途车安排下一站。

也就是说，这是**跨车任务重分配**，不是"返仓动作"，也不是"队列被丢掉"。**这不改变任何计数**：L1-A 仍是 19/19 合法差异、17/19 锚点后首动作不同、13/19 模型侧后缀为空；L1-B 仍是 0/19 覆盖、19/19 未覆盖；全部 sha256 不变。

## 4. 对 H-QUALITY 的影响（仅记录，不构成授权）

这一点恰好落在复核提出的机制问题上：

- 模型侧**系统性地**给在途车安排更少的锚点后工作（13/19 清零、其余 6/19 只留 1 单），距离侧从不清零且保留 2–3 单；
- 因此"是否存在有效的跨车重分配"这一问法是对的，而"是否在返仓"是一个编码误读；
- 但**合法重分配 ≠ 有价值重分配**：现有证据只证明计划合法且 exact-once，完全不能判断把队列移给别的车是否更好（可能更好：释放早返、减少绕行；也可能更差：把工作堆给原本更紧的车）。这必须由 H-QUALITY 的可证伪设计回答，且仍然**不得**升级为 L2 或在线 utility 主张。
