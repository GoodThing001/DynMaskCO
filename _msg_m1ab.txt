S-15 ILLEGAL PLAN MUST NOT REACH THE QUALITY CALLBACK
  Static basis: DOWNSTREAM at d3_composed_certifier.py:110, the legality gates at
  :136-147, and the quality branch inside "if legality_ok:" at :206 with the ONLY
  quality_check_fn call at :291. So zero calls is structurally guaranteed on the
  normal path. The case therefore asserts the CALL COUNT is exactly 0 and that
  quality.state is still QUALITY_CAPABILITY_GAP - not merely that the verdict is
  not-ok, because "reject after calling" would still pass a verdict-only test.
  Verdicts reserved: LEGALITY_FIRST_HOLDS / ILLEGAL_PLAN_REACHED_QUALITY_IMPL /
  REPORT_SCHEMA_INVALID.

S-16 STRICT TYPE CHECKING OF THE QUALITY CALLBACK
  The current implementation is UNGUARDED at the type level: :291 unpacks with no
  check and :292-293 use plain truthiness, so a non-bool qok ("no", [0],
  {..}, 1, numpy.bool_(True)) is read as pass, clears blocking_capability_gaps,
  and can make installable True at :298. A strict adapter-side verifier is
  specified with T1 no-truthiness (type(qok) is bool, never "== True"), T2
  missing-means-refuse (especially omega_membership_checked), T3 adapter-first
  because the composer does none of this. Nine negative controls are specified.

S-17 APPLICABLE DOMAIN AND STRICT-ONLINE INFORMATION ISOLATION
  In-domain/out-of-domain synthetic contexts for the omega membership check; a
  registry gate refusing TEST_ONLY / uncertified / no-omega-declaration /
  SHA-mismatch entries; and a two-track isolation design (least privilege up
  front, plus a post-hoc read_order_ids audit rejecting any order with
  reveal_time > clock). The repository's own paired primitives
  coord_normalize_visible vs coord_normalize, and hard invariant 3 in the root
  CLAUDE.md, are cited as the existing precedent.
  A hard constraint is added: with no audited real quality implementation, even
  a fully passing synthetic suite must leave quality.state at
  QUALITY_CAPABILITY_GAP and installable False. A synthetic pass must never be
  used to claim real decision-time quality certification.

S-12 PRECISION CORRECTION (user's correction accepted)
  The original "base_plans=Pc must be refused" was too strong and would
  misjudge legal candidates that legitimately reconverge to P0. S-12 now tests
  PROVENANCE AND ALIASING instead of value equality: not the same object, no
  shared mutable storage or shared memory, base sourced from a frozen P0 artifact
  with a matching registered SHA, and the candidate generation path must not
  mutate P0. A positive control requires that a candidate whose content EQUALS P0
  is ACCEPTED, proving the case no longer treats content equality as cheating.
